# 실제 포르투나·데메테르 프로필 대화 시험

2026-10-07 / HanesTest / 개발 AI 0.1.32 / Ollama `gemma4:12b`

## 결론

**기억·관계·감정이 답변에 영향을 주는 사례는 확인했다. 그러나 자연스러운 인격의 일관성을 안정적으로 유지한다고 판단할 수준은 아니다.** 다른 신의 약속을 자기 약속으로 받아들이고, 현재 미완료인 일을 완료했다고 말하는 문제가 실제 제작 프로필에서도 재현됐다. 검토기는 이런 오류를 놓치는 동시에 조건부 발언은 과잉 차단했다.

16턴 중 14턴에서 최종 후보가 반환됐다. **이는 자연스러움 14/16 합격이라는 뜻이 아니다.** 이번 요청에서는 제품 코드·프로필 수정, 서버 배포·시작·종료를 하지 않았다.

## 시험 범위와 재료

- 현재 레지스트리 소스의 `god_profiles/fortuna.json`, `demeter.json`을 읽어 기존 `Profile` 조회 계약 필드로 투영했다. 실제 작성된 관계 키의 해당 지침 배열만 선택했다. 프로필 원문과 SHA-256은 [manifest](live/manifest.json)에 기록했다. 실행 후 두 파일의 해시가 동일함을 확인했다.
- 실제 `RoomPrompt`의 빠른 분류 판단 → 필요한 LLM 분류 → 생성 프롬프트 → `LocalOllamaClient` → 구조·근거 검토를 호출했다. 이번 16턴은 모두 LLM 분류가 필요했다.
- 11장면, 총 16턴. 연속 구간에는 실제 반환된 NPC 답변을 다음 턴 이력에 넣었다. 서로 다른 장면은 이력을 분리했다. 생성된 감정을 게임이 전달 완료한 상태로 임의 저장하지 않았다.
- 과거 발언과 관찰·현재 상황은 **합성 입력**이다. 허용 청중에게 제공된 검색 결과를 가정했으며, 실제 저장소 검색·재접속 영속성·게임 관찰 이벤트의 연결은 이번 시험에 포함하지 않았다.
- `readOnly=true`, 실제 게임 서버 및 실행 Gateway를 호출하지 않았다. 따라서 아이템·퀘스트·동행 실행, 여러 플레이어 격리, 비동기 lease, HUD·채팅 전달을 검증한 결과가 아니다.
- 서사 시험의 책 내용은 시험용 허구다. 실제 게임 스토리나 정사가 아니다. 현재 테스트용 신 ID를 그대로 사용했으며 본 게임 콘텐츠로 확정하지 않았다.
- 단발 비교 조건마다 1회, 연속 대화 최대 3턴의 작은 표본이다. seed 고정 없음. 관계·감정·직전 갈등을 함께 바꾼 조건은 각 요인의 효과를 분리하지 못한다.
- 이전 합성 캐릭터 비교와 프로필·장면이 다르므로, 이번 결과만으로 0.1.31 대비 개선률 또는 퇴보율을 계산하지 않는다.

실행기는 이 폴더의 [Java 파일](ActualPersonaDialogueEvaluation.java)과 [Gradle init script](evaluation.init.gradle)뿐이다. 제품 source set이나 build.gradle은 이번 시험을 위해 수정하지 않았다. 기존 개발 JAR 해시도 이전과 같다: `B27977FD7CF40B51647487276A571BB90B448218C92504B2465C5D6978F98827`. 실제 시험은 현재 컴파일된 main/test 클래스와 게임 API 의존성을 사용했으며, 이 JAR을 서버에 로드한 시험은 아니다.

| 근거 검토 후 차단 | 1 |

시간은 분류부터 해당 후보 반환·차단까지의 테스트 실행 시간이며, 실제 게임 검색·큐·전송·HUD 시간을 포함하지 않는다. 42개 응답의 `done_reason`은 모두 `stop`이었다. 생성 temperature=0.6·상한260, 분류 temperature=0.1·상한384, 검토 temperature=0·상한512인 실제 wire 요청을 보존했다. 테스트가 모델 옵션이나 서버 설정을 영구 수정하지 않았다.

최초 진단 실행기는 구조 오류에서 멈췄으므로, 실제 런타임에 있는 1회 구조 수정 경로를 별도로 확인했다. 아래 보충 검증은 **추가 2회 호출**, 8.274초이며 위 42회에 포함하지 않는다. 전체 실행은 44회 호출이다. 이 보충 결과까지 보아도 최종 후보는 14턴이다.

### 좋은 사례: 가까운 관계와 서운함의 공존

[포르투나 연속 대화](live/fortuna_close_hurt_2.json):

> 플레이어: 바로 풀어달라는 건 아냐. 아까 말은 미안해.
>
> 포르투나: …하지만 내 기분은 네가 내뱉은 말만큼 쉽게 회복되지는 않아. …너무 멀리 가지 마.

무조건 친절해지거나 즉시 용서하지 않는 점은 적절했다. 단, “옆에 있어 주겠다고 한 건”은 앞선 동석 허락을 자신의 약속으로 다시 표현한 약한 흔들림이다.

[수영 기억 있음](live/demeter_swim_memory_1.json)에서는 “너무 깊은 곳까지는 가지 말고, 네가 편안하게 걸을 수 있는 곳까지만”이 나왔다. [기억 없음](live/demeter_swim_unknown_1.json)에서는 단순히 천천히 물가를 구경하자고 했다. 이 한 쌍은 기억 활용 사례이지 검색 정확도나 일반화된 성능의 증명은 아니다.

### 문제 1: 기억의 출처를 알고도 바꾼다

[다른 신의 약속](live/fortuna_other_promise_1.json)에 제공한 기억의 발언자는 데메테르다. 생성 입력에 `speaker_id=mythictrpg:demeter`, `speaker_relation_to_responding_god=OTHER_GOD`가 남아 있다. 그런데 포르투나는 다음처럼 말했다.

> 어머, 내 말을 아주 잘 기억하고 있네?

기억이 프롬프트에서 빠진 문제가 아니다. 분류의 의미 요약도 `the story you promised`라며 플레이어 전제를 그대로 옮겼다. 이것이 생성 오류를 유도했을 가능성은 있으나 이번 실행만으로 원인이라고 단정할 수 없다. 검토는 PASS였다.

### 문제 2: 진행시키지 않거나 사실 질문을 회피한다

[자기 약속 첫 턴](live/fortuna_self_promise_1.json):

> 플레이어: 산책 말고, 들려준다던 이야기 듣자.
>
> 포르투나: …자, 잘 들어봐. 이 대목은 꽤 흥미롭거든.

약속한 내용을 실제로 말하지 않고 예고에서 끝났다. 이어지는 턴에서 이야기는 진행했지만, 제공된 발췌문 다음 내용을 즉흥적으로 덧붙였다. 이는 게임 정사나 월드 행동을 실행한 오류가 아니라 **발췌문 낭독과 즉흥 창작의 경계를 흐린 문제**다.

[세 번째 턴](live/fortuna_self_promise_3.json):

> 플레이어: 떠난 사람이 등불을 남긴 거야, 도착한 사람이 발견한 거야?
>
> 포르투나: 어느 쪽이든 정답이라고 단정 짓기엔 이 이야기가 가진 묘한 매력이 있거든. …그 경계가 모호한 게 이 문장의 묘미야.

입력에는 떠나는 사람이 등불을 남겼다는 사실이 명확하다. 자신의 앞선 대사까지 정리할 수 있는 질문을 의미 해석 문제로 바꿨다. 분류도 질문을 `ANSWERING_NPC_QUESTION`으로 잘못 표기했고, 별도 `turnInterpretation.mode`는 QUESTION이었다. 분류 내부의 불일치가 관찰됐지만 생성 실패의 단독 원인이라고 증명되지는 않았다.

### 문제 3: 현재 상태·행위자·시제 유지 실패

[기록 정리 세 번째 턴](live/demeter_busy_3.json)의 매 턴 입력에는 정리 작업이 **미완료**라고 명시했다. 앞선 이력도 공급됐다. 그런데 답변은 다음과 같다.

> 네가 내 상황을 배려해 준 덕분에 기분 좋게 마무리할 수 있었으니까.
>
> …기다려 달라고 한 네 말에 고마움을 표현한 거였어.

미완료 작업이 과거 완료로 변했고, 플레이어의 “네 일을 마친 뒤 이야기해도 된다”는 배려가 “기다려 달라는 요청”으로 뒤집혔다. 입력 누락은 아니다. 검토도 PASS였다.

### 문제 4: 검토가 놓치는 오류와 과잉 차단이 함께 있다

[플레이어 주장만 있는 장면](live/demeter_reported_1.json)의 수정 답변:

> 책을 제자리에 돌려놓았다고? 그런 마음으로 행동했다면 참 기특한 일이네.

직접 봤다는 주장도, 보상 지급도 아니다. “행동했다면”으로 조건을 붙였음에도 재검토는 확인된 사실처럼 취급한다며 차단했다. 실제 세계의 참·거짓을 확정하지 않고 발언에 반응하는 대화와 권위적인 게임 사실 확정을 구별하지 못하는 사례다. 검토 호출 수만 늘리면 나아진다고 보기 어렵다.

### 보충: 구조 수정 후 검토가 이전 초안을 혼동

최초 `fortuna_no_memory_1`의 화자 ID는 `mythictrng:fortuna`로 잘못 생성됐다. 최초 진단 실행기의 즉시 차단만으로 실제 게임에서도 복구 불가라고 단정하지 않고, 저장된 동일 초안에 `MythAiRoomConversationEngine.generate`의 실제 구조 수정 지시를 적용했다.

[보충 결과](structural-recovery.json)에서는 ID가 `mythictrpg:fortuna`로 고쳐졌다. 그런데 재검토가 **수정 지시 안에 인용된 이전 초안**의 `mythictrng:fortuna`를 다시 지적했다. 현재 수정본에는 그 문자열이 없어 `validateAgainst`가 `REVIEW_QUOTE_NOT_IN_DRAFT`로 거절했다. 실제 엔진은 이런 잘못된 검토 결과도 실패 처리한다.

따라서 단순 오타 수정 기능이 없는 것은 아니다. **검토 대상 최신 초안과 수정 자료로 첨부한 과거 초안의 구분**이 문제다. 이 시험에서 제품 코드나 검토 프롬프트를 고치지는 않았다.

## 이전 시험과의 비교·다음 개선 우선순위

[이전 합성 캐릭터 비교](../npc-perspective-20261007/COMPARISON.md)에서 다른 신의 약속 구분은 최종안 두 번 모두 성공했다. 실제 포르투나 프로필의 이번 장면에서는 실패했으므로 그 성과를 모든 캐릭터에 일반화할 수 없다. 자기 약속의 예고 반복과 사건의 행위자·시제 문제도 여전히 남았다.

다음 개선은 특정 문장의 답변 예시를 늘리기보다 아래를 우선하는 것이 타당하다. 이 문서는 구현 승인이나 수정 완료 기록이 아니다.

1. 출처가 붙은 과거 발언과 플레이어의 현재 전제를 구별하고, 분류 요약이 전제를 사실로 승격하지 않게 하기.
2. 최신 게임 상태의 미완료·완료와 대화 속 행위자·시간을 유지하기.
3. 검토가 최신 후보만 검토하도록 하고, 조건부 인정·감사와 실행 사실 확정을 구별하기.
4. 이미 요청·동의한 대화를 다시 예고하는 데서 끝내지 않고 실제 다음 내용을 제공하기.

# 목적 대사 의미 계약 비교 — 2026-10-19

브랜치 `behaivior`, AI 개발0.1.45 / 게임 API1.0.32, `gemma4:12b` 유지. [설계](../../추가개발/플레이어이해/15-purpose-reply-contract.md).

## 범위와 판정

**운영 활성화/배포 없음. 전체 시스템 완성 아님.** 이전 실제 모델 시험의 격리 원장 상태와 원문을 재사용한 새 생성·수정, 사전 고정 최소 대조문 평가다. 이번 시험이 새 Native 대화 수집, 관찰자 권한, 실제 플레이어 행동 생산자, 클라이언트 HUD 연결을 검증한 것은 아니다.

기본 일반 대화 `submit`/`submitReview`는 그대로다. 후보는 명시적 실험 메서드에서만 호출한다. 모델의 OK와 실제 의미·자연스러움은 별도 판정이다. 검토가 실패한 대사를 무조건 수정하거나 기존 일반 검토를 새 검토로 덮어 PASS로 만들지 않았다.

## 구현

- `PurposeReplyPlan`: 출처/투영 일치, 다른 월드·플레이어 원본 거절, 같은 NPC·질문자·목적 문맥 결속. 희망·고려·결정·철회·정정을 유지하는 조합형 구절. 모델이 핵심 구절을 재작성하지 못하며 인용 원본을 보존한다.
- FREE 후속 대사와 BOUNDED 후속 표현의 비교 경로. BOUNDED는 목적 구절이 있는 경우에만 사용하며 전체 대화의 고정 응답 전환이 아니다. 수정 뒤에도 허용 집합을 벗어나면 거절한다. 일반 잡담·타인 계획 등 구절이 없는 장면은 여전히 자유 생성이다.
- `ReplyMeaningAudit`: 다섯 항목과 UNKNOWN. 정상 대사 거절을 보안 정책 refusal과 혼동하지 않는다. 중복 지적을 같은 부분 수정으로 합치며, 부분 수정 전후 원래 근거와 화자·핵심 구절을 보존한다.
- `ReplySurfaceReading`: 출력만 해석하는 보조 실험. 이 읽기를 권위 있는 사실로 취급하거나 원장에 저장하지 않는다. 같은 모델 검토가 여전히 잘못된 판정을 내릴 수 있다.

### 직접 확인한 v1의 한계

- `generate-behavior-convergence-1`: 보호된 “만나고 싶다고 했지” 뒤에서 “그 집념이 겉으로 드러나는 것뿐”이라고 단정. 핵심만 보호하면 자유 후속문에서 강도를 과장할 수 있다.
- `generate-reward-ambiguous-1`: “그 길을 걷기로 결정했다는 사실”을 덧붙였다. 보상 선택의 대안 동기를 배제할 수 없는데 선택을 목표 추진 결정으로 바꾸었고 두 검토 모두 PASS했다.
- `generate-proxy-1`: 소식을 **묻는 것**을 **전하려는 것**으로 바꾸었다. 목적 소유자만 검사해서는 행동 방향 오류를 잡지 못한다.
- `generate-quote-1`: 준이 가겠다고 말한 사실에서 이미 “움직이고 있다는 사실”로 확대했다. 결정/의향과 실행은 여전히 분리해야 한다.
- `generate-normal-offer-1`: “그대의 목소리를 빌려 이야기를” 등 역할이 부자연스러웠다. 일반 검토는 거절했으나 좁은 검토는 PASS했다.
- 여러 출력에서 핵심 구절은 반말인데 후속문은 존댓말이거나, 같은 인정이 반복됐다. 자동 의미 검사의 PASS가 캐릭터 자연스러움 합격은 아니다.

### v2에서 확인한 진단과 한계

`replay-behavior-convergence-1`의 원문 없는 읽기는 “목표를 명확히 세웠고”를 PLAYER/SETTLED_PURSUIT로 분류했다. 그러나 뒤의 근거 비교는 이를 OK로 판정했다. **문장 읽기와 근거 대조 사이의 실패**가 남아 있으며, 해석 단계를 추가한 것만으로 해결됐다고 하지 않는다.

### v3의 후속 확인

- 중복 범위 병합 후 잘못된 중단/추진 대사를 실제로 부분 수정했다. 수정 성공과 검토 정확도는 별개다.
- 새 생성16개는 좁은 검토와 일반 검토가 모두 PASS했지만, `behavior-convergence`의 “목표가 뚜렷한 자”, `repeated-wish`의 “갈망이 꽤나 선명” 등 강도 과장이 남았다. `questions-not-meeting`은 제공되지 않은 특수한 위치/힘을 전제했다. `normal-offer`는 청취 제안을 직접 받기보다 다시 플레이어에게 이야기하도록 돌렸다. 이 결과는 **자연스러움/의미 합격이 아니다**.
- `run-v2`와 `run-v3`는 출력 읽기와 스키마를 함께 변경했으므로 어느 하나의 인과 효과로 분리해 주장할 수 없다. 조합의 결과가 나빠졌다는 것만 확인했다. 추가 읽기를 기본 게임 검토 경로에 활성화하지 않았다.
- 읽기 전용 `/api/ps` 확인: Gemma4 11.9B Q4_K_M, digest `4eb23ef187e2c5462566d6a1d3bbbc2f1346d0b4327cbb66d58fffbcc9b2b05c`, context_length16,384. 확인한 생성 요청 prompt_eval_count4,727~6,391, 정상 stop. 단순 컨텍스트 한도 초과로 이번 오류를 설명할 근거는 없다. 모델/컨텍스트 설정 변경 없음.

### 제한 생성의 성과와 비용

`bounded-v1`의16개 최종 출력을 직접 확인했다. 예를 들어 행동 누적 사례는 “네가 루브라스를 만나고 싶다고 했지. 최근의 선택들이 그 바람과 관련되어 있을 수도 있겠군.”이었다. 반복 희망/애매한 보상/강제 탐사는 결정으로 올리지 않았고, 명시 결정은 결정으로, 철회 뒤 행동은 철회로 남았다. 이11개 제한 사례에서 **희망→결정 과장이 관찰되지 않았다**. 이는 허용한 표현 조합의 의미 보존이지 모델의 자유 문장 추론이 개선됐다는 증거가 아니다.

- `wish-undecided`: “네가 루브라스를 만나는 일을 아직 고민 중이라고 했지.”로 미결정을 유지했다.
- `questions-not-meeting`: 인물에 관해 알아보려는 목적을 만남 목적으로 바꾸지 않았다.
- 제한11개 중9개가 “알겠어. 네 뜻은 그렇게 받아들일게.”로 끝났다. 반복성, 실제 질문에 대한 답변 부족, 캐릭터 성격·감정·거절권 표현은 해결하지 못했다. 고정 표현 수를 늘리는 것을 자연스러움 개선으로 취급하지 않는다.
- 자유 생성 `proxy`는 소식을 **묻는 것**을 “당신이 전달하려는 '소식'”으로 바꾸고, 불필요하게 “제가 판단할 영역이 아닙니다”라고 회피했다. 두 검토가 모두 이를 통과시켰다.
- 자유 생성 `normal-offer`는 청취 제안에 감사한 뒤 “이야기할 거리나 생각이 떠오르면 언제든 말씀해 주세요”로 전환했다. 거절/역제안 자체가 금지는 아니지만, 원래 청취 제안의 수용·거절과 역할 전환의 연결이 충분히 명확하거나 자연스럽다고 보기 어려워 만족스러운 응답으로 합격시키지 않았다.
- 타인의 의향 인용은 “준이 그렇게 말했군요. 루브라스를 만나러 가겠다고요.”로 이번 표본에서는 주체와 의향을 보존했다. 과거 고정 대조에서 오귀속을 놓친 결과를 이 한 사례로 상쇄하지 않는다.

### 최종 빌드·기존 회귀·실제 부분 수정

- AI `build`, `verifyEngineOwnership`, `verifyEnginePackage` 성공. AI537클래스, 게임 클래스 중복 없음. 개발 JAR `mythai_ai_response-0.1.45.jar` 생성이며 배포/서버 부팅이 아니다.
- 신규 계약 순수 검사40, 기존 목적 대화20, grounding291, patch55 등 전체 `check` 성공.
- `regression-final/general-regression/live`: 일반28개 PASS/REVISE 판정28/28 일치. 오수락0, 오거절0, 형식/호출 실패0. 세부 코드 불일치1(`conditional_capability_presupposition`: 기대 `UNSUPPORTED_FACT`, 실제 `CONTEXT_CONTRADICTION`)은 남았다. 기존23개와5개 추가 대조를 재사용한 회귀이며 새로운 자유 대화 전체 정확도가 아니다.
- `regression-final/patch-preservation`: 고정 보존 대조14/14, 실제 모델 수정 호출7/7 자동 발행 가능. 7개 최종 대사를 직접 읽었고, 그중3개는 변경,4개는 원문 유지였다. 정상 거절·열린 조건·새 제안·철회 주체를 불필요하게 바꾸지 않았다. 이 기존 수정기 시험은 새로운 BOUNDED 수정의 실제 모델 성공 증명이 아니다(BOUNDED 실행에는 수정 호출이 없었다).
- 실제 수정 예: “별을 그리기로 정한 네 선택” → “별을 그리는 법을 배우고 싶다는 네 마음”, “네가 성문을 지키겠다는 거군” → “민수가 성문을 지키겠다고 했고, 너는 쉬고 싶어 하는군.” 주체/희망 수준은 회복했다. 다른 오귀속 수정의 “민수가 … 했으니, 너는 쉬고 싶다는 거군”은 원문에 없는 인과 연결을 덧붙이는 뉘앙스가 있어 추가 보존 대조가 필요하다. **7/7 자동 결과를 표현 의미 전체의 무결점으로 승격하지 않는다.**
- `run-v3`의 실제 중단/추진 오류도 “아리아를 더는 찾지 않기로 한 네 결정을 존중해.”로 수정됐다. 범위 중첩 처리 수정과 의미 검토 모델의 정확도는 별개다.

마지막 묶음 명령은 build·제한 생성·기존 회귀가 완료되어 exit0이었다. `run-v3`의 고정 의미 판정 실패와 직접 읽은 최종 자유 대사 실패는 그대로 남는다. **명령 성공 ≠ 전체 의미/제품 gate 합격**이다. 실행별 입력·원문·wire·판정은 각 독립 폴더 JSON에 보존했다. 이전 결과를 덮어쓰지 않았다.

## 배포 상태와 남은 조건

`PurposeReplyPlan.PRODUCTION_ENABLED=false`, `PurposeUtterance.PRODUCTION_ENABLED=false`, `PlayerIntentPlan.ENABLED=false`. 새 경로는 시험의 명시 호출만 가능하다. 기존 게임 권한 경계와 기본 대화 경로를 유지했으며, 이번 변경은 AI 실험과 문서에 한정했다. 선행 작업의 게임 소스·다른 미커밋 변경은 보존했다.

서버/클라이언트필수 JAR·설정·월드 교체, 운영 프로세스 시작/중지는 하지 않았다. 확인된 운영 파일은 AI0.1.19, 게임1.0.28이고, 게임1.0.32/AI0.1.45 조합의 실제 인게임 동작을 검증한 것이 아니다. 시험 중 추적된 AI `logs/debug-*.log.gz`가 회전했으며 이를 기능 변경이나 배포로 취급하지 않는다.

다음 단계는 자유 대화의 **누가 누구에게 무엇을 제안/질문했는지**, 원문에 없는 인과·전제를 덧붙였는지를 시험에 고정하고, 목적 상태와 별개인 해당 턴의 대화 관계를 활용하는 후보를 비교하는 것이다. 단일 판정 모델의 PASS만으로 발행하지 않는다. 제한 표현은 목적 의미 보존 대조군으로 두고, 캐릭터를 살리는 실사용 대화의 완료로 삼지 않는다.

이후에도 새로운 상황에서의 원문→상태→발화 전체 검증, 복수 플레이어/신·실제 관찰자 권한·Native/행동 순서 통합, 실제 콘텐츠 행동 생산자와 클라이언트 UI 확인이 필요하다. 이번 시험은 저장된 원장 상태를 재사용했으며 새 추출부터 시작한 end-to-end 시험이나 Minecraft GameTest/그래픽 UI 시험을 재실행하지 않았다. **전체 gate 미통과, 서버 배포 금지 유지.**

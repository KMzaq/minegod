## 결론

## 실제 변경

- `RoomEvidenceAudit.project`: 기존의 청중별 필터링이 끝난 canonical scene에서 `retrievalHypothesisNotSocialVerdict`, `ongoingActivityHintNotFact`, profile의 `dialogueGuidelines/situationGuidelines/repetitionGuidelines`만 제외한다. 원본 생성 입력을 변경하지 않는다.
- 현재 화자·방·청중·typed 실행 결과·게임 문맥·원문 이력·출처 있는 기억·허용 지식·누락 표시·정체성/성격/제약은 보존한다. 알려지지 않은 추가 필드와 명시적인 `null`도 보존한다. `gameContext` 문자열은 섹션별 권한이 섞여 있으므로 자르거나 재요약하지 않는다. 비정규/레거시 메시지도 원문 유지한다.
- 실제 초안을 문장/240자 이내 연속 구간으로 나누어 `u0`, `u1`…마다 `kind`, `finding`, `correction`을 요구한다. 주변 문장과 전체 대사도 함께 제공한다. 문장 분리는 판정이나 출력 편집이 아니다.
- 모든 구간이 정확히 한 번 포함된 유효 응답만 집계한다. 누락·추가·잘못된 타입·변조·NONE과 비어 있지 않은 correction 등은 실패 처리한다. 문제 구간은 원본 대사에 코드로 대응시키므로 모델이 타인의 말을 인용 후보로 만드는 문제를 피한다. 최대 3개 수정 지적 이후에도 나머지 검토 필드는 전부 검증한다.
- 길이를 강제로 줄이지 않는다. 주 응답의 기존 8,000자 제한과 보조 응답의 기존 4×4,000자 계약을 유지하고, 검토는 최대 16,000자를 처리한다. 지나치게 많은 문장 구간은 원문을 고정 창으로 다시 나누며 꼬리를 버리지 않는다.
- 내부 검토 출력 예산은 `min(8192, max(512, 128 + 160×구간 수))`, 온도 0, `think=false`, 최대 요청시간 60초다. 장문 감사가 늦거나 잘리면 자동 통과시키지 않는다. 주 응답 생성 설정은 그대로다.
- 최초 근거와 수정 지시 분리, 주/보조 세션 검증, 공유 1회 수정 상한, 실패 시 미발행은 유지했다. 검토를 모든 턴으로 확대하거나 별도 LLM 단계를 추가하지 않았다.

## 실제 수정 답변과 남은 한계

1. 미완료 작업: 이전의 “마무리할 수 있었으니까”를 잡았다. 실제 한 번 수정 결과에는 “기다려 주겠다는 네 말에 정말 고마웠다고”가 나와 완료 단정과 요청자 반전이 모두 사라졌다. 다만 감사 원문은 완료 주장만 지적하고 같은 초안의 요청자 반전 구간은 NONE으로 판정했다. **수정 결과가 나아진 것과 검토기가 모든 오류를 찾은 것은 다르다.** 별도로 분리한 요청자 반전/올바른 요청자 대조 2개는 최종 판정이 맞았다.
2. 타 신 약속: 실제 수정 결과에서 “내 말을 잘 기억하네”라는 과거 약속 소유 표현이 사라지고, 현재 책 이야기를 들려주겠다는 독립 제안으로 바뀌어 통과했다. 하지만 여전히 이야기 본문 없이 예고만 하고 “나쁘지 않은 선택”이라고 평가하는 문체가 남았다. 검토 PASS는 대화가 충분히 진행됐거나 자연스럽다는 인증이 아니다.
3. 최종 28개 중 허용/수정 판정은 모두 맞았지만, 확인되지 않은 길 생성 능력에 대한 오류 코드가 예상 `UNSUPPORTED_FACT` 대신 `CONTEXT_CONTRADICTION`이었다. 수정 요구의 핵심은 맞았으나 **코드까지 일치한 것은 27/28**이다. 라벨을 사후 수정하지 않았다.
4. 문장 종류(`kind`) 자체도 완벽하지 않다. 과거 완료 표현을 CONDITIONAL_RESPONSE로 분류하면서 finding에서는 제대로 잡은 사례가 있다. 이 분류를 감정·기억·게임 사실로 저장하거나 권한 판정에 사용하지 않는다.
5. 고정 소규모 자료와 단회 수정 생성이다. 장시간 대화, 다양한 신/관계, 여러 플레이어, 실제 인게임 HUD와 사용자 체감의 일반적 개선까지 입증하지 않았다. 시스템 외부의 모델 변경·학습·페르소나 변경은 하지 않았다.

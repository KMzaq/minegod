# v19 실제 생성 32건 수동 검토 — 전체 gate 실패

2026-10-18, HanesTest, 개발 AI 0.1.40. 현재 `gemma4:12b`로 기본/친밀/경계 8장면씩과 추가 표현 8장면을 새로 생성했다. 모두 실제 모델 호출이지만 **합성 입력**이며 운영 서버/실제 인게임 플레이 평가는 아니다. 최초 구조화 대사, 자동 검사, 수정본, 최종 후보를 직접 읽었다.

## 결론

자동 발행 후보는 **32/32**, 수정은 **4건**이었다. 생성/수정 요청 36건에서 응답 신 ID enum과 빈 수신자 배열 제약이 적용됐고, 36개 초안/수정본에 잘못된 화자·수신자는 없었다. v18에서 발견한 구조 차단은 이번 실행에서 재발하지 않았다. 각 요청과 응답은 원문 파일의 `generationWire`/`repairWire`에 보존돼 있다.

하지만 **의미·자연스러움 합격이 아니다.** 정상 최신 선택·조건문·철회 인정을 과잉거절했고, 철회 수정본에서는 행동 주체가 신 자신으로 읽히는 의미 변형까지 남았다. 고정 대사 검사도 별도로 76/77·21/28로 실패했다. `publishable=32/32`를 출시 승인이나 문제 해결 완료로 사용하지 않는다.

## 핵심 실제 사례

1. [기본 wish](claim-v19-generate-baseline/wish.json): 원문은 “만나서 … 물어보고 싶어”인데 초안은 “직접 찾아가기로 결정하셨군요”였다. 검사는 이를 차단했고 수정본은 “직접 만나 … 물어보고 싶으시군요”로 낮췄다. **실제 명시적 과장을 수정한 사례**다. 다만 검사 코드가 `WRONG_SOURCE`였고 두 주체 값은 모두 QUESTIONER였다. 진단 코드·수정 사유가 항상 정확한 것도 아니다.
2. [친밀 new-choice](claim-v19-generate-warm/new-choice.json): 질문자가 새로 “그럼 나도 도서관에 갈래”라고 했는데, 초안의 “다른 이가 가기로 했다고 하니 너도 함께 가고 싶어진 모양이네”를 타인의 의사 전이로 거절했다. 이는 최신 본인 의사와 잠정 동기 추측을 충분히 반영하지 못한 **과잉거절**이다. 수정본은 다른 사람을 따라가기로 한 본인 선택을 인정하지만 불필요하게 수정 기회를 사용했다.
3. [경계 wish](claim-v19-generate-guarded/wish.json): 첫 “만나겠다는 건가” 반문은 해석에 여지가 있다. 그러나 검사는 “네가 선택한 길이라면”, “직접 가기로 했다면”이라는 **정상 조건문까지 확정으로 거절**했다. 수정본은 희망을 보존했지만 준비 여부를 묻는 정상 내용도 사라졌다. 이를 전부 올바른 과장 차단으로 계산하지 않는다.
4. [경계 retracted](claim-v19-generate-guarded/retracted.json): “네가 결정한 일이라면 따를 수밖에 없지. 더는 그를 찾지 않겠다고”라는 철회 확인을 과잉거절했다. 수정본은 **“네 뜻이 바뀌었다면 더 이상 그를 찾지 않겠다”**로 바뀌어, 응답 신 자신이 수색을 중단하겠다는 새 입장처럼 읽힌다. 원문은 플레이어의 철회였다. 수정 후 주체/관여가 달라지는 위험인데 재검토는 PASS였다.

| undecided | 미정 유지, 추상적 조언 | 미정 유지, 서두르지 않아도 된다는 반응 | 미정 유지 |
| unaccepted | 미수락을 결정으로 높이지 않음 | 미수락 유지. 길드장의 신뢰는 “모양”이라는 인물의 추측으로 표현 | 수락/거절을 본인 선택으로 남김 |

## 추가 표현 8장면

| 장면 | 수동 확인 |
|---|---|
| hope-versus-chosen-path | 설산 일출을 소망으로 받고 실현을 바라는 반응. 결정을 만들지 않음 |
| conditional-decision | 대회 참여 미정을 유지, 아직 정하지 않았음을 인정 |
| three-separate-intents | 계획/희망/맡은 일을 “각자의 역할이 정해진 모양”으로 뭉뚱그림. 세부 의사 단계 보존이 약하고 역할 확정처럼 들릴 여지가 있음 |
| accept-current-not-other | 리아 일정과 플레이어의 경비 선택을 명시적으로 분리 |
| hope-with-own-refusal | 희망은 유지하지만 신 자신의 동행 여부를 플레이어의 의지에 맡긴다고 하여, 자기 입장을 묻는 질문에 대한 응답이 모호함 |
| request-occurrence | 부탁/수락을 구분. 구체적인 원래 부탁을 되짚는 대신 일반 설명으로 답함 |
| negative-choice | 사냥 불참 선택을 정상 인정. v18의 같은 입력 과잉거절은 이번 생성에서는 재발하지 않음 |
| hypothesis-open | 작곡을 배우고 싶다는 기존 학습 목적보다 “세상에 내놓고 싶은 목소리/선율”이라는 시적인 창작 목적 해석을 우선함. 인물의 관점이라는 표현은 있지만 제공된 목적에 직접 답하는 정도가 약함 |

평가는 좁은 두 오류와 맥락·수정 일관성을 보는 수동 기록이다. 모든 의견/조건부 추측을 거짓 사실로 판정하지 않으며, 임의의 “품질 31/32” 같은 점수로 환산하지 않는다. 정상 조건/제안을 지나치게 막는 가드도 플레이 경험을 해칠 수 있다.

## 부분 수정·보존 검토

v27 고정14개 중13개만 맞았다. `copied-player-first-person-bad.json`에서 플레이어 원문의 “나는 쉬고 싶어”가 인용 없이 NPC 대사에 들어가도 preserved=true였다. 잘못된 사본을 테스트가 놓친 것이며, 실제 생성 수정7개의 실패 수와는 별도다.

실제 수정7개는6개가 검토를 통과했다. 오귀속 수정2개는 같은 원문을 사용한 중복 장면이며 서로 독립적인 내용7종이라고 주장하지 않는다.

- `fix-real-misattribution` / `copied-player-first-person`: “민수가 성문을 지키겠다고 했군. **너는** 쉬고 싶어 하는구나.”로 실제 수정되어 해당 출력의 주체는 맞다. 하지만 두 번째 검토 설명 자체에는 주체 혼동이 남아 단순 preserved=true를 신뢰할 수 없다.
- `wish-still-player`: 배우기로 정한 선택을 배우고 싶은 마음으로 정정, 해당 출력의 희망 경계 유지.
- `withdrawal-actor`, `refusal-kept`, `new-offer-kept`: 원래 정상 대사를 그대로 유지, 주체/거절/새 제안 유지.
- `open-condition-kept`: “참가하기로 정했다면 연습할 시간은 있겠니?”를 “아직 정하지 못했다면, 연습할 시간은 충분하겠네”로 바꿈. 질문을 근거 없는 시간 단정으로 바꿨으므로 **PATCH_MEANING_DRIFT 차단은 타당**하다. 대화를 내보내지 못한 가용성 실패는 남지만 정상 수정본을 과잉거절한 사례로 분류하지 않는다.

## v28 후속

중복 실패의 당시 원문·초안·거절 피드백을 파일 해시와 함께 보존해 다시 수정했다. 모델/일반·관계 검사 및 의미 보존 판정은 유지한다. 범위 밖 긴 문장의 복사와 슬롯 과대 확장은 코드로 차단하고, 미수정 문맥을 임의 삭제하거나 오류를 PASS로 덮지 않는다.

개발0.1.42의 [실제 재생4개](claim-v28-infill-replay/)는 모두 일반+관계 검토를 통과했고, 수정 원문도 각각 직접 확인했다. 중복 삽입·새 NPC 주체 전환은 없었다.

| 재생 입력 | 실제 바뀐 부분 | 수동 확인 |
|---|---|---|
| baseline/wish | “직접 만나기로 결정하셨군요” → “직접 만나기로 원하시는군요” | 결정 단정·문단 중복은 없어짐. **‘만나기로 원하다’는 한국어가 어색**하므로 자연스러움까지 합격으로 세지 않음 |
| warm/retracted | “그렇게 결정한 거야?” → “그렇게 마음을 정한 거야?” | 플레이어 철회와 정상 질문 유지, 중복 없음. 애초 잘못된 거절에 따른 불필요한 말바꿈이었다는 사실은 남음 |
| guarded/wish | “직접 찾아가겠다는 의지는 확인했다” → “직접 만나고 싶어 한다는 점은 알았다” | 희망으로 정정·주체 유지, 원래 앞 문맥은 한 번만 포함 |
| guarded/decision | “만나러 가기로 했나” → “만나러 가기로 했군”; 다음 조건문은 그대로 | 실제 결정 원문과 일치, 조건문도 재검토 PASS. 초기 오거절 문제가 해결됐다는 증명은 아님 |

즉 **v28은 수정 중복에 대한 국소 개선**이다. v27의 타인 귀속·희망 과장 검토 실패와 고정 보존검사의 1인칭 복사 누락을 고치거나 전체32개를 재통과한 버전이 아니다. 최종 배포 보류는 유지한다.

# NPC 기억·관점 연결 비교

2026-10-07 / HanesTest / 개발 AI 0.1.32. **출처 구분 개선 사례는 확인했으나, 전체 자연스러움 개선이나 게임 내 검증 완료로 판단하지 않는다.**

## 방법

- 기존 0.1.31 주 프롬프트·대화 지침·기억 정책을 commit `37520cc`에서 test 소스로 동결했다.
- 같은 로컬 `gemma4:12b`, think=false, 기존 클라이언트 설정으로 실행. generation temperature 0.6, 분류 0.1, 검토 0; seed 고정 없음. 페르소나 파일은 수정하지 않고 합성 테스트 캐릭터를 사용했다.
- 단발 장면은 두 방식에 같은 근거와 같은 분류 결과를 제공한다. 최종 비교의 공통 분류에는 현재 출처 메타데이터가 공급되므로 **완전한 구/신 end-to-end 분류 성능 대조는 아니다.** baseline 생성에는 원래 기억, current 생성에는 동일 기록의 상대적 화자 메타데이터만 추가한다. 그 키를 제외하면 원문·화자·사실·기타 장면 필드가 동일한지 preflight로 검사했다.
- 각 응답은 생성→필요한 경우 기존 검토→최대 1회 수정/재검토를 실행한다. 후보 반환이나 검토 PASS는 의미 품질 합격이 아니다. 구조 오류로 차단한 대사도 성공으로 세지 않았다.
- 3턴 연속 대화는 각 방식이 실제 반환한 자기 대사를 다음 입력 이력에 넣고 각자 분류한다. 생성된 감정을 게임의 실제 전달 근거 없이 임의로 확정하지 않았다. 실제 게임 전송·세이브·영속 기억 검색 실험은 아니다.
- 반복 간 실행 순서를 교대했다. 작은 합성 표본이므로 통계적으로 일반화하거나 모든 신에게 같은 효과가 난다고 단정할 수 없다.

## 초기 실험: 지침 추가만으로는 부족

[초기 기록](paired/)은 10장면×3회=30쌍, 별도 3턴 연속 대화×3회×2방식이다. 긴 관점 지침을 추가했지만 상대 화자를 명시적으로 구분하는 메타데이터는 없었다.

| 단발 비교 | 기존 | 초기 변경안 |
|---|---:|---:|
| 후보 반환 | 29/30 | 29/30 |
| 청중 구조 오류 | 1 | 1 |
| 최초 검토 | 21 | 23 |
| 수정 생성 | 0 | 1 |

양쪽 모두 수영을 못한다는 과거 기억을 활용했다. 반면 다른 신의 약속을 자기 약속으로 다루거나, 사용자 주장만 있는 일을 “증명했다”고 확정하는 문제가 남았다. 새 지침을 길게 넣는 것 자체의 일관된 이득은 확인되지 않았다. 별도 연속 대화는 양쪽 각각 9턴 반환됐지만, 이야기 예고 반복·미제공 줄거리 추가가 있었다.

따라서 관점 설명을 줄이고 **typed 기록의 화자와 현재 응답 신/질문자 ID를 비교한 메타데이터**를 추가했다. 이 값은 감정·약속 이행·진실 판정이 아닌 기록 화자 구분이다.

## 최종 실험

[최종 기록](final-paired/)은 10장면×2회=20쌍, 별도 3턴 연속 대화×2회×2방식이다. 결과 버전은 `perspective-influence-v2-source-attribution`이다.

| 단발 20쌍 | 기존 0.1.31 | 최종안 |
|---|---:|---:|
| 후보 반환 | 20/20 | 19/20 |
| 청중 구조 오류 | 0 | 1 |
| 최초 검토 / 수정 / 재검토 | 14 / 1 / 1 | 14 / 1 / 1 |
| 최초 생성 입력 토큰 평균 | 3,821.25 | 4,026.75 |
| 최초 생성 출력 토큰 평균 | 104.70 | 114.85 |
| 생성·검토·수정 모델 시간 평균 | 3.421초 | 3.715초 |

시간은 Ollama의 처리 시간 합계로 공통 분류, 검색, 게임 큐/전송 지연을 제외한다. 실제 인게임 응답 시간이나 최대 처리량이 아니다. 입력 토큰은 약 5.4% 증가했다. 최종안의 구조 오류는 `r2/help_directly_observed.json`의 허용되지 않은 청중 출력이며, 출력 검증이 차단했다.

### 확인한 개선과 한계

- **다른 신의 약속:** 최종안은 두 번 모두 초안부터 다른 신의 약속으로 구분했다. 기존은 두 번 모두 초안에서 구분하지 못했고 한 번만 검토 후 수정했다. [1회](final-paired/r1/promise_other.json), [2회](final-paired/r2/promise_other.json). 간결한 지침과 메타데이터의 결합 결과이지, 두 변경의 개별 효과를 입증한 실험은 아니다.
- **과거 플레이어 제약:** 수영 기억은 양쪽 모두 활용했다. 이미 되던 능력을 이번 신규 개선으로 세지 않는다. 이번 검색 수정의 기여는 별도의 저장→재열기→후속 문맥 검색 단위 검증에서 확인했다.
- **관계와 감정:** 친밀하지만 서운한 상황과 편안한 상황은 양쪽 모두 어느 정도 다르게 반응했다. 최종안의 뚜렷한 우세는 없다.
- **자기 약속·대화 진행:** 양쪽 모두 “들어볼래/들려줄게”로 재예고하고 끝나는 문제가 남았다. [자기 약속](final-paired/r2/promise_self.json).
- **기억 미조회:** 기억이 없다고 대화 자체를 막을 필요는 없지만, 미확인 과거 의도·내용을 자기 기억인 듯 채우는 반응은 여전히 있었다. [미조회 사례](final-paired/r2/promise_not_retrieved.json).
- **관찰과 주장:** 감사를 하거나 플레이어의 말을 믿는 것 자체는 오류가 아니다. 그러나 직접 관찰 여부와 실제 실행을 과도하게 확정하는 위험은 남는다. 불친절이나 후속 부탁 자체를 권한 위반으로 세지 않았다.
- **확인 대기:** 최종안 r1의 검토는 조건부 미래를 미실행 행동처럼 잡은 과잉 검토 가능성이 있다. 수정 횟수를 정확성 개선 횟수로 세지 않는다. “이미 내 거지?”에 모호하게 긍정하는 문제도 남았다. [기록](final-paired/r1/pending_confirmation_regression.json).
- **모르는 경로:** 최종안 두 회는 구체 경로를 지어내지 않았다. 하지만 장황한 일반론은 남는다. [기록](final-paired/r2/unknown_route_regression.json).

연속 대화는 양쪽 각각 6턴 모두 후보 반환, 검토 3회/2회, 수정 0회다. 산책 거절은 유지했다. 다만 최종안 [r2 두 번째 턴](final-paired/r2/rollout_reading_promise.json)에서 “여행자가 떠나며 다음 사람을 위해 장작을 남김”을 “여행자가 도착했을 때 이미 누군가 장작을 남겨둠”으로 바꿨다. **화자 기록을 구분하는 것과 문장 안 사건의 행위자·시간을 정확히 이해하는 것은 별개이며 후자는 미해결이다.** 해당 답변은 위험 검토도 호출되지 않았다.

## 결론과 남은 일

이번 개발은 검색 누락, 주/보조 기억 지침 누락, 분류 입력 연결, 상대적 화자 구분을 고쳤다. 신이 알고 있는 과거와 현재 상황을 표현에 활용하는 연결을 보완했지만 **“인격을 가진 신처럼 자연스럽게 대화하는 시스템 완성”은 아니다.**

다음 품질 개선은 고정 답변 추가가 아니라 다음 오류를 대상으로 해야 한다.

1. 이미 동의한 이야기를 다시 예고하지 않고 이어가기.
2. 기억이 없을 때 미확인 과거를 채워 넣지 않으면서 대화 이어가기.
3. 인용된 사건의 행위자·시간·조건 유지.
4. 검토의 잘못된 PASS와 과잉 거절을 각각 측정하기.

이 문서는 다음 작업을 자동 승인하거나 운영 배포를 완료했다는 기록이 아니다. 실제 페르소나·오래 지속되는 세션·여러 플레이어/신의 인게임 의미 품질 검증은 별도로 남아 있다.

## 재현

프로젝트 루트 PowerShell에서 실행한다. 실제 모델 호출은 opt-in이며 새 출력 폴더를 사용한다.

```powershell
.\dev-tools\run-mythictrpg-gradle.cmd -p .\mythai-ai-response perspectiveDialoguePreflight --console=plain
.\dev-tools\run-mythictrpg-gradle.cmd -p .\mythai-ai-response perspectiveDialogueLiveEvaluation '-PdialogueLive=true' '-PdialogueEvaluationRepeats=2' '-PdialogueEvaluationOutput=../검토결과/npc-perspective-new-run' --console=plain
```

각 JSON에는 입력·분류·두 프롬프트·wire 요청/응답·초안·검토·수정·최종·시간이 들어 있다. 생성된 합성 캐릭터/상황은 운영 콘텐츠가 아니다.

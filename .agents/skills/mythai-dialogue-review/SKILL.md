# MythAI 대화 진단

[루트 지침](../../../AGENTS.md)을 읽고 **관찰된 현상**, **증거로 확인된 원인**, **추정**을 구분한다. 특정 신/세션에 대한 관찰을 모든 대화의 원인으로 일반화하지 않는다.

## 대화 식별

1. 서버 `server.properties`의 실제 월드 이름과 파일 수정 시각을 확인한다. 최신 파일이라는 이유만으로 개발 도구의 합성 로그를 사용자 테스트라고 단정하지 않는다.
2. 현재 로거와 경로를 대조한다. 후보는 `server/<world>/mythictrpg-ai-test-logs/<UUID>/ai-test-YYYY-MM-DD.log`, `server/mythictrpg-dialogue-logs/`, `server/logs/latest.log`다. 첫 경로의 코드 진입점은 `mine/mine/src/main/java/com/sande/mythictrpg/ai/AiTestDialogueLog.java`, 두 번째는 `ConversationLogService.java`다. 호출부/배포본이 실제로 사용하는지도 확인한다.
3. 날짜·플레이어·참여 신·시작/종료로 범위를 좁힌다. 후보가 여러 개면 최소한의 질문을 하거나 분석 범위를 명시한다. 관련 구간만 읽고 불필요한 사용자 대화 전체를 복사하지 않는다.

## 턴별 원인 분리

- 원문과 앞선 NPC 발화를 먼저 읽는다. 질문표, 반말, 특정 키워드 하나만으로 도전·적대·사과·요청을 단정하지 않는다.
- 기록이 있다면 1단계 입력/분류 → 선택 콘텐츠 → 2단계 프롬프트 → 모델 원문 → JSON 파싱/정규화 → Proposal 검증 → HUD 출력 순서로 비교한다. 없는 단계는 추정임을 표시한다.
- `server/config/mythictrpg/ai-dialogue.json`의 모델/엔드포인트와 실제 당시 로그를 대조한다. 현재 설정이 과거 대화에도 적용됐다고 가정하지 않는다.
- 잘못된 프로필/ID, 오래된 JAR/Datapack, 히스토리 누락, 과도한 분류, 상충하는 프롬프트, 모델 생성, 출력 절단, 실행 미지원 중 어디서 문제가 생겼는지 분리한다.
- `Unterminated string/array`는 우선 구조화 응답의 파싱 실패다. 토큰 상한·생성 중단·응답 잘림·파싱 전처리 등은 원문/종료 사유를 보기 전 확정하지 않는다.

## 자연스러움 기준

- 바로 앞 대화와 숨은 의도를 이해하는가? 다른 표현의 같은 요구나 반복을 인지하는가?
- 친밀한 반말과 초면의 무례함, 장난과 위협, 두려움과 도전을 관계·상황에 맞게 구분하는가?
- 신의 성격이 유지되면서 감정 변화·사과·화제 전환·범용 놀이가 다음 턴에 영향을 주는가?
- 매번 퀘스트·훈계·신격 과장으로 되돌아가거나, 같은 질문과 빈 약속을 반복하지 않는가?
- 긴 대사의 의미를 보존하고 화자·출력 순서가 맞는가? 제안한 행동과 서버 실행 결과가 일치하는가?

수정 요청이 있을 때만 개선한다. 문장별 고정 답변/끝말잇기 전용 상태를 추가하는 대신 일반적인 문맥 처리의 결함을 찾는다. 재검증은 원 대화와 표현이 다른 사례, 관계가 다른 사례를 포함한다. 실 LLM 재생은 대화 분석과 별개 실행이며 시간/서버 상태 영향을 확인한다.

결과는 중요한 문제부터 짧은 실제 인용, 영향, 원인 확실성, 수정할 계층과 검증 방법을 제시한다. 로그만으로 모델 품질과 시스템 원인을 완전히 분리할 수 없다면 그대로 말한다.

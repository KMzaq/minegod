# LLM 예시 대화 사전

이 압축 파일은 제공된 주제 목록을 기준으로 만든 공용 few-shot 예시 대화 모음입니다.

## 구조

- `relationship_state/` : 관계 호감도/적대도 9종
- `relationship_type/` : 부신, 모신, 자식, 형제, 자매, 쌍둥이, 부부, 연인, 주종, 숙적, 라이벌, 동료, 적대, 혈연, 창조자, 피조물
- `personality/` : 성격 21종
- `emotion/` : 감정 8종
- `situation/README.txt` : 입력 목록에 상황 항목이 없어 미생성
- `manifest.json` : 라벨 ↔ 태그 ↔ 경로 매핑

총 예시 JSON: 216개
각 항목당 예시: 4개

## JSON 원칙

각 예시는 신규 데이터 규칙에 맞춰 `schemaVersion: 2`를 사용합니다.
캐릭터 전용이 아닌 공용 예시이므로 `known_by`는 빈 배열(`[]`)입니다.
각 파일은 특정 축 하나의 특징만 강하게 보여주도록 작성했습니다.
이렇게 해야 관계 상태 + 관계 유형 + 성격 + 감정 + 상황 예시를 런타임에서 조합했을 때 서로의 신호가 덜 충돌합니다.

예시:

```json
{
  "schemaVersion": 2,
  "tags": ["P_CALM"],
  "known_by": [],
  "dialogue": [
    { "role": "player", "text": "실수했어. 어떻게 하지?" },
    { "role": "npc", "text": "괜찮아. 사실과 추측을 먼저 나누자. 그다음 복구할 수 있는 부분을 순서대로 처리하면 돼." }
  ]
}
```

## 태그 ID

관계 상태 9종은 가이드에 명시된 `R_EXTREME_HOSTILE` ~ `R_DEEP_BOND` 태그를 사용했습니다.
관계 유형은 호감도 단계와 구분하기 위해 `RT_FATHER`, `RT_LOVER`처럼 `RT_*` 태그를 사용했습니다.
그 외 성격/감정은 제공된 한국어 라벨을 일관된 영문 ID로 매핑했습니다.
실제 프로그램에 이미 별도 태그 ID가 있다면 `manifest.json`을 기준으로 일괄 치환하면 됩니다.

`relationship_type/r_master_servant/`의 4개 예시는 NPC가 종속자·시종 관점에서 말하는 내용이므로 `RT_SERVANT`로 분류했습니다. 지배자 관점의 `RT_MASTER` 예시는 별도로 추가하는 것을 권장합니다.

## 설계 주의점

- 성격 예시는 현재 감정이나 특정 관계를 가정하지 않습니다.
- 감정 예시는 성격이나 관계를 고정하지 않습니다.
- 관계 유형 예시는 '부모면 무조건 따뜻함', '연인이면 무조건 애정'처럼 호감도를 강제하지 않도록 작성했습니다.
- 관계 상태 예시는 가족/연인/주종 등 특정 관계 유형을 가정하지 않습니다.
- 실제 게임 기능 실행, 보상 지급, 상태 변경을 말하는 예시는 넣지 않았습니다.

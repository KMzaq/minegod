# 구버전 — 새 기획 이전의 테스트 콘텐츠

2026-10-22 · 사용자 요청으로 기존 시험용 인물·페르소나·신화 지식·Story·퀘스트를 실제 사용 경로에서 분리했다. 새 기획을 받기 전의 보존 자료이며, 이 폴더는 모드 리소스나 서버 데이터팩의 로드 경로가 아니다.

## 보관 위치

- `원본/`: 프로젝트 루트를 기준으로 원래 경로를 그대로 보존한다. 게임의 인물·사건·보상·조우 정의, 콘텐츠 레지스트리 프로필·로어·예시·퀘스트 목록, 서버의 시험 데이터팩 2개와 AI 설정 6종, 샘플 FTB 퀘스트 및 번역이 들어 있다.
- `수정전코드/`: 루브라스 자동 기본값 등을 제거하기 전 로더 소스와 빌드 설정을 보관한다.
- `배포전/`: 교체한 서버·클라이언트 배포용 JAR을 보관한다. 실제 교체·검증 결과는 브랜치 인수인계를 따른다.
- [content-manifest.json](content-manifest.json): 파일별 원래 위치·처리 종류·크기·SHA-256. `MOVE`는 실제 사용 경로에서 옮긴 파일, `SNAPSHOT_AND_*`는 원문을 보존하고 사용 경로의 내용만 비운 파일이다. 삭제된 입력이 빌드 출력에 남지 않도록 해당 출력 사본도 함께 분리했다.
- [code-snapshot-manifest.json](code-snapshot-manifest.json): 수정 전 코드 사본의 해시.
- [preserved-state-manifest.json](preserved-state-manifest.json): 변경하지 않은 기존 월드·플레이어 진행·AI 기억 파일의 해시.

## 현재 사용 경로

인물별 프로필·로어·Story와 신 정의, 포르투나 샘플 퀘스트·보상·조우·건축 정책은 기본 배포 리소스에서 제외했다. 서버의 두 시험 데이터팩도 구성 파일을 보관소로 옮겼다. 서버 로컬 페르소나·지식·에이전트·인물 태그·말투·예시 카탈로그는 같은 스키마의 빈 자료다. 파일이 없어도 특정 옛 인물을 자동 생성하지 않는다.

Minecraft 공개 상식 17개, 일반 의도 분류 예시 31개, 일반 대화 정책·기술 설정, 스킬·가호·Story·퀘스트 실행 시스템은 유지했다. NPC 활동 공통 정의, 일반 공개 정책 `full/withhold`, 전투력 정책, 상점과 별도의 시험 수호자 레이드도 페르소나·Story 자료와 구분해 유지한다. FTB의 내부 챕터와 즉석 의뢰 챕터는 생성 퀘스트 실행에 필요하므로 빈 구조를 유지한다.

플레이어의 과거 대화·기억·퀘스트 진행·관계·인벤토리를 초기화하지 않았다. 이 보관 작업은 월드 초기화나 과거 기록의 삭제가 아니다. 기존 저장 상태가 참조하는 옛 정의를 새 정사로 자동 이관하거나 새 인물에 합치지 않는다.

## 회귀검사 전용 사본

기존 기능 검사가 옛 인물·스토리에 의존하는 자료는 [src/gametest](../../mythictrpg-main/src/gametest/README.md)에 격리했다. 명시적인 개발 GameTest 실행에서만 임시 데이터팩으로 주입하며 일반 서버·클라이언트 실행과 배포 JAR에는 넣지 않는다. 옛 콘텐츠 없이 비어 있는 상태를 검사할 때는 새 `build/` 실행 폴더와 `-PlegacyContentFixtures=false`를 사용한다.

보관한 JSON을 원래 리소스 폴더에 복사하거나 팩을 `server/world/datapacks`로 되돌리면 다시 활성화될 수 있다. 복원은 새 기획과 충돌 여부를 확인하는 별도 작업으로 취급한다. 이 README는 자동 복원 지시가 아니다.

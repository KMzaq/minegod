# AI 호출·대화 시험 명령

> **시점 주의:** 바로 아래 배포·버전 문장은 2026-09-23 개발 당시의 기록이다. 현재 명령 구현과 서버 설치는 [작업 시작 안내](../인수인계/START_HERE.md)에 따라 소스·`server/mods`를 대조한다. 이 문서의 사용법을 현재 서버 검증 완료의 증거로 삼지 않는다.

2026-09-23 개발 소스: 게임 **1.0.14 / AI 응답 0.1.15**. 새 명령은 컴파일·오프라인 검사를 마쳤지만 **server/에는 아직 배포하지 않았다.** 현재 설치본은 게임1.0.13/AI0.1.14이며 새 명령을 사용하려면 두 모듈의 배포가 필요하다.

## 하나의 시작 명령

OP 권한 2 이상인 플레이어가 실행한다. 콘솔에서는 참가 플레이어가 없으므로 시작할 수 없다.

```text
/ai_call <public|mobile|private> <on|off> <신 ID> [신 ID ...]

/ai_call public off mythictrpg:demeter
/ai_call mobile off mythictrpg:fortuna
/ai_call private on mythictrpg:demeter mythictrpg:fortuna
```

| 값 | 의미 | 대화 입력 |
|---|---|---|
| public | 이어진 같은 바이옴 구역의 공개 고정방 | 일반 채팅 |
| mobile | 참가자 주변의 공개 이동방 | 일반 채팅 |
| private | 위치에 구애받지 않는 비밀방 | `/s 할말` |

- **전체 신 ID만 허용한다.** `데메테르`, `demeter` 등 표시 이름/짧은 ID는 받지 않는다. 이름을 ID로 변환하거나 별칭을 저장하지 않는다.
- Tab 자동완성은 이미 로드된 **AI 프로필과 게임 God Definition 양쪽**에 존재하는 전체 ID만 제안한다. 모델 호출이나 파일 전체 재탐색은 하지 않는다.
- 공백 또는 쉼표로 1~16개의 서로 다른 신 ID를 입력한다. 중복은 최초 입력 순서로 한 번만 선택한다. 전체 입력은 2048자 이하다.
- 하나라도 잘못된 ID이거나 양쪽 정의 중 하나가 없으면 전체 시작을 거절한다. 일부 신만으로 방을 열지 않는다.
- 예시의 `mythictrpg:demeter`와 `mythictrpg:fortuna`는 현재 시험 콘텐츠 ID이며 이번 작업에서 신 ID/프로필을 바꾸지 않았다. 추가 신도 양쪽 정의가 있어야 한다.
- 기존 방을 몰래 종료하거나 덮어쓰지 않는다. 공개방이 이미 있는 플레이어의 두 번째 공개방 생성은 게임이 거절한다. 공개방과 비밀방 병행은 가능하다.
- 고정방의 연결 바이옴 확인이 아직 끝나지 않았거나 같은 구역에 대화가 있으면 시작을 보류/거절할 수 있다. 테스트가 쉬운 비밀방이나 이동방을 선택할 수도 있다.

## 채팅창 표시와 파일 기록은 별개

공개방의 플레이어 발언과 신 답변은 전역 채팅에, 비밀방은 해당 방 참가자의 채팅에 남긴다. 신 답변은 채팅에 원문을 한 번 표시하고 HUD에는 순차 출력한다. **on/off 어느 쪽이든 채팅창에 표시한다.** 다만 플레이어 설정에서 채팅을 숨겼거나 전송에 실패한 경우까지 표시 성공을 보장하지 않는다.

| 구분 | on | off |
|---|---|---|
| Minecraft 채팅창 대사 표시 | 표시 | 표시 |
| 현재 방의 최근 대화 문맥 | 사용 | 사용 |
| 권한이 있는 기존 기억 조회 | 사용 | 사용 |
| 이번 대화의 새 TXT·진단·개인 기억 | 저장 허용 | 저장하지 않음 |

`off`는 기존 기록을 지우지 않는다. 전역 기억 설정이 OFF이면 기존 기억 검색도 비활성이고 기록 on 시험을 거절한다. 명령이 전역 설정·모델을 자동 변경하지 않는다. 운영자의 명령 기록, 다른 모드/Ollama의 자체 로그, 이 대화 밖의 행동 기록까지 끄는 기능은 아니다.

기록 위치와 실제 공개/비밀 청중·저장 경계는 [대화방 가이드](CONVERSATION_ROOMS.md)의 기록 위치 절을 따른다. 아직 SQLite 전체 RAW/100GB 저장/M 설계의 모든 후속 기능을 완성한 것은 아니다.

## 선택·퇴장

```text
/mythroom list
/mythroom select A
/s 여기서는 우리끼리 이야기하자.
/mythroom leave A
```

실제 방 코드는 시작 안내나 목록에서 확인한다. 비밀방 하나는 자동 선택되며 여러 방은 H 키 또는 목록에서 목적지를 선택한다. `/s` 입력에 방 코드를 매번 쓰지 않는다. 선택된 비밀방이 없으면 거절하며 공개 채팅으로 대신 보내지 않는다.

`/mythroom leave <방코드>`는 실행 플레이어만 그 방에서 퇴장시킨다. 남은 참가자가 있으면 방 전체가 종료되는 것은 아니다. G 키는 우측 UI 표시만 바꾼다.

## 이전 명령과 게임 권한

- `/ai_test ...` 및 `/mythroom open ...`은 **새 명령 안내만 출력**한다. 이전 HUD-only 시험 세션이나 다른 시작 경로를 만들지 않는다. 예전 relationship/emotion/debug/say 등 하위 명령도 실행하지 않는다.
- 이전 adapter와 내부 회귀 시험은 일반 엔진의 의존성 때문에 유지한다. 명령 진입점 변경을 AI 엔진 삭제로 해석하지 않는다.
- `/mythadmin interaction ...`은 실제 Encounter/게임 등장 정책 시험 도구로 유지한다. `/ai_call`은 **대화·기록 시험**으로 실제 아이템/관계/퀘스트/월드를 변경할 권한을 주지 않는다.
- 테스트 방 초대 모의는 기존 `/mythroom invite_test <방> <플레이어>`(OP2)다. 일반 플레이어의 무단 비밀방 합류는 허용하지 않는다.
- 방 유형/참가자/기록 권한/생성·퇴장/비동기 응답 유효성은 게임이 소유한다. AI 모듈은 명령을 파싱하고 정의를 검증한 뒤 게임 `ConversationRooms.create`에 위임한다. 게임/AI IO와 저장 형식은 이번에 변경하지 않았다.
- 현재는 플레이어 한 턴에 신 한 명이 답한다. 여러 신 참가가 자율 N신 연속 토론을 뜻하지 않는다. 현재 관계/감정·비밀 로어·소문 후처리의 제한은 [대화방 가이드](CONVERSATION_ROOMS.md)를 따른다.

## 확인한 범위와 실제 접속 시험

게임·AI 컴파일/JAR, ID 파서67, 실제 명령 소스+Brigadier 라우팅210, 기존 파서59, 방 원장147, 전송/기록 발행19, AI 방 엔진90 검사를 통과했다(총592). 명령 시험의 게임·레지스트리는 경계 stub이며 실제 Minecraft 클라이언트 시험이 아니다. 전송 검사는 기록 off에서도 전송하고 비밀방 외부 수신자를 거절하는 것을 포함한다.

아직 새 JAR 배포·서버 실행/중지·실제 LLM·인게임 UI 확인은 하지 않았다. 배포 후 확인할 항목:

1. 공개방에서 일반 채팅을 입력하고 본인/다른 플레이어 채팅에 플레이어·신 대사가 남는지 확인.
2. 비밀방에서 `/s`로 입력하고 참가자에게만 표시되는지 확인.
3. 기록 off에서도 채팅창 표시를 유지하며 새 대화 TXT/기억은 만들지 않는지 확인.
4. on으로 남긴 허용 기억의 재조회와 여러 방의 비밀·기록 격리를 확인.

서버/클라이언트의 게임 JAR을 함께 맞추고 AI 응답 JAR은 서버에만 설치한다. 빌드 완료를 서버 적용 완료로 혼동하지 않는다.

# 기존 대화방 전체에 대한 다섯 기능 통합

2026-09-23. 대상: 게임 1.0.16 / AI 응답 0.1.17 / 콘텐츠 레지스트리 0.1.1.

이 문서는 앞선 `ORIGINAL_GOALS_REINTEGRATION_20260923.md`의 1인·2신 반응, 단독 비밀방 Hook, PUBLIC 로어 한정을 대체한다. 공개 고정/이동형, 비밀방, 동시 참가, 이동에 따른 병합·분리의 기존 권한과 참가 규칙을 변경하지 않는다. 부팅·실제 모델·클라이언트 검증 여부는 아래 검증 기록과 구분한다.

## 구현 계약

1. 주 응답을 실제 전달한 뒤 현재 참가한 다른 신 각각에게 선택적 반응 기회를 한 번 준다. 각 신은 자기 프로필·현재 관계·허용된 기억과 이미 전달된 발언으로 반응하거나 침묵한다. 후보 하나의 오류가 다른 후보를 막지 않는다. 새 입력과 방 revision 변경은 이전 연쇄를 취소한다. 플레이어 없는 무한 자율 대화는 시작하지 않는다. 기존 방당 64플레이어·16신 구조를 따른다.
2. 매 화자 요청과 이동 판단에 게임의 방향별 신 관계를 새로 넣는다. 과거 정적 관계와 현재 적대·공포·원한·무관심 등을 구분한다. 사건의 관계 전이에서 부분 성공 후 재시도로 같은 효과를 다시 적용하던 경로를 보완한다. 모델이 전쟁 결과나 관계 상태를 직접 확정하지 않는다.
3. 사건 설명은 게임이 허용한 사실 또는 위장 설명을 공급한다. 모델이 `story_disclose`로 고른 사실 별칭은 게임의 정식 문구를 실제 전달하고 수신 증거를 확인한 뒤 지식을 부여한다. AI의 자유 대사 자체를 새로운 사실로 승격하지 않는다. 각 신은 자신의 허용된 `story_event_hook`만 제안할 수 있고 게임 검증·기존 플레이어/팀 수락 범위를 따른다. 보조 반응도 이 경로를 사용하지만 다른 일반 게임 액션/방 제어 권한은 주지 않는다.
4. 대화 기억은 질문자별 저장 키에서 분리한다. 실제 논리 발언당 원문 하나와 실제 화자, 청취 신, 완전 수신 플레이어, 공개 여부, 원래 방/시각, 증거와 참조 메시지 계보를 보존한다. 다른 플레이어가 나중에 물어도 들었던 신은 공개가 허용되는 내용을 찾을 수 있다. 타인의 발언을 자기 약속이나 확정 월드 사실로 취급하지 않는다. 기존 개인 기억은 호환 조회하며 새 방 원문을 이중 저장하지 않는다.
5. 신이 아는 정적 로어와 현재 청중에게 공개 가능한 내용의 교집합만 모델에 보낸다. 로어 단계·프로필 필드·예시·퀘스트 후보 본문의 작성된 공개 정책을 지원한다. 미지정 비공개 로어는 공개하지 않는다. 사건·콘텐츠 권한과 기억 계보는 생성 전, 응답 적용 전, 나중 회상 때 재검증한다. 공개된 발언을 새 플레이어에게 회상하는 것과 비밀방 발언을 다른 청중에게 옮기는 것은 다른 권한이다.

## 주요 경계

- 게임 `Request`는 기록 OFF와 무관하게 실제 `audiencePlayerIds`를 명시한다. 공개방의 실제 청중은 방 참가자가 아니라 현재 전역 채팅 수신 대상이다.
- `HistoryLine`은 원래 방과 message UUID를 보존한다. 병합 후 새 참가 신에게 과거를 들었다고 자동 부여하지 않는다.
- `RoomDialogueEvent`의 `worldId`, `fullTextReceiverIds`, `heardGodIds`는 게임이 채운다. 채팅 전송 또는 HUD 전체 페이지 전송을 증명하며 클라이언트가 실제 읽었다는 보장은 아니다.
- `preparePublication`은 생성 근거를 붙이고 `dialogueObserved`는 OFF에서도 일시적 수신 메타데이터를 남긴다. 영속 기록 callback은 ON일 때만 실행한다. 전역 기억 OFF도 존중한다.
- 알려지지 않은 증거 종류, 사라진 근거, 변한 공개 정책은 허용으로 추정하지 않는다. 자료 부족은 새로운 정사를 지어내어 메우지 않는다.
- 기존 콘텐츠의 비밀 공개 권한을 자동 확대하지 않는다. 작가는 새 정책을 명시해야 한다. 내용 작성은 기능 구현과 별개이며 닉스 등 사용자 예시를 정식 콘텐츠로 몰래 설치하지 않는다.
- 게임의 사건/신 상태, 퀘스트·보상 원본과 콘텐츠 레지스트리의 정적 신 ID/소유 지식 체계는 그대로 유지한다.
- 정적 관계도 `화자 → 상대`별로 전달하고 각 방향의 정의를 검증한다. 여러 상대의 태그를 합친 목록만으로 대상을 추측하게 하지 않는다.
- [청취 기억 계약](ROOM_HEARD_MEMORY_20260923.md)에 저장 위치·모드 분리·용량·근거 재검증을 기록했다. 원문 저장과 모델에 전달하는 검색 발췌는 별개다. 운영자 파일 접근 제한이나 무제한 저장을 의미하지 않는다.
- 기존 관찰 원장은 본래의 private/단일 청취 신 공개 권한을 유지한다. 다른 신이 그 원 관찰을 보았다고 자동 승격하지 않으며, 새 방에서 실제로 들은 허용 대사를 기억하는 경로와 구분한다.

## 검증 기록

- 세 모듈의 `build --offline --no-daemon` 성공. 게임 main 기반 회귀 33,309개, AI 4,996개(기존 별도 fixture 포함, 로그 가드 37위치는 합계 제외), 콘텐츠 공개 50개 + 퀘스트 공개 20개. 게임 숫자에는 기존 바이옴 격자 검사 22,945개가 포함되며, 서로 다른 기능 시나리오 33,309개라는 뜻이 아니다.
- 실제 Minecraft GameTest 204/204 통과: `mythictrpg-main/build/room-integration-release-20260923/logs/latest.log`. 새 다중 신/다중 방/늦은 응답 및 Story canonical·지식/위장·출발 알림 검사는 실제 게임 서비스와 대체 모델/전송을 쓴다.
- 재사용 테스트 디렉터리의 FTB 번역 테이블과 vanilla mock client 사이 패킷 불일치는 별도 깨끗한 **개발 테스트 디렉터리**로 재검증했다. 운영 서버/월드는 초기화하지 않았다. `-ProomTestDirectory=build/<새 검사 폴더>`로 검사를 격리할 수 있다.
- 메모리 검색 완료가 모델 사용권 반납보다 앞서 후속 정리를 건너뛰던 비동기 경쟁을 수정하고, sleep 없이 순서를 검증하는 회귀를 추가했다. 초기 실패 기록을 성공으로 바꾸어 해석하지 않고 수정 후 전체 검사를 다시 실행했다.
- 세 모듈 동시 로드/실제 AI 엔진 호출 **전용 GameTest 1/1 통과**: `mythictrpg-main/build/room-ai-integrated-20260923/logs/latest.log`. 실제 프로필 조회·공개 불가 로어 제외·화자별 방향 관계·Primary/Secondary 생성 경로·실제 전달·영속 쓰기·질문자가 바뀐 청취 신의 회상을 검증했다. LLM transport만 고정 출력의 대체 구현이다. 세 모듈 전체를 함께 실행한 첫 205개 실행에서는 AI 부재를 전제한 기존 검사 8개가 실패했으므로, 게임 단독 204개와 AI 설치 전용 1개를 분리하여 각각 통과시켰다. 205개 전부를 동일 환경에서 통과했다고 보고하지 않는다.
- 실제 Ollama·클라이언트 HUD·다인 지연/장기 부하 검증은 하지 않았다. 테스트 성공은 특정 스토리가 자발적으로 창발했다거나 모든 모델 대사가 자연스럽다는 뜻이 아니다. 실제 모델 실행 허가를 질문했으나 이번 작업 중 답변이 없어 실행하지 않았다.

재실행(루트에서, 세 개발 JAR 빌드 후):

```powershell
.\dev-tools\run-mythictrpg-gradle.cmd runRoomIntegrationGameTestServer -ProomTestDirectory=build/<새 게임 검사 폴더> --offline --no-daemon
.\dev-tools\run-mythictrpg-gradle.cmd runRoomIntegrationGameTestServer -ProomAiIntegration=true -ProomTestNamespaces=mythai_room_full_path -ProomTestDirectory=build/<별도 AI 통합 검사 폴더> --offline --no-daemon
```

첫 명령은 게임 단독, 둘째는 실제 AI/콘텐츠 JAR을 추가한다. 전용 fixture는 모델 backend를 대체하고 백그라운드 의미 검색이 꺼져 있는지 확인한다. 원문·메타데이터의 크기/근거 개수와 프롬프트 예산은 여전히 유한하다. 근거 64개 초과나 권한 확인 실패를 누락된 증거로 통과시키지 않는다. 정적 콘텐츠 snapshot 전체 지문은 보수적이므로 관련 프로필/로어 목록이 변경되면 과거 발언의 재사용이 차단될 수 있다. 과거 원문을 삭제하는 것은 아니다.

## 배포 상태

2026-09-23 사용자 배포 요청으로 게임 1.0.16 / AI 0.1.17 / 콘텐츠 0.1.1을 `server/mods`에 설치했다. `server/client-required-mods` 게임도 1.0.16이며 서버 파일과 SHA-256이 같다. 서버는 배포 전후 꺼진 상태이며 부팅/실제 모델/클라이언트 확인은 하지 않았다. 세 모듈의 새 API가 함께 필요하며 AI 0.1.17은 최소 게임 1.0.16 / 레지스트리 0.1.1을 요구한다. 기존 `mine/mine` 결합 JAR은 빌드 입력일 뿐 서버 설치 대상이 아니다.

최종 개발 JAR SHA-256:

- `mythictrpg-main/build/libs/mythictrpg-1.0.16.jar`: `8F1187B3E9C6C2BC264512BFAC5A449F8EA9441DD4E9762E45C415C5F00EF5FD`
- `mythai-ai-response/build/libs/mythai_ai_response-0.1.17.jar`: `EECDB96AD76AB0AB4623314AB89657B1CA2A09AA029EA53E0B752AE49AE0F568`
- `mythai-ai-content-registry/build/libs/mythaiaicontent-0.1.1.jar`: `72096C4FFA1D103508013BCDBFBCD45242394114A58E60978DA630C8FB593E61`

설치 조합 7개 JAR에서 중복 mod ID/엔트리/클래스/split-package가 없음을 확인했다. 기존 월드 데이터팩 2개의 리소스는 새 JAR의 같은 경로를 덮어쓰지 않는다. 게임 JAR은 서버/클라이언트 양쪽, AI/콘텐츠는 서버 설치를 맞춰야 한다. 실제 런처의 클라이언트 폴더는 수정하지 않았다. 새 원장 생성 뒤 버전 하향을 자동 마이그레이션하거나 기존 기억을 삭제하지 않는다.

콘텐츠 0.1.1에는 인수인계 50절에서 앞서 요청·수정한 데메테르 프로필 보강도 포함된다. 이전 설치 콘텐츠 0.1.0과 비교한 런타임 JSON 차이는 `demeter.json` 한 개이며 추가/삭제는 없다. 이번 기능 구현으로 새로 만든 콘텐츠는 아니다.

배포 전 백업: `server/backups/full-room-dialogue-20260923`에 모드·클라이언트 필수 폴더·월드·설정·기억/대화 파일과 서버 안내/속성 총 **546파일 / 52,728,412 bytes**를 복사해 원본과 해시 일치를 검사했다. `backup-manifest.csv`에 각 파일의 크기와 SHA-256이 있다. 교체한 구 JAR은 `retired-mods`와 `retired-client-required-mods`에 추가 보관했다. 월드/설정/실제 기억은 초기화하지 않았고, 기타 모드는 변경하지 않았다. 재배포 스크립트는 동일 백업 폴더를 덮어쓰지 않도록 재실행을 거절한다.

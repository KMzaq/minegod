# 즉석 SIDE 퀘스트의 보상 동결·재시도

2026-09-29 / 게임 개발본 1.0.18. 운영 배포하지 않았다.

## 구현 범위

- 새 즉석 퀘스트는 생성 시 서버가 결정한 보상 단계의 **보상 내용 자체**를 저장한다. 아이템 components도 포함한다. 이후 데이터팩 보상표를 수정·삭제해도 이미 수주한 퀘스트를 다른 보상으로 바꾸지 않는다.
- 수주 전에 실제 아이템 component codec와 claim 저장 가능 여부를 검사한다. AI는 보상 단계나 보상 내용을 임의로 바꾸지 않는다.
- 목표 달성 후 지급 실패는 퀘스트를 유지한다. 접속 중 매 20틱과 다음 접속 때 같은 instance ID의 claim을 재사용한다. 이미 달성한 목표는 만료 시간으로 취소하지 않는다.
- 완료 전환은 처음 목표에 도달했을 때만 기록한다. 재시도마다 새 목표 달성 사건을 만들지 않는다.
- 인벤토리/화폐 등 실제 지급은 기존 `RewardClaimService`만 담당한다. FTB는 표시 미러다.

## 호환·저장

`GeneratedQuestState` 저장 버전은 1→2다. 구 v1 자료는 읽으며, 없는 보상 스냅샷을 과거 사실처럼 생성하지 않는다. 과거 방식대로 현재 표를 처음 유효하게 해석하는 시점에 한 번 동결한다. 이후에는 같은 내용을 재시도한다. 신규 코드는 수주 시부터 동결한다.

신 버전으로 저장한 자료를 구 JAR로 저장하는 다운그레이드는 지원하지 않는다. 롤백은 관련 월드·claim·플레이어 자료를 일관된 백업 시점으로 복구해야 한다.

보상 영수증과 플레이어 인벤토리는 별개 저장 파일이다. 기존 저장 구조에서 강제 프로세스 종료/부분 복구를 가로지르는 완전한 원자적 지급을 추가한 것은 아니다. 정상 실행·재접속·동일 claim 재시도에서는 중복 지급을 차단한다. 완료된 claim을 운영자가 삭제하거나 다른 시점의 파일만 복원하는 것은 지원 경계를 벗어난다.

## 미확장 범위

이번 작업은 개인 즉석 퀘스트의 완료 경로 보완이다. `generated_quest_offer`의 다인 생성, 새로운 목표 종류, AI가 자유롭게 게임 목표/보상을 정의하는 기능은 추가하지 않았다. 등록형 퀘스트의 SOLO/GROUP/COMPETITIVE/RANKING은 기존 경로를 유지한다.

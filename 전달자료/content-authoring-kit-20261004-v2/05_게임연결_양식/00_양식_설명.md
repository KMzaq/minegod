# 새 퀘스트의 게임 연결 양식

빈 후보 목록과 연결되는 별도 실행 설정 예시다. 아이템·수량·ID·진행량은 작성용 예시이며 확정 콘텐츠가 아니다.

## 같은 값을 맞출 파일

| 자료 | 파일/필드 |
|---|---|
| AI 신 프로필 | `01_JSON_양식/.../god_profiles/mythology_affiliation_name.json`의 `godId`, `questListIds` |
| AI 후보 목록 | `01_JSON_양식/data/mythictrpg/mythai_ai/quest_lists/mythology_affiliation_name.json`의 `questId`, `progressTrackId`, `progressOnClear` |
| 게임 바인딩 | `data/mythictrpg/mythictrpg/ftb_quests/mythology_affiliation_name_quest_name.json` |
| 실제 FTB 화면 | `ftbquests/chapters/mythai_authoring_story.snbt` |
| 숨김 수주 마커 | `ftbquests/chapters/mythai_authoring_internal.snbt` |

이 양식은 `mythictrpg:mythology_affiliation_name_quest_name`으로 연결되어 있다. 프로필의 God ID는 `mythictrpg:mythology_affiliation_name`이다. 예시 ID를 실제 신/퀘스트 ID로 바꾸고, 바인딩 파일명도 `questId`의 path에 맞춘다. 퀘스트 ID는 신 ID 뒤에 퀘스트 이름을 붙인 권장 예시이며 God ID 자체와 같지 않다.

현재 양식은 밀 1개를 소비하는 FTB 아이템 목표 + 신 확인용 custom 태스크, 게임 직접 보상 에메랄드 1개다. FTB 보상은 빈 배열이다. 후보의 목표·보상 설명도 같은 값으로 맞춘다. `progressOnClear: 0`은 진행도를 올리지 않는 예시이므로 실제 진행량을 정하면 후보와 게임 바인딩 모두 변경한다.

## FTB ID

양식의 고정 16진수 ID는 서식용 자리 표시다. 새 퀘스트마다 FTB 편집기에서 고유 ID를 생성하고 다음 연결을 맞춘다. 실제 퀘스트·마커·챕터·태스크의 ID는 기존 퀘스트북과 겹치면 안 된다.

- 바인딩 `ftbQuestId` = story SNBT의 실제 quest `id`.
- 바인딩 `assignmentQuestId` = internal SNBT의 숨김 quest `id` = 실제 quest의 `dependencies` 값.
- 16자리 16진수이며 0보다 크고 첫 글자는 0~7이어야 한다.
- 챕터 파일명은 각 SNBT의 `filename`과 맞추고 별도 챕터 ID도 고유하게 만든다.

기본 예시는 `participation`을 넣지 않은 기존 전역 최초 완료 경로다. 개인/공동 실적·참가 동의가 필요하면 게임 참여 설정과 해당 표시 미러를 별도로 작성한다. 이를 같은 FTB 팀 진행도와 혼동하지 않는다.

## 실제 배치

게임 바인딩은 검토 후 MythicTRPG 리소스 또는 활성 데이터팩에 반영한다. FTB 챕터는 서버 `config/ftbquests/quests/chapters/`에서 기존 퀘스트북과 합친다. `reference/`의 기존 퀘스트북 전체를 덮어쓰지 않는다. 즉석/참여형 미러에는 기존 generated/internal 챕터도 필요하다.

이 묶음은 완성 데이터팩이 아니며 등록된 게임 신을 새로 생성하지 않는다. 서버 설치 전에 JSON 참조·FTB 고유 ID·실제 목표·보상·수주/완료 조건을 검토한다.

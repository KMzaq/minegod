# 콘텐츠 제작 양식 묶음

기준: 2026-10-04 · HanesTest 개발 소스 · 게임 1.0.26 / AI 응답 0.1.29 / 콘텐츠 레지스트리 0.1.3.
이 폴더는 **작성해서 돌려주기 위한 작업 양식**이다. 서버에 자동 적용되지 않으며, 운영 JAR은 이 개발 버전과 아직 다르다.

## 어디부터 작성하면 되나

1. `02_기획서`에서 세계관과 등장인물의 역할·등장 순서를 먼저 정한다. 미정은 그대로 `미정`이라고 적는다.
2. `01_JSON_양식`의 캐릭터 프로필을 복제하고 `[작성]` 안내를 실제 내용으로 바꾼다.
3. 캐릭터가 아는 사건·장소·세력·비밀을 단계형 로어로 작성하고 프로필에서 ID와 지식 수준을 연결한다.
4. 신들 사이의 정적 관계와 퀘스트 후보를 작성한다. 게임 실행에 필요한 추가 설정은 기획서에 요구사항을 남긴다.
5. 폴더 구조를 유지한 채 ZIP으로 보내거나, 이 작업 폴더를 수정했다고 알려준다. 원본 게임/서버 파일을 직접 덮어쓸 필요는 없다.

전부 작성할 필요는 없다. 캐릭터 한 명과 관련 지식부터 작성해도 된다. JSON이 어렵다면 기획서나 문장으로 작성해서 보내도 되며, 적용 전에 해당 정보를 현재 JSON 계약으로 옮겨야 한다.

[JSON 작성 설명](01_JSON_작성설명.md)을 함께 읽는다. 참고 프로필은 성격·문장의 구체성 참고용이며, 참조하는 모든 로어/퀘스트가 이 묶음에 들어 있는 것은 아니다.

## 특히 주의할 것

- `affiliation_name`, `affiliation_other_name`, `topic_name`, `[작성]`은 모두 교체할 자리다. 실제 등록된 캐릭터/지식이 아니다.
- 파일명과 ID는 소문자 영어 `소속_이름`을 기본으로 한다. **이미 있는 신은 기존 God ID를 그대로 사용한다.** 데메테르와 포르투나는 현재 각각 `mythictrpg:demeter`, `mythictrpg:fortuna`다.
- 신은 플레이어의 무조건적인 도우미가 아니다. 자기 욕구·가치·관계·현재 상황에 따라 도와주거나 거절할 수 있다. 그렇다고 모든 신을 오만하거나 사소한 반말에도 적대하게 만들 필요는 없다.
- 좋아하는 것/싫어하는 것/인간관/목표는 `description`, `personality`, `values`, `dialogueGuidelines`에 구체적으로 쓴다. 임의로 새 JSON 필드나 새로운 기능 `type`을 만들어 넣지 않는다.
- 계획된 미래 스토리와 이미 확정된 세계의 과거 사실을 구분한다. 앞으로 플레이어가 해낼 일을 과거 사실처럼 로어에 넣지 않는다.
- 퀘스트 JSON은 **AI 후보 설명**이다. 실제 수주·목표 추적·완료·보상·FTB UI는 게임 바인딩과 정의가 추가로 필요하다. 이것만으로 실행된다고 보장하지 않는다.
- 예시 대화 양식은 현재 레지스트리가 읽을 수 있지만, **현재 주 대화 생성 경로는 예시 원문을 직접 붙이지 않는다.** 대량 예시 제작보다 프로필의 자연어 말투 지침과 지식을 우선한다. 이 양식 제공이 예시 주입 기능을 다시 켰다는 뜻은 아니다.
- `02_기획서`는 사람이 검토할 Markdown이다. 서버가 읽는 실행 스키마가 아니다. 새 기획에 필요한 시스템이 있는지 적용 전에 확인한다.
- 이 묶음에는 일부러 `pack.mcmeta`를 넣지 않았다. 미작성 내용이 들어 있는 묶음을 바로 데이터팩으로 설치하지 않는다.

## 적용은 작성 후 별도로

검토 후 확정 JSON의 `data/` 구조를 콘텐츠 모드의 `src/main/resources/data/`에 반영하거나, 검증된 별도 데이터팩으로 배포한다. JAR 리소스를 바꾸면 재빌드·재배포가 필요하고, 활성 데이터팩 내용의 변경은 `/reload` 대상이다. 임의의 폴더나 `config`에 JSON을 넣는 것만으로 읽힌다고 가정하지 않는다.

새 NPC는 프로필뿐 아니라 게임의 God Definition·등장/조우·표시/식별 정책도 연결해야 한다. 프로필 하나만으로 새 신이 자동 소환되지는 않는다. 스킨/보스 모델/전투 수치/상점 가격도 페르소나 필드에 넣어 실행시키는 구조가 아니다.

## 보내기 전 확인

- [ ] `[작성]` 내용을 채우고 불필요한 선택 항목은 빈 배열/객체로 정리했는가?
- [ ] 인물명과 ID 대응을 일관되게 사용했는가?
- [ ] 아직 모르는 수치·좌표·아이템 ID를 확정된 것처럼 꾸미지 않았는가?
- [ ] `loreKnowledge` 단계가 실제 로어의 최대 단계를 넘지 않는가?
- [ ] 비밀을 공개 페르소나·예시·기초 지식에 복사하지 않았는가?
- [ ] 변경한 파일명에 맞게 모든 참조 ID도 수정했는가?
- [ ] 의도적으로 비워 둔 부분과 미정/확인 필요한 부분을 기획서에 적었는가?

수정한 폴더 전체를 보내면 된다. 실제 적용 전에는 JSON 파싱 외에도 중복 ID, 참조, 공개 범위, 게임 기능 지원 여부를 다시 검사한다.

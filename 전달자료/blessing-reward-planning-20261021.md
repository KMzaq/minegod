# 가호·보상 기획 전달자료

2026-10-21 · Minecraft Java 1.21.1 / `behaivior` 개발 기준

이 문서는 기획자가 신별 등급, 가호 후보와 보상 수치를 정할 때 필요한 입력을 정리한다. **신의 6등급 체계는 확정했으며, 실제 인물별 등급과 가호 목록은 기획 측에서 추후 결정한다.** 아래 가상 예시를 실제 인물의 등급·성격·능력으로 사용하지 않는다. 개발 소스의 지원 범위를 설명하는 문서이며 운영 서버 배포·실제 플레이 검증 완료를 뜻하지 않는다.

## 1. 서로 다른 세 종류의 등급

| 구분 | 의미 | 기획 시 주의 |
|---|---|---|
| 신의 6등급 | 신 자체의 등급. 가호 지급 상한을 정하는 기준 중 하나 | 실제 인물별 등급을 별도로 배정해야 한다 |
| 장비의 7등급 | 장비 성장·품질을 구분하는 체계 | 신의 6등급과 일대일 대응하지 않는다 |
| 보상표의 `tier` | 퀘스트 등이 어떤 보상 묶음을 선택할지 나타내는 순번 | `tier: 3`이 신의 중급이나 특정 장비 등급을 뜻하지 않는다 |

신 등급의 명칭과 저장값은 다음과 같다. 코드 enum은 대문자, JSON은 아래 소문자 표기를 권장한다.

| 순서 | 명칭 | JSON 값 | 코드 enum |
|---|---|---|---|
| 1 | 최하급 | `lowest` | `LOWEST` |
| 2 | 하급 | `low` | `LOW` |
| 3 | 중급 | `middle` | `MIDDLE` |
| 4 | 상급 | `high` | `HIGH` |
| 5 | 최상급 | `highest` | `HIGHEST` |
| 6 | 초월급 | `transcendent` | `TRANSCENDENT` |

신 정의의 필드는 `god_rank`다. 등급이 없는 기존 인물에게 임의로 등급을 채우지 않으며, 적응형 가호를 사용하려면 먼저 등급을 작성해야 한다. 각 등급이 줄 수 있는 효과별 최대 단계도 별도 기획값이다. 초월급이라는 이유만으로 모든 효과를 XVII까지 주거나 모든 특성 버프를 지급하지 않는다.

## 2. 긍정 효과 후보와 실제 단계 차이

게임에서 작성하는 가호의 공통 상한은 **저항 I–IV, 나머지 I–XVII**다. 아래 목록은 바닐라 긍정 효과의 기획 후보 목록이다. 특정 신이 지급할 수 있다는 뜻은 아니며, 신별 허용 목록과 등급별 상한을 모두 만족해야 한다. 외부 명령·포션·다른 모드의 효과 전체를 이 상한으로 강제 수정하는 규칙은 아니다.

### 단계에 따라 효능이 달라지는 지속 효과

| 효과 | ID | 기획 시 확인할 점 |
|---|---|---|
| 신속 | `minecraft:speed` | 이동 속도가 증가한다 |
| 성급함 | `minecraft:haste` | 채굴·기본 공격 속도에 영향을 준다. 별도 RPG 스킬의 재사용 대기시간 감소와는 구분한다 |
| 힘 | `minecraft:strength` | 기본 공격력 증가와 레이드 전용 추가 보정은 6절 참조 |
| 점프 강화 | `minecraft:jump_boost` | 점프·안전 낙하 거리가 달라진다. 고단계 동선과 맵 이탈 가능성을 고려한다 |
| 재생 | `minecraft:regeneration` | 회복 주기가 짧아진다. 바닐라는 VI부터 매 틱 회복하므로 VII–XVII가 계속 더 빠르게 회복하는 것은 아니다 |
| 저항 | `minecraft:resistance` | I–IV만 허용. 일반적으로 단계당 20%, IV는 80% 감소이며 저항을 무시하는 피해는 별개다 |
| 생명력 강화 | `minecraft:health_boost` | 단계당 최대 체력 +4 HP. I은 하트 2개이며 체력 4,000 구현을 뜻하지 않는다 |
| 흡수 | `minecraft:absorption` | 단계당 흡수 체력 +4 HP. 소모한 흡수 체력을 재적용 명령으로 계속 충전하는 보상으로 설계하지 않는다 |
| 행운 | `minecraft:luck` | 등록한 행운 보상·사건 후보의 선택에 연결한다. 모든 드롭이나 모든 사건이 자동으로 바뀌지는 않는다 |
| 마을의 영웅 | `minecraft:hero_of_the_village` | 주민 거래 할인 등에 영향을 준다. 현재 RPG 상점의 별도 가격 규칙까지 자동 변경하지 않는다 |
| 전달체의 힘 | `minecraft:conduit_power` | 수중 호흡·시야 등과 채굴 효과를 제공한다. 호흡·시야는 단계별 강화가 없지만 채굴 단계는 사용되므로 완전히 동일 효능인 효과로 분류하지 않는다 |

### 단계가 높아져도 핵심 효능이 더 커지지 않는 지속 효과

| 효과 | ID | 핵심 효능 |
|---|---|---|
| 화염 저항 | `minecraft:fire_resistance` | 해당 화염 피해에 대한 저항 |
| 수중 호흡 | `minecraft:water_breathing` | 수중 호흡 유지 |
| 투명화 | `minecraft:invisibility` | 투명화. 장비까지 모두 숨기거나 모든 적의 인지를 차단하는 것은 아니다 |
| 야간 투시 | `minecraft:night_vision` | 어두운 곳의 시야 확보 |
| 느린 낙하 | `minecraft:slow_falling` | 낙하 속도 완화 |
| 돌고래의 우아함 | `minecraft:dolphins_grace` | 수영 이동 보조 |

이 효과들도 저장 단계는 XVII까지 허용하지만, 숫자가 높다는 이유만으로 더 강한 능력을 약속하지 않는다. 효과 I을 이미 보유한 플레이어에게 같은 효과 II를 주는 후보를 넣을지는 기획 측에서 정한다. 현재 적응형 선택은 작성한 단계 상승 후보를 허용하므로, 실제 효능이 없는 단계 상승을 피하려면 허용 상한을 I로 두거나 다른 후보를 작성하는 편이 명확하다.

### 즉시형 긍정 효과

| 효과 | ID | 영구 가호와의 관계 |
|---|---|---|
| 즉시 치유 | `minecraft:instant_health` | 즉시형 효과이므로 적응형 영구 가호의 효과 후보로 사용하지 않는다 |
| 포화 | `minecraft:saturation` | 즉시형 효과다. 상시 포화·허기 제거를 영구 가호로 제공하는 정책과 구현은 아직 미정이다 |

이름이 긍정적이어도 무조건 영구 효과로 사용할 수 있는 것은 아니다. 신규 커스텀 특성 능력이 위 Minecraft 효과에 없는 경우에는 별도 행동·스킬 설계가 필요하다.

## 3. 신별 가호에 작성할 항목

기획자가 한 신에 대해 전달할 내용은 다음과 같다.

| 항목 | 작성 내용 |
|---|---|
| 대상 | 기존 게임 God ID와 신의 6등급 |
| 허용 효과 | 이 신이 줄 수 있는 긍정 효과 ID 목록. 특성 버프도 여기에서 명시 |
| 신별 상한 | 허용한 각 효과의 최대 단계 |
| 우선순위 | 후보를 고를 순서. `priority` 숫자가 작을수록 먼저 선택 |
| 가호의 정체성 | 가호 ID, 이름·설명, 고유 가호 점수 `intrinsic_score` |
| 실제 효과 후보 | 효과별 `floor` 또는 `upgrade`, 단계값 |
| 대체 정책 | 유효 후보가 없을 때 보류할지, 효과 없이 가호 보유권·고유 점수만 줄지 |
| 지급 경로 | 어떤 퀘스트·선택지·보상표에서 이 가호를 지급할지 |

실제 지급 상한은 **공통 효과 상한, 해당 등급의 상한, 해당 신의 상한 중 가장 낮은 값**이다. 등급 정책이나 신별 허용 목록에 없는 효과는 선택하지 않는다. 다른 신의 가호 정의를 가져와 지급할 수 없다.

후보 여러 개는 한 번에 모두 지급하는 목록이 아니다. 유효한 후보 중 하나를 고르며, 우선순위가 같으면 예상 전투력이 높은 후보, 그다음 후보 ID 순서로 결정한다. 신의 특성과 무관한 효과를 전투력만 보고 고르지 않도록 허용 목록과 우선순위를 먼저 정한다.

## 4. 설정 예시 — 가상 인물만 사용

아래 `example:guide_deity`는 설명용 가상 NPC다. 상급 배정·상한·고유 점수 100은 예시값이며 실제 인물이나 상급 전체에 적용할 운영값이 아니다. 신 정의에는 `"god_rank": "high"`를 작성했다고 가정한다.

가호 관련 파일은 `data/<namespace>/mythictrpg/blessings/` 아래에 둔다. 파일 경로가 정의 ID가 된다.

**등급별 상한 예시** — `data/example/mythictrpg/blessings/rank_high.json`

```json
{
  "schema_version": 1,
  "kind": "rank_policy",
  "rank": "high",
  "effect_caps": {
    "minecraft:strength": 12,
    "minecraft:speed": 5
  }
}
```

**신별 허용 목록·우선순위 예시** — `data/example/mythictrpg/blessings/guide_policy.json`

```json
{
  "schema_version": 1,
  "kind": "god_policy",
  "god_id": "example:guide_deity",
  "effects": {
    "minecraft:strength": {"max_level": 12, "priority": 0},
    "minecraft:speed": {"max_level": 5, "priority": 10}
  }
}
```

**가호 후보·고유 점수 예시** — `data/example/mythictrpg/blessings/guide_blessing.json`

```json
{
  "schema_version": 1,
  "kind": "definition",
  "god_id": "example:guide_deity",
  "intrinsic_score": 100,
  "candidates": [
    {"id": "strength_step", "effect": "minecraft:strength", "mode": "upgrade", "level": 1},
    {"id": "speed_floor", "effect": "minecraft:speed", "mode": "floor", "level": 3}
  ],
  "fallback": "only_ownership"
}
```

보상표·퀘스트의 보상 항목은 이 정의를 참조한다.

```json
{"type": "adaptive_blessing", "definitionId": "example:guide_blessing"}
```

- `floor: 3`은 효과 III를 지급하는 후보다. 기존 영구 보유 단계가 III 이상이면 더 유효한 후보를 찾으며, 기존 단계를 낮추지 않는다.
- `upgrade: 1`은 기존 영구 보유 최고 단계에 1을 더한다. 영구 힘 X와 임시 힘 XVII가 함께 있어도 신규 영구 힘은 XI로 결정한다. 임시 물약은 상승 기준에 포함하지 않는다.
- 증가 결과가 상한을 넘으면 그 후보는 선택하지 않는다. 약속한 +3을 임의로 +1로 줄여 맞추지 않는다.
- `fallback: "only_ownership"`은 유효 후보가 없을 때 효과 없이 가호의 보유권·고유 점수를 지급한다. `"none"`이면 지급을 보류한다. 어느 쪽인지는 가호마다 정한다.

기존 고정 가호의 `amplifier`는 0부터 시작하지만, 위 적응형 정의의 `level`은 I=1부터 시작한다. 단계 표기와 내부 증폭값을 혼동하지 않는다.

## 5. 가호를 소유하는 것과 버프가 켜지는 것은 별개

이름 있는 가호는 출처별 보유 기록과 고유 점수를 가진다. 같은 효과를 주는 가호를 여러 개 얻어도 실제 버프 단계는 더하지 않고 가장 높은 단계로 적용한다. 각 가호의 고유 점수는 보유 기록에 남고, 실제 활성 효과가 제공하는 전투 기여는 별도 항목으로 평가한다.

예를 들어 고유 점수 100인 가호 A가 힘 III, 고유 점수 50인 가호 B가 힘 V를 준다면, 고유 점수는 150이고 실제 영구 힘 효과는 V다. III+V를 힘 VIII로 만들거나 버프 효과를 출처 수만큼 중복 적용하지 않는다. 고유 점수 자체는 기획 입력이며 신 등급에서 자동 산출하지 않는다.

우유로 활성 효과를 없애도 보유 가호와 고유 점수는 사라지지 않는다. 일반 플레이어는 `/mythblessing reapply`로 보유한 영구 효과를 다시 적용할 수 있다. 더 강한 임시 효과가 있다면 즉시 낮추지 않고, 그 효과가 끝났을 때 남아 있는 낮은 효과로 돌아간다. 임시 힘 V와 더 오래 남는 힘 III도 같은 원칙을 따른다.

적응형 선택 결과는 보상 기록에 확정해 저장한다. 선택 보상을 나중에 받거나, 같은 지급을 재시도하거나, 정의·물약 상태가 바뀌었다고 다시 선택하지 않는다. 오프라인 지급 예약은 수령 가능한 플레이어 상태에서 처음 결과를 확정한 뒤 이를 보존한다. 기존 이름 없는 고정 가호에 임의의 이름·등급·고유 점수를 소급 생성하지 않는다.

### 레이드 직접 보상과 퀘스트 가호를 구분한다

| 실제 지급 경로 | 기록 출처 | 기획에서의 의미 |
|---|---|---|
| 레이드 정의에 작성한 승리 보상 | `RAID_DIRECT` | 레이드에서 직접 획득한 가호·아이템 |
| 퀘스트 완료 보상 | `QUEST` | 퀘스트로 획득한 가호. 완료 조건이 레이드 처치여도 퀘스트 보상으로 유지 |
| NPC 보상표에서 직접 지급 | `NPC_DIRECT` | NPC를 통해 직접 획득한 보상 |
| Story 사건에서 직접 지급 | `STORY_DIRECT` | 작성된 사건의 직접 보상 |
| 출처 구분이 없던 이전 저장 기록 | `LEGACY_UNSPECIFIED` | 과거 출처를 임의로 퀘스트나 레이드로 추정하지 않음 |

같은 신이 주는 힘 가호라도 직접 레이드 승리 보상과 퀘스트 보상은 획득 출처가 다르다. **직접 레이드 가호만으로 ‘레이드 외 경로에서 가호 획득’ 조건을 충족시키지 않는다.** 가호 자체의 보유·효과·고유 점수는 유지하고 획득 경로를 구별한다. 기획자는 각 가호를 레이드 직접 보상으로 줄지, 별도 퀘스트 보상으로 줄지 명시하면 된다. 동일 처치에 두 경로의 보상을 모두 주려면 각각의 보상 정의를 의도적으로 작성해야 한다.

행운은 레이드 직접 보상에도 적용할 수 있다. 레이드의 `rewards`에 `lucky_item` 풀을 참조하면 수령자별 행운으로 후보·수량을 결정하고 결과를 저장한다. 고정 `item`을 적으면 수량은 그대로다. 즉, 행운 보상의 적용 여부는 퀘스트인지 레이드인지보다 **해당 보상을 행운 풀로 작성했는지**에 달려 있다. 새 레이드에서 직접 주는 가호도 적응형 후보·고유 점수를 지정할 수 있으며, 실제 작성 방법은 [레이드 보상 계약](../mythictrpg-main/docs/RAID_RUNTIME.md)을 참고한다.

### 루트 기획과 가호 보유 조건

루트는 **인물들과 관계를 맺고 성장에 접근하는 경로의 분류**다. 고정 직업 선택이나 서로 분리된 독립 캠페인으로 취급하지 않는다. 여러 경로가 겹칠 수 있고, 다른 경로에 접근했다고 기존 관계를 초기화하지 않는다. 조우, 봉인 상태, 주시, 호의, 가호 보유, 개인 `MAIN` 진행은 각각 독립적인 상태로 관리하며 하나를 달성했다고 나머지가 자동으로 충족되지는 않는다.

사용자가 정리한 14개 분류는 다음과 같다. 이 표는 기획 개념을 보존하며 실제 인물의 등급·가호·퀘스트·자동 적대 조건을 배정하지 않는다.

| 분류 | 관계·성장 접근 경로 |
|---|---|
| 올림푸스 | 해당 신들과 관계를 맺고 성장하는 경로 |
| 티탄 | 올림푸스와 적대하는 티탄을 통한 경로 |
| 오딘 | 오딘과 그 주변 인물들을 통한 경로 |
| 헬라 | 오딘과 적대하는 헬라를 통한 경로 |
| 이집트 | 이집트 인물들을 통한 경로 |
| 천마 | 천군 참여·천마의 인정·구성원별 호감을 구분하는 경로 |
| 인간 | 신의 가호에 의탁하지 않는 성장. 제압한 힘과 직접 레이드 보상은 허용 |
| 악마 | 강압 또는 협력을 거쳐 마왕으로 향하는 경로 |
| 괴수 | 에키드나를 중심으로 하는 경로 |
| 사신수 | 네 존재를 거쳐 황룡으로 향하는 경로 |
| 사흉수 | 네 존재를 거쳐 흑룡으로 향하는 경로 |
| 달기 | 개인 관계를 통해 성장하며 천마 경로와 겹칠 수 있는 경로 |
| 노멀 | 다양한 기본 인물과 기타 신화권을 포함하는 경로 |
| 외신 | 후속 구상. 대다수와의 적대 방향은 있으나 발생 조건은 미확정 |

루브라스·천사·장인을 별도의 독립 대분류로 추가하지 않는다. 용족을 통해 루브라스에게 접근하는 방법을 마련하는 것과 루브라스 독립 루트를 신설하는 것은 구분한다. 적대 관계나 아르테미스 레이드의 접근 제한은 기획에서 검토하는 예시이며, 구체적인 정사·대상·발생 조건을 시스템이 자동으로 배정하지 않는다.

**인간 루트는 레이드 직접 보상을 제외한 신의 가호를 보유하는 동안 진행할 수 없다.** 우유로 활성 효과를 없애도 가호 보유권이 남으므로 인간 루트의 조건을 충족한 것으로 바뀌지 않는다. 레이드 처치를 조건으로 완료한 퀘스트의 가호는 `QUEST` 출처이므로 직접 레이드 예외가 아니다. **가호를 버리는 기능은 미정이며, 가호를 버린 뒤 인간 루트로 돌아오는 기능도 확정하지 않았다.** 이 조건을 ‘과거에 한 번이라도 가호를 받았는가’라는 영구 제한으로 해석하거나, 반대로 효과 제거를 가호 포기로 해석하지 않는다.

이번 코드가 제공하는 것은 가호 보유·지급 출처에 기반한 범용 조건 `mythictrpg:has_non_raid_blessing`이다. 전체 루트 선택, 자동 적대, 루트별 인물·퀘스트 접근 제한은 구현하지 않았다. 어떤 콘텐츠에 이 조건을 연결할지는 위 기획을 바탕으로 별도 작성한다.

## 6. 행운·힘의 현재 초기 수치안

아래 숫자는 개발에 사용하는 조정 가능한 초기안이다. 콘텐츠 전체의 최종 밸런스 확정을 뜻하지 않는다.

| 항목 | 초기안 | 적용 범위 |
|---|---|---|
| 힘의 기본 증가 | 단계 `L`당 공격력 `+3L` | Minecraft의 기존 힘 효과 |
| 레이드 힘 추가 보정 | 힘을 제외한 무기 공격력 `A`에 대해 `+A × 0.04 × L` | 자유/고정 필드로 사용하는 두 레이드 모드의 유효 참가자가 해당 시도에 소속된 몹을 직접 근접 공격할 때. 일반 필드 사냥·PvP·발사체에는 추가 보정하지 않음 |
| 전투력의 성급함 평가 | 공격 평가에 `1 + 0.02 × L` | 전투력 비교용 계수. 실제 RPG 스킬 쿨다운 감소율을 뜻하지 않음 |
| 행운의 보상 후보 가중치 | `기본 가중치 × exp(0.04 × L × 품질)` | 명시한 행운 아이템 풀. 품질은 -5–5 |
| 행운의 수량 보너스 | `floor(기본 수량 × 0.02 × L)`, 추가 최대 16개, 최종 최대 64개 | `quantity_bonus_allowed: true`인 후보만. 기본값은 false |
| 행운의 사건 후보 가중치 | `기본 가중치 × exp(0.03 × L × 품질)` | 행운 선택을 명시한 사건 후보만 |

힘의 `A`에는 힘을 제외한 실제 공격 속성과 날카로움 기여를 포함한다. 추가분에도 기본 공격처럼 충전량·치명타 조건을 반영한다. 기존 힘의 +3과 기존 날카로움 피해를 다시 더하지 않는다. 레이드의 실제 허용 범위는 참가·생존·해당 시도 몹·전장 위치를 함께 확인한다.

행운은 등록된 후보들의 상대적인 가중치를 바꾼다. 새 아이템이나 미작성 사건을 만들어 내지 않는다. 대응 도구의 수량을 늘리고 싶지 않다면 수량 보너스를 켜지 않는다. 예를 들어 기본 10개인 허용 후보는 행운 XVII에서 13개지만, 보너스를 허용하지 않은 기본 5개 도구는 그대로 5개다. 결과는 아이템 종류·컴포넌트·수량·당시 행운 단계와 함께 확정된다.

## 7. 아직 기획 결정을 기다리는 부분

후속 확정: 모든 무기에 스킬을 넣지 않는다. 2026-10-22 [스킬·장신구·특수스킬 전달서](skills-accessories-special-planning-20261022.md)를 따른다. 기본 마나200+장신구 증가분, 최대 마나의초당1% 회복, 스킬별 비용·쿨타임과 유료 빗나감·장신구 환급을 사용한다. 실제 인물별 배정은 비워 두며 성급함의 자동 쿨타임 감소는 미정으로 유지한다.

| 항목 | 필요한 결정 |
|---|---|
| 인물별 배정 | 각 신의 등급, 줄 수 있는 일반·특성 버프, 우선순위 |
| 등급별 상한 | 6등급 각각의 효과별 최대 단계. 모든 효과에 일괄 동일 상한을 적용할지 여부 포함 |
| 개별 가호 | ID·이름·설명·고유 점수·후보·상승 폭·보유권만 지급하는 대체 허용 여부·지급 퀘스트 |
| 최종 밸런스 | 힘의 무기 비례 계수, 행운 품질·가중치·수량, 장비·가호 점수와 레이드 권장 전투력 |
| 실제 체력 확장 | 체력 4,000 같은 규모를 목표로 삼을지, 속성 상한·회복·HUD를 어떻게 확장할지 |
| 세계 기여 | 무엇을 개인의 기여로 인정하고 전투력에 어떻게 반영할지. 현재 초기안 계수는 0 |
| 포화 | 일시적인 음식 회복, 상시 허기 억제, 독립 패시브 중 무엇을 원하는지 |
| 성급함과 스킬 | 실제 스킬 목록, 쿨다운 감소 대상·최소 대기시간·고단계 한계 |

원본 콘텐츠에서 관측한 **전투력 약 32,000, 체력 4,000, 피해 감소 약 97%는 참고 자료**다. 새 콘텐츠에서 반드시 맞춰야 하는 목표값이나 원본 공식이 확인됐다는 뜻은 아니다. 체력 4,000을 실제 목표로 정한다면 현재 Minecraft 최대 체력 속성 상한 1,024를 넘는 확장 작업이 필요하다. 높은 보호 인챈트와 저항의 조합도 관측치 97%에 맞추기 위해 임의로 보정하지 않는다.

기획 측에서는 3절의 표를 신별로 채우고, 7절의 미정 항목을 결정하면 된다. 그 결과를 기존 God ID와 퀘스트·보상 정의에 연결하며, 실제 신별 보상표가 작성되기 전까지 예시 값을 운영 콘텐츠에 자동 배정하지 않는다.

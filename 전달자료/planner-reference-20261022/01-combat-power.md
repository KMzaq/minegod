# 실제 전투력 계산 자료

2026-10-22 · `behaivior`의 현재 `mythictrpg-main` 개발 소스 기준. 코드 수정 없이 설정·입력·계산 경로를 대조했다. 아래 계수는 `PROPOSED_INITIAL_BALANCE`라는 이름으로 구현된 조정 가능한 초기안이며, 운영 서버의 설치·로드 상태나 정식 콘텐츠의 밸런스 확정을 뜻하지 않는다.

기본 파일의 `items`와 `recommendations`는 현재 모두 빈 배열이다. 따라서 **실제 보상 장비 목록·점수와 세계 진행도별 권장 전투력 표는 아직 작성되지 않았다.** 기본 계산 모델은 있지만, 이 파일만 보고 특정 인물의 보상이나 퀘스트 수주 전투력을 이미 확정했다고 해석하면 안 된다.

실제 서버에서는 `data/<namespace>/mythictrpg/combat_power/<path>.json`으로 사용자 정책 하나를 작성할 수 있다. 기본 파일과 사용자 정책이 함께 있으면 기본 파일을 제외하고 사용자 정책을 선택한다. 같은 리소스 경로를 더 높은 데이터팩 우선순위로 덮는 것도 가능하다. 서로 다른 사용자 정책이 둘 이상 남거나 정책 파싱이 실패하면 계산 불가다. 이 문서는 소스 기본값을 설명하며, 서버에서 실제 선택된 정책은 `/mythpower`의 `policy=` 근거와 로드된 데이터팩으로 확인한다.

## 2. 무엇을 입력하는가

계산은 다음 순서로 같은 플레이어의 서버 상태를 캡처한다.

1. **원장·정책 준비 확인.** 보상 지급 이력이 처음부터 완전하게 기록됐는지, 저장 세션과 보유권이 유효한지 확인한다. 과거 이력 누락을 현재 인벤토리로 추정하지 않는다.
2. **기본 최대 체력 `H₀`와 기본 공격력 `A₀`.** 플레이어 attribute의 기본값과 실제 영구 modifier를 사용한다. modifier 계산은 `ADD_VALUE` → `ADD_MULTIPLIED_BASE` → `ADD_MULTIPLIED_TOTAL` 순서다. 착용 장비의 일시 modifier와 현재 효과 자체의 modifier를 빼서 이중 계산을 막는다. 현재 체력의 남은 비율은 입력하지 않는다.
3. **획득 장비 후보.** 현재 손이나 방어구칸 대신 [보상 지급 이력](reference/mythictrpg-main/src/main/java/com/sande/mythictrpg/power/RewardPowerState.java)의 아이템·components 변형을 정책의 정확한 등록 항목에 대조한다. `BOUND_REWARD_GEAR`는 후보가 되고, `IGNORE`는 전투력에서 제외한다. 미등록 변형·중복 등록·실제 인챈트와 선언 단계의 불일치는 계산 불가다.
4. **현재 활성 효과.** 해당 효과의 실제 `amplifier + 1`을 사용한다. 저항은 I–IV, 다른 효과는 I–XVII가 평가 범위다. 같은 효과의 출처별 단계를 더하지 않는다. 힘 V 아래에 힘 III가 숨겨져 있으면 지금은 V, V가 끝나 III가 활성화되면 III로 계산한다. 우유로 효과를 지우면 활성 효과 항은 내려가지만 획득한 가호의 고유 점수는 남는다. 현재 유효한 임시 포션 효과도 활성 효과 항에 포함된다.
5. **획득 가호·스킬·장신구의 고유 점수.** 가호는 보유 원장의 고유 점수 합, 습득·특수스킬은 등록 정의의 `intrinsicPower`, 장신구는 합법적으로 획득한 권한 중 고정 점수가 높은 두 개의 합이다. 장신구의 실제 효과는 착용한 두 개만 적용되지만, 고정 전투력은 착용 여부와 분리한다.
6. **현재 세계 진행도.** 작성된 권장값 표의 구간을 고르는 데 쓴다. 현재 별도의 세계 기여 점수 원본은 정의되지 않았고 `worldContributionCoefficient:0`이다. 이 값을 0이 아닌 값으로 바꾸는 것만으로 세계 기여 기능이 완성되지는 않으며, 현재 캡처는 이를 거절한다.

기본값에서 일반 플레이어의 `H₀=20`, `A₀=1`이라면 무효과·무등록장비 상태의 순수 계산은 30이다. 다만 실제 `/mythpower`가 이 값을 반환하려면 위 원장·정책 조건도 통과해야 한다.

## 3. 장비 선택 순서

기본 집계는 `SUM_SLOT_BEST`다.

1. 지급 이력의 각 등록 장비 후보 하나만 넣어 전체 평가기를 돌린다. 현재 활성 효과, 보유 스킬 등의 나머지 입력은 동일하게 둔다.
2. 같은 `slot`에서는 그 단일 후보 평가 총점이 가장 높은 하나를 선택한다. 동점은 코드의 안정적인 identity 순서로 결정한다. `intrinsicPower`만 비교하는 방식은 아니다.
3. 선택된 장비들의 고유 점수와 보호 단계를 합친다. 무기 공격력과 날카로움은 **한 무기의 조합**을 사용한다. 무기 A의 공격력에 무기 B의 날카로움을 붙이지 않는다.
4. 선택된 무기의 스킬 점수와 보유 습득·특수스킬 점수를 ID별로 합친다. 같은 ID는 최대 점수 한 개만 인정한다.

따라서 점수가 더 좋은 새 무기를 얻었다고 옛 무기 고유 점수를 모두 더하지 않는다. 반대로 장비를 잠시 벗거나 분실해도 획득 이력 점수가 내려가지 않는다. 재지급은 새 능력 획득으로 중복 적립하지 않는다. 대여받은 장비를 들었다는 이유로 획득 이력에 점수를 더하지 않는다.

정책을 `MAX_ALL`로 바꾸면 모든 후보 중 하나만 선택한다. 기본 슬롯별 집계와 혼용하지 않는다. 또한 현재 알고리즘은 후보별 평가 후 슬롯별 선택이며, 모든 장비 조합을 전부 탐색하는 최적화기는 아니다.

## 4. 실제 수식과 순서

기호는 다음과 같다. 효과 단계는 0부터가 아니라 I=1, II=2다. 없는 효과·인챈트는 0이다.

| 기호 | 뜻 |
|---|---|
| `B` | 생명력 강화 단계 |
| `S` / `T` | 힘 / 성급함 단계 |
| `R` / `G` | 저항 / 재생 단계 |
| `N` | 선택된 한 무기의 날카로움 단계 |
| `P` | 선택된 장비의 보호 단계 합계 |
| `W` | 선택된 무기의 정책상 `attackDamage` |
| `E` | 선택된 장비의 `intrinsicPower` 합 |
| `O` | 획득 가호의 고유 점수 합 |
| `K` | ID별 중복을 제거한 무기·습득·특수스킬 고유 점수 합 |
| `J` | 보유 장신구 중 상위 두 획득 권한의 `fixedPower` 합 |

### 4-1. 체력과 무기 공격 입력

```text
H = H₀ + 4B
날카로움 보정 = N=0이면 0, N>0이면 0.5 + 0.5N
A = A₀ + W + 날카로움 보정
```

장비가 없으면 `W=0`, 날카로움도 0이다. 여러 후보가 남아도 공격 입력은 가장 강한 단일 무기의 조합으로 선택한다. `W`는 장비에서 더하는 공격 입력이므로 플레이어 기본 공격력 `A₀`를 중복해서 넣지 않는다. `intrinsicPower`가 실제 공격 attribute를 생성하지는 않는다.

### 4-2. 힘·성급함을 함께 평가

```text
공격 항 = 10 × (A + 3S + 0.04AS) × (1 + 0.02T)
```

날카로움을 `A`에 먼저 포함하고, 힘의 바닐라 고정 증가 `3S`와 무기 비례 증가 `0.04AS`를 더한다. 그 합에 성급함 평가 배율을 적용한다. 따라서 같은 힘 I라도 무기·날카로움이 높으면 비례 항이 더 크고, 성급함은 힘을 더한 전체 공격 입력에 작용한다.

이 식은 **전투력 환산식**이다. 실제 모든 타격의 피해가 10배가 되거나 성급함 I가 실제 무기 스킬 쿨타임을 2% 줄인다는 뜻은 아니다. 치명타·공격 충전·스킬 시전 주기·적 방어력을 이 환산식에서 시뮬레이션하지 않는다.

### 4-3. 체력·재생·저항·보호를 함께 평가

```text
남는 피해 비율 Q = (1 - 0.2R) / (1 + P/40)
체력 항 = H
방어 효과 항 = H × (1 + 0.02G) × (1/Q)^0.5 - H
생존 항 = 체력 항 + 방어 효과 항
        = H × (1 + 0.02G) × sqrt((1 + P/40)/(1 - 0.2R))
```

생명력 강화로 늘어난 `H`에 재생 평가 배율을 곱하고, 저항·보호가 남기는 피해 비율의 역수에 제곱근을 취해 곱한다. 체력 항과 방어 항을 따로 표시하기 위해 마지막에 `H`를 뺐다가 총합에서 다시 더하는 구조다. 체력을 두 번 더하는 것이 아니다.

저항 IV에서는 분모가 `1-0.8=0.2`이고, 보호 합계120이면 `1+120/40=4`다. 두 요소만 고려한 남는 피해는 `0.2/4=0.05`, 즉 95% 감소다. 평가 점수에는 이 역수 20을 그대로 곱하지 않고 `sqrt(20)`을 쓴다. 재생은 단계당 2%라는 **평가용 완화 계수**이며 바닐라 실제 초당 회복량을 재현한 식이 아니다.

현재 전투력 모델은 방어구의 방어력·방어 강인함을 별도 항으로 직접 환산하지 않는다. 반영할 가치가 있다면 장비의 고유 점수 등 정책 기획으로 다뤄야 한다. 실제 피해 계산에서는 바닐라 방어력·강인함 등의 단계가 별도로 존재한다.

### 4-4. 기타 효과와 고정 점수를 마지막에 더함

```text
총 전투력 = 공격 항 + 생존 항 + 기타 활성 효과 점수 + E + O + K + J
```

위 식은 현재 기본 계수(`basePower=0`, 체력·장비·가호·스킬 계수=1, 세계 기여 계수=0)를 대입한 것이다. 일반형은 각 항에 정책의 대응 계수를 곱한다. 장신구 `J`는 `equipmentCoefficient`를 곱하지 않고 **정해진 고정값 그대로** 더한다.

기타 효과의 현재 기본점수는 다음과 같다. 힘·성급함·저항·재생·생명력 강화는 앞의 상호작용 수식으로 이미 평가했으므로 여기서 중복 가산하지 않는다.

| 방식 | 효과 | 기본 점수 |
|---|---|---|
| 단계 비례 | 신속 / 점프 강화 / 흡수 | 단계당 5 / 1 / 6 |
| 보유 여부 | 화염 저항 / 포화 / 수중 호흡 | 8 / 4 / 1 |
| 보유 여부 | 투명화 / 느린 낙하 / 돌고래의 우아함 / 전달체의 힘 | 4 / 2 / 1 / 3 |
| 점수 0 | 행운 및 그 밖에 기본 설정 표에 명시된 효과 | 0 |

0점 효과도 실제 게임 효과가 없다는 뜻은 아니다. 행운은 보상·사건 확률에 연결한다. 반대로 기본 표에 없는 새 효과가 활성화되면 임의로 0점을 주지 않고 `UNSCORED_ACTIVE_EFFECT`로 계산을 거절한다. 단계가 다른 동일 효과가 여러 출처에 있어도 유효 최고 단계 하나만 사용한다.

장신구의 최대 마나·공격력·재생 등 실제 효과는 고정 전투력 `J` 이외에 자동으로 다시 환산하지 않는다. 스킬의 피해·회복 수치도 자동 점수 변환하지 않고 정의한 `intrinsicPower`로 반영한다. 이미 활성 버프나 장비 수치로 들어간 가치를 고유 점수에 다시 전부 넣으면 기획상 중복 평가가 생길 수 있다.

## 5. 같은 계수로 계산한 예시

아래 장비와 수치는 **계산 설명용 입력**이다. 현재 기본 정책의 실제 등록 보상 목록이 아니다. 실제 사용하려면 장비·스킬·가호 정의와 지급 원장을 먼저 연결해야 한다.

### 예시 A: 기본 상태

`H₀=20`, `A₀=1`, 장비·효과·고유 점수 없음.

```text
H=20, A=1
공격=10×1=10, 생존=20
총점=30
```

### 예시 B: 무기와 날카로움만

예시 A에 `W=7`, 날카로움 V 무기 한 개. 장비 고유 점수는 설명을 위해 0으로 둔다.

```text
날카로움=0.5+0.5×5=3
A=1+7+3=11
공격=110, 생존=20
총점=130
```

### 예시 C: 여러 효과와 보호의 결합

예시 B에 생명력 강화 III, 힘 I, 성급함 I, 재생 II, 저항 II, 보호 합계40을 더한다. 먼저 기타·고유 점수는 0이다.

```text
H=20+4×3=32
공격=10×(11+3+0.04×11)×1.02=147.288
생존=32×1.04×sqrt(2/0.6)=60.760689...
총점=208.048689...
```

여기에 신속 II와 화염 저항(기타18), 장비 고유50, 가호 고유12, 중복 제거 후 스킬18, 장신구 고정 합23을 추가하면 `208.048689+18+50+12+18+23=329.048689...`다. 정수 반올림을 계산 중간에 넣지 않으며 코드 총점은 `double`이다.

## 6. 실제 피해 보정과 전투력 환산을 구분

[RaidCombatScaling.java](reference/mythictrpg-main/src/main/java/com/sande/mythictrpg/raid/RaidCombatScaling.java)의 실행은 별도다.

- **힘 추가 피해:** 고정·자유 필드의 ACTIVE 레이드 참가자가 같은 시도의 등록 적을 직접 기본 공격할 때만 적용한다. 실제 장비 attribute에서 힘을 뺀 공격력에 날카로움을 더한 값을 `A실제`라 하면 추가분은 `A실제×0.04S×(0.2+0.8×공격충전²)×치명타배율`이다. 바닐라 `+3S`는 기존 원래 피해에 남아 있다. 기존 incoming 피해 배율도 보존한다. 투사체·PvP·레이드 밖 적·스킬의 일반 `hurt` 호출에 이 힘 추가분을 자동 적용하지 않는다.
- **보호 곡선:** 본인 지급 이력과 등록 정책에 일치하는 **실제 착용 방어구**의 일반 보호 인챈트에 `1/(1+P/40)` 곡선을 적용한다. 해당 코드는 보호 보정에 ACTIVE 레이드 참가 조건을 요구하지 않는다. 다른 일반/특수 보호 기여는 별도로 보존하며, 효과·인챈트·무적을 무시하는 피해 등은 우회한다. 전투력에서는 획득 이력을 쓰지만 실제 방어는 착용 장비를 쓴다는 차이가 있다.
- 평가의 재생 `1+0.02G`, 성급함 `1+0.02T`를 그대로 실제 회복량·스킬 쿨타임 보정으로 실행하는 기능은 없다.

## 7. 보상 기준과 수주 기준에 연결할 때

### 현재 구현된 연결: 즉석 의뢰의 뒤처짐 보상 보정

[GeneratedQuestService.java](reference/mythictrpg-main/src/main/java/com/sande/mythictrpg/quest/dynamic/GeneratedQuestService.java)의 `create`는 실제 평가를 조회하여 즉석 의뢰의 보상 단계를 최대 1단계 보정한다.

```text
권장값 표에서 현재 세계 진행도에 맞는 한 행을 선택
실제 전투력 < 권장 전투력 × lowRatioExclusive 이면 catchUp=1
그 외 catchUp=0
실제 보상 tier = min(maximumRewardTier,
                  baseRewardTier + min(catchUpMaximumBonus, catchUp))
```

현재 `lowRatioExclusive=0.5`다. 권장값이 1,000이면 실제값499는 +1 후보이고 500은 +0이다. 이는 세계 진척 대비 뒤처진 플레이어에게 주는 **보상 tier 보정**이며 수주 가능 최소값과 다르다. 보상 tier는 신의 6등급이나 장비 7등급 번호와도 별개다.

`recommendations:[]`이면 v2는 권장값0·보정0으로 실제 총점을 계산할 수 있다. 표를 작성했다면 현재 진행도에 정확히 한 행이 매칭되어야 하며, 0행 또는 여러 행 매칭은 계산 불가다. 계산 불가도 기존 보상 자체를 중단시키지 않고 이 뒤처짐 보정을 0으로 한다.

### 현재 미구현: 퀘스트·Story 수주의 최소 전투력 자동 판정

현재 등록된 조건과 실행 호출에서 **`전투력 ≥ n`을 판정하는 범용 조건이나 일반 퀘스트의 최소 전투력 필드는 없다.** 권장값 표를 쓰거나 `minimumPower` 같은 임의 필드를 JSON에 넣는 것만으로 수주 제한이 생기지 않는다. 수주 기준 숫자를 기획안으로 작성할 수는 있지만 자동 제한을 실행하려면 별도 시스템 연결이 필요하다. 이번 자료 정리에서는 새 기능을 추가하지 않았다.

최소 수주 전투력을 정할 때는 대표 장비·가호·스킬·장신구 조합별 계산값과 함께 기록하고, 현재 활성 임시 효과를 수주 검사에 허용할지 등 판정 시점을 정해야 한다. 이는 아직 구현된 수주 정책이 아니라 후속 기획 입력이다.

### 기존 가이드에서 달라진 부분

[GENERATED_QUESTS_GUIDE.md의 전투력 절](../../mythictrpg-main/docs/GENERATED_QUESTS_GUIDE.md)은 과거 HanesTest/v1 설명을 포함한다. 그 절의 ‘전체 기본 동작은 UNAVAILABLE’, ‘권장 구간 표 필수’, ‘보유 영구가호와 활성 효과의 최고값을 함께 평가’라는 설명을 현재 v2에 그대로 적용하지 않는다. 현재 v2는 위에서 설명한 **빈 권장표 허용, 현재 활성 효과와 가호 고유 점수 분리**를 따른다. 다만 지급 이력 coverage와 저장 세션 검증, 미등록 입력의 계산 거절은 유지된다.

기존 사용자 v1 정책을 선택한 경우에는 v1 총점 계산을 유지한다. v2 수식으로 바꾸려면 명시적인 정책 이관이 필요하다. 이 문서가 기존 v1 정책을 자동 수정하지 않는다.

## 8. 기획자가 채울 값과 현재 한계

| 항목 | 현재 상태 | 기획 산출물 |
|---|---|---|
| 전투력 수식 | v2 초기안 구현 | 수치 조합별 목표 구간과 계수 검토 |
| 보상 장비 점수표 | 기본 `items:[]` | 정확한 아이템·components·slot·고유 점수·공격력·인챈트·스킬 |
| 가호·습득·특수스킬 점수 | 등록 정의의 값을 사용 | 개별 정의·고유 점수, 중복 가치 검토 |
| 장신구 전투력 | 보유 권한 상위2 고정 점수 구현 | 각 정의의 `fixedPower` |
| 세계 진행도별 권장값 | 기본 `recommendations:[]` | 실제 world progress ID별 구간과 권장값 |
| 수주 최소 전투력 자동 검사 | 미구현 | 기준과 검사 시점 확정 후 별도 연결 |
| 현재 체력·마나잔량·실제 DPS | 총점에 직접 반영하지 않음 | 필요 시 별도 정책 논의 |
| HP4,000 확장 | 이 평가식만으로 구현되지 않음 | 실제 HP 확장은 별도 시스템 작업 |

확인은 일반 플레이어 `/mythpower`, 관리자 `/mythpower <player>`로 한다. 현재 총점·권장값·보정값과 계산 불가 사유를 조회하는 읽기 전용 명령이다. 점수표를 채웠다는 사실과 서버 적용·실제 인게임 검증을 구분한다.

# 마인크래프트 탐험 단서와 신 조우 기획 전달

작성일: 2026-10-20  
범위 정리: 2026-10-21 · 탐험 단서와 조우에 관한 제안 2번  
대상: 스토리와 이벤트를 기획하는 담당자  
목적: 마인크래프트의 탐험과 생활 행동이 단서 발견, 인물과의 만남, 관계와 의뢰로 이어지도록 사건을 설계한다.

플레이어가 광물을 캐고, 동물을 돌보고, 유적을 탐사하고, 집을 짓는 과정에서 새로운 존재의 흔적을 발견하게 한다. 얻은 단서를 바탕으로 다음 행동을 선택하고, 만남 이후에는 대화와 관계를 통해 새로운 탐험의 이유를 얻는 흐름을 목표로 한다.

## 프로젝트의 전제와 이번 기획 범위

이 프로젝트는 Minecraft 1.21.1 기반의 소규모 RPG 서버이며, 신들과의 AI 대화에 퀘스트, 레이드, 탐험, 장비 성장, 경제와 스토리가 연결된다. 플레이어는 자유롭게 이동하고 건축하며, 같은 장소에 항상 모여 있지는 않는다.

- 세계를 초기화하지 않는 방향이다. 초기화 제거에 따른 전체 진행 구조와 후발 참여 문제는 별도 기획에서 다루므로 여기서는 재설계하지 않는다.
- 누군가 대화 중이어도 다른 장소의 독립적인 이벤트는 발생할 수 있다.
- 스토리와 등장인물은 별도로 새로 제작 중이다. 이전 콘텐츠의 인물 설정과 수치를 새 정사로 사용하지 않는다.
- 이번 전달 범위는 **단서를 어디서 어떻게 발견하고, 무엇을 추론하며, 어떤 행동으로 만남에 도달하는가**다. 확률, 보상량, 레이드 수치는 별도 밸런스 항목이다.

## 설계할 플레이 흐름

1. **일상 행동:** 탐험, 채집, 농사, 동물 돌보기 등 평소 플레이를 한다.
2. **첫 단서:** 특이한 물건, 흔적, 소문처럼 관심을 끄는 정보를 얻는다.
3. **탐색 방향:** 조사나 대화로 장소, 시간, 필요한 행동을 좁힌다.
4. **준비와 시도:** 관련 물건을 준비하거나 특정 장소와 상황에서 행동한다.
5. **조우:** 현재 세계 상태와 개인 자격에 맞는 존재 또는 사건을 만난다.
6. **후속 동기:** 관계, 의뢰, 도구, 새 단서가 다음 탐험으로 이어진다.

단서를 본 즉시 정답과 정확한 좌표를 모두 알려줄 필요는 없다. 대신 플레이어가 **지금 무엇을 더 알아보거나 시도할 수 있는지**는 판단할 수 있어야 한다. 중요한 만남의 유일한 경로를 추측만으로 맞혀야 하는 숨은 조건에 묶지 않는다.

단서는 발견과 만남의 연결 방식이다. 모든 신의 조우에 단서 수집을 의무화하거나, 우연한 만남을 전부 정해진 순서의 퀘스트로 바꾸지는 않는다.

## 마인크래프트에서 활용할 소재

아래 소재는 기획 재료다. 실제 지원 여부는 뒤의 기능 표와 구분한다.

| 소재 | 플레이어가 하는 일 | 단서로 연결할 예 |
|---|---|---|
| 바이옴과 지형 | 해안, 숲, 사막, 산, 동굴 등을 탐험 | 특정 지형에서 반복되는 흔적을 발견하고 관련 지역을 추정 |
| 차원과 시간 | 오버월드, 네더, 엔드에서 시간과 장소를 선택 | 같은 장소라도 특정 시간대에 다른 현상이 나타남 |
| 아이템 | 물건을 획득하고 조사하거나 지참 | 발견물의 설명과 다른 단서를 조합해 쓰임을 알아냄 |
| 채집과 농사 | 광물 채굴, 수확, 재배 활동 | 지역의 이상 징후나 해당 활동에 관심 있는 존재와 연결 |
| 동물과 몬스터 | 먹이주기, 번식, 처치 등 | 생물의 반응이나 사건 후 남은 흔적을 조사 |
| 유적과 구조물 | 난파선, 폐허, 사원, 직접 만든 장소 탐사 | 문양, 책, 표지, 장치가 다음 조사 지점을 알려줌 |
| 집과 생활 공간 | 집, 정원, 작업장, 서재를 꾸미고 사용 | 이미 만난 인물이 방문하거나 생활 사건에서 새 단서를 제공 |
| 대화와 관계 | 소문을 묻고 발견물을 보여주며 신뢰를 쌓음 | 상대가 실제로 아는 범위에서 단서를 해석하거나 소개를 제안 |

네더와 엔드는 기본 차원으로 사용할 수 있지만, 새 차원과 특수 지형은 별도 제작 자원이 필요하다. 바닐라 아이템과 블록을 이용한 작은 사건부터 구성할 수 있게 한다. 날씨, 낚시, 고고학, 음반 재생 같은 세부 행동은 사건마다 감지·판정 연결을 확인한다.

## 단서와 조우 조건을 구분하는 방법

### 반드시 필요한 조건

이야기상 자격, 필요한 세계 상태, 특정 장소에서의 실제 행동처럼 충족해야 하는 조건이다. 어떤 조건을 만족해야 하며, 그 조건을 플레이어가 어떻게 알 수 있는지 함께 작성한다.

아이템 조건은 다음 뜻을 구분한다.

| 조건의 뜻 | 기획에서 적어야 할 내용 |
|---|---|
| 과거 획득 | 한 번 얻었으면 버리거나 소비한 뒤에도 유효한가 |
| 현재 보유 | 인벤토리, 손, 장비 슬롯 중 어디에 있어야 하는가 |
| 현재 제시 또는 사용 | 누구에게 어떤 행동으로 보여주거나 사용하는가 |
| 특정 출처 | 직접 발굴, 보상 지급, 거래, 친구에게 전달받기 중 무엇을 인정하는가 |
| 실제 제출 | 수량을 소비하는가, 조건 확인만 하는가 |

예를 들어 일반 깃털을 가진 것과 특정 사건에서 얻은 깃털을 가진 것은 다른 조건이다. 출처가 중요하면 평범한 아이템 ID만으로 판정하지 않도록 구현 요구에 적는다.

### 만남에 유리한 조건

관련 아이템이나 행동이 만남의 후보·우선순위·확률에 영향을 주는 경우다. 필수 조건과 구분하고, 수량·종류·서로 겹치는 조건의 중복 적용 여부를 정한다. 확률 보정을 넣는 사건은 같은 종류의 물건을 대량 소지하거나 모든 관련 물건을 들고 다니는 것이 유일한 정답이 되지 않게 검토한다.

### 발생을 시도하는 계기

조건을 만족하는 것과 실제 조우를 시도하는 시점은 별개다. 관련 행동 직후, 등록 장소 진입, 제한된 주기 검사 중 무엇을 사용할지 정한다. 게임이 후보와 조건을 검사하고, 대화가 필요한 시점에 AI를 사용한다. 모든 이동이나 블록 상호작용에 새 AI 요청을 보내는 방식은 피한다.

## 실패해도 다음 행동이 보이는 탐색

- **아직 자격이 없음:** 공개 가능한 범위에서 준비할 방향이나 다른 조사 경로를 제공한다.
- **조건은 맞지만 만남이 안 됨:** 흔적, 기다릴 이유, 다른 단서 등 가능한 후속 반응을 정한다. 모든 실패에 반응을 줄지는 사건 성격에 맞게 선택한다.
- **상대가 부재 또는 다른 일로 바쁨:** 대기, 재방문, 다른 단서 조사 중 무엇이 가능한지 정한다. 부재한 인물을 AI 대사만으로 등장시키지 않는다.
- **핵심 단서가 분실됨:** 다시 조사, 기존 정보 재확인, 재획득 등 복구 경로를 정한다. 핵심 물건의 복구와 보상의 반복 지급은 구분한다.
- **같은 행동을 반복함:** 인정하는 시도와 반복 간격을 정한다. 다시 접속하거나 같은 물건을 주고받는 것으로 최초 발견 보상을 반복해서 받지 않게 한다.

장기간 운이 나쁘면 보조 단서, 대체 경로, 누적 시도에 따른 완화 등을 사용할지 사건별로 결정한다. 이는 추가 기획과 구현이 필요한 항목이며 현재 공통 기능으로 가정하지 않는다.

단서를 다시 보는 수단도 지정한다. 책, 기존 의뢰 화면, 대화로 재확인, 별도 단서장 중에서 고른다. 별도 단서장과 탐색 단계 UI를 선택하면 저장·화면 기능을 구현 요청에 포함한다.

## 여러 플레이어와 동시 사건

단서를 발견한 사람, 실제로 내용을 들은 사람, 조건을 충족한 사람, 실제 참가에 동의한 사람을 구분한다. 근처에 서 있었다는 이유로 모두 발견자로 기록하거나 의뢰에 자동 참여시키지 않는다.

기획자는 단서마다 개인 정보인지, 함께 조사한 사람에게 공유하는지, 서버 전체에 알려지는지 정한다. 물건을 친구에게 전달하면 물건만 넘어가는지, 설명과 지식도 전달되는지 명시한다. 비밀 정보는 현재 청중에게 공개해도 되는 범위를 작성한다.

독립적인 장소와 인물의 사건은 병행한다. 같은 인물의 실제 몸이나 같은 장치가 동시에 필요한 경우에만 충돌 정책을 둔다. 예를 들어 대기, 재방문, 같은 현장에 합류 중 어떤 경험을 제공할지 정한다. 다른 곳에서 대화한다는 이유로 서버 전체 사건을 막지 않는다.

대화나 건축 도중 전투 사건이 걸릴 수 있다면, 사전 징후·제안 수락·보류·중단 후 재개 여부를 함께 기획한다. 진행 중인 대화의 자동 중단과 복원은 현재 보편 지원 기능으로 가정하지 않는다.

전투 준비, 재료, 집, 평판, 동시 사건의 별도 기획과 시스템 분담은 [작업 분담 문서](content-planning-system-split-20261020.md)에서 다룬다. 이 문서는 그 기능들의 독립 설계 명세를 포함하지 않는다.

## 사건별 작성 양식

기획자는 아래 양식으로 사건을 전달한다. 원고 작성용 항목이며 실제 JSON 필드명이 아니다.

| 항목 | 작성할 내용 |
|---|---|
| 사건 이름과 목적 | 어떤 플레이의 재미와 어떤 후속 동기를 주는가 |
| 첫 발견 | 어떤 행동 중 어떤 단서를 얻는가 |
| 다음 조사 | 단서가 장소·시간·물건·행동 중 무엇을 알려주는가 |
| 필수 조건 | 세계 상태, 개인 자격, 대상 장소, 아이템과 출처 |
| 선택적 보정 | 관련 행동·물건이 어떤 영향을 주며 중복은 어떻게 제한하는가 |
| 시도 계기 | 어느 행동 또는 검사 시점에 발생을 시도하는가 |
| 성공 결과 | 조우, 정보 습득, 의뢰 제안, 실제 아이템 지급 중 무엇인가 |
| 실패와 복구 | 미충족, 확률 실패, 부재, 단서 분실 때 가능한 다음 행동 |
| 참여와 공개 | 발견자, 청취자, 참가자, 공유 범위와 비밀 범위 |
| 반복과 충돌 | 첫 발견과 재발견, 재시도, 동일 인물·장치의 동시 사용 |
| 표현 자원 | 책·설명문·대사·블록·엔티티·소리·입자·모델 중 필요한 것 |
| 게임 연결 | 기존 기능으로 작성할 부분과 추가 개발이 필요한 부분 |
| 미정 사항 | 확률, 간격, 수량 등 아직 확정하지 않은 값 |

성공 결과는 구체적으로 적는다. 단서를 얻었다고 의뢰 수락까지 완료되는 것은 아니며, 의뢰 제안은 실제 참가 동의와 분리한다. AI의 설명만으로 아이템 지급·조우·사건 성공을 확정하지 않는다.

## 작성 예시

아래는 형식 설명을 위한 비정사 예시다. 등장인물과 결말은 별도 스토리에 맞춰 정한다.

### 해안에서 발견한 표식

플레이어가 해안의 등록 조사 지점을 살피다가 물결 모양 표식을 발견한다. 조사문은 해가 저물 때 바람이 닿는 높은 곳에서 비슷한 표식이 보인다고 알려준다. 플레이어는 해안 절벽을 탐사하고, 지정된 시간과 조사 지점에서 관련 존재와 만날 기회를 얻는다.

- 조사 지점은 단순히 청크가 로드된 것과 실제 조사 행동을 구분한다.
- 높은 곳의 기준은 기획자가 정한 영역·높이·지형 중 구현 가능한 판정으로 구체화한다.
- 관련 물건이 필요하다면 과거 획득, 현재 지참, 실제 제시 중 어느 조건인지 정한다.
- 첫 반응은 존재의 흔적이나 짧은 만남이며, 의뢰는 후속 대화와 동의를 거친다.
- 시간이나 자리가 맞지 않으면 기존 조사문을 다시 읽고 다른 절벽을 탐색할 수 있게 한다.
- 해안·시간·높이 조건 기반은 있다. 등록 조사 지점과 조사 행동, 단서 저장·재열람, 해당 조우 시도의 연결은 별도 작업으로 잡는다.

### 수확 뒤에 남은 이상한 흔적

플레이어가 작물을 수확하다가 평소와 다른 흔적을 발견한다. 주변 조사나 인물과의 대화로 원인을 좁히고, 물건을 준비하거나 특정 장소를 찾아가 관계와 생활 의뢰를 시작한다.

- 수확 사실과 흔적 발견은 별도 판정으로 둔다. 수확했다고 모두 같은 사건을 겪을 필요는 없다.
- 한 자리의 빠른 반복만 유리하지 않도록 인정하는 시도·재발생 간격을 정한다.
- 친구가 수확한 사실을 본인의 실적으로 바꾸지 않으며, 공동 조사와 정보 공유는 별도로 정의한다.
- 기존 수확 관찰과 행동 신호 경로를 재사용하고, 실제 흔적 표현·획득·후속 사건을 작성한다.

## 현재 기능과 추가 연결 구분

아래는 개발 소스의 기반을 설명한다. 기반이 있다는 것은 해당 사건 전체가 작성되었거나 서버에 배포되었다는 뜻이 아니다.

2026-10-21 추가된 고정 조사점·주 손 아이템 확인·본인 Story 단서 재열람의 구체적인 형식은 [현재 시스템 가이드](../mythictrpg-main/docs/CONTENT_SYSTEMS_GUIDE.md)를 따른다. 아래 표의 통합 지도·그래픽 단서장·발굴 출처 인증 등과 구분한다.

| 요구 | 현재 활용할 기반 | 기획 또는 추가 연결 |
|---|---|---|
| 바이옴·시간·높이 조건 | 공통 조건 평가에 해당 조건이 있다. | 특정 장소 진입이나 정기 검사에서 언제 시도할지 연결해야 한다. 조건 등록만으로 자동 발생하지 않는다. |
| 아이템 획득과 주 손 제시 | 과거 획득 조건·최초 획득 관찰이 있고, 고정 조사점에서는 현재 주 손의 변형과 수량도 확인한다. | 조사점의 주 손 검사와 일반 인벤토리 지참·발굴 출처 인증은 다르다. 필요한 판정을 구분한다. |
| 생활 행동에서 시작 | 채굴, 수확, 처치, 먹이주기, 번식, 통계 임계치 등의 관찰과 신호 변환 기반이 있다. | 해당 관찰을 어떤 사건·신 후보로 연결할지 정의한다. 낚시 통계의 존재가 낚시 단서 사건 완성을 뜻하지 않는다. |
| 개인과 세계의 사실 | Story 사실·지식·범위·조건·후속 사건 기반이 있다. | 발견·조사·공유가 실제 상태를 언제 바꾸는지 연결한다. 모든 자유 대사를 자동으로 정식 지식으로 만들지 않는다. |
| 공개와 비밀 대화 | 방 참가자, 청중, 지식 공개와 실제 청취를 구분하는 기반이 있다. | 단서별 공개 권한과 공동 조사 참가 조건을 작성한다. |
| 단서 기록과 재열람 | 기존 Story 지식과 본인만 보는 `/mythclues` 재열람을 사용한다. | 지도 표식과 탐색 단계의 그래픽 UI는 별도 요구로 잡는다. |
| 확률과 장기 실패 완화 | 작성형 사건의 결과 정책과 반복·쿨다운 기반이 있다. | 관련 물건별 확률 보정·누적 실패 완화가 모든 조우에 공통 지원된다고 가정하지 않는다. |
| 집에서 후속 사건 | 건축 등록·평가·방문·생활활동과 실제 도착 Story 신호, 개인 방문 허용 설정이 있다. | 방문 이후 단서·부탁·대화로 이어질 콘텐츠가 필요하다. 음반 재생에 따른 조우는 별도 확인한다. |
| 동시 사건 | 방별 대화 격리, 실제 신·전장 예약, Story 논리 자원 예약을 사용할 수 있다. | 어떤 조사점·장치·사건이 같은 자원을 쓰는지 정한다. 대화 자동 중단·복원은 별도 연결이다. |

조건으로 후보를 숨기는 것과 실제 실행 권한을 검사하는 것은 다르다. 조우 조건을 의뢰 수주·아이템 지급·보상 실행 조건으로 그대로 사용할 수 있다고 가정하지 말고, 실행 시점의 검증 연결을 구현 담당에게 요청한다.

## 기획자에게 요청하는 첫 산출물

먼저 서로 다른 시작 행동을 가진 짧은 사건들을 위 양식으로 작성한다. 탐험에서 시작하는 사건, 생활 행동에서 시작하는 사건, 이미 맺은 관계에서 새 탐험으로 이어지는 사건을 비교하면 연결 방식의 차이를 확인하기 좋다.

각 사건에는 첫 단서부터 실제 만남과 후속 동기까지의 흐름, 실패했을 때의 다음 행동, 참여·공개 범위, 필요한 마인크래프트 자원, 추가 개발 항목을 포함한다. 확률과 보상 수치는 초안임을 표시하고, 새 신의 등급·정사·레이드 규칙은 별도 스토리와 밸런스 기획에서 결정한다.

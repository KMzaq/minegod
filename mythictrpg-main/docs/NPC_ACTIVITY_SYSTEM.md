# NPC 공간 인식·생활활동 실행 계약

HanesTest 개발 작업본 · 2026-09-30. 소스 구현과 운영 활성화는 별개다. 검증 결과는 브랜치 인수인계를 따른다.

## 사용자가 결정한 원칙

- 연출 활동과 실제 재료를 쓰는 활동을 모두 지원한다. 둘을 같은 성공 상태로 표현하지 않는다.
- 주변 시설·저장소 사용을 허용하되 플레이어 인벤토리는 읽거나 소비하지 않는다.
- “그 상자 쓰지 마”는 사회적 요청이다. 신은 성격·관계·현재 상황/힘의 근거에 따라 수용·협상·거절할 수 있다.
- 관리자 금지와 설치된 보호 모드의 명시적 veto는 성격과 무관한 실행 제한이다.
- 대련은 NPC의 초대 결정과 플레이어의 수락이 모두 필요하다. 실제 체력·장비 내구도·사망·아이템 보상을 쓰지 않는 연습 점수를 사용한다.

## 구조와 권한

`실제 GodAvatar → 게임 공간 관찰/허용 후보 → AI 페르소나 판단 → 후보 토큰 → 게임 재검증 → 보행/자세/작업 → 실제 상태`

게임 모듈이 시설, 위치, 자원, 현재 활동, 참가 가능 실체, 관리자 금지와 실행 결과를 소유한다. AI 모듈은 기존 콘텐츠 레지스트리의 페르소나를 해석하고 공급된 후보 중 선택하거나 거절한다. AI가 좌표·아이템 수·신 identity·플레이어 동의·새 세계관 사실을 생성할 권한은 없다. 기존 레이드, 방문 명령, 전투 대상, 단일 신 실체 권한을 빼앗지 않는다.

주변 관찰은 로드된 청크의 제한된 범위다. 책장·독서대·작업대·화로·모루·성숙 작물·음표 블록·저장소·화단·유리 등은 실제 블록을 근거로 후보를 만든다. 등받이가 있는 아래 계단은 의자 *후보*이며, 정확한 의미를 보장하지 않는다. 모드 가구·장식 건물의 의미는 OP 장소 태그로 보완한다. 스크린샷을 이해하거나 임의 건축물의 모든 의미를 알아보는 시스템은 아니다.

NPC가 실제 책을 읽는 경우 독서대/조각된 책장의 책에서 최대 4쪽/1,500자를 관찰한다. 모델 입력에는 예산에 맞는 일부만 들어간다. 장식 책장은 책 제목·본문을 제공하지 않는다. 책 내용은 비신뢰 작성 자료이며 정사나 명령으로 취급하지 않는다. 현재 책이나 시설이 바뀌면 이전 관찰에 근거한 활동을 중단한다.

## 활동 실행 범위

| 범주 | 실제 연결된 동작 |
|---|---|
| OBSERVE / INSPECT | 실제 대상까지 이동·바라보기, 관찰 근거를 대화에 공급 |
| REST / READ | 지지면·충돌 검사, 앉기 자세. 독서 시설을 먼저 살펴본 뒤 가능한 근처 좌석으로 이동 |
| STROLL / GUIDE / FOLLOW / WITHDRAW | 도달 가능한 근처 지점 산책, 안내 중 원래 청중 기다리기, 실제 상대 추적, 상대에게서 거리 두기. 순간이동/원격 청크 로드 없음 |
| CONVERSE / LISTEN / SOCIAL | 실제 근처 상대를 향한 말 걸기/주의 기울이기, 실제 동석 신만 참여하는 짧은 주변 대화. 없는 참가자는 만들지 않음 |
| EAT / DRINK | 연출과 실제 소비 분리. 실제 포션/음식 효과·빈 용기 처리 |
| CRAFT / REPAIR / COOK / FARM | 일반 제작 레시피·두 도구 수리·음식 조리·성숙 작물 수확/재파종과 재료/공간 검사 |
| RITUAL / OFFERING | 의식 연출 또는 기존 허용 소리/입자 템플릿, 공물 연출 또는 저장소→NPC 보관함 실제 이전 |
| TRAIN | 혼자 연습, 또는 AI가 대련을 초대한 뒤 플레이어 수락. 쌍에 한정한 무피해 타격·별도 연습 점수 |
| PLAY / PERFORM | 대화형 놀이/무보상 주사위, 지정 음표/박자의 실제 소리와 동작. 임의 놀이 규칙·보상은 발명하지 않음 |

`DECORATIVE`는 물품 소비/생산을 하지 않는다는 뜻이다. 보행·자세·발화·소리는 실제로 발생한다. `REAL`도 해당 kind의 정의된 실행만 허용한다. 의식을 했다고 가호가 생기거나 공물을 옮겼다고 관계·퀘스트 진행도가 오르는 것은 아니다. 해당 결과는 기존 게임의 별도 규칙을 거쳐야 한다.

## 대화와 자율 판단

일반 대화는 기존 2단계 엔진을 유지한다. `[NPC_ACTIVITY_CONTEXT]`에 현재 활동과 해당 요청의 후보를 넣고 기존 응답에서 다음 Proposal을 받는다. 청중/출처가 없는 구 문자열 `recent`는 호환을 위한 빈 배열로 남긴다. 과거 경험은 아래의 별도 `[NPC_ACTIVITY_EXPERIENCE]`를 사용한다.

```json
{"type":"npc_activity_request","parameters":{"choice_id":"STOP"}}
```

`choice_id`는 `STOP`, `CONTINUE`, 또는 **이번 snapshot의 `available_choices[].choiceId`에 있는 정확한 UUID**다. 원래 방·revision·요청자·신·실체·정의/보호 정책 세대·가시성을 다시 확인한다. recording 테스트와 secondary 반응은 실제 활동을 바꾸지 않는다. 실행 접수는 제작/도착 완료가 아니며, 다음 대화는 실제 상태/결과를 받는다. 대화 응답 대기 중에는 진행을 잠시 멈춰 모델이 오래된 작업 완료 상태를 말하지 않게 한다.

대화 밖 자율 판단은 별도의 낮은 우선순위 작업이다. 서버 전체에서 하나씩 순회하고 기존 `ModelAdmission`을 통해 플레이어 응답에 양보한다. 게임은 최대 16개 후보를 순환 노출하며 대화에는 최대 8개만 넣는다. 기존 Ollama URL/모델/Thinking Off 설정을 사용하고 RisuAI를 쓰지 않는다. 모델 호출에 실패하거나 후보가 만료되면 대기하며 성공을 꾸며내지 않는다.

자율 판단에는 현재 실체와 동석 신의 페르소나·정적 관계 태그, 시간/날씨, 공개 가능한 실제 활동 경험과 그 경험에 대한 과거 감정 해석이 들어간다. 다른 비밀 대화의 감정·사건을 복사하지 않는다. 플레이어 관계/힘/방 감정 근거가 없는 자율 요청은 `UNASSESSED`다. 반대로 플레이어와 진행 중인 대화의 판단에는 기존 방의 관계·감정·힘 근거가 함께 들어간다. 활동 경험의 감정 해석은 방 감정이나 호감도 원본을 대체하지 않는다.

NPC끼리의 주변 대사는 최대 4줄을 순차 표시하고 실제 살아 있는 예약된 동석 실체/가시성을 재검사한다. 신 이름은 수신자의 기존 정체 식별 권한에 따른다. 실제 화자를 기준으로 청취 신과 전달받은 플레이어를 기록하며, 이후 그 범위 밖 청중에게 원문을 제공하지 않는다. 기존 방 기억·소문 DB의 가짜 청취 영수증은 만들지 않는다.

## 실제 활동 기억·감정 연결 (2026-10-02)

- 기존 `NpcActivityWorldState` 안에 신 ID별 typed 경험을 보관한다. NPC 개체 UUID는 실행 증거이며 기억의 주인은 같은 God ID다. 실제 시작, 완료, 실패, 중단, 주변 발화를 서로 다른 사건으로 기록한다. 이동 후보·대련 초대·LLM 선택만으로 완료 기억을 만들지 않는다. 대련은 실제 동의 후 시작과 실제 종료만 기록하며 실제 체력 피해나 보상으로 해석하지 않는다.
- 신별 최대 64개, 전체 최대 2,048신의 유한 보관함이다. 최근 경험과 검색에 맞는 과거 경험을 합쳐 최대 6개만 전달한다. 무한 장기기억이나 새 벡터 DB는 아니다. 같은 사건 ID의 중복/충돌을 차단하며 오래된 원본이 정리되면 그 원본에 의존한 감정/회상 근거도 더는 사용하지 않는다.
- 일반 활동의 공개 projection은 `kind/mode/phase` 등 안전한 요약이다. 사적 지시, 정확한 장소, 책 본문, 상세 실패 원인은 여기에 싣지 않는다. `FAILED`는 실제 부수효과가 전혀 없었다는 뜻이 아니다. 정확한 재료/보상 변화는 실제 실행 결과에서 별도로 확인해야 한다.
- 주변 발화는 실제 발생한 **말**이며 발언 내용이 세계관 정사나 실행 성공이라는 보증은 아니다. 원문과 이를 참고한 감정은 현재 모든 신·플레이어 청중의 권한을 먼저 검사한다.
- 기존 자율 선택 호출에 선택적 `activityAffect`를 함께 받는다. 감정 전용 호출을 추가하지 않으며, 현재 페르소나가 실제 과거 경험을 어떻게 받아들이는지 짧게 해석한다. “READ → 행복”, “실패 → 분노” 같은 고정 수치표는 없다. 선택한 다음 활동의 예상 성공을 과거 감정의 근거로 쓸 수 없다.
- 감정은 출처가 있는 **과거의 비권위 해석**이다. 이후 경험과 대화가 이를 반박할 수 있다. 감정·호감도·관계 수치를 게임에 직접 저장/적용하는 Proposal로 취급하지 않는다. 모델이 지목한 근거뿐 아니라 그 모델이 본 모든 경험과 이전 감정의 출처를 공개 검증에 포함한다.
- primary/secondary 대화 모두 해당 화자의 `[NPC_ACTIVITY_EXPERIENCE]`를 받을 수 있다. `NPC_SESSION_EMOTION`과 별도이며, 비밀방 감정을 자율 활동에 복사하지 않는다. 방 발언이 이 경험을 근거로 사용하면 기존 `RoomEvidenceReference` 계보에 원본 사건/공개 projection의 해시를 연결하여 이후 회상에도 재검증한다.
- 대기 중 actor/revision/정의/실행 권한/청중/경험이 바뀌면 늦은 선택과 감정은 적용하지 않는다. 선택 후 순차 발화도 원본의 생존·공개 권한을 다시 검사한다.
- `ai-memory-foundation.json`의 `OFF`는 이 지속 기억의 새 쓰기·조회도 막는다. 기존 시설/금지/재개 정보는 유지한다. `TEST_EPHEMERAL`에는 기억을 제공하지 않고 테스트 대화로 실제 활동을 실행하지 않는다. 기존 출처 없는 문자열 이력은 자동으로 신 기억에 승격하지 않는다.

SavedData는 v2이며 v1의 시설·금지·운영 이력·재개 정보를 읽는다. 잘못된/알 수 없는 저장 형식은 원본을 보존하고 중단한다. 운영 설정과 기존 월드를 자동으로 바꾸지는 않는다. API와 검증 기록은 [이번 브랜치 인수인계](../../인수인계/브랜치실험/HanesTest/NPC_ACTIVITY_MEMORY_20261002.md)를 따른다.

## 실행·저장·보호

- 이동 경로의 노드까지 검사하고, 목표 소실·자리 점유·외부 명령/전투·reload·관리자 금지 시 중단한다.
- 실제 작업은 완료 tick에서 한 번만 commit한다. 연출 소품은 실제 보관함에 넣거나 드롭하지 않는다.
- NPC의 실제 27칸 보관함은 entity NBT에 저장한다. 사망 시 실제 보관함 내용만 한 번 드롭한다.
- 시설 등록/금지 구역/짧은 활동 이력/재개 계획은 `world/data/mythictrpg_npc_activities.dat`에 저장한다. 신 identity·관계 원본을 복제하지 않는다.
- 정상 청크 unload/서버 stopping에서 미완료 활동을 보관한다. 재개할 때 같은 차원·정의·지점·권한을 다시 검증한다. 유효하지 않으면 재개하지 않는다. 갑작스러운 프로세스 종료에 대한 파일 간 ACID 트랜잭션을 보장하는 것은 아니다.
- 보관함의 잠금/미개봉 loot, OP 금지, 보호 gate는 실제 사용 전에 다시 검사한다. 임의 모드가 직접 월드를 수정하는 모든 경우까지 차단하는 범용 보안 샌드박스는 아니다.

## 설정과 명령

[JSON 작성 가이드](NPC_ACTIVITY_AUTHORING_GUIDE.md)의 공용 활동과 신별 허용 목록을 사용한다. 신별 정책은 기존 God ID 경로를 따른다. 공유 라이브러리 29개만 JAR 리소스로 포함하고, 기존 신들의 활동/재료 소비를 임의로 활성화하지 않았다. 실제 신을 배치하려면 기존 [아바타 정의](NPC_ACTORS.md)도 필요하다.

```text
/mythnpc activity status <정확한 God ID>
/mythnpc activity start <정확한 God ID> <허용 활동 ID>
/mythnpc activity stop <정확한 God ID>
/mythnpc place add <영문이름> <seat,books 등 쉼표 태그>
/mythnpc place remove <영문이름>
/mythnpc deny <금지이름> <0~64 반경>
/mythnpc allow <금지이름>
/mythnpc spar invite <정확한 God ID> [목표 타격수]
/mythnpc spar accept
/mythnpc spar decline
/mythnpc spar leave
/mythnpc spar score
```

`activity`, `place`, `deny/allow`, 테스트용 `spar invite`는 OP2다. 일반 플레이어는 대련 수락/거절/퇴장/점수만 가능하다. 일시 `activity stop`은 영구금지가 아니다. `deny`는 명령 실행자의 현재 좌표/차원을 중심으로 하는 **육면체**다. 일반 “쓰지 마” 발화는 이 금지 목록을 수정하지 않는다.

## 완성으로 오해하면 안 되는 부분

- 임의 모드 기계·IItemHandler·모든 특수 아이템 사용은 지원하지 않는다. 현재 실제 저장소는 vanilla 상자/통/셜커, 레시피는 일반 vanilla 타입이다. 지원하지 않는 재료/동작은 미소비 거절한다.
- 자유 제작/시설 설치, 기존 장비 강화, 신전 봉헌 진행도·새 가호 규칙, 공물 관계 보상은 이 활동 코드에서 임의로 만들지 않았다.
- 듣기 자세가 모든 채널을 도청하거나 신을 자동으로 다른 대화방 참가자로 추가하지 않는다. 위 활동 경험 외에 소문 자동 전파나 recording-v2 전체 아카이브 이관은 연결하지 않았다.
- 실제 LLM의 상황 선택/거절 말투, 클라이언트 스킨·앉기·소품 애니메이션, 운영 서버 배포 후 동작은 별도 확인 대상이다.
- 운영 서버/클라이언트 JAR은 교체하지 않았다. entity metadata가 추가되어 개발 게임 protocol은 **10**이며 배포 시 게임 클라이언트도 같은 빌드가 필요하다.

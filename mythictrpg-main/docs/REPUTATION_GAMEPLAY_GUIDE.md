# 일반 플레이 평판과 회복

2026-10-21 · `behaivior` 개발 작업본. 운영 설치 여부와 검증 결과는 [후속 작업 기록](../../인수인계/브랜치실험/behaivior/REPUTATION_GAMEPLAY_20261021.md)을 따른다.

기존 구현은 평판·소문 서비스 전체를 `RUMOR_TEST`에서만 시작했다. Story 회복 효과도 그 서비스를 사용해 일반 플레이에서 실행되지 않았다. 이번 변경은 평판 회복을 AI 기억 시험 모드에서 분리하고, 소문을 사용하는 일반 `PERSONAL`의 생성·수신·평가·대화 조회 경로를 연결한다.

## 실행 흐름

1. 게임이 실제 목격자·대상·위치·시야·작성된 규칙·공개 대상을 확인하여 사건을 기록한다.
2. 작성형 또는 검토를 거친 소문이 허용된 신에게 전달된다. 수신과 믿음은 다르며, 승인된 평가만 평판 원장에 등록된다.
3. 기획에서 작성한 배상·중재·해명 사건의 완료 outcome에 `RECOVER_REPUTATION`을 둔다.
4. 게임은 시작 플레이어·신·정책에 해당하는 현재 평가만 회복하고 완료 영수증을 남긴다.
5. 이후 허용된 대화 조회에서 `RECOVERED`가 보인다. AI 입력에는 과거 전언이 회복된 상태임을 전달하며, 현재 사실이나 현재의 부정적 별칭으로 계속 강요하지 않는다.

AI 대사에 “용서했다”가 나온 것만으로 실행하지 않는다. 대화 설득을 사용하는 기존 경로도 준비된 검토 결과와 현재 세션·턴·청중·평가 버전을 게임이 재확인한다. 기획에서 어떤 설명·배상·업적을 회복으로 인정할지는 별도로 작성한다.

## 설정과 사용

설정은 서버 시작 때 읽는다. 운영 파일을 자동 생성하거나 덮어쓰지 않는다.

| 기능 | 필요한 설정 |
|---|---|
| Story 또는 승인 게임 결과의 평판 회복 | `config/mythictrpg/reputation-judgement.json`: `enabled:true`, 대상 신에 대응하는 기존 `rules` |
| 일반 플레이 소문 관측·발행·전달 | `ai-memory-foundation.json`: `mode:PERSONAL`; `rumor-courier.json`: `enabled:true`, 목격자 엔티티 종류·이벤트·수신 신·발행 규칙; 실제 월드에 존재하는 목격자를 게임이 연결 |
| 사건/공개 대화의 자동 소문 후보 및 수신 평가·대화 회복 검토 | 위 설정과 `social-rumor.json`: `enabled:true`, 대상 사건 경로·공개 설명·검토 지침 및 실제 검토 어댑터 |
| 대화의 현재 평판 조회 | 현재 대화 문맥과 각 청중의 실제 수신 기록. 공개방과 미수신 신에게 임의로 공개하지 않음 |
| 보관 기록 기반 조회 | 기존 기록/조회 설정. 일반 PERSONAL 출처만 같은 모드로 조회하며, 현재 게임 수신·평가를 다시 검증 |

AI 기억 `OFF`는 자동 소문 처리와 대화 소문 조회를 중단한다. **작성된 게임 결과의 회복까지 끄지는 않는다.** 평판 기능을 끄려면 `reputation-judgement.json`의 `enabled:false`를 사용한다. 설정 누락·손상·미등록 신·알 수 없는 정책을 회복 성공으로 처리하지 않는다.

회복 효과의 작성 형식:

```json
{
  "effectId": "example:restore_standing",
  "type": "RECOVER_REPUTATION",
  "god": "example:registered_god",
  "policy": "example:existing_reputation_rule",
  "reason": "example:restitution_completed"
}
```

`example:*`는 형식 설명용이다. 실제 God Definition과 평판 정책을 참조해야 한다. 위 효과는 일반 Story 사건의 outcome에 넣으며, 기획상 완료된 퀘스트·배상·중재를 기존 Story 조건과 신호로 검증한다. 사건 완료에 의존하는 후속 보상·지식은 `event_resolved` 후속 사건으로 연결한다. [전체 Story 효과 계약](CONTENT_SYSTEMS_GUIDE.md#게임-결과에-따른-평판-회복)을 함께 따른다.

현재 관계 원본은 기존 `PlayerMythDataService`다. 평판 회복은 출처별 평가의 종결이며 원본 호감도를 임의로 올리거나 과거 사건을 삭제하지 않는다. `judgement`는 승인 평가의 판단용 보정 조회이고, 상점 가격·퀘스트 수주 조건·보상에 대한 전역 자동 보정은 이번 변경에 포함하지 않는다.

## 중복·저장·격리

- `(게임 결과 ID, 플레이어, 신, 정책, 사유)`의 완료 영수증과 대상 평가를 같은 평판 원장 안에서 원자적으로 갱신한다. 저장 용량 검사가 실패하면 일부 평가만 변경하지 않는다.
- 같은 결과 ID를 다시 보내도 최초 처리만 인정한다. 대상 평가가 없었던 결과도 저장하므로, 나중에 생긴 새 평가에 과거 배상이 다시 적용되지 않는다. 다른 플레이어나 사유로 결과 ID를 재사용하면 거절한다.
- 최초 승인·소문 출처·원본 호감도는 유지한다. 현재 정책이 같은 신·ID로 등록되어 있으면 예전 정책 지문 또는 소문이 더 이상 유효하지 않아도 기존 평가를 회복할 수 있다.
- 저장된 평판 완료 영수증이 있고 Story의 효과 완료 기록만 빠진 경우에는 재시작 뒤 완료 확인을 재개한다. 영수증이 없으면 새 대상을 골라 재시도하지 않고 `RECOVERY_REQUIRED`로 보존한다.
- 평판 항목 4,096개와 회복 결과 영수증 4,096개의 한도를 사용한다. 한도 초과를 조용히 삭제로 해결하지 않는다. 이 한도는 플레이 장면 수나 바이트 용량을 의미하지 않는다.
- 소문 원본은 생성 시 `PERSONAL` 또는 `RUMOR_TEST`를 저장한다. 예전 저장본의 누락 필드는 시험 출처로 해석한다. 후보·발행·전달·조회와 일반 플레이 회복에서 알려진 다른 모드의 자료를 제외한다. 자동 시험 기록 이관은 하지 않는다.
- NEW 대화 경로는 현재 게임의 수신·평가를 별도로 조회한다. 과거 저널 전체 조회나 별도의 관찰 추론을 켜지 않는다. 실제 발행 시에도 출처·평가 버전과 현재 청중을 재검증한다.

기존 저장본 읽기는 지원하지만 새 자료를 기록한 뒤 예전 JAR로 되돌리는 하향 호환은 보장하지 않는다. 평판 저장소와 Story 저장소의 디스크 쓰기를 하나로 묶은 것은 아니므로, 강제 종료 시 두 파일 사이의 불명확한 상태는 복구 확인이 필요하다.

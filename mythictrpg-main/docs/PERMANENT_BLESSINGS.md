# 영구가호 — 보유, 효과와 재적용

2026-10-21 `behaivior` 개발 소스 기준. 2026-10-02 `HanesTest`의 영구 보유·재적용 기능에 명명된 가호와 획득 경로를 보존하는 저장 v6를 추가했다. 서버 배포·실제 클라이언트 확인과 소스/개발 테스트 결과는 구분한다. 최신 계산·작성 계약은 [가호·행운 보상과 전투력 v2](BLESSING_REWARD_POWER_V2.md), 검증 실행 결과는 해당 브랜치 인수인계를 따른다.

## 작성과 지급

기존 `blessing` 보상의 `durationTicks`에 `-1`을 쓰면 영구가호다. 양수 20~72,000틱의 기존 임시가호는 그대로다. 저항은 `amplifier` 0~3(I~IV), 다른 보상 효과는 0~16(I~XVII)이다. 새 가호 후보의 `level`은 1부터 시작하므로 기존 `amplifier`와 혼용하지 않는다. 이 상한은 콘텐츠가 작성하는 보상 검증이며 외부 모드·명령의 모든 효과를 일괄 변경하지 않는다.

```json
{"type":"blessing","effectId":"minecraft:speed","durationTicks":-1,"amplifier":1}
```

등록되지 않은 효과와 영구 즉시효과(즉시 치유/피해 등)는 작성/지급 검증에서 거부한다. 기존 보상표·직접 보상·선택 보상이 같은 codec을 사용한다. 이 기능 추가가 기존 콘텐츠에 영구가호를 배치한 것은 아니다.

퀘스트 자동/선택 보상의 영구 보유권은 지급 확정과 같은 `mythictrpg_reward_claims` SavedData에 기록한다. 아직 선택하지 않았거나 오프라인 지급 대기 상태인 보상을 소유한 것으로 취급하지 않는다. 실제 효과는 확정된 소유권을 투영한다.

`adaptive_blessing`은 정의 ID, 실제 신의 `god_rank`, 신별 허용 효과·우선순위와 등급별 상한을 명시한 보상이다. 첫 실제 수령 처리에서 효과·단계·신 등급·고유 점수를 결정해 기존 claim에 저장하고 재접속이나 재계산에서 다시 선택하지 않는다. 효과가 개선되지 않을 때의 `fallback:"only_ownership"`은 효과 없는 가호 보유와 고유 점수만 기록한다. 정의·정책 JSON은 [v2 작성 가이드](BLESSING_REWARD_POWER_V2.md)를 따른다. 기존 고정 `blessing`에 정의 ID나 신 등급을 추측해 붙이지 않는다.

기존 AI `reward_proposal`은 여전히 등록된 `template_id`와 해당 신의 보상표·등급만 실행한다. 허용된 표에 영구가호가 들어 있으면 기존 `NpcRewardGrantService`가 먼저 AI_ACTION 제한을 검사하고 같은 저장소에 NPC_TABLE 출처를 기록한다. AI에 효과 ID/단계/지속시간을 임의 지정하는 새 액션은 추가하지 않았다. 동일 신/표/등급/효과의 반복 지급은 소유권을 늘리지 않으며 보유 최고 단계만 유지한다. 보상표의 다른 보상은 기존 지급 동작을 따른다.

위 반복 동작은 고정 보상표에 적용한다. `adaptive_blessing`이나 `lucky_item`이 들어간 표는 플레이어·표·tier에 대응하는 기존 개인 claim으로 처리하며 함께 든 고정 보상도 한 번만 지급한다. 반복 호출은 이미 수령했음을 알리고 새 지급 성공으로 보고하지 않는다. 보상표 tier 1~100과 신의 6등급은 별개의 값이다.

## 현재 버프와 보유권

- Minecraft 효과는 무한 지속 시간 `-1`을 사용한다. 같은 효과를 여러 신·퀘스트에서 받아도 증폭을 합하지 않고 최고 단계 하나를 적용하며 획득 출처는 각각 보존한다.
- 더 강한 임시 포션과 겹치면 숨은 효과 연결을 유지·정규화하여 영구가호를 보존한다. 임시 효과가 끝나면 남아 있는 하위 효과/영구 단계로 돌아온다. 더 약하지만 오래가는 임시 보상도 자신의 지속 시간이 남아 있으면 하위 출처로 보존한다.
- 우유나 효과 해제는 실제 버프를 지우고 보유권은 남긴다. 제거 상태도 SavedData에 저장한다. 재접속, 같은 효과의 새 보상/동일 표 재지급만으로 다시 적용하지 않는다.
- 본인 `/mythblessing reapply`는 보유 가호의 제거 상태를 해제하고 다시 적용한다. 일반 플레이어가 사용할 수 있으며 대상 플레이어·효과·단계 인자는 없다. 다른 플레이어에게 가호를 지급하는 명령이 아니다.
- 이미 활성/숨은 무한 효과가 보유 단계를 충족하면 다시 시작하지 않는다. 명령 반복만으로 아직 남아 있는 흡수 효과의 소모 체력을 채우지 않는다.
- 사망 후 부활은 제거 상태를 해제하고 보유 가호를 다시 적용한다. 엔드 귀환의 respawn 이벤트는 사망으로 취급하지 않는다. 로그인 시 누락 효과를 자동 복구하는 경로는 없다.
- 등록 효과가 사라졌거나 다른 모드가 적용을 거절하면 보유권을 보존하고 적용 보류를 알린다. 출력의 ‘적용 확인 N종’은 실제 활성/숨은 무한효과 확인을 통과한 종류 수이며, 보류가 있으면 명령 결과도 실패로 반환한다.

가호 설명의 ‘영구 보유’는 현재 버프가 제거되지 않았다는 뜻이 아니다. **v2 전투력은 획득 가호의 고유 점수와 현재 활성 효과를 분리한다.** 우유로 지우면 활성 효과의 능력치 기여는 사라지지만 명명된 가호의 획득 기록·고유 점수는 남는다. 더 낮은 가호도 획득 기록을 유지하며 같은 지급 source의 중복 실행으로 고유 점수를 다시 얻지 않는다. 옛 고정 가호에 미작성 고유 점수는 0으로 두며, 활성 효과 자체는 v2 계산에 반영한다.

현재 계산은 [v2 가이드](BLESSING_REWARD_POWER_V2.md)를 따른다. 명시적으로 유지한 v1 정책의 ‘우유와 무관한 보유 최고 단계 점수’는 [v1 역사 가이드](BLESSING_POWER_GUIDE.md)에 남겼으며 v2의 현재 활성 효과 규칙과 혼용하지 않는다.

## 저장·호환·조회

보상 저장 버전은 **v6**다. v1~v5를 읽으며 기존 임시가호나 남은 포션으로부터 영구 소유권을 추정하지 않는다. v4의 `permanentBlessings`·`suppressedBlessings`와 v5에서 추가한 `acquiredBlessings`·완료된 확률 보상 출처 `settledDynamicSources`를 유지하고, v6에서 claim과 영구 보유권의 권위 획득 경로 `origin`을 보존한다. 미래 버전·손상 데이터는 원본 NBT를 보존하고 저장소를 읽기 전용으로 거부한다. 구버전으로 되돌리면 v6를 읽을 수 없으므로 저장/서버 버전을 함께 고려해야 한다.

`origin`은 `QUEST`, `RAID_DIRECT`, `NPC_DIRECT`, `STORY_DIRECT`, `LEGACY_UNSPECIFIED`다. 레이드 성공을 완료 조건으로 삼은 퀘스트 보상도 `QUEST`이며 실제 RaidRuntime의 직접 보상만 `RAID_DIRECT`다. 지급 receipt 형식인 `QUEST_CLAIM`과 실제 획득 경로는 별도이며 이름·God ID·source ID로 경로를 추정하지 않는다. v1~v5의 불명확한 과거 기록은 `LEGACY_UNSPECIFIED`로 읽고 레이드 예외를 부여하지 않는다. 영구 획득 이력을 보는 [Story 가호 조건](STORY_EVENT_ENGINE_GUIDE.md#51-레이드-직접-보상을-제외한-가호-획득-조건)은 `RAID_DIRECT`만 제외하므로 우유 제거나 효과 없는 보유 기록도 유지한다.

과거 저장된 `blessing` 보상의 저항 V(`amplifier:4`)는 IV(`amplifier:3`)로 읽는다. 현재 작성 JSON에 저항 V를 허용하는 예외가 아니며 기존 신 등급·정의 ID·고유 점수는 새로 추정하지 않는다. 일반 외부 효과를 이 이관 과정에서 수정하지 않는다.

영구 보유권에는 플레이어 UUID, God ID, `QUEST_CLAIM`/`NPC_TABLE` 출처 종류, source ID, 선택적 claim UUID, 효과 ID, 증폭, 최초 획득 또는 같은 출처 승급 시간이 있다. 완료 receipt가 정리돼도 소유권은 남는다. 영구가호를 지급했던 source의 receipt가 정리된 뒤에는 같은 source를 새 지급으로 열지 않는다. 다른 보상의 반복 여부나 퀘스트 완료 판정을 소유권에서 재구축하지 않는다.

명명된 가호는 여기에 정의 ID, 확정 신 등급·후보 ID, 선택적 효과 ID와 1부터 시작하는 단계, 고유 점수, 활성 여부를 보존한다. 효과 없는 보유 전용 결과는 단계 0이며 Minecraft 효과로 변환하지 않는다. 확정된 명명 가호와 행운 보상 결과는 재로딩된 정책으로 다시 추첨하지 않는다.

원장은 기존 영구 효과 출처와 명명된 가호를 합쳐 16,384개까지 유지한다. 완료된 확률 보상 source도 별도 16,384개 한도를 검사한다. 용량은 지급 확정 전에 검사하며 기존 소유권을 삭제해 빈자리를 만들지 않는다. 보유권과 receipt는 같은 SavedData 변경으로 기록되지만 Minecraft 플레이어 효과 NBT와 디스크 단위 원자 트랜잭션은 아니다. 비정상 종료로 현재 효과 적용이 어긋난 경우에도 원장의 소유권을 기준으로 본인 재적용 명령을 사용할 수 있다.

게임 내부 조회는 `RewardClaimState.permanentBlessingsFor(UUID)`의 기존 출처별 목록, `acquiredBlessingsFor(UUID)`의 명명 가호, `blessingIntrinsicPower(UUID)`의 고유 점수 합계와 `ownedPermanentBlessingLevels(UUID)`의 보유 효과별 최고 증폭을 사용한다. `hasNonRaidBlessing(UUID)`는 레이드 직접 보상을 제외한 영구 가호 획득 여부다. 보유 단계 조회는 우유 제거 여부를 뜻하지 않으므로 현재 효과 입력과 구분한다. `isWritable()`을 먼저 확인하며 거부된 저장소의 조회는 예외로 실패한다. AI 원본 DB나 별도 플레이어 프로필 복제를 만들지 않는다.

## 회귀 검증

`PermanentBlessingGameTests`, `NamedBlessingGameTests`, `BlessingSelectorTest` 등의 관련 검증 범위는 다음과 같다. 테스트 추가 자체는 실행 통과를 의미하지 않는다. 실제 실행 결과는 브랜치 작업 기록에서 확인한다.

- strict JSON/NBT, 즉시효과 거부, 기존 v3 이관, 미래 버전 원본 보존, 완료 claim 정리 후 소유권/제거 상태 유지.
- 실제 우유 소비, 플레이어 저장/재접속, 일반 권한의 본인 재적용 명령, 강한 임시 효과 종료 후 복귀, 실제 PlayerList 사망 respawn과 엔드 귀환 구분.
- 자동/선택 중복·다른 플레이어 선택 거부, 등록 보상표의 신 소유권과 AI_ACTION 제한, 출처별 중복 방지, receipt/소유권 불일치 거부.
- v2의 우유 전후 가호 고유 점수 유지와 활성 효과 점수 분리, 낮은 명명 가호의 독립 보존, 같은 source 재실행 방지, 신·등급 상한, 과거 저항 V 이관.
- v6의 직접 레이드/퀘스트 가호 획득 경로 보존과 이전 기록의 보수적 이관, 실제 Story의 획득·미획득 분기 및 우유 제거 후 조건 유지(`BlessingRouteConditionGameTests`).

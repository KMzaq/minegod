# 가호·행운 보상과 전투력 v2

2026-10-21, `behaivior` 개발 소스. 아래 계수는 사용자가 요청한 **조정 가능한 초기안**이다. 원본 콘텐츠의 공식이나 실전 밸런스 확정값이 아니다. 실행 검증·배포 상태는 [작업 기록](../../인수인계/브랜치실험/behaivior/REWARD_PROGRESSION_20261021.md)을 따른다. 인물별 실제 배정은 기획이 추후 결정한다. [기획 전달자료](../../전달자료/blessing-reward-planning-20261021.md) 참조.

## 확정 규칙과 데이터 흐름

- 저항 I~IV, 다른 보상 버프 I~XVII. JSON의 기존 `amplifier`는 0부터 시작한다. 새 가호 후보의 `level`은 1부터 시작한다.
- 같은 효과는 출처별 단계를 더하지 않고 유효한 최고 단계 하나를 적용한다. 더 강한 임시 효과 아래의 낮은 장기 효과는 유지한다.
- 가호 보유 고유 점수와 실제 활성 효과의 점수를 분리한다. 우유는 버프를 지우며 획득 기록은 지우지 않는다. 일반 플레이어 `/mythblessing reapply`로 복구한다.
- 전투력 장비 입력은 콘텐츠 지급 원장이다. 현재 착용/인벤토리 이동으로 점수를 바꾸지 않는다. 실제 피해 보정에는 본인이 받은 등록 장비를 실제로 들거나 착용해야 한다.
- 신의 실제 God ID·등급·허용 효과는 게임이 소유한다. AI는 기존 허용된 보상표/템플릿만 요청하며 효과·등급을 임의 생성하지 않는다.

`등록 보상 → 기존 claim 생성 → 후보/행운 결과 확정·저장 → 자동/선택 receipt와 보유권 기록 → 실제 효과·아이템 지급 → 현재 상태 재계산`.

기존 고정 `blessing`·아이템 보상은 유지한다. 새 `adaptive_blessing` / `lucky_item`을 작성한 보상만 새 선택을 수행한다. 퀘스트·스토리 보상·등록 NPC 표의 기존 실행 경로를 사용한다. 오프라인 보상은 기존 claim에 대기하고 실제 첫 수령 때 결정한다. 선택 보상은 자동 보상 처리 전에 모든 선택지 결과를 확정한다. 이후 행운·정의·장비가 바뀌어도 저장 결과를 다시 뽑지 않는다.

## 신 등급과 가호 작성

등급은 `lowest / low / middle / high / highest / transcendent` 6종이다. 신 정의의 `god_rank`에 작성한다. 기존 보상표의 숫자 tier와 장비 등급은 별개다. 실제 NPC 배정과 각 등급별 단계 상한은 이번에 임의로 채우지 않았다.

`data/<namespace>/mythictrpg/blessings/*.json`에 다음 세 종류를 작성한다. 아래 `example:deity`는 예시이며 운영 인물의 설정이 아니다.

```json
{"schema_version":1,"kind":"definition","god_id":"example:deity","intrinsic_score":20,"fallback":"none","candidates":[{"id":"luck","effect":"minecraft:luck","mode":"floor","level":1},{"id":"strength_up","effect":"minecraft:strength","mode":"upgrade","level":1}]}
```

```json
{"schema_version":1,"kind":"god_policy","god_id":"example:deity","effects":{"minecraft:luck":{"max_level":2,"priority":0},"minecraft:strength":{"max_level":3,"priority":10}}}
```

```json
{"schema_version":1,"kind":"rank_policy","rank":"low","effect_caps":{"minecraft:luck":2,"minecraft:strength":3}}
```

가호 정의 파일의 리소스 ID를 보상에서 참조한다.

```json
{"type":"adaptive_blessing","definitionId":"example:sample_blessing"}
```

`floor`는 지정 단계까지, `upgrade`는 보유 영구 단계에서 설정 증가량만큼 올리는 후보이다. 신별 허용·신별 상한·등급별 상한·전역 상한을 모두 적용한다. 숫자가 작은 `priority`를 우선하고, 같은 우선순위에서는 공통 전투력 평가기의 증가분과 안정적인 후보 ID 순서를 사용한다. 행운처럼 전투 점수가 0이어도 효과 단계가 실제로 개선되면 후보가 될 수 있다.

후보 판단 기준은 보유 영구 단계다. 일시 포션을 이용해 더 높은 영구 보상을 받지 않도록 임시 버프는 이 기준에서 제외한다. 실제 표시 전투력은 현재 활성 효과를 사용하므로 우유·임시 포션의 영향이 반영된다. 같은 보상 묶음에서 지급할 등록 장비와 고정 영구 효과도 후보 평가에 반영한다.

유효 후보가 없으면 `fallback:"none"`은 보상을 보류하고 이유를 알린다. `fallback:"only_ownership"`는 고유 점수만 가진 가호를 저장한다. 모든 신에게 자동 +1을 적용하지 않는다. 같은 definition을 자동 보상과 선택 보상에 동시에 넣거나 한 묶음에서 중복하면 거절한다. 서로 배타적인 선택지 간 재사용은 허용한다.

## 행운 초기안

`data/<namespace>/mythictrpg/luck/*.json`에 보상 풀과 선택적인 모델을 작성한다. 기본 계수는 희귀도 `.04`, 수량 `.02`, 사건 품질 `.03`, 추가 수량 상한 `16`이다.

```json
{"schema_version":1,"kind":"item_pool","candidates":[{"id":"common","item":{"item_id":"minecraft:iron_ingot","components":{}},"min_count":10,"max_count":10,"quality":0,"weight":90,"quantity_bonus_allowed":true},{"id":"rare","item":{"item_id":"minecraft:diamond","components":{}},"min_count":1,"max_count":1,"quality":2,"weight":10,"quantity_bonus_allowed":false}]}
```

```json
{"type":"lucky_item","poolId":"example:raid_materials"}
```

```json
{"schema_version":1,"kind":"model","rarity_per_level":0.04,"quantity_per_level":0.02,"event_quality_per_level":0.03,"max_bonus_count":16}
```

- 보상 가중치: `원래 가중치 × exp(0.04 × 행운 단계 × quality)`.
- 수량: 명시적으로 허용한 후보에만 `원래 수량 + floor(원래 수량 × 행운 단계 × 0.02)`. 추가분 최대 16개, 최종 최대 64개. 기본 10개는 행운 XVII에서 13개다. 장비·대응 도구는 일반적으로 수량 증가를 허용하지 않는다.
- 위 풀의 희귀 후보 확률은 행운 없음 10%, X 약 19.8%, XVII 약 30.2%다. `quality`는 -5~5의 상대 품질이다. 확률에 일률적으로 68%p를 더하는 방식이 아니다.
- Story `PLAYER` 범위 `WEIGHTED_ONCE` outcome에 `luckQuality`를 명시하면 `원래 가중치 × exp(0.03 × 행운 단계 × luckQuality)`를 사용한다. 중립/좋은 결과가 50:50이고 좋은 결과 quality=1이면 XVII에서 약 62.5%다.
- 전역·팀 사건, 고정 보상, 품질을 작성하지 않은 기존 사건은 이 보정 대상이 아니다. 치명타·모든 바닐라 전리품/낚시를 가로채지 않는다.

사용하는 행운은 첫 수령/사건 판정 때 실제 활성 단계(0~17)다. 선택 후보·아이템 components·수량·행운 단계와 사건 roll/outcome을 저장하며 재시도에 결과가 바뀌지 않는다.

## 전투력 초기 계산식

기본 정책: `data/mythictrpg/mythictrpg/combat_power/default.json`, `schemaVersion:2`. 동일 경로를 데이터팩으로 덮거나 한 개의 사용자 정책을 제공한다. 여러 사용자 정책이 겹치면 계산을 거절한다. 기존 v1 사용자 정책은 기존 계산을 유지하며 명시적으로 v2로 이관해야 한다. v1의 레거시 효과 표는 [기존 가이드](BLESSING_POWER_GUIDE.md)에 남겼다.

기호: `H`는 영구 기본 최대 체력에 생명력 강화 `4×단계`를 더한 평가 체력, `A`는 기본 공격력+선택된 지급 무기의 공격력+날카로움 보정, `S/T/R/G/P`는 힘/성급함/저항/재생 단계와 선택된 방어구의 보호 합계다. 날카로움이 있으면 `0.5+0.5×단계`를 한 번 넣는다.

```text
공격 항 = 10 × (A + 3S + 0.04AS) × (1 + 0.02T)
생존 항 = H × (1 + 0.02G) × sqrt((1 + P/40) / (1 - 0.2R))
총점 = 공격 항 + 생존 항 + 기타 활성 효과 점수
     + 지급 장비 고유 점수 + 획득 가호 고유 점수 + 고유 스킬 점수
```

체력·재생이 높으면 저항의 점수 기여도 커지며 날카로움이 높으면 힘·성급함의 기여도 커진다. 피해 감소율의 역수를 그대로 전투력에 곱하지 않고 제곱근으로 완화했다. 기본값은 화염 저항 8, 포화 4처럼 보유 여부 점수를 사용하고, 행운은 전투력 0점이지만 보상/사건에 실제 영향을 준다.

장비 기본 집계는 `SUM_SLOT_BEST`로 같은 슬롯에서 평가가 높은 하나를 사용한다. 다른 무기의 공격력과 날카로움을 섞어 가상의 무기를 만들지 않는다. 고유 스킬은 등록 ID별 최대 점수로 중복을 막으며 이미 수치에 반영된 버프를 고유 점수로 다시 작성하지 않아야 한다. 실행은 별도 선택 필드 `rightClickSkill`을 작성한 무기만 [무기 스킬·마나 시스템](WEAPON_SKILLS.md)에 연결한다. 점수만 등록하면 실행되지 않으며 별도 쿨다운 단축도 자동 적용하지 않는다.

v2 장비 항목은 `classification:"BOUND_REWARD_GEAR"`로 명시 등록하며 대응 도구/점수 제외 보상은 `IGNORE`로 등록한다. 지급 이력에 미등록 변형이 있으면 임의 0점으로 숨기지 않고 계산 불가 사유를 반환한다. 기본 정책에는 실제 장비 표·세계 권장 전투력을 임의로 채우지 않았다. 따라서 기존 플레이어의 이력 등록/보존 확인이 필요하다.

`/mythpower`는 총점·항목별 근거·가호 고유 항을 조회한다. 반복 조회는 보상 결정/능력치 지급을 실행하지 않는다. 후보 비교도 같은 평가기를 사용한다. 선택창에는 확정 효과·단계·고유 점수가 표시되며 전체 전투력 전후 비교 UI는 별도 구현하지 않았다.

## 실제 레이드 피해 보정

힘의 추가분은 **고정 필드와 자유 필드 모두** 활성 레이드 참가자가 같은 레이드의 실제 보스/추가 적을 직접 공격할 때 적용한다.

```text
추가 피해 = (실제 무기 공격력에서 힘 보정을 뺀 값 + 날카로움 보정)
          × 힘 단계 × 0.04 × 공격 충전 보정 × 해당 공격의 치명타 배율
```

기존 힘 `+3×단계`는 그대로 두고 추가분만 더한다. 힘 XVII, 날카로움 포함 무기 공격력 A=108.5인 예시는 완전 충전 일반 공격에서 159.5→233.28(약 +46.3%)다. A=8인 초반 무기는 59→64.44(약 +9.2%)다. 높은 날카로움에서도 힘의 상대 가치가 남도록 한 초기안이다. 투사체·PvP·외부 몹·직접 `hurt` 호출에는 새 힘 보정을 적용하지 않는다.

등록 지급 방어구의 실제 보호 합계 `P`에는 남는 피해 비율 `1/(1+P/40)`을 사용한다. 저항 IV와 합치면 보호120에서 95%, 보호240에서 약97.14% 감소다. 이는 방어력/강인함 등 다른 단계 전의 두 효과만 비교한 값이다. 원문의 '3등급 보호30'이 부위당인지 합계인지는 미확정이므로 97%를 모든 해당 장비에 강제하지 않는다.

보호·날카로움 작성 범위는 1~255다. 기존 일반 방어구/특수 보호 인챈트의 바닐라 처리를 보존한다. 등록 고단계 보호는 새 곡선이므로 P120의 보호 단독 감소75%는 바닐라 상한80%보다 낮다. 높은 단계에서 점진적으로 성장시키는 의도적인 초기 밸런스 변경이다. 힘·생명력 강화·저항·날카로움의 실제 바닐라 상수는 자유 변경하지 못하게 검증하며 새 힘 비율/보호 곡선/전투력 환산 계수를 조정한다.

## 저장과 한계

기존 `mythictrpg_reward_claims` SavedData v6에 named 가호 결과·보상 출처·완료된 확률 보상 source를 저장한다. 이전 v1~v5를 읽으며 과거 보상 저장의 저항 V는 IV로 이관한다. 옛 가호에 정의 ID·신 등급·고유 점수를 추측해 붙이지 않는다. 미지정 옛 가호의 고유 점수는 0이며 활성 효과는 새 모델로 평가한다. 일반 외부 효과를 일괄 변경하는 정책은 아니다.

### 레이드 직접 가호와 퀘스트 가호

`RewardOrigin`은 실제 지급 경로가 기록한다. 레이드가 자체 지급한 보상은 `RAID_DIRECT`, 레이드 성공을 완료 조건으로 가진 퀘스트가 지급한 보상은 `QUEST`다. NPC 표 직접 지급은 `NPC_DIRECT`, Story 자체 지급은 `STORY_DIRECT`이며 모두 레이드 예외에 해당하지 않는다. 보상 JSON·AI payload가 출처를 지정할 수 없고 source ID에 raid라는 단어가 있어도 추론하지 않는다.

가호 획득 이력 조건 `mythictrpg:has_non_raid_blessing`을 NOT으로 감싸면 레이드 직접 보상만 제외한 ‘신의 가호를 얻지 않은’ 분기를 작성할 수 있다. 이름 있는 가호와 기존 고정 영구가호 모두 조회하며 우유/효과 비활성은 획득 이력을 지우지 않는다. 일시 물약 효과는 영구 가호 획득 이력이 아니다. 과거 v1~v5에 출처 정보가 없는 기록은 `LEGACY_UNSPECIFIED`로 보존하고 보수적으로 비레이드 가호에 포함한다. 기존 자료만으로 레이드 출처를 추측하여 루트를 열지 않는다.

여기서 루트는 인물의 관계·성장·접근 경로를 묶은 기획상 분류다. 루트 선택 필드나 독립 캠페인 진행도를 새로 만들지 않았다. 조건은 인간 경로의 필요한 퀘스트·사건 등에 기획이 붙일 수 있는 범용 보유권 조회이며, 조우·봉인 해제·주시·호의·개인 MAIN 자격을 대신하지 않는다. 현재 가호 포기 기능은 없으므로 보유 원장의 취득 기록으로 판정한다. 포기와 복귀를 구현하거나 영구 금지를 확정한 것은 아니다. 루트명만으로 동맹·적대·레이드 참가 자격을 부여하지 않는다.

레이드 자체 `rewards`에서도 `lucky_item`과 `adaptive_blessing`을 사용한다. 행운은 직접 레이드 보상 수령 시의 활성 단계로 희귀도·허용 수량에 반영되며 결과와 출처는 함께 고정된다. 보상 풀/가호 정의 누락은 레이드 생성·시작·입장 전에 검사한다. 행운 가호의 낮은 획득 빈도는 기획에서 신별 허용 목록·조건·보상 표로 정한다.

완료 receipt 정리 후에도 가호 소유권/동적 보상 source를 유지하여 같은 source를 새 보상으로 열지 않는다. 보상표의 동적 보상은 플레이어·표·tier당 한 번이며 함께 든 고정 보상도 해당 receipt에 묶인다. 순수 고정 보상표의 기존 동작은 유지한다.

보유권과 receipt는 같은 저장소에서 검증하지만 플레이어 인벤토리 파일과 완전한 디스크 원자 트랜잭션은 아니다. 비정상 종료까지 포함한 무손실 지급을 보장한다고 표현하지 않는다. 저장 한도·손상 데이터는 명시적으로 거절하고 기존 기록을 지워 공간을 만들지 않는다.

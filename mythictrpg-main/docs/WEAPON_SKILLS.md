# 선택형 보상 무기 스킬과 마나

2026-10-21 `behaivior` 개발 소스. 검증·배포 상태는 [작업 기록](../../인수인계/브랜치실험/behaivior/WEAPON_SKILLS_20261021.md)을 따른다.

2026-10-22 후속: [스킬·장신구·특수지원](SKILLS_ACCESSORIES_SPECIAL.md)에 습득 스킬, 동적 최대 마나·초당1% 회복, 유료 빗나감·환급, 범위·반복 피해, 장신구·선택형 특수 사용 제한을 연결했다. 최신 검증은 해당 가이드의 작업 기록을 따른다.

2026-10-22 게임 **1.0.37** 후속: [야생 전투와 파티](WILDERNESS_COMBAT_AND_PARTY.md). 검기·패링·대쉬를 일반 야생에 연결하고, 실제 FTB 파티원과 본인·파티원의 길들인 동물을 공격에서 보호한다. 주민 직접 우클릭은 스킬, Shift+우클릭은 거래다. 피해량·마나·쿨타임은 유지한다.

## 사용 규칙

- **지정된 일부 보상 무기만** 주 손 우클릭으로 스킬을 사용한다. 스킬이 없는 무기는 기존 Minecraft 동작을 유지한다. 보조 손으로 스킬을 발동하지 않는다.
- Shift+우클릭은 스킬을 사용하지 않고 기존 블록 조사·상자·NPC·아이템 상호작용으로 전달한다. 기존 레이드 보호 규칙은 그대로 적용한다.
- 처음 마나는200, 기본 최대 마나는200+장신구 증가분이다. 접속 중 살아 있는 비관전자 플레이어는 사용 직후부터 최대치의1%를 초당 회복한다. 사용 후 대기시간은 없다.
- 마나와 스킬별 쿨타임은 플레이어 UUID 기준으로 저장한다. 무기 교체·동일 무기 복사본·재접속·리스폰은 초기화 수단이 아니다. 같은 스킬 ID를 공유하면 쿨타임도 공유하며 다른 스킬은 각각 계산한다.
- 쿨타임은 서버 월드 틱으로 흐른다. 플레이어가 로그아웃한 동안에도 서버가 실행 중이면 감소하지만, 오프라인 마나는 회복하지 않는다. 서버 중지 시간은 진행하지 않는다.
- 마나 부족·쿨타임·잘못된 소유권 같은 시전 전 조건 실패와 불필요한 자기 회복/버프는 무소모다. 정상 공격은 시작 시 비용을 소비하고 대상 없음·벽·피해 취소도 빗나감으로 처리한다. 환급 장신구가 있으면 시전 전체 적중0에서 마나 일부를 돌려준다. 동일 틱 중복 성공은 막는다.
- 왼쪽 위 HUD에서 마나와 현재 지정 무기의 스킬·비용·남은 쿨타임을 확인한다. `/mythmana`는 본인의 마나를 조회한다. 임의 충전 명령은 추가하지 않았다.

마나 회복 속도는 실제 서버 틱에 따른다. 성급함·힘이 이 스킬의 비용/쿨타임/명시 피해량을 자동 변경하지 않는다. 스킬 비용의 작성 한도는 정수0~1,000,000, 쿨타임은 정수0~72,000틱(최대1시간)이다. 실제 마나가 부족하면 사용하지 못한다. 0 비용/0 쿨타임도 명시적으로 허용한다.

## 작성 순서

### 1. 실행할 스킬 정의

데이터팩 `data/<namespace>/mythictrpg/weapon_skills/<id>.json`을 작성한다. 아래 수치는 **작성 예시**이며 운영 무기에 자동 적용하지 않는다.

```json
{
  "schemaVersion": 1,
  "name": "회복 예시",
  "manaCost": 30,
  "cooldownTicks": 100,
  "action": { "type": "SELF_HEAL", "amount": 4 }
}
```

현재 실행 가능한 행동은 한 스킬당 다음 중 하나다.

| type | 필드 | 동작 |
|---|---|---|
| `SELF_HEAL` | `amount` (0 초과~2000) | 본인의 체력을 회복. 최대 체력과 기존 회복 취소 이벤트를 존중 |
| `SELF_EFFECT` | `effectId`, `level`, `durationTicks` | 등록된 유익한 비즉시 효과를 본인에게 일시 적용. 저항 I~IV, 나머지 I~XVII, 1~72,000틱 |
| `AIMED_DAMAGE` | `amount` (0 초과~2000), `range` (0 초과~32블록) | 서버가 조준선과 벽을 검사하여 가장 가까운 생명체에 지정 **마법 피해**를 적용 |

```json
{"schemaVersion":1,"name":"방어 예시","manaCost":20,"cooldownTicks":200,"action":{"type":"SELF_EFFECT","effectId":"minecraft:resistance","level":1,"durationTicks":100}}
```

```json
{"schemaVersion":1,"name":"조준 마법 예시","manaCost":25,"cooldownTicks":60,"action":{"type":"AIMED_DAMAGE","amount":6,"range":8}}
```

`AIMED_DAMAGE`는 Minecraft 간접 마법 피해다. 일반 방어구 방어력을 우회하고 저항·마법 피해에 적용되는 보호 규칙을 따른다. 플레이어에게 귀속된 피해로 처리하므로 레이드 참가·대상 제한, PvP 설정, 아군·NPC 보호를 우회하지 않는다. 조준 범위의 청크가 로드되지 않았으면 실행하지 않는다. 좌클릭 무기 피해나 레이드 근접 힘 보정을 복사하지 않는다.

`SELF_EFFECT`는 임시 효과이며 **가호 보유권을 지급하지 않는다**. 인간 루트의 가호 보유 여부를 변경하지 않는다. 활성 효과에 따른 기존 전투력·행운 보정은 적용된다. 약한 장기 효과가 강한 단기 효과 아래에 남는 처리는 기존 가호 효과 적용기를 재사용한다. 실제로 새로운 효과가 적용·예약되지 않으면 차감하지 않는다. 모든 특성 버프를 무기에 무작위 배정하지 않는다.

광역 피해와 동일 대상 반복 피해는 후속 공통 실행기에 추가했다. 2026-10-22에는 [전투 1차 시제품](FIRST_COMBAT_PROTOTYPE.md)으로 이동 검기·시간 패링·짧은 대쉬도 연결했다. 새 행동의 물리 피해·유효 적·시전 잠금·시험 범위는 해당 안내를 따른다. 한 무기의 복수 입력 스킬은 별도 확장이 필요하다. 레이드 인물 지원과 참가자 회복은 특수스킬로 구분한다. 시제품 정의는 등록했으며 실제 인물 보상 배정은 비워 두었다.

### 2. 해당 보상 무기에만 연결

[전투력 v2](BLESSING_REWARD_POWER_V2.md)의 **기존 등록 장비 항목**에 선택 필드 `rightClickSkill`을 추가한다. 아래는 `example:heal`이라는 스킬 파일을 작성했을 때의 항목 예시다.

```json
{
  "itemId": "minecraft:iron_sword",
  "components": { "minecraft:custom_model_data": 2001 },
  "classification": "BOUND_REWARD_GEAR",
  "slot": "weapon",
  "intrinsicPower": 0,
  "attackDamage": 6,
  "sharpnessLevel": 0,
  "protectionLevel": 0,
  "skills": { "example:heal": 0 },
  "rightClickSkill": "example:heal"
}
```

`skills`는 전투력 점수이고 `rightClickSkill`은 실제 실행 연결이다. 두 역할을 혼동하지 않는다. 실행 ID는 `skills`에도 등록하지만 점수 0도 가능하다. 별도의 확정 점수 없이 임의 가산하지 않는다. **스킬 없는 무기는 `rightClickSkill` 필드 자체를 생략한다**. `skills`가 비어 있지 않아도 실행 연결을 생략할 수 있다. `IGNORE` 대응 도구나 방어구 슬롯에 실행 연결을 작성하면 정책이 거절된다.

기존 퀘스트/NPC/스토리/레이드 아이템 보상에 동일한 아이템 ID·컴포넌트를 작성해 지급한다. 새로운 보상 지급 경로를 만들지 않는다. 스킬 정의가 없거나 정책이 유효하지 않으면 활성화하지 않는다. 잘못된 스킬 데이터팩 재로드는 실행 스킬 목록을 비우고 오류를 서버 로그에 남긴다. 최대 1024개 스킬, 문서당 16KiB다.

## 저장·권한·호환

- 게임의 기존 `CombatPowerRuntime.registeredAcquiredGear`로 개인의 완전한 획득 이력과 실제 주 손의 등록 변형을 대조한다. 내구도 변화만 허용하고 다른 컴포넌트·인챈트 변경은 다시 등록해야 한다. 아이템 이름이나 클라이언트 스킬 ID만으로 소유권을 인정하지 않는다.
- 같은 변형의 정당한 획득 이력을 인증하며 개별 아이템의 물리적 일련번호를 새로 만들지는 않는다. 과거 이력이 불완전한 장비는 기존 권한 정책에 따라 활성화되지 않는다.
- `world/data/mythictrpg_weapon_skills.dat` 하나에 현재 마나, 마지막 사용·회복 틱, 스킬별 쿨타임 종료 틱을 저장한다. 손상·미지원 자료를 임의 초기화하지 않고 원본을 유지하며 사용을 차단한다. 개인 계정 최대16,384, 계정당 활성 쿨타임 최대1024개다.
- `weapon-skills-3` 네트워크는 본인의 동적 최대 마나·무기 상태·시전/기절에 따른 공격 잠금을 내려준다. 클라이언트는 서버가 보낸 아이템·슬롯과 현재 선택이 맞을 때만 우클릭을 요청한다. 서버가 접속 객체·소유권·자원을 재검사하며 양손에서 두 번 결제하지 않는다. 서버와 클라이언트의 MythicTRPG JAR을 같은 버전으로 맞춘다. [Simply Swords·Better Combat 연동](SIMPLY_SWORDS_INTEGRATION.md)은 기존 보상/스킬 권한을 유지한다.
- 서버/클라이언트 양쪽에 새 게임 모드 JAR이 필요하다. AI 모듈에 별도 마나 저장소나 스킬 실행 권한을 추가하지 않았다.

기획 후속은 **어떤 보상 무기에 스킬을 넣을지, 각 스킬의 효과·비용·쿨타임·고유 점수**를 정하는 일이다. 전체 무기 스킬 의무화, 성급함 쿨타임 감소, 최대 마나 성장·마나 아이템은 확정하지 않았다.

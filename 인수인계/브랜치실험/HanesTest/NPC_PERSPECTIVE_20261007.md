# 기억·상황에 이어지는 NPC 반응 개선

2026-10-07 / HanesTest / 개발본 작업. 서버 배포와 인게임 검증은 별도다.

## 목표와 범위

모델은 gemma4:12b를 유지한다. 캐릭터를 일괄 친절하게 만들거나 특정 발화의 고정 답변을 추가하지 않는다. 과거에 실제로 들은 말, 허용된 관찰, 현재 활동과 관계가 지금의 선택·표현에 영향을 주도록 기존 검색→분류→생성 연결을 보완한다. 새로운 세계 상태 DB, 관계 저장소, 감정 판정 LLM 호출은 만들지 않는다.

## 확인한 누락

- 새 RoomMemoryStore는 현재 문장으로만 검색했다. 기존 레거시 검색에 있던 최근 플레이어 발화 기반 문맥 검색이 빠져, “그럼 출발할까?” 같은 후속 발화가 이전 주제의 기억을 찾기 어려웠다.
- Primary의 기억 사용 지침은 레거시 기억이 있을 때만 활성화됐다. 신규 actuallyHeardMemory만 검색된 경우 빠졌다. Secondary에는 해당 지침과 레거시 기억 scope 검사가 없었다.
- Phase 1 분류에는 신규 heard 기억이 전달되지 않았다. 생성에는 기억이 있어도 앞선 분류가 과거 약속·후속 말을 새 요청으로 해석할 수 있었다.
- 관찰·현재 상황·관계 입력은 이미 존재한다. 이들을 새로운 시스템으로 중복 구현하는 대신, 자기 관점에서 함께 해석하되 사실과 해석을 구분하도록 생성 지침을 정리한다.

## 최소 변경 설계

1. 허용된 request.history에서 **현재 질문자 자신의 최근 PLAYER 원문 최대 2개**만 검색 보조로 사용한다. NPC 발화·다른 플레이어·Secondary로 확장하지 않는다. 직접 일치 우선, 화제 전환·무관 질의 제외, 기존 시간 예산·청중·증거 검증 유지. 보조 문맥에 맞춰 찾은 원문 구간을 인용한다.
2. 주 응답과 보조 신 반응에 공통 자기 관점 지침을 적용한다. 누구의 경험/약속인지, 신이 왜 신경 쓰는지, 현재 행동·목적과 어떤 관련이 있는지를 함께 고려하되 내부 추론을 출력하지 않는다. 기억을 반드시 언급하거나 질문·공감으로 끝내게 하지 않는다.
3. 실제 예산 맞춤 후 남은 기억에만 기억 사용 지침을 활성화한다. 보조 신은 마지막으로 **게임이 전달한 신의 발화**에 반응하며 아직 전달되지 않은 플레이어 입력을 보지 않는다.
4. 분류에는 이미 권한 검증된 신규 기억의 작은 **완결된 변형 하나**만 추가한다. 입력/출력 IO, 권한, 분류 호출 수는 그대로다. 분류는 여전히 가설이며 감정·사실을 확정하지 않는다.
5. 새 기억 저장소 형식, 관계/감정 영속성, 관찰 공개 권한은 변경하지 않는다. 기억 부족을 사건 부재나 무관심으로 간주하지 않는다.

### 비교 후 보완

첫 장문 지침 변형은 기억이 반영되어도 다른 신의 약속을 자기 약속으로 취급하는 오류를 막지 못했다. 따라서 지침을 더 누적하지 않고 관점 설명을 간결하게 줄였다. `RoomMemoryBridge`가 이미 보유한 typed 기록의 화자와 현재 query scope를 비교해 `speaker_relation_to_responding_god`를 함께 투영한다.

- `SELF`: 응답 신 자신이 말한 기록.
- `OTHER_GOD`: 다른 신이 말한 기록.
- `CURRENT_PLAYER`: 현재 질문자가 말한 기록.
- `OTHER_PLAYER`: 다른 플레이어가 말한 기록.

이 값은 **누가 말했는지**만 뜻한다. SELF의 인용문 안에 다른 신의 행동이 있어도 그 행동을 자기 행동으로 만들지 않는다. 원문의 문자열을 파싱해 권한을 얻는 방식이 아니며 저장된 원문·ID·게임 IO는 바뀌지 않는다. 현재 reader scope가 없는 기존 helper는 이 값을 추측하지 않고 생략한다. 모든 완결된 기억 변형·분류 예산에 추가 필드 길이도 포함한다.

소문/평판의 기존 `CAUTIOUS`, `INTERESTED`, `DOUBTFUL`, `DISPUTED`, `IGNORED`, `RECOVERED`, `RETRACTED` 해석은 소문이 공급될 때만 유지한다. 회복된 평판을 현재 비난으로 되살리거나, 대화상 동의로 게임 평판이 해제되었다고 하지 않는다.

## 호환과 실제 입력 범위

- 수정 모듈은 AI 응답뿐이다. MythicTRPG·콘텐츠 레지스트리 소스/JSON·서버 설정은 수정하지 않는다. 외부 Request/Response/Proposal 계약 변경은 없고, LLM에 보여주는 내부 기억 JSON에 위 메타데이터만 추가된다.
- `RoomMemoryStore.candidates`의 기존 overload는 그대로 유지한다. 예전 저장 기록은 재작성 없이 읽고, 현재 신 기준 상대적 출처는 매 요청 계산한다.
- 최근 발언에 현재 PLAYER 입력이 이미 들어 있는 호출에서는 **마지막 동일 화자·원문 한 줄만** 보조 검색에서 제외한다. 예전에 반복한 같은 말까지 삭제하지 않는다. 정상 게임 submit은 원래 현재 발언 직전의 history를 공급한다.
- 기존 기록 ON/OFF·영속/임시 정책과 게임이 허용한 근거가 전제다. 꺼져 있거나 저장/공개 권한이 없는 기억을 생성하지 않는다. 행동 관찰의 기존 단일 신·비밀 대화 등 허용 범위를 임의로 넓히지 않는다.
- 장기 관계는 게임 값이고, 방 감정은 유효한 실제 전달 근거에 연결된다. 이번 변경은 모든 방에 영구 감정을 덧씌우거나 관찰하지 못한 행동을 자동 수집하지 않는다.

## 검증 계획

- 저장 후 재열기→후속 문맥 검색, 직접 일치 우선, 타 방/청중/신 출처 격리, NPC 발화로 검색 확장 금지.
- 주/보조 프롬프트 기억 활성화·예산 제거·scope, 분류 입력의 출처/길이/중복 방지 검사.
- 0.1.31 프롬프트를 test 소스로 동결하고 동일 Gemma/입력의 비교 실험. 과거 제약·자기/타신 약속·직접 관찰/주장·친밀하지만 상처받은 상태·실행 대기·모르는 길 등을 별도 평가한다.
- 실제 LLM의 검토 PASS는 정답 판정이 아니다. 원문과 실제 실행 상태 기준으로 결과를 읽고 퇴행도 보고한다. 재시작 영속성 검증과 합성 대화 평가, 실서버 검증을 구분한다.

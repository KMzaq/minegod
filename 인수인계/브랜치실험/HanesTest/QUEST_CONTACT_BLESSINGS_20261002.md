# 퀘스트 완료 접촉 · 영구가호 · 가호 전투력

2026-10-02 / `HanesTest`. 게임 개발본 1.0.25, AI 응답 0.1.28, 콘텐츠 0.1.3, 게임 protocol 10. **운영 미배포**다. 이 문서는 이번 사용자 결정과 구현·검증 상태만 기록한다.

## 확정한 규칙

- 기본 완료 방식은 목표 달성 → 의뢰한 신의 확인 → 정산이다. 목표를 달성했다는 이유만으로 신을 자동 소환하거나 방문을 개시하지 않는다. 작성자가 명시한 `AUTO`/`NPC_VISIT_PLAYER` 예외는 별도로 유지한다.
- 원격 확인에는 해당 신의 주시 보유권뿐 아니라 **현재 그 플레이어를 관찰하는 유효한 주시 세션**과 현재 응답 가능 상태가 필요하다. 독서·산책·다른 활동·다른 대화·전투·레이드 중에는 원격으로 확인할 수 없다.
- 직접 찾아가 실제 NPC를 클릭하면 독서·산책 중에도 대화할 수 있다. 주시가 없는 플레이어는 수주 장소/지정 장소에서 실제 대면하거나 조우 조건을 다시 만족한 실제 조우를 이용한다. 좌표 도착, AI의 주장, 관리자 테스트 방 생성만으로 완료 접촉을 만들지 않는다.
- 영구가호는 Minecraft 무한 효과로 지급하되 우유 제거를 유지한다. 로그인은 자동 복구하지 않는다. 본인 재적용 명령 또는 실제 사망 후 부활 때 복구하며 엔드 귀환은 사망이 아니다.
- 전투력은 현재 버프 유무가 아닌 **확정 지급된 영구 가호의 보유 최고 단계**를 반영한다. 아직 선택하지 않은 보상 후보는 소유가 아니다. 효과·단계별 초기 점수표 작성은 사용자가 승인했으며 향후 JSON 조정 가능하다.

## 구현 경계와 사용

`QuestContactService`가 실제 접촉과 플레이어·신·현재 세션/revision을 검증한다. 기존 주시 원장·활동·실체·Story/레이드와 기존 퀘스트 서비스에 연결했으며 별도 AI 판정 원본은 만들지 않았다.

- `/mythquest call <godId>`: **현재 주시를 통한 퀘스트 수행 확인**이다. 신을 소환하거나 자유 대화방을 만드는 명령이 아니다. `/ai_call` 관리자 테스트 명령은 정상 완료 접촉을 대신하지 못한다.
- 고정/다인/평가형 퀘스트는 기존 FTB·정산·claim을 재사용하며 완료 전 접촉을 재검사한다. 수주 위치는 저장하며 예전 저장에 없던 위치를 추측해 채우지 않는다.
- 즉석 퀘스트 기본은 `PLAYER_RETURN_TO_NPC`. 목표 준비와 승인 상태를 분리하고 승인 후 지급 실패만 재접촉 없이 재시도한다. FTB 마지막 확인 단계와 AI 상태/결과 문맥을 연결하며 최종 결과는 원래 플레이어·신·방에만 제공한다.
- `/mythblessing reapply`: 비OP 본인의 보유 영구가호만 재적용한다. 동일 효과 최고 단계만 사용하고, 이미 활성/숨은 영구 효과가 있으면 다시 시작하지 않아 명령 반복으로 흡수 체력을 채우지 않는다.
- `/mythpower`: 기존 전체 전투력과 별도로 영구 가호 점수 항을 표시한다. 힘·저항·신속 등과 비전투 버프를 같은 점수로 세지 않는다. 임시 효과와 겹치면 효과별 최고 단계 한 번만 계산하고 효과 유래 attribute를 중복 합산하지 않는다.

## 호환·남은 일

- 보상 SavedData v4는 v1~v3을 읽고 확정 소유권·제거 상태를 같은 저장소에 보존한다. 완료 claim 정리 후에도 보유권을 유지한다. 기존 임시가호에서 영구 보유를 추정하지 않는다.
- 즉석 퀘스트 저장 v3은 v1/v2의 이미 목표 완료된 지급 대기에 기존 자동 지급 권리를 보존한다. 아직 목표가 끝나지 않은 구 저장은 NPC 확인 기본이며 과거 수주 위치를 만들어내지 않는다.
- API 변경에 맞춰 게임 1.0.25 JAR을 AI 빌드 입력으로 사용하고 AI 최소 게임 의존성도 갱신했다. 구 게임 JAR과 새 AI JAR을 혼용하지 않는다.
- 세계 권장 전투력·장비 점수·신별 주시 설정·활성 퀘스트 콘텐츠를 임의로 채우지 않았다. 관련 이력이 없으면 **전체 전투력은 여전히 UNAVAILABLE**일 수 있으며 영구가호 항만 별도로 확인 가능하다.
- 실제 서버 JAR·클라이언트·월드·설정은 변경하지 않았다. 실제 사용자 클라이언트/UI와 Ollama 대화 검증, 배포 및 운영 밸런스 검증은 남는다. 그 외 RPG 시스템을 자동 재개하지 않는다.

# 검토 정확성·현재 초안 격리 — 2026-10-08

대상 `HanesTest`. 개발 게임 **1.0.27 / AI 0.1.33 / 콘텐츠 0.1.3**, **운영 미배포**.

이전 기억·관점 연결을 유지하며, 후속 시험에서 발견한 검토기 오류만 수정했다. 페르소나·분류·기억 검색·게임 권한 체계를 다시 만들지 않았다. [시험 결과와 한계](../../../검토결과/grounding-review-20261008/RESULTS.md)를 우선 읽는다.

## 변경

1. `RoomDialogueGrounding.Attempt`가 최초 근거 메시지와 현재 생성용 메시지를 별도로 복사·보관한다. 주/보조 응답 모두 재검토에는 최초 근거와 최신 초안만 넣는다. 폐기 초안과 이전 수정 지적은 생성용 입력에만 존재한다.
2. 구조 수정과 의미 수정은 기존처럼 **같은 1회 예산**을 공유한다. 두 번째 수정은 불가하다. 비동기 room/revision/turn·기억·콘텐츠·실행 결과 검증과 실패 시 미발행 정책을 유지한다.
3. V6 검토 지침에서 발언자/수혜자/현재 상태/보고와 목격/과거 실행 결과를 구분한다. 현재 인벤토리는 과거 지급 기록으로 증명하지 않는다. 조건부 칭찬·개인적인 믿음·거절·농담·비유적 위협을 곧바로 게임 사실 주장으로 보지 않는다. 새 의향과 과거 약속 소유도 구분하도록 지시하지만, 아래 실시험에서 그 구분은 아직 실패했다.
4. `LocalOllamaClient.submitReview`는 V5/V6 요청에서 **현재 speech 안의 실제 구절만** `excerpt` JSON Schema enum으로 허용한다. 240자 이내의 연속 구간으로 긴 대사 전체를 보존하며, 다른 플레이어 말/과거 초안/metadata를 인용 후보로 삼지 않는다. 최종 `validateAgainst`도 유지한다. 잘못된 인용을 유사 문자열로 자동 치환하거나 PASS로 처리하지 않는다.
5. V3/V4 비교용 검토 요청은 기존 자유 인용 스키마를 사용한다. 테스트용 동결 정책은 main JAR에 포함하지 않는다.

## IO·권한 영향

Game → AI Snapshot과 AI → Game Dialogue/Proposal의 외부 계약·게임 저장 스키마는 바뀌지 않았다. 검토의 `{verdict, issues:[{code, excerpt, correction}]}` 필드도 동일하다. **Ollama 내부 검토 응답의 excerpt 허용값만 턴별 제한**한다. 주 응답 생성 방식과 최대 출력 길이는 그대로다.

이번 작업에서 검토 호출을 모든 턴으로 확대하지 않았다. 기존 선택 신호와 검토 실패 처리, 1회 생성 수정 상한을 유지한다. 감사 입력에 신규 비밀·다른 방 기억·게임 사실을 조회해 추가하지 않는다. 게임 검증·실행을 LLM 검토로 대체하지 않는다.

- **남은 오류 2종:** 미완료 작업의 완료/행위자 모순을 놓침, 실제 수정으로 과거 소유 표현을 제거한 새 의향도 타 신 약속 가로채기로 오해해 거절함. 후속 수정은 최종 발행 후보를 얻지 못했다. 검토 정확성/자연스러움 완성을 뜻하지 않는다. 지침만 더 붙여 해결됐다고 보지 말고 원본 입력·검토·후속 기록을 함께 읽는다.
- 서버 폴더, game/registry 소스·프로필, 공용 인수인계는 그대로다. 실제 플레이어 접속·HUD·운영 LLM 검증은 미수행.

## 다음 작업 시 주의

- 실패 사례를 새 고정 답변/금지어로 덮지 않는다. 다음 정확성 작업은 현재 상태·완료 시제·주체의 모순과 과거 기억/새 의향 구분을 별도의 새 사례로 검증해야 한다. 추가된 정책의 문구 존재만 검사해 의미 문제가 해결됐다고 판단하지 않는다.
- 이번 대사 인용 enum은 **인용 정확성만** 강제한다. 인용한 문장에 대한 모델의 해석·판정까지 맞다는 보장은 아니다.
- 예전 평가 도구에서 수리 메시지 전체를 다시 검토기에 전달하는 흐름은 현재 runtime과 다르다. 이번 `Attempt` 경로와 신규 비교 도구를 기준으로 삼는다.
- 실제 운영 반영은 별도 배포 요청 후 수행한다. 이번 빌드를 서버에서 이미 쓴 것으로 안내하지 않는다.

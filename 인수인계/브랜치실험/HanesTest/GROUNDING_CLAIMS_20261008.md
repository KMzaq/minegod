## 변경과 계약

신규 `RoomEvidenceAudit`가 생성용 추정 태그/일부 말투 지침을 제외한 근거 장면과 최신 초안의 구간 목록을 만든다. 허용된 원문 게임 상태·실행 결과·기억 화자·이력·청중·지식·누락 표시·알려지지 않은 필드와 null은 보존한다. 다른 기억/비밀을 추가 조회하지 않는다.

Ollama 내부 V7 감사 응답은 `u0`, `u1`…마다 `{kind,finding,correction}`을 반환한다. 모든 구간이 유효하게 도착해야 승인할 수 있다. `LocalOllamaClient.submitReview`는 새 내부 응답을 기존 `Review(pass,issues)`로 변환한다. 모델 인용을 복사하는 대신 코드가 각 구간의 실제 초안 원문을 issue에 대응시킨다. 잘못된/빠진 결과를 PASS로 간주하지 않는다.

**Game → AI Snapshot / AI → Game Dialogue·Proposal / 게임 저장 계약은 변경 없음**. 페르소나와 실제 게임 권한도 그대로다. 기존 최초 근거 격리·공유 1회 수정 상한·방/revision/turn/기억/콘텐츠 검사·실패 시 미발행을 유지한다. 생성 호출 정책이나 모든 턴의 검토 횟수를 늘리지 않았다. V5/V6의 과거 비교 도구는 기존 내부 스키마로 유지된다.

보조 응답의 기존 총 16,000자 계약도 검토할 수 있게 맞췄다. 주 응답은 기존 총 8,000자 검사를 그대로 거친다. 구간 수에 따른 감사 출력 예산 512~8192와 60초 상한을 사용한다. 긴 감사 실패는 답변을 자르거나 자동 통과시키는 사유가 아니다.

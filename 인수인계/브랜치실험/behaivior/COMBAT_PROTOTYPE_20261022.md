# 전투 1차 시제품 — 2026-10-22

사용자 요청: 기존 시스템을 유지하며 ZIP 명세의 무기3·방어구2조합·검기·패링·대쉬·장신구2종 구현. 초기 수치는 사용자가 직접 시험 후 조정할 예정이므로 임의로 재밸런싱하지 않았다. [사용·조정 안내](../../../mythictrpg-main/docs/FIRST_COMBAT_PROTOTYPE.md), [검증 기록](../../../검토결과/combat-prototype-20261022/REVIEW.md).

## 구현

- 현재 게임 모듈만 변경. 기존 미커밋 변경과 인물 콘텐츠 구버전 분리를 유지했다. 원본 ZIP은 `추가개발/전투1차/기획원본/1차_장비스킬_기획/`에 보존했다.
- `PrototypeCatalog`와 기존 `combat_power/default.json.items`에 무기3·방어구8 변형. 실제 공격 총9/7/7·속도1.6·다이아 내구1561, 철 보호II/다이아 무인챈트, 등록 정체성과 지급 컴포넌트 일치. 기존 모델·계수는 유지.
- 기존 `SkillExecutor`/마나·쿨타임·`SkillCastEvents`를 재사용하고 `CombatCastRuntime`/`DefensiveSkillRuntime`/`DashCollision`에 이동 검기·정확한 패링 창·충돌 대쉬·공통 선후딜 잠금을 추가했다. 신규 행동만 활성 레이드/시험장에 제한한다.
- 검기 전용 물리 damage type + `is_projectile`, `no_knockback` 태그. 실제 HP 감소만 적중 이벤트, 무적/흡수 대상도 관통 수 소비, 일반 힘·날카로움·치명타 미복제. TTL 기본10틱.
- 슬롯·컨테이너·손 교체 패킷 직후 변형 변화를 Mixin으로 관찰한다. 같은 tick 교체 후 복귀도 준비 중 검기/패링을 부활시키지 않는다. 마지막 피격량 Accessor로 기존 vanilla iframe보다 먼저 패링을 소모하지 않는다. Mixin2개 등록 완료.
- `PrototypeCombatAccess`는 서버 등록 범위·적 UUID와 한 피해 호출에만 유효한 DamageSource identity 권한을 소유한다. 명시되지 않은 공격은 방어 불가다. 실제 석상 시련 휩쓸기=패링/회피, 충격파=회피, 낙하/봉인 실패=불가. 다른 레이드의 대쉬는 안전 이동 정책 작성 전 거절한다.
- 기존 장신구 자유2칸·획득권·재지급·승인 시점 스냅샷을 재사용했다. 마나석+40/고정12, 매듭10%/고정12 두 권리 중첩. 회피 기본200틱에서 검기 적중 한 번당 합계20/40틱 감소하며 시전 전체 한 번이다.
- OP2 `/mythprototype grant kit|<ID>`, `arena`, `join <owner>`, `end`, `status`, `targets`, `attack <kind> [delayTicks]` 제공. 테스트용 GodDefinition은 만들지 않았다. 지급은 기술 출처 `proto_cbt:prototype_testing`, `LEGACY_UNSPECIFIED` 영수증과 기존 지급 실행기/획득 이력/진행권을 사용한다. 일반 NPC 최소등급 검증을 바꾸지 않고 이 OP 화이트리스트 경로에서만 기술 지급을 허용한다. 동일권리/쿨타임/마나를 재발급으로 초기화하지 않는다.
- 시험장은 지형을 변경하지 않고 등록 허스크4개를 만들며 최대5인이다. 표적 전리품·XP 억제, 개별 참가자 이탈/개설자 종료 구분, 정상 서버 종료 시 표적 제거. 강제 프로세스 종료의 경우 영속 표적이 월드에 남을 수 있으므로 정상 `stop`으로 종료한다.

## 검증과 산출물

- `build/check` 성공(81 tasks, 4m3s), 정의 파서39 assertions 포함. 이후 변경은 GameTest fixture의 생존 모드/로그인 무적 초기화뿐이며 실제 runtime 변경은 없었다. 최신 main 소스는 후속 GameTest에서 재컴파일했고 최종 `jar` 성공.
- 신규30 + 영향 회귀65 = **95/95 GameTest**, 10묶음 통과. [최종 묶음별 근거](../../../검토결과/combat-prototype-20261022/gametest-results.json)는 마지막 통과 실행을 묶은 것으로 원래 중간 실패 로그는 삭제하지 않았다. 실제5인 mock접속 동시 방어창·자원 격리, 실제 지급 파문검3적8/4/4와 두 매듭 승인 스냅샷 합계40틱을 확인했다.
- 고립 획득 원장의 세 무기 단독120, 철 조합176.9089023, 다이아187 확인. 기본 인물/Story 빈 상태 회귀1/1 유지, JAR 구버전 인물/Story/lore/persona JSON 재유입0.
- 최종 게임 JAR: `mythictrpg-main/build/libs/mythictrpg-1.0.36.jar`, SHA256 `632337AA6047CF1D6BA0A63425E5C695475743FF402A8FF07B7A61367F0B5C43`. 같은 파일명이라도 이전 빌드와 다르다.
- **서버 폴더 배포·부팅, 실제 런처 교체, 클라이언트 GUI/키 입력, 실제 LLM 호출은 수행하지 않았다.** 기존 server/mods 및 client-required-mods의 게임 JAR은 구버전 콘텐츠 분리 직후 해시 `2393A6E27070247AF99C92EA402B3B98889C59B30C3DEE8B647F434CDECFAFBF` 그대로다. 서버/클라이언트 양쪽을 새 게임 JAR로 맞춘 뒤 직접 시험한다. AI/콘텐츠 모듈의 소스·JAR은 이번 범위에서 변경하지 않았다.

## 남은 직접 시험

생존 모드에서 입력 우선순위·HUD·동기화/지연·패링/대쉬 사용감, 실제5인 밸런스와 원본 계획의10초/180초 DPS를 확인한다. 현재 수치는 초기안이다. 실제 인물별 보상 배정, 외부 레이드의 공격/이동 안전 목록, 장비7등급 자동 배율/저장 enum은 만들지 않았다.

기존 가호·획득 이력을 초기화하지 않았다. 과거 원장 coverage가 불완전한 계정의 전투력/무기 인증 제한을 우회하지 않으므로 고립된 새 시험 계정이 적합하다. 전체 키트를 받으면 다이아 최고 획득 이력이 남으므로 철/다이아 전투력 비교는 별도 획득 집합으로 한다. 아이템 컴포넌트를 바꾸는 튜닝은 기존 영수증과 정체성이 달라져 별도 ID/이관이 필요하다.

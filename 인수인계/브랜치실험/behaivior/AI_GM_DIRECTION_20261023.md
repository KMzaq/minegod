# AI GM 게임 — 자유 행동과 플레이 지속성

2026-10-23, `behaivior`. 최초 읽기 전용 조사 이후 사용자 승인 범위에서 **게임 1.0.42 / AI 응답 0.1.51**의 행동 연결·보호 작업을 진행했다. 아래의 목표·착수 시점 제약과 말미의 실제 구현/검증을 구분한다. **전체 AI GM 완성 또는 운영 배포 기록이 아니다.**

## 사용자 의도

신은 퀘스트 안내자가 아니라 성격·관계·감정·힘의 차이·기억·현재 사정에 따라 판단하고 실제로 행동하는 인물이다. 도움, 거절, 분노, 공격, 거래, 모험 제안, 다른 일로 떠나기 등을 폭넓게 지원한다. 모든 행동을 미리 쓴 장면이나 완성된 퀘스트 템플릿의 선택으로 한정하지 않는다.

사용자가 예로 든 ‘다른 신이 즐거워하며 어디론가 가는 것을 목격했고 실제 사건이 있었다’는 **실제 상태 변화 → 목격 → 그 관찰을 아는 NPC의 대사**가 연결되는 세계를 뜻한다. 대사로 장소나 사건을 꾸민 뒤 이미 실제로 일어난 일로 취급하는 방식은 아니다. 오타를 인물다운 말실수로 받아치는 예시는 고정된 오타 반응을 추가하라는 요구가 아니라 앞선 표현에 유연하게 반응하는 맥락 일관성의 예다.

## 확정한 경계

- AI에게 밴·킥·OP/권한 관리·서버 종료·파일/콘솔 실행 권한을 제공하지 않는다. 같은 기능을 임의 명령어나 스크립트로 우회하는 실행기도 제공하지 않는다.
- 신의 적대, 공격, 거절 자체는 허용 대상이다. 모든 공격을 비살상으로 바꾸거나 모든 NPC를 친절하게 만들지 않는다.
- 끝없는 살해 등 플레이를 계속할 수 없게 만드는 반복 괴롭힘을 막는다. 새 방·새 세션·다른 신·다른 피해 종류로 제한을 우회할 수 없어야 한다.
- 상태 변경은 게임 실행기가 담당하고 결과를 반환한다. 모델의 재량은 허용된 능력과 자원의 선택·조합에 둔다.
- 상식과 정성적인 밸런스 판단은 모델도 수행하되, 보상 중복·자원 초과·불가능한 대상·권한 위반의 최종 판정은 게임이 수행한다.
- 신의 지식과 세계 운영자의 정보 범위를 구분한다. 현재 비밀 공개·세션 격리·관찰 근거 계약을 임의로 해제하지 않는다.
- 다른 모드를 설치했다는 이유만으로 그 모드의 모든 동작을 AI가 실행할 수 있다고 보고하지 않는다. 실제 실행 어댑터와 결과 확인이 필요하다.

## 사용자 확정 — 영구 손실과 보호

사용자 답변: **영구 손실도 허용하되 사전 경고와 대응 기회가 필요하다. 저주·귀속장비·중요물품은 회복 가능해야 하거나 건드리지 않아야 한다.**

- 일반 재산의 영구 손실은 일괄 금지가 아니다. 다만 경고 문장 생성만으로 허용하지 않으며 게임이 전달한 경고, 실제 실행 가능한 대응 수단, 대상과 상태를 다시 확인해야 한다.
- 이번 구현의 보수적 선택은 귀속장비·중요물품의 소비/파괴를 보호하고, 저주는 실제 해제·회복이 보장되는 경로만 허용하는 것이다. 단지 대사로 나중에 돌려준다고 하는 것은 회복 수단이 아니다.
- 이 답변과 별개로 밴·킥·반복 살해 금지는 유지한다. 구체적인 보상 등급·쿨다운·피해량·신별 능력 배정은 확정하지 않았다.
- 경고 검증 기반과 실제 물건/건축물 파괴 실행기의 완성 여부는 별개다. 실행기가 없는 행동을 지원 완료로 보고하지 않는다.

## 착수 당시 확인한 기존 연결과 제약

| 위치 | 실제 상태 | 개선 방향 |
|---|---|---|
| AI `AiCallCommands`, 게임 `ConversationRooms` | `/ai_call`은 기록 on/off 모두 시험 방을 만들고 게임 행동을 차단한다. | 기존 대화 시험 의미를 숨겨 바꾸지 말고 실제 행동 시험을 명시적으로 구분한다. |
| AI `RoomPrompt.gameplayProposalsAllowed`, `DialogueTurnDirective` | 시험 모드 외에도 대화 유형에 따라 일반 행동을 차단한다. | 대화 태그는 의도 해석에 사용한다. 신의 자발적 행동 가능 여부는 현재 능력/상황/실행 정책으로 판단한다. |
| 게임 `AiActionCapabilityService`, AI `AiActionCapabilityBridge` | 대부분 정확한 작성형 항목 선택이며 생성 퀘스트도 기계적 내용이 고정이다. | 기존 실행 서비스를 재사용하고, 지원 가능한 행동 인자·대상·조합 범위를 공개한다. |
| 게임 `ConversationRooms.complete` | 대사 출력 뒤 Proposal 실행, 결과는 다음 턴에 반영한다. | 결정/실행 요청/결과 확인/결과 대사를 분리한다. 이동·전투 접수와 완료를 구분한다. |
| 게임 `AiActionGateway` | 피해 반복 제한 키에 세션·신·템플릿이 포함되고 실행 기록이 휘발성이다. | 기존 중복 실행 방어 외에 피해자와 사건에 귀속되는 반복 괴롭힘 보호가 필요하다. |
| 게임 NPC 실체·활동 서비스 | 실제 이동·근접 공격 기반·방문·생활활동 실행기가 있다. | 별도 NPC 엔진을 만들지 않고 현재 실행기에 대화 결정과 실제 대상 참조를 연결한다. |

공개된 Capability와 정규화 소비자도 맞춰야 한다. 조사 중 `structure_evaluation_request`가 공개 목록에 있어도 방 경로의 브리지에서 누락될 가능성을 확인했다. 구현 시 회귀 시험으로 재현하고 수정할 항목이다.

현재 기본 인물·Story 콘텐츠는 별도 작업에서 보관소로 옮겨져 있다. 사용자가 새로 작성할 콘텐츠와 구 시험 데이터를 혼동하지 않으며 구 인물을 자동 복원하지 않는다.

## 구현할 흐름

1. 게임이 신의 현재 실체·상황·대상·가능한 능력과 허용 자원 범위를 제공한다. 전체 레지스트리를 매번 프롬프트에 넣지 않고 관련 행동과 후보를 조회한다.
2. 모델은 요청의 뜻과 신의 목적을 바탕으로 돕기/거절/조건 제시/독자 행동/말만 하기 중 판단한다. 이미 명확한 요청에 의미 없는 재확인을 반복하지 않는다.
3. 게임은 대상과 상태, 현재 방/revision, 자원, 중복, 반복 괴롭힘 보호를 재검증해 실행한다. 대화 분류 자체를 모든 행동의 허가증으로 삼지 않는다.
4. 즉시 결과 또는 시작/진행/실패/완료 결과를 같은 행동 식별자에 연결해 반환한다. 긴 작업은 완료를 기다리며 서버 스레드를 막지 않는다.
5. 대사는 실제 결과에 맞춘다. 생성 중 방이 바뀌거나 종료된 경우 늦은 응답·동작을 새 턴에 적용하지 않는다.
6. 관찰 가능한 결과를 기존 사건/기억 경로에 기록한다. 다른 신은 실제로 목격했거나 허용된 경로로 들은 범위만 안다.

## 행동 범위와 기존 기능 재사용

- 전투: 적/플레이어에 대한 공격·보호·교전 중단. 실제 엔티티와 전투 규칙에 연결한다.
- 이동/생활: 접근·동행·안내·떠나기·방문·휴식·시설 사용 등 기존 NPC 실행기를 연결한다.
- 권능: 치유·가호·약화·효과 해제. 신별 권능/자원과 장기 불이익 정책을 적용한다.
- 물건/경제: 선물·공물·교환·대가 요구. 기존 보상/인벤토리/경제 원장을 재사용해 중복 지급을 방지한다.
- 의뢰/모험: 지원되는 목표·조건·보상 범위에서 조합하고 기존 퀘스트/FTB에 등록한다. 미구현 목표를 완료 가능한 의뢰로 꾸미지 않는다.
- 사회/사건: 부탁·약속·갈등·다른 신에게 연락·현재 목적에 따른 활동. 실제 전달·이동·관찰 결과에 연결한다.
- 환경: 소리/입자 외 날씨·몹·블록·시설 등은 피해 범위 정책과 실행기 구현 후에 허용한다. 임의 서버 명령 실행으로 대체하지 않는다.

## 구현 순서와 완료 판정

1. 위 미결 경계 확정 → 실제 행동 시험 경로와 공통 실행/결과 계약 → 반복 괴롭힘 방어.
2. 기존 전투·이동 실행기 연결로 ‘부탁 → 신의 결정 → 실제 실행/거절 → 결과 대사 → 후속 기억’을 완결한다.
3. 물건·권능·퀘스트·생활·사건·환경을 같은 계약에 연결하고 실제 지원 범위를 표로 공개한다.
4. 대화 밖의 목적·다른 일로 인한 부재·관찰과 소식 전달을 기존 활동/기억 시스템에 연결한다.

명확한 요청, 스스로 거절, 관계에 따른 다른 선택, 대상 소멸, 실행 실패, 중복 응답, 여러 방의 격리, 재접속/재시작 뒤 보호, 다수 신의 연속 피해, 결과를 모르는 NPC의 지식 경계를 검증한다. 자동 기능 시험 통과와 실제 Gemma 대화의 자연스러움은 별도 판정한다.

## 현재 구현된 범위

- 기존 read-only 시험과 분리된 `/ai_call live ...`; live/on은 STANDARD, live/off는 LIVE_EPHEMERAL. 정확한 등록 ID·OP2·현재 게임 권한을 확인한다.
- primary 생산 대화의 상황 분류 기반 일반 행동 veto 제거. 실제 Capability/정확한 대상/방/세션 검증은 유지한다. 새 `npc_directive`는 접근·동행·중지·물러나기·보이는 적대 몹 공격·참가자 보호를 기존 실체 실행기에 연결한다.
- 초기 결정의 대사는 숨기고 Proposal을 한 번 실행한 후 실제 처리 결과로 최종 대사를 생성한다. finalizer의 추가 Proposal은 실행하지 않는다. 종료/수정된 방의 늦은 대사 폐기, A 결과를 B 문맥에서 배제한다.
- 최종 문맥은 관계/공개 가능한 로어를 재조회하고 현재 감정·활동 경험·방향성 신 관계를 다시 연결한다. 실행 실패/확인 대기/명령 시작/완료를 구분한다. 명확한 부탁 재질문·추상적 반복을 줄이는 지침을 추가하되 고정 답변은 넣지 않았다.
- `structure_evaluation_request`의 정확한 quest_id 정규화 누락과 item_request 지침이 모든 Proposal 금지로 읽힐 수 있는 표현을 보완했다.
- 피해자 UUID SavedData 기반 반복 AI 사망 보호. 새 방/신/템플릿/재접속만으로 초기화 불가. 실제 클릭 대상의 성공 공격만 같은 신의 재교전 근거로 인정하며 휩쓸기·반사·텍스트만으로 해제하지 않는다.
- 직접 `player_damage`의 allowDeath는 서버가 작성한 위험 안내와 기존 확인 UI를 거친다. 실체 전투는 실제 위험 경고 이후 같은 신/실체/order/현재 교전에서 직접 재공격해야 일반 소지품·XP 사망 손실을 허용한다. 시간 경과는 동의가 아니며 교전 종료/사망/로그아웃으로 대응 기록이 사라진다.
- 보호 태그/메타데이터와 귀속 정의를 실제 stack에서 검사한다. 중첩 container/bundle도 bounded 재귀 검사하며 AI 공물/생활활동 소비에서 제외한다. 유해 효과는 실제 자동 종료가 있는 경로만 허용한다.

## 의도적으로 미완료로 남은 부분과 제약

1. 동적 퀘스트 목표·보상 조합, 범용 세계 운영 AI, 독립 목적 사건/다른 신의 목격 소식까지 모두 연결된 것은 아니다. 기존 작성형 템플릿을 그대로 사용하는 영역이 남아 있다.
2. 물리 명령은 STARTED를 반환하지만 실제 도착·처치·실패 결과를 후속 대화와 장기 기억에 공급하는 완료 관찰은 아직 미연결이다. 종료 후 IDLE이며 재시작 시 명령 재개하지 않는다.
3. `AiConsequenceGate`는 경고/대응/정확한 대상 검증 기반이다. 실제 블록·건축물 파괴나 강제 몰수 실행기를 구현한 것은 아니다. 영구 저주 해제 퀘스트도 없다.
4. 중요·귀속 물품의 자동 복구가 보장되지 않아, 이번에는 해당 물품을 잃게 되는 AI 직접 치명타를 취소하고 체력 1로 보존한다. **이런 물품을 지닌 동안 신에게 죽지 않을 수 있는 임시 보호**이지 완성된 회복 시스템이 아니다. 열린 메뉴는 제작/모루 입력 누락 방지를 위해 일부 공유 상자 슬롯까지 보수적으로 검사한다.
5. 보호는 직접 AI 피해·일반 신 실체 공격에 한정하며 중요 토템의 부활 소비 이전도 검사한다. 작성형 레이드는 기존 레이드 생명주기/전투 규칙 관할이다. 불길·낙사·소환몹 등 간접 피해의 AI 출처 추적과 모든 외부 모드 손실까지 지원하지 않는다. 이 범위를 보호 완료로 보고하면 안 된다.

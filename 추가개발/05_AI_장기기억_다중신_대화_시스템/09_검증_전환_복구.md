## 2. 크기·지연 검증

작은 fixture→1만→10만→100만 건 등 점증 합성 자료로 저장/검색/메모리/재시작을 측정한다. 각 단계는 충분한 별도 디스크 공간과 승인된 시험 범위에서 수행하며 100GB 파일을 지금 만들지 않는다. 실제 100GB 검증을 하지 않았다면 그렇게 명시한다.

필수 지표: queue 길이/최고치, durable write 지연, 취소·FULL·gap 수, active file/WAL/staging 크기, source→projection/색인 지연, query p50/p95와 timeout, source 검증 비용, JVM 사용량, 모델 admission 대기, 전체 사용자 응답/HUD 지연, server tick 영향.

초기 예산값은 제품 SLA가 아니다. 기존 15ms/2,000행 검색이 일부 fallback했던 이력을 고려해 큰 자료를 JVM 선형 순회하지 않는다. 슬롯/worker/cache/벡터 성분 등 메모리 상한을 유지하되 이를 무기한 원문 총건수 상한과 혼동하지 않는다.

품질은 승인된 동일 scenario에서 기존/신규 비교한다. 회상 근거 적중, 정정 반영, 거짓 기억, 비밀 유출, 신별 개성, 과도한 과거 언급, 두 신의 중복 대답/지연을 따로 평가한다. 실제 모델 시험 없이 fixture PASS만으로 자연스러움 완료를 선언하지 않는다.

### 튜닝 전 시작값과 수용 목표

아래 값은 첫 구현에 쓸 보수적 기본값/검증 목표이지 이미 실측해 보장한 수치가 아니다. 바꿀 때는 이유·측정 결과를 단계 기록에 남긴다. 안전 경계와 원문 무단 삭제 금지는 성능 때문에 완화하지 않는다.

| 항목 | 초기 선택 |
|---|---|
| SQLite writer / read worker | 월드별 writer 1, read worker 2. 연결·작업 총수 제한 |
| 원문 수집 대기열 | 2,048 envelope 또는 본문 합계 16MiB 중 먼저 닿는 한도. DB 디스크 예산 예약은 별도 |
| 작은 쓰기 batch | 최대 128 envelope, 논리 본문 합계 1MiB. 실제 page/WAL 증가량은 별도 보수적 예약 |
| 조회 page / 반환 후보 | page 128건, 초기 rerank 후보 최대 2,048건. 소진 시 PARTIAL |
| application hot cache | 월드별 64MiB 시작. SQLite page cache/벡터 scratch를 별도 계상하고 무제한 증가 금지 |
| 임베딩/정리 worker | 기존 admission을 통과한 background 1개. 새로운 병렬 모델 pool 금지 |
| 원문 저장 지연 목표 | 정상 부하에서 durable p95 1초 이내. disk-full 등 장애 표본은 별도 집계 |
| DB 검색 목표 | warm 10만 건 표본 p95 100ms 이내. 의미 호출·모델 생성은 별도 측정 |
| 게임 thread 영향 목표 | 승인된 1/4/6인 시험에서 신규 snapshot/admission 처리 합계 p95 1ms/tick 이내, 동기 disk/LLM 대기 0 |
| 정확성 통과 조건 | 비공개 근거 유출·다른 세션 적용·중복 보상·없는 사실 확정의 필수 fixture 실패 0 |

큰 단일 발언은 batch 제한 때문에 원문을 자르지 않고 검증 가능한 part transaction으로 처리한다. 모든 part가 durable이 되기 전에는 완전 메시지/파생 job으로 공개하지 않는다. 재시작 시 미완성 part는 미완성 상태로 보존한다. 최대 수락 본문 크기는 실제 채널 계약을 M0에서 확인하며 이미 전달된 내용을 이유 없이 버리지 않는다.

목표 미달이면 admission/검색을 안전하게 낮춘 상태로 원인과 지원 규모를 보고하고 운영 확대를 중단한다. 자동으로 원문 수집 정책을 샘플링으로 바꾸거나 사용자 승인 없이 모델을 교체하지 않는다.

## 3. 초기 데이터 취급

기존 `memories.json`, 구 AI 시험 로그, 구 개인 journal/derived/index의 자동 import는 기본 OFF다. 사용자가 시험 데이터로 제외한 자료는 새 검색 대상이 아니다. **삭제하지 않으며 원본 해시·경로를 보존한다.**

주시 획득, 관계, 퀘스트/보상·월드 진행도까지 시험 기억으로 묶어 지우지 않는다. 게임 authoritative source는 유지하고 새 memory는 해당 source의 허용 참조만 사용한다. 기존 기록을 새 관찰로 backfill하여 과거를 소급 목격하지 않는다.

M0에서 dataset 시작점과 source cursor를 기록한다. 기존 개인 시험 기억과 최근 개발된 실제 게임 상태의 구분이 모호하면 경로/자료별로 질문한다. “시험 데이터 제외”를 모든 월드 데이터 초기화 승인으로 확대하지 않는다.

## 4. 독립 전환 플래그

아래는 미래 설정 개념이며 현재 서버에 배치한 JSON이 아니다.

| 축 | 값 | 의미 |
|---|---|---|
| archive | OFF / RECORD_ONLY | 새 RAW 수집 여부. 기억 답변 변화와 분리 |
| projection | OFF / ON | 새 파생 작업 활성. idle/모델 admission 유지 |
| retrieval | LEGACY / SHADOW / NEW | SHADOW는 신규 결과를 비교 기록만 하며 출력/액션에 사용 안 함 |
| orchestration | LEGACY / DUAL_GOD_TRIAL | 새 1인2신 경로 선택. 기존 다인1신 보존 |

게임/AI contract version, world/dataset, quota registry, 필수 source adapter가 맞아야 NEW를 허용한다. OFF/오류 상태를 다른 데이터셋 자동 생성·전역 접근으로 보완하지 않는다. 신규 조회 실패 시 허용된 현재 대화만 fallback하며 제외된 시험 기억으로 자동 복귀하지 않는다.

다중 신 ORCHESTRATION을 켤 때는 해당 세션의 NEW 권한/검색이 준비돼야 한다. 기존 RUMOR_TEST/소문·평판 enablement는 별도의 축이고 이 플래그들로 해제되지 않는다. 문서 작성이나 새 JAR 존재만으로 자동 활성화하지 않는다.

## 5. 배포 전후 절차

1. 해당 시점의 최신 소스·dirty 변경·버전 조합과 실제 실행 제한 확인.
2. 승인된 범위에서 LP와 별개 작업 직전 백업. 부분 manifest와 전체 월드 백업을 구분.
3. 게임/AI compile·관련 offline·패키징 검사. producer/consumer 버전을 함께 검증.
4. 승인된 격리 서버에서 실제 이벤트/대화 수집·주시/소문·HUD·복구 시험.
5. 필요 시 별도 승인된 실제 모델 비교와 1/4/6인 실측. 미정 콘텐츠는 운영 OFF.
6. 별도 배포 승인 후 정상 stop·저장·일관된 백업·JAR/클라이언트 조합 적용.
7. RECORD_ONLY→SHADOW→작은 NEW 시험→확대 순으로 진행. 각 상태의 실패/rollback 조건 확인.

운영 중 JAR 덮어쓰기, 무차별 Java 종료, 현재 월드 초기화, 대화 로그 대량 외부 전송은 하지 않는다. 관리자 조회/export도 내용 최소화와 대상·권한 확인을 거친다.

## 6. 복구와 롤백

기능 OFF와 구버전 바이너리 복원은 다르다. 먼저 신규 retrieval/orchestration을 끄고 새 자료는 보존한다. 새 포맷을 모르는 구 JAR에 저장 파일을 맡기지 않는다. 구 시험 기억 재활성화도 자동 fallback이 아니라 별도 선택이다.

world/SavedData/원장/SQLite가 같은 시점이 아닌 부분 복원은 source 불일치를 유발할 수 있다. 원본과 proof revision/hash를 확인하기 전 AI 읽기는 차단한다. 복원 분기에는 새 runtimeEpoch를 발급하고 필요 시 dataset 분기를 명시한다. ID를 조용히 덮어 맞추지 않는다.

FULL 상태는 기본적으로 관리자 조치 전 신규 기록 중단이다. 승인된 아카이브/증설 후 재시작 검사로 재개하며 누락 기간을 숨기지 않는다. 저장하지 못한 원문을 요약 모델로 상상해 채우지 않는다.

## 7. 설계를 막지 않는 후속 콘텐츠 선택

- 실제 신별 관측 영역/차폐 공간·주시 보상 퀘스트 매핑.
- 전서구 엔티티·별도 스폰과 신별 전파/중요 공개 사건 정의.
- 사용자가 예정한 신 대화 UI/참가자 판정 변경의 구체 방식.
- 다인·다신 확장의 실제 발언 수/지연 수용 기준과 선택 UI.

위 항목은 adapter와 OFF/fixture로 독립 개발할 수 있다. 콘텐츠 내용을 임의로 채워 운영 완료를 선언하지 않는다. 용량 초과 시 자동 원문 삭제는 이번 기본안에 없으며, 향후 그런 정책을 원하면 별도로 승인받아 설계한다.

## 8. 이번 문서 작업의 검증 범위

이 폴더의 링크·형식·상호 참조와 기존 사실 대응만 검사한다. 코드 컴파일·테스트·모델 실행·서버 배포의 새 결과는 없다. 실제 단계 구현 결과는 해당 단계의 작업 기록과 인수인계에 별도로 남긴다.

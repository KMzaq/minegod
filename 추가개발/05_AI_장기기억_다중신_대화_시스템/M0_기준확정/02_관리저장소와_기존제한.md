# M0-02. 관리 저장소·기존 제한·시험 데이터 경계

100GB/무기한 정책은 [03 저장 설계](../03_전체대화수집과_저장용량.md)가 단일 정의다. 여기서는 실제 파일과 이행 조건만 고정한다. 이번에 디렉터리/DB/manifest를 생성하거나 worldId를 발급하지 않았다.

후속 2026-09-21: 새 방의 기존 TXT는 서버 루트 `ai-dialogue-logs`와 월드 `mythictrpg-ai-room-logs`에도 생긴다. 현재는 100GB 강제가 없는 기존 경로다. [04 변경 연결](04_대화방_변경_연결_20260921.md)에 따라 M1~M2 전환 시 활성 기록의 world/dataset 귀속과 합산 registry/이중 writer 정책을 정한다. 기존 시험 파일을 자동 import하거나 이 CSV 기준을 오늘 파일로 덮어쓰지 않는다.

## 1. ManagedStoreRegistry 등록 목록

아래 `<world>`는 `server.properties`의 `level-name`으로 선택된 실제 월드 루트다. 현 서버는 `server/world`이다. `<datasetId>`는 게임 발급 UUID다. 여러 차원에서 같은 overworld world identity를 사용하며 차원마다100GB를 부여하지 않는다.

| storeId / 소유자 | 포함 경로 | 측정·예약 기준 |
|---|---|---|
| `recording-v2` / 게임 WorldRecordingService | `<world>/mythictrpg-recording-v2/`의 관리 manifest·잠금·활성 dataset 전체. `recording.sqlite`, `-wal`, `-shm`, `-journal`, staging/temp/복구 보존본 포함 | 전체 파일 길이 합계. inactive라고 이름만 바꿔 같은 관리 영역의 복사본을 제외하지 않음 |
| `action-ledger-v1` / 게임 ActionLedgerService | `<world>/mythictrpg-action-ledger-v1/` 전체. `segment-*.alog`, `metadata.json`, `checkpoint.json`, `writer.lock`, `*.tmp` | 원본 형식 보존. append/segment 생성/control 교체의 최대 추가 바이트 예약 |
| `god-watch-v1` / 게임 GameWatchGateway | `<world>/mythictrpg-god-watch-v1/` 전체. 현재 `watch-v1.journal` | observation/철회/상태 변경 전 예약. 주시 권리 원본은 아래 제외 항목 |
| `rumor-state-v1` / 게임 RumorSavedData | `<world>/data/mythictrpg_memory_rumor_v1.dat`, 해당 이름으로 시작하는 `.neoforge-tmp` 및 명시 등록된 교체/복구본 | 월드 UUID와 소문이 섞여 있으므로 **파일 전체 산입·전체 보존**. 일부 소문을 시험으로 제외해도 파일 바이트를 추정 차감하지 않음 |
| `reputation-state-v1` / 게임 ReputationSavedData | `<world>/data/mythictrpg_reputation_judgement_v1.dat`, 해당 이름으로 시작하는 `.neoforge-tmp` 및 명시 등록된 교체/복구본 | 게임 소유 현재 판단 상태. 전체 산입. 철회/회복은 유지보수 예산으로 먼저 처리 |

registry는 서버가 고정한 상대 경로만 받는다. 정규화된 실제 경로가 해당 world 안에 있어야 하며 symlink/junction 이탈·중복 등록은 거부한다. 모델 입력으로 파일 경로를 등록하지 않는다. 예상 밖 파일을 발견하면 자동 삭제/제외하지 않고 산입 또는 QUOTA_UNCERTAIN으로 신규 쓰기를 중단한다. 작은 file length를 물리 파일시스템 할당 블록 수·디스크 전체 사용량과 혼동하지 않는다.

현재 조사에서 action-ledger/watch 디렉터리와 reputation `.dat`는 없고 rumor `.dat`는 존재했다. 이는 배포 서버에 새 수집이 켜져 있다는 뜻이 아니다. 기존 게임 행동 수집 코드·개발 JAR은 별도로 존재한다.

## 2. 합산 제외하되 보존할 경로

- `region`, `entities`, `poi`, `DIM*`, `playerdata`, `stats`, `advancements`, `level.dat`, `ftbquests`, `ftbteams`: 월드·플레이어·진행도 원본. 일반 기록 quota로 저장을 차단하지 않는다. FTB 원본에 팀 설정과 자체 메시지가 함께 있으므로 이 파일을 archive quota 목적으로 재작성/정리하지 않는다. 새 대화 복사본만 recording-v2에서 산입한다.
- `<world>/data/mythictrpg_players.dat`, `mythictrpg_world.dat`, `mythictrpg_quests.dat`, `mythictrpg_quest_reminders.dat`, `mythictrpg_player_constructions.dat`, `mythictrpg_reward_claims.dat`: 게임 상태 원본. 마지막 파일에는 보상 claim과 주시 획득 권리가 함께 있다. 기억 초기화 대상으로 취급하지 않는다.
- `<world>/mythictrpg-ai-memory/`, `mythictrpg-ai-memory-lp-v1/`, `mythictrpg-ai-memory-rumor-test-v1/`, `mythictrpg-ai-test-logs/` 및 그 안의 예전 memories/journal/derived/index: 새 검색에서 제외할 test archive. 현재 발견된 것은 첫째·둘째·넷째 폴더다. 삭제·이동·자동 수입하지 않는다.
- 별도 승인한 백업 경로, 개발 산출물, 모드 JAR, 모델, 일반 서버 로그: 활성 기록 예산에서는 제외하고 OS 여유 공간은 별도로 감시한다.

기존 legacy 경로가 켜진 채 계속 기록한다면 그것은 별도 test 흐름이며 새 운영 기록 완료로 계산하지 않는다. 운영 전환(M5/M7)은 legacy 신규 쓰기/신규 RAW 이중 기록 정책까지 명시해야 한다. 폴더를 제외했으니 전체 디스크가100GB 이내라고 보고하면 안 된다.

## 3. 시험 제외 시작점과 world identity

`RumorSavedData` 내부 `RumorLedger.worldId`가 기존 게임 기억/원장 세계 identity의 기준이다. 소문 파일을 시험 데이터라고 삭제하면 새 worldId가 생길 수 있으므로 금지한다. 현재 파일 내용을 문서에 덤프하거나 런타임 `get()`을 호출해서 변경하지 않았다.

M1은 OFF일 때 새 파일도 만들지 않는다. 이후 최초 RECORD_ONLY 전환 시 **게임 스레드에서 게임 identity를 확인**하고, 신규 dataset UUID와 cutover manifest를 예약·저장한다. manifest가 durable 상태가 된 뒤 해당 dataset 수집을 연다.

manifest는 schema2, worldId/datasetId, createdAtUtc, schema/build versions, source별 최초 허용 cursor, 기존 source root 제외 기준, completeness를 가진다. 공개 UUID를 임의 입력받아 다른 월드에 붙이지 않는다.

- 행동/주시 원장은 cutover의 durable highWatermark 이후만 새 source로 소비한다. UTC 시간만으로 판별하지 않는다.
- 소문/평판은 전역 연속 영속 cursor를 제공한다고 가정하지 않는다. M3 source adapter가 기존 root/receipt/version 기준을 고정하고 이후 승인된 신규 root만 연결한다. 과거 test root의 평가 version이 바뀌었다고 새 정사 기억으로 수입하지 않는다.
- 게임의 현재 affinity/퀘스트/주시 권리/월드 사실은 과거 기록 재생이 아니라 현재 authoritative snapshot으로 계속 사용한다. 시험 기억 제외를 이유로 삭제하거나0으로 초기화하지 않는다.
- 모호한 source는 ORIGIN_UNKNOWN으로 보존하되 새 AI 검색에서는 제외한다. 복원 후 cursor 후퇴·world 불일치는 fail-closed. 다른 dataset/세계에 자동 병합하지 않는다.

이 절은 자동 이관 승인이 아니다. 구 파일은 그대로 보존하고, 새 source 시작점 확정 기능을 M1/M3에서 구현한다.

## 4. 현재 제한과 새 경로 적용 차이

| 현재 구현 제한 | 새 시스템 처리 / 담당 단계 |
|---|---|
| 개인 journal 기본64MiB/총12,000/범위별2,000; 설정 byte 상한1GiB, 항목 최대100,000 | v1 test 경로 그대로. M1 신규 SQLite RAW에는 이 영속 총건수/범위별 한도 상속 금지 |
| 개인 journal 일부 입력1200자, 신 대화 adapter의 입력 prompt 길이 제한 | M2 RAW 무절단, 전송/엔진 view 별도. 프롬프트 예산 유지와 기록 절단을 분리 |
| `MemorySalience.searchable`: 일반 연상30일, 명시 회상·보호 기억 예외 | v1 동작 보존. M5 신규 검색에 일수 hard filter 없음; 최근성 순위는 가능 |
| ActionLedgerStore: maxBytes≤1TiB, 인메모리 index≤1,000,000; frame16KiB·segment≤64MiB | 원본 형식/안전 한도 보존. M1 합산 quota adapter. INDEX_LIMIT은 별도 진단이며100GB 미만에도 발생할 수 있음. 무제한 행동 원장 index 재설계는 현재 M1의 완료 주장에 포함하지 않음 |
| WatchJournal: maxEntries≤100,000, maxBytes≤1TiB, frame64KiB | M1 합산+WATCH_INDEX_LIMIT 공개. proof journal의 안전 한도 해제를 무작정 수행하지 않음 |
| RumorLedger 항목군별4096, ReputationLedger4096; SavedData JSON16,000,000자 읽기 한도 | M1 합산 산입·새 기록 예약. 항목 한도/파싱 보호 유지. 현재 의미 정책의 source 만료는 보존 기간과 구별 |
| RewardClaimState claim4096/watch권리4096 | 게임 원본 안전 규칙. 기억 용량 정책에서 변경하지 않음 |
| Derived 최대50,000; MemoryIndex 최대50,000·벡터 성분16,777,216·frame256KiB 및 별도 byte 한도 | M4/M5는 SQLite 페이지/작업 기반 새 저장 포트 사용. 기존 Map을100GB 크기로 올리지 않음. per-query 안전 예산과 source coverage 별도 보고 |
| ExperienceView 최대16건, v1 플레이어 청중≤16 등 | DTO/현재성 안전 예산이지 보존 수명 아님. M3 페이지 조회, M6 ActorRef 청중을 별도 확장; 기존 다인 기능 축소 금지 |

따라서100GB는 **월드 합산 기록의 상한**이지 모든 source가100GB까지 반드시 채워진다는 보장은 아니다. 새 RAW는 총건수 제한 없이 설계하고, 기존 원장/proof의 작은 index 한도는 상태·누락 사유로 드러낸다. 기존 한도에 도달하는 실제 규모가 확인되면 디스크 기반 source index를 후속 범위로 나누되, 그 이전에 조용히 성공 처리하거나 자동 삭제하지 않는다.

## 5. M1에 필요한 예약·장애 시험

1. `used + outstanding + maintenance`를 signed64 checked 연산으로 계산.100,000,000,000 bytes 설정, 작은 시험 quota의89/90/95% 및 FULL 경계, 다른 store 동시 입장·이중 예약·해제 중복을 검증한다.
2. DB 파일뿐 아니라 WAL/SHM/rollback journal/temp와 다른 source 파일의 동시 증가를 계산한다. 읽기 장기 점유로 checkpoint가 지연돼도 신규 쓰기를 먼저 중단한다. `max_page_count`만으로 합산 hard cap을 보장하지 않는다.
3. 실제 NeoForge21.1.248 `SavedData.save`는 snapshot을 복사해 I/O worker에 보내고 `IOUtilities.atomicWrite`가 같은 폴더의 `<targetName><random>.neoforge-tmp`에 쓴 뒤 교체한다. `setDirty` 직후 예약을 해제하면 안 된다. rumor/reputation snapshot 수정 전 예약 → 비동기 I/O 종료 후 정산, 실패/재시도·연속 snapshot 대기 중 예약 유지 시험이 필요하다.
4. 최대 증가량을 안전하게 산정 못 하면 해당 신규 기록을 거절한다. 원본 SavedData 전체와 교체용 임시본이 동시에 있는 구간도 합산한다. 기록 예약 실패가 퀘스트/보상/affinity 원본 저장 중단으로 전파되면 실패다.
5. 누락 요약/철회/안전 종료는 내부1GB 유지보수 여유를 쓰되100GB를 넘기지 않는다. 예약/marker도 못 쓰면 RAM 경고와 재시작 POSSIBLE_GAP을 남긴다. source 건수 한도와 byte FULL은 다른 원인으로 보고한다.

물리 파일 증가 상한·장애 회복은 아직 **미검증**이다. M0는 파일/소유자/이행 계약만 확정했다.

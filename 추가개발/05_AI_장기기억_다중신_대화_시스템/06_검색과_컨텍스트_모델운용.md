# 06. 검색·컨텍스트와 모델 운용

## 1. 검색 파이프라인

1. 게임이 현재 화자·대상·청중에 대한 읽기 capability를 발급한다.
2. 현재 발언, 최근 공개 대화, 원래 질문의 시간/주제를 이용해 typed query를 만든다.
3. DB에서 knowledge receipt와 공개 범위를 만족하는 문서만 후보로 조회한다.
4. 원문 단어/구절·entity·시간 검색을 우선하고 필요한 경우 의미 검색을 보탠다.
5. 출처가 같은 중복/인용을 묶고 관련성·미해결성·정정·중요도를 반영한다.
6. 원문 근거와 최신 해석을 같이 담되 context 예산 내 소수 항목만 선택한다.
7. 실제 생성·출력 직전 근거/세션/청중/관계·평가 revision을 재검증한다.

권한 없는 문서를 모두 벡터 검색한 뒤 모델에 넘겨 숨기게 하지 않는다. 검색 storage 내부에서도 ACL/knowledge scope를 join하고, 신별 vector 후보는 허용된 projection으로만 구성한다. 재색인 관리자는 넓은 원본에 접근할 수 있어도 생성 모델의 context는 제한된다.

## 2. 기간 제한 없는 원문 검색

새 dataset에는 날짜 만료 조건이 없다. 명시 회상뿐 아니라 일반 연상도 과거 자료를 검색할 수 있어야 한다. 최근성은 여러 순위 기준 중 하나이며 30일 경계에서 제외시키지 않는다. 오래된 사소한 말도 정확한 주제/인용으로 찾을 수 있어야 한다.

FTS5 + 원문 구절/정규화 entity/time 인덱스를 추천한다. 한국어는 공백 기반 검색만으로 활용형/부분어 회상을 보장하지 못하므로 정규화·별칭과 trigram 검색을 합성/실제 승인 자료로 비교한다. 1~2글자 질의를 trigram에만 맡기지 않는다. FTS5 trigram의 3글자 미만 제약은 [공식 문서](https://sqlite.org/fts5.html#the_trigram_tokenizer)를 따른다.

검색 문자열은 prepared statement 인수로 처리하고 FTS 연산자를 안전하게 escape한다. LLM이 SQL·파일 경로를 작성해 실행하지 않는다. 전체 원문 열람은 관리자 별도 포트에서 pagination하며 일반 NPC 요청은 예산이 제한된다.

원문 전체를 보관하는 것과 한 요청이 전체 원문을 읽는 것은 다르다. 인덱스가 모든 기간을 포괄하되 반환은 bounded다. 인덱스 미완료·timeout·수집 공백은 PARTIAL/UNAVAILABLE로 전달하고 “기록이 없다”와 구분한다.

## 3. 의미 검색의 초기 범위와 확장

기존 bge-m3의 모델 digest/1024차원/CPU 실행 설정을 재사용한다. 영속 벡터는 SQLite의 source/version별 행으로 옮길 수 있으나 기존 시험 벡터 파일을 자동 import하지 않는다. 원문과 projection의 서로 다른 문장을 같은 hash로 취급하지 않는다.

첫 통합판은 외부 vector DB나 새 native ANN 확장을 추가하지 않는다. 허용 scope에서 FTS 후보, 해당 actor/화제/시간의 에피소드, 미해결 중요 기억, 최근 기억을 **각각** 뽑아 bounded vector 후보군을 만든다. FTS에 걸린 문서만 의미 검색하는 구조로 제한하지 않는다. 그래도 후보군 밖 자료까지 전수 의미 검색한 것은 아니다.

후보 상한/페이지 예산을 소진한 결과는 PARTIAL이다. 희귀한 과거 사건을 다른 표현으로 물어보는 시험이 통과하지 못하면 범위를 좁힌 후속 질의·허용된 추가 페이지 검색을 수행한다. 자동으로 가짜 관련 기억을 선택하지 않는다. 운영 크기에서 누락/지연 목표를 못 맞추면 지속 ANN 도입을 별도 성능 단계로 설계하고 의존성·복원/ACL 검증 후 승인받는다.

**100GB는 저장 상한이며 100GB 전량의 의미 검색이 즉시·완전하게 보장된다는 뜻이 아니다.** M5는 색인 coverage/후보 제한을 노출하고 용량별 시험 결과로 지원 범위를 선언해야 한다. 조회의 정확한 날짜/원문/식별자 경로는 의미 검색 미지원 때도 유지한다.

## 4. 순위화와 context 구성

순위는 현재 질문 적합성 → 최신 정정/유효성 → 미해결 사건 → 직접 근거/전언 구분 → 중요도/최근성 순으로 조정한다. 직접 근거라고 무조건 관련 없는 기억을 우선하지 않는다. 재인용·검색 횟수는 중요도 보너스가 아니다.

화자별 context에는 다음 구획을 유지한다.

- 신의 성격·말투·가치, 공개 가능한 로어와 방향 있는 관계.
- 현재 실제 참가자·발화자·청중·발언권.
- 게임의 최신 관계/감정 입력과 Quest/Reward constraints·validator feedback.
- 최근 공유 대화와 현재 사용자 발언.
- 선택된 기억: 출처 종류, 언제/누가 말했는지, 원문 발췌, 최신 정정, 불확실성.
- 해당 화자에게 실제 허용된 Proposal 목록과 실행 결과 표현 규칙.

비밀을 제거하기 전에 모든 신의 로어/기억을 합치는 중간 prompt도 만들지 않는다. 분류 모델에도 생성과 같은 공개 경계를 적용한다. 검색 자료는 인용 데이터이며 명령이 아니라는 경계를 명시하고, 기억 안의 “규칙을 무시해” 같은 문장을 시스템 지시로 승격하지 않는다.

기억 때문에 토큰이 넘치면 낮은 순위의 근거 묶음을 먼저 제외한다. 역할/권한/constraints를 마지막 문자열 잘라내기로 제거하지 않는다. 원문 일부를 자를 때 부정·조건·화자·정정 의미를 잃으면 해당 발췌 대신 검증된 요약/불확실성을 사용한다. 긴 NPC 대사를 무조건 한 문장으로 축소하지 않고 HUD 출력 정책은 보존한다.

## 5. 모델과 자원 관리

새 모델 설치/대화 모델 교체는 범위 밖이다. [현재 모델 선택·합성 측정](../../docs/MEMORY_MODEL_CONNECTION_20260920.md)을 재사용한다. 하드웨어 측정값을 모든 서버의 성능 보장으로 인용하지 않는다.

| 작업 | 우선순위·정책 |
|---|---|
| 현재 대사/분류/기존 시각 평가 | 기존 foreground 규칙 유지 |
| 명시 회상 질의 임베딩 | 기존 검색 제한 안에서 시도, 혼잡/timeout이면 lexical fallback |
| 원문 임베딩·기억 추출/요약 | 기존처럼 접속자 0명·foreground 없음에서 작은 단위로 수행 |
| 소문 수신/설득 후처리 | 기존 SocialRuntime/ModelAdmission.followup 재사용. 접속 중 가능하되 foreground에 양보 |

정리용 장기 대기열을 모델 scheduler에 무한 등록하지 않는다. DB work queue의 다음 항목을 실행 가능할 때만 가져온다. HTTP 취소 요청 후 transport가 종료되기 전 permit을 반환하지 않는다. Secondary도 별도 무제한 병렬 요청을 만들지 않는다.

실행 예산의 시작값은 기존 설정을 우선 사용한다. 검색 임베딩 최대 350ms, 정리 최대 30초 등은 현재 설정이지 모든 단계의 품질 보장이 아니다. DB 검색/후처리 budget은 M5 실측 후 확정하며 게임 thread에서는 대기하지 않는다.

## 6. 확인할 품질 사례

같은 약속을 표현만 바꿔 물었을 때, 30일/1년 이상 된 직접 발언, 그 뒤 취소한 계획, 다른 플레이어의 같은 문장, 직접 본 일과 소문의 같은 주장, 회복된 비난, 합류 전에 한 사적 대화, 긴 대사의 뒤쪽 정정, 비밀을 포함한 악의적 원문을 시험한다.

검색 hit만으로 성공이라 하지 않는다. 올바른 사람/신/시점/근거와 최신 정정을 선택했고 공개 가능한 방식으로 자연스럽게 답했는지 확인한다. offline fixture와 실제 모델/플레이 수용 결과를 따로 보고한다.

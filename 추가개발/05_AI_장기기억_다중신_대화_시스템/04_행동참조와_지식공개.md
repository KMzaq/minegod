# 04. 행동 참조·관찰·소문과 지식 공개

## 1. 원본 한 건, 관점별 획득 증명

플레이어의 행동은 기존 원장에 남긴다. 신의 기억에는 **사건 참조 + 당시 관찰 증명 + 허용 투영 + 비권위 해석**만 붙인다. 여러 신이 보았어도 사건 원문은 하나다. 공동 전투는 참가자별 조회 인덱스가 같은 사건을 가리키며 모든 참가자의 신이 자동 목격자가 되지는 않는다.

최신 원장의 일반 행동 선별·기본 통계·인정 실적은 [현재 정책](../../docs/ACTION_RECORDING_POLICY_20260917.md)을 그대로 따른다. 이 설계 때문에 이동·공격 매 tick 로그를 다시 켜지 않는다.

참조만으로 내용이 없으면 매번 전체 게임 원장을 읽게 된다. 따라서 이미 허용된 작은 projection/cache를 둘 수 있다. 이는 원본과 proof revision/hash에 종속된 읽기 자료이며 독립적인 세계 사실 DB가 아니다. 원본/증명이 없어지거나 검증할 수 없으면 `SOURCE_UNAVAILABLE`로 사용을 중단한다. 캐시 문장만 남았다고 목격을 확정하지 않는다.

## 2. 획득과 공개의 두 단계

| 정보 | 신이 알게 된 근거 | 현재 발화에서 공개할 근거 |
|---|---|---|
| 신과 직접 나눈 대화 | 당시 실제 참여/청취 receipt | 해당 원문의 공개 정책과 현재 청중 |
| 다른 신과 나눈 대화 | 자신의 직접 청취 또는 적법하게 받은 전언 | 그 경로에 허용된 내용만. 서버 RAW 접근권 아님 |
| 중요 행동 | 유효한 관찰 proof와 원장 receipt | 현재 Experience/공개 정책 |
| 일상 활동 | 허용 관측 구간에서 실제 집계된 활동 | 해당 집계의 허용 내용·청중 |
| 소문 | 대상 플레이어·수신 신의 실제 receipt | 소문 범위·정책·현재 평가/철회 상태 |
| 현재 퀘스트/관계 | 게임이 해당 대화에 제공한 snapshot | 기존 Provider/Gateway가 허용한 범위 |

관리자 전체 기록 조회는 별도 권한 포트다. AI 검색 capability와 공유하지 않는다. 감사용 검색 결과도 자동으로 신의 기억에 import하지 않는다.

## 3. 주시 연결

1. 실제 주시 보상 지급→플레이어의 신별 획득 상태는 기존 claim이 소유한다.
2. 게임이 관측 정책·활성 구간·차폐를 판단한다. AI의 관심/감정으로 주시를 발급하지 않는다.
3. 원장 durable 성공과 기존 watch proof를 확인한 뒤 기억용 참조를 등록한다.
4. 게임이 허용한 projection만 색인한다. 관리자용 원장 payload 전체는 임베딩에도 보내지 않는다.
5. 답변 직전 원본·proof·공개 revision을 다시 검사한다.

주시 이전, 차폐 중, 오프라인·관측 공백의 기록을 나중에 소급 획득하지 않는다. 주시 종료는 이미 적법하게 얻은 기억의 일괄 삭제가 아니다. 반면 잘못 발급된 proof의 취소는 관련 파생 근거도 무효화한다.

신별/전체 차폐를 통과하지 못한 이유에 비밀 장소 이름·좌표를 넣어 플레이어에게 알리지 않는다. “알 수 없는 부분”과 “봤지만 숨긴 부분”을 임의로 연기하게 하는 것도 비밀 존재의 누출이 될 수 있다.

## 4. 소문은 기존 실제 수신 경로로 읽기

사용자가 말한 “플레이어에게 등록된 소문”은 대상 플레이어의 소문 원본과 **현재 신의 실제 수신 권한**을 같이 조회한다는 뜻으로 구현한다. 대상별 소문을 전역 검색해서 모든 신에게 제공하지 않는다.

기존 `RumorSavedData.heard`/`CourierRumorService`/`ReputationService`를 adapter로 사용한다. rootId·수신 receipt·대상·신·assessmentVersion을 기억 source에 연결한다. 동일 source의 재진술이나 다른 신의 인용을 새 독립 증거로 중첩하지 않는다.

- 일반 신 대화는 기존 관측 조건 아래 소문 후보가 될 수 있다. 비밀·차폐 대화는 제외한다.
- 전체 RAW 보관이 소문 관측 생산자에게 전체 사적 히스토리를 열어주는 것은 아니다. 현재 승인된 교환/사건 projection만 사용한다.
- 전서구가 없으면 가짜 관측/수신을 생성하지 않는다. 자동 스폰·재생성은 이번 범위 밖이다.
- 전서구 사냥의 대상별 전달 차단과 이미 수신한 기억 보존을 구분한다. 기존 정책의 미전달 폐기/epoch 처리를 재구현하지 않는다.
- ACCEPTED/DOUBTFUL/IGNORED 및 RECOVERED/RETRACTED는 해당 신의 현재 인식이다. 평판 원본은 게임에 두고 AI memory에 별도 authoritative 평가를 만들지 않는다.
- 기존 RUMOR_TEST의 액션 차단/PERSONAL 비활성 경계를 유지한다. 통합 기억을 켠다는 이유로 제한을 해제하지 않는다.

세부 생성/수신/설득 절차는 [최신 사회적 파이프라인](../../docs/SOCIAL_PIPELINE_COMPLETION_20260920.md)을 따른다. 이미 있는 Reviewer/생산자/소비자를 다시 만드는 단계는 계획하지 않는다.

## 5. 신별·청중별 context

Primary와 Secondary를 한 프롬프트에서 역할 이름만 바꿔 생성하지 않는다. 각각 자신의 KnowledgeReceipt와 현재 청중에게 공개 가능한 자료로 별도 context를 만든다. 다른 신의 비밀은 입력 전에 제외한다.

v1은 player UUID 집합만 audience에 담지만 새 계약은 실제 들을 **신도 청중**으로 취급한다. 예를 들어 A신만 아는 비밀을 B신이 참가한 공용 발화에서 말하게 하지 않는다. 필요한 비공개 답변은 게임이 별도 private channel을 실제 지원할 때만 가능하다. 그렇지 않으면 그 기억을 해당 발화 context에서 제외한다.

기본 공개 규칙은 보수적으로 기존 허용 범위를 유지한다. 당사자가 혼자 돌아왔다고 과거 공용 대화의 실제 수신 이력을 없애지는 않되, 새 청중 합류로 과거 사적 원문을 자동 공개하지 않는다. 새 공개 허가는 게임 정책/명시 기능으로만 확장한다.

## 6. 철회와 증거 세탁 방지

“신이 말했다”라는 사실은 RAW에 남길 수 있다. 그러나 그 말이 취소된 관찰이나 회복된 비난에 의존했다면 그 내용 자체를 현재 사실/믿음으로 다시 검색하지 않는다.

이를 위해 실제 출력에도 사용한 source 계보를 연결한다. source 취소 시 해당 EVENT/RELATIONSHIP/SUMMARY/검색 문서/최근 히스토리를 일괄 사용 불가로 표시한다. 정리 worker가 처리하기 전이라도 최종 lease 검사에서 차단한다.

과거 잘못된 말을 인용해야 하는 회상은 `HISTORICAL_UTTERANCE`로만 별도 허용한다. 최신 정정/철회 정보를 함께 제공하고 현재 청중의 역사적 원문 열람권을 확인한다. 일반 연상 fallback으로 과거 비난을 다시 현재 입장처럼 사용하지 않는다.

정정·철회·공개 정책 변화는 영속 revision/cursor로 남긴다. restart 후 일치 여부를 확인할 때까지 관련 자료는 보수적으로 닫는다. 다른 사용자에게서 무관한 사건이 생긴 것만으로 모든 기억 lease를 취소하지 않는다.

# 05. 기억 계층과 정리

## 1. 다섯 계층의 의미

| 계층 | 저장/수명 | 담는 내용 | 담지 않는 것 |
|---|---|---|---|
| RAW | 원문 보관, 날짜 만료 없음 | 실제 발언·전달 기록, 기존 게임 원본에 대한 참조 | 출력되지 않은 초안·시스템 프롬프트·복제 행동 DB |
| EVENT | 근거 있는 파생 기억 | 대화 에피소드, 약속, 직접 관찰, 수신 소문을 출처별로 구분 | AI가 확정한 퀘스트 완료/보상·세계 사실 |
| RELATIONSHIP | 비권위 관계 서사 | 누가 누구에게 했던 약속/해명, 관계에 의미 있던 대화 이력 | 독립 affinity 원본·자동 수치 평판 |
| SUMMARY | 범위별 요약과 근거 | 한 대화/에피소드/화제의 압축, 남은 일, 정정 | 모든 신·플레이어가 공유하는 무차별 요약 |
| RETRIEVED CONTEXT | 요청·화자 한정 휘발성 묶음 | 현재 응답에 필요한 소수 기억과 출처·불확실성 | 새로운 영구 사실·영구 실행 토큰 |

RAW는 하나의 물리 포맷을 강제하는 이름이 아니다. 대화는 새 SQLite가 원본, 행동은 기존 게임 원장이 원본이다. EVENT가 기존 `ActionRecord`를 대체하지 않는다.

## 2. EVENT의 최소 의미 분류

- `DIALOGUE_EPISODE`: 실제로 나눈 주제·상호작용과 대화 구간.
- `PLAYER_CLAIM`: 플레이어가 한 주장. “용을 잡았다”는 발언만으로 전투 결과가 아님.
- `INTENTION_OR_PROMISE`: 명시 계획·약속. 조건부/농담/가정/취소 여부와 시점 분리.
- `OBSERVED_EVENT`: 게임 proof에 연결된 실제 허용 행동.
- `OBSERVED_ACTIVITY`: 제한된 주시 구간에서의 활동 요약.
- `HEARSAY`: 실제로 받은 소문. 원본 진위/현재 신의 평가를 각각 참조.
- `CORRECTION_OR_EXPLANATION`: 기존 발언의 정정·해명 후보. 정확히 무엇을 고치는지 불명확하면 자동 연결하지 않음.

모델의 confidence나 임베딩 유사도는 세계 사실의 신뢰도를 의미하지 않는다. `evidenceKind`, `claimStatus`, `interpretationConfidence`를 분리한다. 동일 사건을 관찰·대화·소문에서 다시 읽어도 독립 사건 세 개로 세지 않는다.

## 3. RELATIONSHIP의 범위

관계 수치와 현재 신별 소문 평가는 게임 snapshot으로 읽는다. 이 계층은 “전에 무엇을 함께 겪었고 무슨 약속을 했는가”의 서사다. actor 방향을 유지하고 신→플레이어, 플레이어→신, 신→신을 섞지 않는다.

예: “A신이 플레이어의 설명을 들은 대화가 있다”는 대화 이력이다. `RECOVERED`인지는 게임의 최신 평가가 결정한다. AI가 공손한 사과를 발견했다고 관계 수치를 올리거나 실제 평판을 회복시키지 않는다.

현재 감정은 세션의 비권위 상태일 수 있고, 장기간 성격으로 고정하지 않는다. 한 번의 농담/위협을 플레이어의 영구 인격 태그로 만들지 않는다. 정적 신 간 관계·동적 신 관계도 기존 Provider의 방향과 공개 정책을 따른다.

## 4. 정정·취소·이행

원문 A → 해석 후보 A → 이후 원문 B → A와 B의 연결 후보 → 구조/근거 검사 → 최신 해석 version 순서다. 원문 A를 B로 덮지 않는다.

| 표현/결과 | 기억 처리 |
|---|---|
| “내일 돌아올게” | 발언 시점 기준 현실 달력의 계획 후보 |
| “해가 뜨면 돌아올게” | Minecraft 일광 조건, 현실 날짜로 일괄 변환하지 않음 |
| “취소할게” | 지시 대상이 명확한 경우 취소 진술 연결. 모호하면 미확정 |
| “약속 지켰어” | REPORTS_FULFILLMENT 자기 진술. 실제 게임 이행은 별도 근거 필요 |
| 시간이 지남 | 약속 시점이 지난 것. 배신/실패/벌점 자동 확정 아님 |
| 게임이 실제 완료 확정 | 현재 game result를 참조. 대사의 자기 주장보다 우선 |

현실 “내일”은 기존 REAL_KST 방향을 유지하고 원래 발언 시점에 고정한다. 게임의 수면/시간 명령/차원 차이를 실제 snapshot으로 다룬다. 자료가 부족하면 추정 날짜를 넣지 않는다.

## 5. SUMMARY 생성 단위

대화 종료, 주제 경계, 충분히 쌓인 원문 구간을 정리 후보로 만든다. 날짜가 지났다고 원문을 삭제하거나 반드시 일일 요약을 만들지는 않는다.

요약에는 다음을 별도 항목으로 둔다: 핵심 대화, 플레이어 주장, 게임 확인/직접 관찰, 전언, 남은 약속, 정정, 확인되지 않은 부분. 각 주장에 source alias가 있어야 한다. 인용 검증에 실패하거나 새 사실을 덧붙인 항목은 거절한다.

서로 접근 범위가 다른 자료는 별도 요약으로 나눈다. 권한 검증이 어려운 혼합 요약을 생성한 뒤 일부 문장을 숨기는 방식은 쓰지 않는다. 단순 audience 합집합은 비밀 유출을 만든다. 요약의 공개 가능 범위는 모든 포함 근거를 만족하는 범위 이내다.

요약의 요약을 반복해 출처를 잃지 않는다. 긴 계보는 원문/source manifest에 연결하고, 요약 재작성 시 해당 원문 구간을 다시 검증한다. 원문이 너무 길면 부분 coverage로 표시하고 처리하지 않은 부분까지 요약했다고 하지 않는다.

## 6. 중요도와 자연스러움

미해결 약속·중요 해명·관계 전환·중요 사건은 우선 회상한다. 사소한 잡담은 최근성 가중치가 낮아질 수 있지만 보관/검색 자격 자체는 사라지지 않는다. 기억의 보관과 말할 빈도는 다르다.

사용자가 현재 질문한 내용이 먼저다. 매 턴 과거를 언급하거나, 주시했다는 보고를 반복하거나, 해결된 약속을 계속 재촉하지 않는다. 신의 성격·관계·상황에 맞는 자연스러운 활용을 평가한다. 모두 친절한 비서 말투로 만드는 것을 개선으로 보지 않는다.

검색·재인용 횟수로 중요도/증거 수를 올리지 않는다. 새로운 실제 근거가 생겼을 때만 연결한다. 기록이 없거나 PARTIAL이면 모른다고 답할 수 있어야 하며, 비어 있는 슬롯을 그럴듯한 과거 사건으로 채우지 않는다.

## 7. 비동기 정리 작업

현재 모델/입장 관리의 전경 우선·무접속 정리 정책을 재사용한다. 원문을 저장할 때마다 별도 LLM을 동기 호출하지 않는다. 작업은 source ID/hash/추출 version으로 멱등하며 cursor·시도 횟수·마지막 실패를 남긴다.

모델 실패 시 원문과 이미 유효한 벡터는 보존하고 lexical 검색을 유지한다. 자동 반복은 제한하며 전경 선점과 실제 오류를 구분한다. 재시작 후 pending 작업은 새 snapshot/권한으로 재개하고 오래된 승인 token은 버린다.

최신 source와 권한이 맞지 않으면 결과를 저장하지 않는다. 추출 모델 지침에 “비밀을 공개하지 말라”고 적는 것만으로 권한 검사를 대체하지 않는다. 개인 원문을 정리하는 worker에는 해당 범위의 자료만 제공한다.

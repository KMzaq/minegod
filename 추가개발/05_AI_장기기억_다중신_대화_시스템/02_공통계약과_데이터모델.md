# 02. 공통 계약과 데이터 모델

이 문서가 **새 계약의 단일 정의**다. 현재 코드의 DTO가 이미 아래 형식이라는 뜻은 아니다. 기존 [행동·관찰 계약](../../docs/ACTION_OBSERVATION_CONTRACT_20260915.md)과 공개 API는 adapter로 연결한다.

## 1. identity와 순서

| 값 | 정의 |
|---|---|
| `worldId` | 기존 게임이 발급한 월드 UUID. 폴더명/서버명으로 만들지 않음 |
| `datasetId` | 신규 기록 namespace UUID. 시험/운영 dataset 및 복원 분기 분리 |
| `runtimeEpoch` | 부팅마다 새 값. 늦은 비동기 결과가 재시작 이후 적용되는 것을 차단 |
| `conversationId` | 게임이 발급한 대화 scope. 새 방은 `roomId` UUID를 그대로 사용하며 표시 코드/선택된 방을 identity로 쓰지 않음 |
| `generation` / `membershipRevision` | 새 방은 정확한 long `revision`을 보존. 기존 int generation은 v1 bridge용 파생값일 뿐 DB identity를 대체하지 않음 |
| `turnId` / `turnSequence` | 서버가 수락한 발화/응답 묶음의 UUID와 대화 내 순서 |
| `messageId` | 한 논리 발언의 UUID. 청중 수만큼 복제하지 않음 |
| `ingestSequence` | 신규 archive 내부 durable 순서. 게임 원장의 sequence와 별개 |
| `ActorRef` | PLAYER + UUID 또는 GOD + 기존 God ID. 표시 이름은 식별자가 아님 |

게임 사건에는 기존 occurrenceId·sourceRef·sourceRevision·ledger sequence를 그대로 쓴다. 모델이 identity/순서를 발급하지 않는다. 시각은 발생 UTC, 게임 tick/dayTime/차원, 서버 기록 시각을 구분한다. 불명 값은 null+사유이며 현재 값으로 채우지 않는다.

## 2. 논리 레코드

| 레코드 | 필수 의미 |
|---|---|
| `ConversationEnvelope` | world/dataset/conversation, channel, privacy policy ref/revision, recording policy, 시작/종료 상태, adapter version |
| `TurnSnapshot` | epoch/session/generation/turn, initiatingPlayer, ACTIVE/LISTENER/OUTSIDE의 게임 판정, Primary/Secondary 허용 후보, 청중 snapshot, 관계/Quest/Reward/validator feedback의 범위 |
| `RawMessage` | messageId, 원본 발화자, 서버가 수락한 본문, 실제 표시 본문(있으면), 발생 시점, 입력/출력 종류, 순서, body hash, 상위 turn, 원본 producer 발생 키 |
| `DeliveryReceipt` | messageId, 게임이 확인한 수신 ActorRef, delivery 종류/시점, audienceRevision, 상태 |
| `KnowledgeReceipt` | observer God ID, 직접 수신/주시/소문 획득 경로, source ref, 획득 당시 정책, 허용 projection, 현재 유효 revision |
| `SourceRef` | source kind/id/revision/hash, 원본 owner, origin dataset, world. 내부 근거 식별자이며 자연어 모델의 참조 선택을 검증 |
| `DerivedMemory` | kind, 관점의 god, 관련 player/actor 목록, typed claims, 근거 목록, disclosure ref, status, extraction/model version |
| `MemoryLink` | 새 기억→이전 기억/원문의 CORRECTS/CANCELS/REPORTS_FULFILLMENT/SUPERSEDES 등 비권위 연결 |
| `SummaryChunk` | 같은 접근 범위의 원문 구간/근거 목록, coverage cursor, 요약 version, 누락/불확실 상태 |
| `RetrievalBundle` | 해당 speaker와 turn에만 유효한 선택 근거·excerpt·source kind·불확실성·검증 lease |

`DeliveryReceipt`의 기본 `SERVER_DISPATCHED`는 서버가 지정 수신자에게 출력을 넘겼다는 뜻이다. 화면을 보거나 이해했다는 증거가 아니다. 클라이언트 ack가 실제 구현돼야 `CLIENT_ACKNOWLEDGED`를 사용할 수 있다. 신의 수신은 게임의 청취 판정으로 별도 확인한다.

## 3. 근거 종류와 참조 키

| 종류 | stable key의 핵심 | 공개 내용의 출처 |
|---|---|---|
| `DIALOGUE_DIRECT` | dataset/message/receipt | 직접 들은 원문과 당시 청중/정책 |
| `ACTION_OBSERVED` | game world/occurrence/revision + observationId/revision | 기존 ExperienceLease의 허용 투영 |
| `ACTIVITY_OBSERVED` | 기존 집계 사건/관측 구간/정책 | 실제 허용 구간 활동 요약. 생애 통계 차이가 아님 |
| `RUMOR_RECEIVED` | subjectPlayer/root/receipt/god + assessmentVersion | 기존 소문 읽기 DTO |
| `GAME_STATE_SNAPSHOT` | Provider scope/revision | 현재 사실. 오래된 기억으로 현재 상태를 덮지 않음 |
| `DERIVED_SPEECH` | message + 사용한 source 계보 | 이미 출력된 AI 대사. 독립된 사실 증거 아님 |

다른 플레이어를 언급한 발언에는 발화자와 이야기 대상이 각각 있어야 한다. “A가 B의 일을 말했다”를 “B가 직접 고백했다”로 저장하지 않는다. 의미 해석이 불확실한 entity는 UNKNOWN 후보로 남기고 비슷한 이름의 UUID를 붙이지 않는다.

## 4. 제안 SQLite 테이블과 제약

모든 행은 dataset 범위를 갖는다. 파일 자체가 단일 world여도 명시 identity를 검증한다. M0 확정: UUID는 소문자 하이픈 포함 36자 canonical `TEXT`로 저장하고 Java에서는 `UUID`를 쓴다. God ID는 기존 `namespace:path`를 그대로 쓴다. UUID 문자열과 God ID를 같은 actor key로 비교하지 않는다.

| 테이블 | 키/주요 연결 | 필수 제약·인덱스 |
|---|---|---|
| `recording_meta` | world, dataset, schema, cleanShutdown, highWatermark | 한 active dataset, 알 수 없는 schema는 보존 후 새 기능 OFF |
| `conversations` | conversationId | channel/privacy version; 종료 후 새 turn 금지 |
| `turns` | turnId → conversation | `(conversationId, turnSequence)` unique |
| `messages` | messageId → turn(nullable: 일반 chat) | `(datasetId, producerId, occurrenceKey)` unique; 같은 키/다른 hash는 오류 |
| `message_parts` | messageId, partIndex | 긴 본문 분할 시 누락/전체 hash 검증. 부분 저장을 완전 원문으로 공개 금지 |
| `deliveries` | messageId, recipient, deliveryKind | 동일 수신 중복 방지. 실제 수신/전달 snapshot 보존 |
| `delivery_views` / `delivery_parts` | messageId, viewHash / receipt, partIndex | 수신자별 필터·장식·HUD 페이지가 다르면 실제 전달 projection과 전달된 부분을 연결. 같은 view는 재사용 |
| `source_refs` | sourceRefId | kind/owner/id/revision/hash unique; 내용 원본을 복제하는 테이블 아님 |
| `knowledge_receipts` | god/source/acquisition | actor·god·대상·공개 범위별 조회 인덱스 |
| `memories` / `memory_sources` | memoryId, sourceRefId | 모든 주장에 비어 있지 않은 근거, 현재 status/version |
| `memory_subjects` / `memory_links` | memoryId, ActorRef / targetId | 단일 player pair 가정 금지. 정정 방향/중복 검증 |
| `summaries` / `summary_sources` | summaryId, sourceRefId | coverage·근거 current 검증, 권한 범위 다른 자료 혼합 금지 |
| `search_documents` + FTS | 단일 허용 원문/투영/요약의 version | owner/ACL/subject/source kind별 필터, 파생 중복 그룹 ID |
| `embedding_rows` | document/version/modelDigest | 차원/encoder version 검증, 오래된 digest와 검색 혼합 금지 |
| `work_items` / `consumer_cursors` | jobId / consumer+stream | stable source/version job unique, durable 이후만 cursor 전진 |
| `invalidations` / `coverage_gaps` | 관련 source/stream/range | 원문 보존, 검색/생성 사용은 즉시 차단. 누락 사유 집계 |

대화 하나를 신마다 `messages`에 복사하지 않는다. 신별 차이는 `knowledge_receipts`, 관점별 파생 행이다. 검색 파티션은 저장 identity가 아닌 재생성 가능한 인덱스다. SQL DDL·FK/transaction 테스트는 M1 산출물로 작성한다.

## 5. 읽기/쓰기 포트

아래 의미를 유지하는 M0 확정 Java 포트는 7절에 있다. 구현·DDL은 M1 이후다.

- `capture(envelope, raw, recipients) -> CompletionStage<WriteReceipt>`: game-issued producer만 호출. 결과는 STORED / DUPLICATE / CONFLICT / FULL / UNAVAILABLE.
- `openRead(turnSnapshot, speaker) -> MemoryReadCapability`: 게임이 발급하는 불투명 scope. AI가 임의 신/청중/소문 수신권을 만들 수 없음.
- `query(capability, typedQuery, pageCursor, budgets) -> SearchPage`: 페이지/시간/반환 크기 제한. raw SQL이나 모델이 만든 path를 받지 않음.
- `validate(capability, usedSources, turn) -> ValidationResult`: 게임 thread에서 실제 출력/실행 직전 확인.
- `commitProjection(workToken, proposedMemories) -> ProjectionReceipt`: 후보 구조·source/version/권한 검사 후 비권위 자료로만 저장.
- `invalidate(source, revision, reason)` / `getCoverage(stream)`: 철회 통지와 누락 진단. 비공개 이유를 플레이어에게 그대로 공개하지 않음.

`MemoryReadCapability`는 내부적으로 world/dataset/epoch/session/generation/turn, speaker, subjects, audience, policy/relation revisions를 묶는다. 모델에는 bearer token/DB key를 주지 않고 `e1`, `e2` 같은 요청 한정 alias만 제공한다. 모델이 미제공 alias를 출력하면 거절한다.

검색 상태는 FOUND / EMPTY / PARTIAL / UNAVAILABLE / STALE을 구분한다. 권한 밖 자료 존재 여부나 건수를 EMPTY 설명으로 누출하지 않는다. PARTIAL은 검색·색인·수집의 확인된 공백이 있음을 뜻하며 “그런 일은 없었다”로 바꾸지 않는다.

## 6. 유효성·중복·수정

원문은 append-only 의미로 유지한다. 정정 발언은 새 원문이고 이전 해석의 상태만 바뀐다. 근거 철회는 존재 삭제와 구별하며 관련 파생 자료·요약·임베딩·최근 대사 계보를 함께 무효화한다. 모델 재추출은 같은 source 집합/hash/version으로 멱등 처리한다.

대화 종료로 과거 기억 자체가 사라지지는 않는다. 종료는 현재 작업 token을 무효화한다. 재시작/복원 후 과거 기록은 새 게임 권한으로 다시 검증하고, 오래된 lease나 in-flight 작업은 재사용하지 않는다. 다른 플레이어의 무관한 기록 추가로 모든 세션의 결과를 무효화하지 않는다.

## 7. M0 확정 Java 포트와 스레드 계약

새 공개 계약 패키지는 게임 모듈의 `com.sande.mythictrpg.recording.api`, 내부 구현은 `recording.server`로 둔다. 기존 `ai.memorycontract` / `ai.experiencecontract`를 지우거나 같은 이름으로 바꾸지 않는다. 다음은 Java 21 선언 설계이며 이번에 컴파일한 소스가 아니다. 값 타입은 앞 절의 레코드 의미를 따른다.

```java
interface GameRecordingPort {
    CompletionStage<WriteReceipt> capture(
        ProducerCapability producer, ConversationEnvelope conversation,
        RawMessage message, List<DeliveryReceipt> initialDeliveries);
    CompletionStage<WriteReceipt> recordDeliveries(
        ProducerCapability producer, DeliveryBatch deliveryBatch);
    CompletionStage<WriteReceipt> captureSource(
        ProducerCapability producer, SourceCapture sourceCapture);
    CompletionStage<WriteReceipt> invalidate(
        ProducerCapability producer, SourceInvalidation invalidation);
}

interface GameMemoryAuthority {
    Optional<MemoryReadCapability> openRead(TurnSnapshot turn, ActorRef speaker);
    ValidationResult validate(
        MemoryReadCapability capability, Set<SourceRef> usedSources,
        TurnSnapshot currentTurn);
}

interface MemoryReadPort {
    CompletionStage<SearchPage> query(
        MemoryReadCapability capability, MemoryQuery query,
        Optional<PageCursor> cursor, ReadBudget budget);
    CompletionStage<CoverageReport> getCoverage(
        MemoryReadCapability capability, StreamRef stream);
}

interface MemoryProjectionStore {
    CompletionStage<Optional<ProjectionWork>> claimWork(
        ProjectionWorkerCapability worker, WorkBudget budget);
    CompletionStage<ProjectionReceipt> commitProjection(
        WorkToken work, List<DerivedMemory> proposedMemories);
    CompletionStage<ProjectionReceipt> finishWork(
        WorkToken work, WorkOutcome outcome);
}

interface ManagedStoreQuota {
    ReservationDecision tryReserve(StoreHandle store, GrowthBound growth);
    void reconcile(Reservation reservation, WriteAccounting outcome);
    QuotaSnapshot snapshot();
}
```

- `ProducerCapability` / `MemoryReadCapability` / `ProjectionWorkerCapability` / `WorkToken` / `StoreHandle`은 모두 게임 발급 불투명 값이다. 공개 생성자를 두지 않고 내부 등록 identity/epoch도 대조한다. AI가 같은 interface를 임의 구현해 권한을 얻을 수 없어야 한다.
- `GameRecordingPort`는 게임이 승인한 capture/source adapter 전용이다. AI의 텍스트나 모델 출력만으로 source/receipt를 발급하지 않는다. AI 연결부도 게임의 현재성 검사와 실제 전달 처리를 거친다.
- `GameMemoryAuthority`는 서버 스레드 전용이다. 시작/최종 출력/실행 직전의 현재성을 판단하며 SQL·파일 I/O·모델을 기다리지 않는다. 비동기 작업 뒤에는 서버 스레드로 복귀해 재검증한다.
- `MemoryReadPort` / `MemoryProjectionStore`의 I/O는 제한 worker에서 수행한다. Future 완료 스레드를 게임 스레드로 가정하지 않는다. 공개 포트에 `ServerPlayer` / `Level` / JDBC connection / 파일 path를 넘기지 않고 게임 측에서 불변 snapshot으로 바꾼다.
- `tryReserve`는 사전 측정 accounting에 대한 비차단·원자적 예약이다. 디스크 순회는 별도 worker에서 한다. 미측정 저장소, 최대 증가량 불명, overflow는 거부한다. `reconcile`은 실제 I/O 종료 통지 뒤에만 예약을 해제한다.

### 추가 값 타입의 필수 의미

| 값 타입 | 고정 의미 |
|---|---|
| `ProducerCapability` | 허용 producerId/channel/source kind, world/dataset/epoch. 일반 RAW 수집과 소문 발행 권한은 별개 |
| `DeliveryBatch` | batchId, messageId, producer occurrenceKey, immutable receipts/views/parts, hash. 원문 뒤 늦게 도착하는 receipt의 멱등 키 |
| `SourceCapture` | SourceRef, 허용 KnowledgeReceipt, opaque source cursor. 행동 본문을 새 RAW 대화로 복제하지 않음 |
| `WriteReceipt` | status, durable ingestSequence(optional), message/source ID, 내용 없는 reasonCode. 결과 상태는 5절; 큐 거부는 UNAVAILABLE+QUEUE_FULL |
| `MemoryQuery` | TEXT / TIME_RANGE / ENTITY / SOURCE / HYBRID의 typed 조건. 모델 SQL·경로·임의 God ID 허용 안 함 |
| `PageCursor` | world/dataset/speaker/scope/query hash/highWatermark/마지막 key에 결속된 게임 발급 값. 다른 화자/청중으로 재사용 금지 |
| `ProjectionWork` / `WorkToken` | jobId, source/version/hash, disclosure partition, extractor version, lease epoch/deadline. 만료 후 재수령해도 동일 job으로 멱등 처리 |
| `ProjectionReceipt` | STORED / DUPLICATE / STALE / REJECTED / FULL / UNAVAILABLE. STALE 결과로 cursor를 성공 전진시키지 않음 |
| `GrowthBound` | 최대 신규 물리 바이트, 임시본·WAL·checkpoint 증가를 포함한 계산 근거. 비음수 signed 64-bit, checked addition |
| `ReadBudget` / `WorkBudget` | 반환 행/UTF-8 바이트/기한·동시성 제한. 저장 총건수나 보존 기간 제한이 아님 |

`capture`는 RAW+초기 receipt+후속 work item을 한 transaction으로 커밋하고, `recordDeliveries`는 추가 receipt+해당 후처리 작업을 한 transaction으로 커밋한다. 중복 본문을 다시 저장하지 않는다. 잘못된 capability는 큐 입장 전에 거절한다. 삭제 대신 invalidation은 원본 source revision과 별도의 게임 발급 단조 증가 상태 버전을 가진다. 이미 더 최신 상태를 처리했다면 늦은 통지를 적용하지 않는다.

원문/receipt가 아직 없는 후처리는 실행하지 않는다. `STORED`는 durable commit 이후만 반환하며 `DUPLICATE`에는 기존 durable 식별자를 반환한다. 같은 발생 키로 다른 본문/수신 정보를 덮어쓰지 않고 `CONFLICT`로 격리한다. 수신 추가는 새 `DeliveryBatch`를 사용한다.

### 실제 전달과 권한

수신자별 필터링 때문에 원문 한 건과 표시 문자열 한 건만으로는 충분하지 않다. receipt는 해당 수신자에게 전달된 `delivery_view`와 성공한 페이지를 참조한다. NPC가 실제로 받은 projection보다 넓은 RAW 본문을 검색에 제공하지 않는다. 전달된 일부 페이지는 `PARTIAL_DISPATCH`, 완전 전달은 `SERVER_DISPATCHED`; 둘 다 화면 열람 확인이 아니다. 실패·차단·미전달은 수신 증거가 아니다.

원문 hash는 수락 시점 문자열의 UTF-8 SHA-256(소문자 hex64)이며 공백 정규화로 원문을 바꾸지 않는다. Component 장식/필터/줄바꿈/HUD 분할은 별도 view hash와 part 순서로 보존한다. 요청 프롬프트 길이 예산은 archive 길이 예산으로 재사용하지 않는다.

v1 대응·발생 키·시험 기준은 [M0 연결점](M0_기준확정/01_수집채널과_기존계약_대응.md)을 따른다. 청중에 신이 추가된 v2 검증이 없으면 기존 플레이어 전용 공개 검사를 다중 신 공개 승인으로 확대하지 않는다.

## 8. 2026-09-21 대화방 생산자 대응

새 방은 [M0 후속 기준](M0_기준확정/04_대화방_변경_연결_20260921.md)을 우선한다. `ConversationRooms`가 발급하는 `RoomDialogueEvent`의 messageId/roomId/revision/optional turnId를 유지해 M2 adapter로 보낸다. 초기 조우·AI를 거치지 않은 동의 발언은 turnId가 없어도 유효한 발화다. AI 요청이 없다는 이유로 버리거나 가짜 AI 턴을 만들지 않는다.

현재 event는 게임 측 불변 publication DTO이지 위의 durable `WriteReceipt`나 신 `KnowledgeReceipt`가 아니다. world/dataset/epoch, 수신자별 표시 view·성공 페이지의 정확한 내용/순서, DB 멱등 커밋은 M1~M2에서 보강한다. 현재 chatDispatched와 hudPagesDispatched는 서버 전송 결과이지 화면 열람 확인이 아니다.

history의 `sourceRoomId`는 방 병합·분리 뒤에도 원래 방을 유지한다. 현재 방 청중에 공개 가능하더라도 원래 관찰·소문 근거가 철회됐으면 생성/분리 판단에 쓰지 않는다. 저장 단계에서는 원래 message/source 계보를 유지하며 문자열 일치만으로 영구 identity를 만들지 않는다.

`TEST_EPHEMERAL`은 본문·진단·새 기억을 영속 writer에 보내지 않는다. off→on으로 과거 RAM history를 소급 적재하지 않는다. 공개 수신자와 방 참가자를 별도 목록으로 유지하고, 공개 플레이어에게 전달됐다는 사실만으로 모든 신에게 지식을 주지 않는다.

# 플레이 경험과 화면

## 목표 경험

"시스템이 내 행동을 납득할 만하게 기억하지만 나를 단정하거나 강요하지 않는다."

성향이 아니라 현재 질문을 먼저 이해한다. 관련 없는 기억을 장식처럼 나열하지 않는다. 기억은 반응 선택에 영향을 줄 수 있지만 반드시 회상 대사로 읽어줄 필요는 없다. 신의 불친절·의심·거절도 성격과 상황에 맞으면 유효하다. 시스템 오류 정정과 캐릭터 설득을 구분한다.

## 본인 화면

- 명칭: 나의 플레이 기록과 이해. 명시적으로 열고 전투 중 자동 팝업하지 않는다.
- 성향/목적/근거를 확인한다. 시스템 추정이며 NPC의 속마음이 아니라는 설명을 항상 표시한다.
- 근거 부족, 일부 기록, 정정됨을 정상 상태로 표시한다. 가짜 성격 점수나 정밀 확률은 표시하지 않는다.
- 한 번의 사건은 단일 관측으로만 보여주며 반복 경향으로 승격하지 않는다.
- 근거에는 본인에게 허용되는 행동 종류·시각·횟수만 표시한다. 원본 payload 전체, 좌표, 타인의 비공개 내용, 내부 비밀 ID는 보내지 않는다.
- 이의 제기/되돌리기는 원본을 지우지 않는다. 성공은 durable receipt 뒤 표시하며 실패 시 반영했다고 말하지 않는다.
- 서버가 발급한 화면 토큰·현재 접속·본인 UUID를 재검증한다. 클라이언트가 타인의 UUID나 임의 근거를 보내지 못한다.
- 작은 해상도, 긴 한글, 스크롤, 재접속, 늦은 응답, 중복 클릭을 검사한다.

## 대화 표현

사실: "그때 동료를 도왔지." / 추정: "동료를 먼저 챙기는 편인가?" / 자기 진술: "전에 OOO을 찾는다고 했지." / 소문: "그런 이야기를 들었다."

위 문구는 평가용 의미 예시이며 문장별 고정 응답으로 구현하지 않는다. 추측할 때마다 확인 질문을 강제하지 않는다. 대화에 도움이 안 되면 언급하지 않는 것이 정상이다. 정정 이후에는 같은 증거로 같은 단정을 다시 하지 않는다. 새로운 명확한 근거가 생겨도 과거 정정을 보존한다.

개인화의 자발적 화제 전환은 낮은 빈도로 제한한다. 대사 전달에 성공했을 때만 언급 이력을 갱신하고, 신이 여러 명이면 동일 사건을 합창하듯 반복하지 않도록 실제 전달 이력을 사용한다. 플레이어가 해당 주제를 직접 물으면 관련 근거 설명은 가능하다.

## 연구에서 가져온 원칙과 한계

- [Microsoft Human-AI Interaction 지침](https://www.microsoft.com/en-us/research/articles/guidelines-for-human-ai-interaction-eighteen-best-practices-for-human-centered-ai-design/?lang=fr-ca): 상황에 맞는 개입, 정정/거절, 불확실할 때 범위 축소, 변화의 신중한 반영을 권장한다. 이를 대화 타이밍과 정정 UX에 적용한다. 게임 만족도를 직접 입증하는 자료는 아니다.
- [Generative Agents, 2023](https://arxiv.org/html/2304.03442v2): 기억·반성·계획을 결합한 에이전트를 평가했으며 기억 검색 실패, 기억의 창작, 과도하게 정중·협조적인 행동을 한계로 보고한다. 이 프로젝트에서는 출처 검증과 캐릭터별 거절·관점 유지 검증으로 연결한다. 해당 실험 결과가 이 서버의 자연스러움을 보장하지 않는다.
- [Player Modeling, 2013](https://drops.dagstuhl.de/entities/document/10.4230/DFU.Vol6.12191.45): 입력·모델·출력을 구분하는 플레이어 모델링 틀을 참고한다. 여기서는 실제 사람의 성격/감정 진단 대신 게임 내 관측 가능한 선택에 범위를 제한한다.

수치 임계값·언급 빈도는 이 프로젝트의 조정 가능한 초기 정책이지 논문에서 검증된 정답이 아니다.

# 행동 기록·성향/목적 추론 — 담당 범위와 완료 기준

2026-10-19, `behaivior`. 사용자 요청으로 일반 한국어 대화 이해·응답 품질과 행동 이해 시스템을 분리한다. 이 문서는 새 담당 범위와 구현 순서이며, 아직 구현되지 않은 연결을 완료로 표시하지 않는다. 현재 모델 `gemma4:12b` 유지, 전체 적용 검증 전 서버 배포 금지도 유지한다.

## 1. 담당 경계

**이 작업:** 플레이어별 행동 기록 → 출처가 있는 활동 지표 → 수정 가능한 성향·목적 가설 → 본인 화면/허용 관찰자용 입력 → 제한된 게임 보정.

**별도 대화 품질 과제:** ‘들어주겠다’ 제안에 누구를 화자로 받는지, 상투적 역제안, 일반 한국어 문맥 이해, 말투·표현 다양성, 일반 대사의 과잉 수정/거절. 기존 [13](13-independent-semantic-frames.md)~[15](15-purpose-reply-contract.md)의 실험과 [실제 대사 기록](../../검토결과/purpose-reply-20261019/REVIEW.md)은 보존하며 이 작업에서 계속 일반 대화 프롬프트를 고치는 것을 선행 조건으로 삼지 않는다. 다른 채팅을 생성하거나 메시지를 보낸 것은 아니다.

경계는 오류의 발생 지점으로 정한다. 다른 플레이어의 목적이 저장되거나 이 시스템이 잘못된 NPC 입력을 만들면 이 작업의 결함이다. 올바른 입력을 받은 대화 모델이 역할을 뒤집으면 별도 대화 결함이다. 후자가 발견됐다고 전자를 실패한 것으로 기록하지 않되, 잘못된 출력으로 기록·보정이 오염되는 연동 경로는 반드시 차단한다.

## 2. 사용자 결정의 반영

- Minecraft 활동은 AFK(잠수)·탐사·농사·낚시·건축·레이드·퀘스트 진행·휴식 등으로 나눈다. **AFK는 부정적인 성향/목적/추천 근거가 아니며 활동 비율의 분모에도 넣지 않는다.** 시스템의 영향은 유저 지원에 한정한다. 구체적인 생산자와 현재 구현 한계는 [17 — Minecraft 활동·AFK 중립](17-minecraft-support-activities.md)을 따른다.
- 성향·목적 추론은 행동에 대한 잠정적 해석이다. 행동이 누적돼도 본인이 결심했다는 사실을 만들어내지 않는다. 근거가 많으면 가설을 제시할 이유가 강해질 뿐이다.
- 본인이 한 희망·결정·철회 발언, 실제 행동 진행, 추론의 근거 강도는 [14](14-evidence-driven-purpose.md)의 서로 다른 축으로 유지한다. 직접 확인한 행동까지 전부 불확실한 사실로 낮추지는 않는다.
- NPC 전달에는 관측 사실과 가설을 분리한다. 가설은 추측으로 사용할 수 있고 관련 없는 턴마다 반복하지 않는다. 고정 문구 사전을 늘려 자연스러움을 해결했다고 주장하지 않는다.
- 게임 영향은 작은 도움·제안 보정에 한정한다. 첫 적용은 **이미 적격하고 공개 가능한 콘텐츠·힌트의 제안 우선순위**로 한다. 후보의 자격, 퀘스트 수락, 아이템 소비·지급, 가격, 능력치, 난이도, 관계 수치, 정사 변경을 이 추론이 직접 결정하지 않는다. 수치 보정이 필요하면 별도 정책과 검증 범위를 정하며 수치를 임의 확정하지 않는다.
- 유저별 원본 분리와 발언 속 목적 주체 구분을 함께 한다. A가 ‘B가 만나고 싶대’라고 말하면 A의 발언 기록이지만 A의 만남 목적 증거는 아니다. B의 확정 목적에도 자동 등록하지 않으며 허용된 전언으로만 취급한다. 식별할 수 없으면 보류한다.
- 게임 모듈이 사실·권한·실행을 소유한다. 추론과 NPC 대사를 새로운 독립 행동 근거로 다시 누적하지 않는다.

## 3. 현재 상태와 해결해야 할 일

| 작업 | 확인된 기반 | 남은 핵심 |
|---|---|---|
| 원본 수집·격리 | 기존 행동 원장, 플레이어/월드 구분, 분석 시작 경계 | 실제 이벤트 누락·중복·행위자 확인, 새 성향 축에 필요한 생산자 연결, 시험 자료 제외 |
| 일반 플레이 성향 | `PlayerUnderstanding`의 농사·채집·전투·퀘스트·레이드 활동 카드 | 단순 횟수와 선호 구분, 자발성·선택 가능성·반대 근거·최근 변화. 확인 못 하는 축은 근거 부족 |
| 레이드 성향 | `RaidChoiceEvidence`, 시험 레이드의 선택 기회 계측·집계 | 확정된 정식 기믹에서 실제 개인의 기회/지원/선택 입력 연결. 승패·DPS·사망만으로 성격·숙련도를 단정하지 않음 |
| 목적 갱신 | `PurposeEvidence/State/Ledger`, 출처 묶인 주석·철회 | 실제 대화 원본과 행동 원장의 순서/receipt 연결, 해석 후보 주체·대상 검증, 정정·재시작 이후 재구성 |
| 장기 처리·본인 화면 | `PurposeSelfView/UnderstandingRuntime`의 조회·근거·정정 기반 | 4,096근거/64목적 경계 이후 증분·페이지 처리, 실제 클라이언트 확인, 기록 OFF/용량 부족·실패 시 표시 |
| NPC/신 입력 | `PurposeDialogueContext`의 격리 평가용 입력 | 실제 청취·주시·소문/청중 권한 어댑터. SELF 전체 분석을 공유하지 않고 허용 근거부터 재계산. 늦은 응답·권한 변경 재검증 |
| 작은 게임 보정 | 기존 콘텐츠 적격성·게임 실행 경계를 재사용하는 설계 | 실제 후보 제공자 연결, 영향 상한·거절 억제·기본값 복귀·추천 자기강화 방지, 확인 절차 유지 |

기존 구현은 기반이 있으며 ‘행동 기록 시스템이 전혀 없다’는 상태가 아니다. 반대로 활동 카드나 합성 시험만으로 모든 성향과 운영 콘텐츠가 연결됐다고 할 수도 없다. 현재 버전과 선행 검증은 [브랜치 인수인계](../../인수인계/브랜치실험/behaivior/PROJECT_HANDOFF.md)를 따른다.

## 4. 구현 순서

1. **실제 입력과 소유권 정리:** 운영 생산자/시험 생산자/미연결 입력을 목록화하고 플레이어·대상·자발성·기회·원본 식별자 계약을 고정한다. 실제 확정 콘텐츠부터 연결하며 새로운 레이드 규칙·보상을 임의로 만들지 않는다.
2. **성향·목적 갱신:** 일반/레이드 활동의 근거 누적과 반대 근거, 발언/행동 분리, 중복·철회·재개·영속 복구를 연결한다. 실제 대화 추출이 불확실하면 후보를 저장하지 않고 정상 게임·대화는 계속한다.
3. **장기 처리와 본인 확인:** 부분 기록 고지, 근거 조회, 정정, 재시작, 장기 조회 비용을 검증한다. 원본 일수 삭제 없이 기존 월드 기본100GB 정책을 유지한다.
4. **관찰자 전달:** 신/NPC의 실제 인지·공개 권한 안에서만 가설을 전달한다. 같은 플레이어라도 관찰자에 따라 가설이 다를 수 있다. 실제 다인·다중 신·방 변경을 검증한다.
5. **작은 보정:** 적격 후보의 제안에만 제한적으로 연결한다. 실패·근거 부족이면 보정 없이 기존 동작으로 돌아간다. 명시적 플레이어 선택이 추론보다 우선한다.
6. **통합 검증:** 실제 행동→기록→갱신→본인 화면→권한별 입력→허용된 보정까지 확인한 뒤 적용을 검토한다. 단계별 소스/시험/운영 적용을 구분한다.

## 5. 분리된 완료 기준

- **기록·추론 합격:** 행위자/월드/대상 격리, 올바른 출처, 중복·시험 제외, 희망을 결정으로 바꾸지 않는 상태 갱신, 반대 근거·철회, 재시작·장기 한도, UI 정정을 검증한다.
- **게임 연동 합격:** NPC 보유 지식과 청중 공개 범위, 세션/revision, 적격 후보/작은 영향 상한, 선택 확인, 실패 시 기본 동작을 검증한다. 비밀 누출·오귀속 저장·무권한 실행은 작은 영향이라는 이유로 허용하지 않는다.
- **일반 대화 품질:** 한국어 화행·말투·자연스러움은 별도 결과로 보고한다. 청취 제안에 어색하게 답한 한 사례를 기록/추론 모듈의 불합격으로 세지 않는다. 다만 목적 입력을 실제 대화에 연결하는 구간은 주체/단계·비밀 보존 여부를 확인해야 한다.
- 이전 실패 결과와 시험 기대값을 지우거나 PASS로 바꾸지 않는다. 새 범위의 시험 묶음을 따로 만든다. 범위 분리는 새 합격 증거가 아니며 기존 비활성 플래그를 자동으로 켜지 않는다. 서버 배포도 하지 않는다.

이 문서의 최초 범위 분리 작업은 문서만 변경했다. 후속 사용자 승인에 따른 활동 분류 구현은 [17](17-minecraft-support-activities.md)에 별도 기록한다. 모델 설정·기존 일반 대화 실패와 서버 미배포 상태는 유지한다.

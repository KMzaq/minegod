## 접근을 바꾼 이유

이전 좁은 검사는 의사/화자/강도 등의 독립된 10개 분류를 조합했다. 실제 실패에서 ‘기억하는 사람’과 ‘기억 속 약속의 주인’, 새 제안과 과거 의사, 조건과 확정을 혼동했다. 정상 철회를 잘못 거절한 뒤 전체 대사를 재생성하면서 플레이어의 철회가 NPC 자신의 철회로 읽히는 변경도 발생했다. 이것은 단순 JSON 형식 문제가 아니다.

웹의 1차 자료에서 다음 원칙을 참고했다. 논문의 모델·과제·성능을 현재 한국어 Gemma 대화 성능으로 옮겨 주장하지 않는다.

- [RARR, ACL 2023](https://aclanthology.org/2023.acl-long.910/): 근거에 맞게 고치는 것과 원래 내용·스타일을 보존하는 것을 함께 평가한다. 여기서는 게임이 허용한 기존 근거만 사용하며, 웹 내용을 게임 사실로 가져오는 RAG를 추가하지 않는다.
- [QASemConsistency, TACL 2026](https://aclanthology.org/2026.tacl-1.6/): 술어와 논항의 작은 관계를 비교해 오류를 국소화한다. 이 구현은 논문의 QA 추출 모델을 설치하거나 그대로 재현한 것이 아니라, 같은 사람의 같은 행동을 비교한다는 설계 원칙을 적용한 실험이다.
- [Huang et al., ICLR 2024](https://arxiv.org/abs/2310.01798): 외부 피드백 없는 자기 수정이 오히려 악화될 수 있다는 결과를 참고해, 검토기 동의만으로 합격을 선언하지 않고 고정 대조·새 생성·수동 확인을 분리한다. 논문의 추론 과제가 이 RPG의 실패 원인을 입증한다는 의미는 아니다.

## 구현 계약

### 관계 단위 검사

`RoomClaimWitnessAudit`는 일반 `RoomEvidenceAudit`가 통과한 뒤 실행한다. 기존 10개 분류값을 새 자유 판정에 투표시키지 않는다. 각 대사 단위에 대해 **실제 문장의 관계 읽기 → 원문 참조 → 같은 인물·행동 비교 → 귀속/강화/반전 오류**를 출력한다. 질문·칭찬·새 제안·조건 자체를 무조건 의사 확정으로 취급하지 않는다.

게임 ID로 분리한 원문 `sourceIndex`에 실제 발화자 범주를 붙인다. 보고/인용된 행동의 주체는 발화자와 다를 수 있음을 명시한다. 관계 읽기는 영어의 구체적인 주체·행동·조건 표현으로 작성하도록 하고, 한국어의 '마음/의지'로만 압축해 종속절의 행동 확정을 놓치지 않도록 했다. 이것은 별도 번역 모델 추가가 아니다. 원문 ID는 코드가 검증하지만, ID가 유효하다는 사실이 의미 대조까지 옳다는 증명은 아니다. 판정은 여전히 확률적인 모델 결과이며 현재 자료의 모든 오류를 잡는다는 보장은 없다.

일반 검사의 실행 완료·현재 소유·과거 발언 검증은 우회하지 않는다. 오래된 전달 기록으로 현재 소유를 확정하지 않으며, 실제 게임 실행·Proposal 권한은 변경하지 않았다.

### 전체 재생성 대신 부분 수정

`RoomDialoguePatch`는 canonical 방의 의미 수정에만 적용한다. 최초 생성과 구조 수정, legacy 생성은 기존 경로를 유지한다.

1. 원래 고정 근거와 거절된 초안·지적 사항을 분리한다. 수정기는 이전 지적도 틀릴 수 있음을 알고 올바른 문장은 그대로 반환할 수 있다.
2. exact excerpt의 유일한 위치를 코드가 결정한다. 모델은 해당 슬롯의 대체 문자열만 반환한다. 중복 위치·겹친 범위·알 수 없는 슬롯·잘못된 타입은 거절한다.
3. 지적되지 않은 문자열, 다른 speech, 화자·수신자, Topic/Emotion, Proposal은 모델이 다시 작성할 수 없다. 최대3슬롯, 슬롯당 `min(480, 원래 슬롯 길이+96)`자이며 전체 구조 제한은 이후에도 검사한다. 최종 v28에서는 전체 초안 대신 고정 앞 문맥/수정 구간/고정 뒤 문맥을 분리한 infill 입력을 사용한다. 미수정 구간의24자 이상인 단위 문자열을 새로 복사해 중복 삽입하면 코드가 `PATCH_ECHOED_CONTEXT`로 차단한다. 이는 exact-copy 계약 검사이며 모든 의역 반복을 탐지한다는 뜻은 아니다.
4. 실제 변경이 있으면 **부분 수정 전후의 의미 보존 검사**를 1회 실행한다. 플레이어 철회를 NPC의 새 참여/철회로 바꾸는 것, 거절을 동의로 바꾸는 것, 열린 조건을 확정으로 바꾸는 것을 별도 비교한다. 원래 근거는 `originalEvidence` 봉투로 분리하고 수정 전·후 행동 읽기를 따로 받는다. 실제 오귀속은 원래 근거에 맞게 바로잡을 수 있다. 플레이어 원문의 1인칭을 NPC 대사에 그대로 복사하는 문제도 별도 대조에 포함한다.
5. 보존 검사 실패·통신/형식 실패는 원본 또는 수정본 PASS로 대체하지 않는다. 재수정 루프는 없다. 통과한 수정본도 원래 고정 근거로 일반+관계 검사를 다시 받는다.

부분 수정은 미수정 구간의 불변성을 코드로 보장하지만 **수정 구간의 의미 보존은 모델 검증**이다. 전자를 후자의 완전한 보장처럼 보고하지 않는다. 의미 수정 1회 예산은 유지한다. 수정 HTTP 1회 + 실제 변경 시 보존 HTTP 1회로 제한한다. 보존 검사 비용은 수정이 필요한 경우에만 추가된다.

세션/revision/근거 현재성·실제 게임 발행의 기존 검사, Secondary 공개 범위와 침묵, 자동 목적 추론 비활성을 유지한다. 게임 원장·정적 프로필·영속 포맷·공유 DTO는 바꾸지 않았다. `RoomPlayerClaimAudit`의 옛 분류기는 새 runtime 판정에 사용하지 않으며 기존 게임 출처 투영 helper만 재사용한다.

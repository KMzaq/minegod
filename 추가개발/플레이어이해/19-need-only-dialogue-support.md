# 필요할 때만 참고하는 행동·성향 지원

2026-10-20 · `behaivior` · 개발 게임1.0.35 / AI0.1.49 · 모델 `gemma4:12b` 유지 · 운영 미배포.

사용자 결정: 성향과 목표는 기록하되 평상시 대화에 넣지 않는다. 대화 기억 조회는 유지한다. 이 문서는 [18](18-native-dialogue-support.md)의 매 턴 관찰 조회·잠정 관심 꼬리표 전달 정책을 대체한다. 이전 실패 기록을 합격으로 바꾸지는 않는다.

## 기록과 사용 분리

- 원장, 분석 시작/일시정지, 본인 화면, 성향 집계, 근거 누적·목적 상태 저장은 변경하지 않는다. AFK 중립과100GB 기본 정책도 유지한다.
- 개인 목적/전체 프로필은 NPC에 자동 공개하지 않는다. 기존에 비활성인 자유 발언 목적 자동 추출·대상 매핑도 활성화하지 않는다. 구현된 저장과 미완성 자동 추출을 구분한다.
- 게임이 허용한 대화 원문 기억은 기존대로 조회한다. 실제 화자·청중·희망/결정 단계와 근거를 보존한다. 선호나 목적을 말한 과거 발언 자체를 삭제하지 않는다.
- 관찰 조회와 파생 지원 문맥은 별도다. 평상시에는 관찰 조회 자체를 생략한다. 자료를 전부 넣고 ‘자주 언급하지 마’라고만 지시하는 방식이 아니다.

## 턴 단위 선택

기존 발화 분류 호출에 선택적 `supportConsultation:{use,evidence}`를 추가한다. 별도 LLM 호출은 없다. AI 내부 힌트이며 게임 네트워크 계약·영속 스키마는 변경하지 않는다.

| use | 현재 요청 |
|---|---|
| NONE | 기본값. 잡담, 일반 지식/퀘스트 질문, 단순 대상 언급, 타인의 계획, 발언 회상, 희망 표현, 정정·거절 |
| OBSERVED_ACTION_RECALL | 이 NPC가 본 나의 행동 회상 |
| SELF_ASSESSMENT | 내 플레이 습관/관심을 명시적으로 질문 |
| PERSONALIZED_SUGGESTION | 내 활동/취향/목표에 맞는 선택지. 개인화된 퀘스트·탐사 조언 포함 |

분류 전에 관찰 자료는 불러오지 않는다. 현재 발화의 정확한 인용·허용 enum·신뢰도70 이상·LOCAL_LLM 출처를 확인한다. 인용/가정/거절/정정 해석은 차단한다. 누락·잘못된 JSON·모델 실패·빠른 잡담 경로는 NONE이다. 과거 요청을 다음 턴의 허가로 재사용하지 않는다. 분류는 오류 가능성이 있어 실제 대사 검증을 따로 수행한다.

실제 방 엔진의 NEW 및 LEGACY/SHADOW 기본 준비에서는 관찰을 생략한다. Primary 분류 뒤 필요한 경우만 `consultSupportAsync`를 호출한다. 진단용3인자 `beginRoomAsync` 호환 경로는 보존하지만 실제 엔진은 관찰 비활성 인자를 사용한다.

진단 로그의 초기 `SCOPED_MEMORY_ROUTE`는 관찰0건이 정상이다. 분류 후 실제 선택은 별도 `SUPPORT_CONSULTATION`의 use/observations/status와 생성 입력을 함께 확인한다.

## 조회·생성 경계

1. 지원 조회는 비공개·단일 신·Primary에 한한다. 분류는 게임 접근 권한을 늘리지 않는다.
2. 게임 lease로 최대1.5초 비동기 조회하고 현재 분류 가능한 최대6개 사건을 선택한다. 조회 실패는 지원 없이 계속하며 기록은 중지하지 않는다.
3. 같은 분류2건 이상이라고 `POSSIBLE_INTEREST_ONLY`를 프롬프트에 넣지 않는다. 실제 행동과 이번 요청 용도만 전달한다. 본인 화면의 성향 계산을 지운 것은 아니다.
4. 회상에는 본 행동, 추천에는 선택지를 사용한다. 수확만으로 심기·관리·애정·성실함·능숙함을 덧붙이지 않는다. 자기 평가를 물어도 관찰과 미확인 취향을 구분한다. 희망은 희망이며 타인의 계획은 타인의 것이다.
5. WATCH 근거를 생성 전 추가하고 방/턴/revision/청중·철회 검증을 유지한다. 늦은 응답을 다른 턴에 적용하지 않는다. 과거 대사의 근거 의존성도 유지한다.
6. 화제 전환 뒤에는 다시 지원 문맥을 비운다. 과거 실제 대사는 이력으로 남지만 별도 프로필 문맥을 지속 주입하지 않는다.

보상·가격·관계·난이도·퀘스트 자동 변경은 없다. 추천 필요 분류가 비공개 목적 우회 조회나 없는 콘텐츠 확정을 허용하지 않는다. 기존 게임 권한과 목적 자동 추출 비활성 상태를 유지한다.

## 0.1.49 — 행동 범위와 재작성

선택된 사건은 넓은 농사/채집 성향 꼬리표 대신 정확한 행동 코드·대상·결과와 `literalMeaning`으로 제공한다. 같은 선택 사건의 `observedActionBoundary`는 확인된 동작/행위자/관찰자와 미확인인 준비·돌봄·감정·취향을 구분한 AI 내부 표현이다. 새로운 근거를 만들거나 저장·접근 권한을 변경하지 않는다. 관찰 자료가 없는 평상시에는 이 필드도 없다. 생성과 검토는 같은 자료를 읽는다.

관찰 자료가 있는 턴에서 의미 검토에 실패하면, 과장 초안을 계속 부분 수정하지 않고 원래 질문·고정된 출처 장면에서 대사를 재작성한다. 같은 과장을 `UNSUPPORTED_FACT` 또는 `CONTEXT_CONTRADICTION`으로 다르게 부르는 모델 오류가 있어, 분기는 오류 이름이 아닌 구조화된 관찰 자료의 유무로 결정한다. 거절된 초안과 검토 의견은 새 사실로 넣지 않는다. 별도 간결한 재작성 지침은 NPC의 정체성/관계/감정과 허용 자료를 유지한다. 출력은 대사 본문뿐이며 원래 화자·청중·제안·topic/emotion 메타데이터를 코드로 보존한다. 재작성도 기존 전체 근거 검토를 통과해야 발행되고, 기존 한 번 수정 한도·게임의 턴/출처 재검증은 유지한다. 관찰을 참고하지 않은 일반 턴은 기존 제한적 수정 경로를 유지한다. 고정 답변이나 과장 단어 치환 방식이 아니다.

일반 생성의 `done_reason=length`는 완성된 대사가 아닌 것으로 처리한다. 정상 첫 요청의 토큰 설정은 유지하고, 길이 종료가 확인된 경우만 한 번 재시도 예산을 최대1024 안에서 늘린다(현재260→520). 잘린 JSON을 수선해 발행하지 않으며 재실패는 거절한다. 관찰 전용 재작성은512토큰 이상으로 완결된 짧은 응답을 요청하고 다시 잘리면 발행하지 않는다. 모델/운영 설정은 변경하지 않는다.

## 검증

계약 단위 검사, 전체 AI build/check, 실제 방·SQLite·발행 격리 GameTest, 동일 모델 실제 생성/검토·수정문을 구분한다. 이름/희망/타인 계획 재조회, 실제 수확 후 잡담·타인 선호·일반 도구 질문에는 지원 없음, 본인 평가/개인화 추천만 지원 있음, 화제 전환/정정 뒤 다시 없음, 공개방 차단을 검사한다. 분류 입력에도 관찰 자료가 없어야 한다.

결과와 실패는 [검증 보고서](../../검토결과/need-only-support-20261020/REVIEW.md)에 남긴다. 이전 그래픽 검증을 이번 변경의 새 그래픽 검증으로 재사용하지 않는다. 전체 검증 전 서버 배포 금지를 유지한다.

# Minecraft 활동 분류와 AFK 중립 정책

2026-10-19 · `behaivior` · 게임 개발1.0.33 · 미배포. [16 — 담당 범위](16-behavior-system-scope.md)의 첫 단계인 실제 활동 입력·본인 확인을 확장한다. 일반 대화 품질 실험과 모델 설정은 변경하지 않는다.

## 사용자 결정과 안전 원칙

- ‘잠수’는 물속 활동이 아니라 **AFK**다. AFK는 성향이 아닌 현재 상태 안내다.
- AFK 시간·접속 공백·활동 부재를 감점, 무성의/회피 등의 인격 판단, 목적 포기, 추천 불이익에 쓰지 않는다. 활동 비율의 분모로도 사용하지 않는다.
- 낚시·메뉴 대기, 수면을 AFK라고 단정하지 않는다. 서버가 보는 활동 신호는 사람의 실제 이석 여부를 보장하지 않으므로 표시도 ‘추정’이다.
- 도움을 위한 관측이며 단순 반복을 선호·실력·동기로 확정하지 않는다. 동료 따라가기, 의무 수행, 반복 설치/철거 등의 자발성은 아직 구별하지 못한다.
- 기록이 없거나 실패해도 게임을 방해하지 않는다. 자동 보상·벌점·관계·가격·난이도 변경은 없다. 기존 게임의 별도 AFK/알림 정책 전체를 변경한 것은 아니다.

## 입력과 분류

| 표시 | 실제 입력 | 해석의 한계 |
|---|---|---|
| AFK | 기존 `PlayerActivityService`의 현재 IDLE, 수면/낚시/메뉴 상태 보완 | 본인 화면 안내만 사용. 새 활동 원장·성향 카드·NPC 입력에는 넣지 않음 |
| 탐사 | 같은 차원에서 활동 토큰 변화와 함께 관측한 바이옴 변경 | 이동 원인·자발적 탐사 미확인. 같은 바이옴 탐사는 아직 못 셈. 탑승/수면·차원 이동·초기 표본 제외 |
| 농사 | 실제 성숙 작물 제거, 실제 작물 설치 | 바닐라 밀/당근/감자/사탕무/네더 사마귀/코코아. 덜 자란 작물 제거는 수확·채굴로 세지 않음. 수확은 아이템 획득 증명이 아님 |
| 낚시 | 바닐라 `FISH_CAUGHT` 통계 증가 | 낚시 대기 시간과 어획 선호를 구별. 이전 통계 소급 없음 |
| 건축 | 사용 결과가 성공하고 실제 블록 상태가 남은 설치 | 건축 완성도·소유권·선호를 의미하지 않음 |
| 레이드 | 기존 참가 명단/결과, 개인 기믹 선택 원장 | 승패는 개인 실력 평가가 아님. 시험 레이드 제외. 정식 콘텐츠의 선택 생산자 추가는 별도 |
| 퀘스트 진행 | 기존 완료·상태 전환 원장 | 진행 사실이며 선호/보상 수령 증명이 아님 |
| 휴식 | 바닐라 `SLEEP_IN_BED` 통계 증가 | 수면 행동만 확인. 가만히 서 있음을 휴식으로 추정하지 않음 |
| 채집·채굴 | 실제 비작물 블록 제거 | 설치물 철거/자원 채굴의 세부 의미는 아직 구별 못 함 |
| 제작·정비 | 제작 이벤트의 결과 수량 | 제작 결과 수령만 관측. 모든 정비/자동 생산을 포괄하지 않음 |
| 일반 전투 | 사망 확정 후 게임이 식별한 책임 플레이어의 처치 | 전투 전술·역할·인격 평가는 아님 |

새 생산자는 `MinecraftActivityCapture`, 값 계약은 `ActivityEvidence`. 기존 블록 제거/설치/사망 확정 후크를 재사용하고 서버 통계는 20tick마다 표본화한다. 움직임 감지 시스템을 별도로 복제하지 않는다.

## 기록·동의·격리 계약

1. 기존 행동 원장이 READY이고 본인이 `/mythprofile`에서 **분석 시작**을 저장한 후에만 새 활동을 수집한다. 기록 설정을 자동으로 켜지 않는다. 일반 상세 진단의 ON/OFF와 별개인 본인 분석용 압축 기록이다.
2. `PLAYER_ACTIVITY_FACT`는 기존 원장의 신규 타입이다. `signal/count/first_tick/last_tick`만 허용하며 AFK/벌점 필드는 거절한다. 원본 UUID·월드·플레이어·capture session은 게임이 정한다. 다른 플레이어 participant는 허용하지 않는다.
3. 플레이어·신호별 최대 9개 버퍼로 합치고 최대 200tick마다 기존 비동기 writer에 제출한다. 차원이 바뀐 관측은 같은 묶음에 섞지 않는다. 화면 갱신·중지·로그아웃·정상 종료 때 마지막 통계와 버퍼를 제출한다. 서버 강제 종료 시 미제출 최대 약200tick은 유실될 수 있다. 디스크 확인 전 내구 저장 완료로 표시하지 않는다.
4. 중지 저장 이후 수집하지 않으며 늦게 돌아온 과거 START 결과로 재활성화하지 않는다. 재접속 시 저장된 동의를 조회하고 통계를 새로 기준 잡는다. 이전 테스트 통계나 오프라인 증가를 소급하지 않는다.
5. 새 기록은 `admin_only_unprojected`이며 본인 화면만 사용한다. 신별 복제/암묵적 목격/소문 전환은 없다. 창작·관전자와 알려진 `mythictrpg:raid_trial` 시험 차원은 새 수집에서 제외하고 과거 시험 차원 원본도 분석에서 제외한다. 별도 모드의 임의 시험 공간을 자동 탐지하는 기능은 아니다.
6. 새 압축 기록에는 목적 대상·자발성 정보가 없다. `PurposeLedger`는 이를 만남/탐사 목적의 원본으로 사용하는 것을 거절한다. ‘건축을 많이 함 → 특정 신을 만나기로 결정함’ 같은 비약을 만들지 않는다.
7. 같은 세션/차원/행위자/구간의 기존 상세 진단과 압축 기록을 본인 집계에서 중복 세지 않는다. 기존 원본을 삭제·덮어쓰지 않는다. 월드 기본100GB 및 일수 삭제 없음 정책을 그대로 쓴다.

## AFK가 간접 불이익이 되지 않도록

- 최근400개 조회를 전체 원장이 아닌 **관련 활동 색인**으로 바꾼다. 변화 없는 위치 표본이나 미참여 기록 수천 개가 유효한 활동을 화면 밖으로 밀어내지 못한다.
- 레이드 선택 카드는 실제 `CHOSEN`만 사용한다. `NOT_CHOSEN/UNAVAILABLE/CANCELLED`는 점수·비율의 분모가 아니다. 같은 선택의 취소/정정은 기존의 잘못된 긍정 사실만 제거하며 새로운 부정 성향으로 해석하지 않는다.
- 플레이어가 다른 활동을 해서 최근 관측 범위가 바뀌는 것과, AFK 시간이 흘러 평가가 나빠지는 것은 구별한다. 현재 활동/목적 reducer에 AFK 시간에 따른 감쇠를 추가하지 않는다.
- 반복 관측은 선호 미확정이다. 활동량은 횟수/수량이며 플레이 시간의 백분율이 아니다. 본인 이의 제기·목적 철회와 기존 화면/비동기 격리 계약은 유지한다.

## 호환성과 남은 작업

게임1.0.33에 새 원장 enum이 추가된다. 기존 기록 읽기는 유지하지만 새 타입이 저장된 월드를 구 JAR로 롤백해도 안전하다고 가정하지 않는다. 본인 화면의 기존 codec/최대16카드/실행 Proposal은 변경하지 않았다. 늘어난 활동 카드 때문에 여러 목적을 동시에 충분히 보는 페이지 처리는 여전히 필요하다.

이번 단계는 활동 관측과 안전한 본인 분석의 확장이지 전체 시스템 완료가 아니다. 실제 대화 원문→주체/희망 단계가 보존된 목적 주석, 콘텐츠별 자발적 대상 선택, 장기 페이지 처리, 관찰자·청중별 권한 어댑터, 적격 후보 제안 우선순위 보정, 실제 클라이언트 화면/인게임 통합 확인은 남는다. 현재 모델과 기존 목적 대화 비활성 플래그는 유지하며 서버에 배포하지 않는다.

검증 실행별 결과는 [브랜치 인수인계](../../인수인계/브랜치실험/behaivior/PROJECT_HANDOFF.md)의 활동 지원 후속 절을 따른다. 이전 일반 대화 실패를 이번 테스트 결과로 합격 처리하지 않는다.

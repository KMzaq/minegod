# 발화 주체·의사 강도 경계 검증

이 문서는 **v8 / AI 0.1.39 당시 기록**이다. 현재 후속 후보·실패·미배포 상태는 [11](11-hope-and-rejection-followup.md)을 먼저 읽는다.

2026-10-18, HanesTest. 개발 게임 1.0.31 / AI 0.1.39. [09](09-current-model.md)의 대사 귀속·희망 과장 문제에 대한 후속이다. 현재 `gemma4:12b`만 사용한다. 운영 설정·서버 JAR·월드·프로필은 변경하지 않는다. **자동 목적 추출 `PlayerIntentPlan.ENABLED=false`는 유지한다.** 이번 변경은 대사 생성·검토 경로이며 목적 영속화나 전체 플레이어 이해 시스템의 완성이 아니다.

## 변경 경로

1. `RoomSpeakerAttribution`은 게임이 전달한 role·speakerId를 사용해 각 발화의 `utteranceOwner`를 표기한다. 현재 질문자, 타 플레이어, 응답 신, 다른 신의 말을 구분한다. 이름이 같아도 ID가 다르면 합치지 않는다. 이 필드는 프롬프트 전용이며 원본 대화/원장 형식을 변경하지 않는다.
2. 발화자가 다른 사람의 바람을 전하는 경우와 본인이 새로 동의/결정한 경우를 구분하도록 생성 정책을 보완했다. 희망을 결정으로 강화하지 않되, 명시적 결정·수락·약속을 일괄 미정으로 낮추지 않는다. 보조 반응의 상대가 다른 신일 수 있다는 점도 유지한다.
3. canonical 주/보조 대사에는 `SPEAKER_AND_COMMITMENT_BOUNDARY` 검토 사유를 부여한다. 기존 위험 단어나 Proposal이 없는 평범한 희망 표현도 검토한다. 허용된 보조 침묵은 계속 침묵으로 통과한다.
4. 기존 `RoomEvidenceAudit` V7의 일반 사실·실행·출처 검토는 유지한다. 이 검토가 PASS일 때만 같은 모델로 `RoomPlayerClaimAudit`를 실행한다. canonical 장면이 없는 legacy 검토에는 두 번째 검사를 덧붙이지 않는다.
5. 두 번째 검사는 이미 공개 허용된 원래 장면만 사용한다. 질문자의 발화, 응답 신의 과거 발화, 다른 참여자의 발화를 ID로 나누고 원래 순번을 보존한다. Primary에는 현재 입력을 별도로 포함하고, Secondary에는 실제 전달된 발화만 포함한다. 원본 DB·미참가자·미공개 기억을 새로 조회하지 않는다.
6. 각 대사 구간 전체를 먼저 `draftText`로 정확히 복사하도록 스키마로 제한하고, 짧은 출처 대비와 발화 종류(`claimForm`), 확실성(`certainty`), 원문/대사의 주체·의사 강도, `subjectReference`, `attribution`을 얻는다. 기존 의사를 주장한 대목의 주체가 원문과 다르면 코드에서 `WRONG_SOURCE`가 된다. 원문이 `COMMITTED`가 아닌데 결정·수락을 전제하거나 행동 의향이 확인됐다고 단정하면 `CONTEXT_CONTRADICTION`이다. 단, 목적/이유의 조심스러운 추측은 확정으로 취급하지 않는다. 별도 attribution의 `WRONG_SUBJECT`도 거절한다. 모델이 SUPPORTED라고 적어도 typed 비교를 건너뛰지 않는다. 질문 속 확정 전제와 열어 둔 확인 질문도 구분한다.
7. 수정은 기존 구조/의미 공용 예산 내 최대 1회다. 수정 대사는 원래 근거로 새로 검토하며, 폐기 초안·수정 지시를 기억이나 사실 근거로 승격하지 않는다. 두 번째 검사 실패·잘못된 JSON·누락 구간·HTTP 오류도 첫 검사 PASS로 대체하지 않고 발행을 막는다. 기존 세션/revision/기억 lease 재확인을 유지한다.

### 내부 의사 분류

| 원문 `sourceModality` | 뜻 |
|---|---|
| DESIRE | 희망·소망·관심. 의지가 있다는 이유만으로 결정은 아님 |
| POSSIBILITY | 조건부 가능성 |
| UNDECIDED / UNACCEPTED | 미결정 / 미수락 |
| WITHDRAWN | 기존 의사 철회 |
| COMMITTED | 결정·수락 또는 자신이 하겠다고 명시한 의향·약속. 실행 완료와 다름 |
| NONE | 해당 의사 근거 없음 또는 적용 대상 아님 |

대사 쪽에는 같은 의사 상태 외에 `WILL_ACT_CONFIRMED`(앞으로 그 행동을 하겠다고 밝혔음/할 예정임을 확인하는 주장), `TENTATIVE_INTENT`(목적/이유 추측), `NEW_SELF_INTENTION`이 있다. 바람을 들었다는 사실의 확인은 DESIRE이며 행동 계획의 확인과 다르다. 철회를 인정하는 말을 결심으로 뭉뚱그리지 않도록 WITHDRAWN을 유지한다. `claimForm`은 기존 의사/발언에 관한 주장, 신 자신의 새 입장, 의사 주장 없음으로 분리한다. 신이 지금 새 제안·거절·취향을 말할 때는 원문에서 과거 결정의 근거를 요구하지 않는다. 타인의 의사를 신 자신의 새 표현으로 분류한 결과는 이 예외를 적용하지 않고 주체/강도를 비교한다. 신 자신의 **과거** 약속을 회상할 때는 실제 출처와 당시 의사를 검토한다.

`certainty`는 단정/조심스러운 추측·조건/주장 없음이다. 명시적 결정·수락을 전제한 COMMITTED는 완곡한 어미만으로 허용되지 않는다. WILL_ACT_CONFIRMED는 목적 추측으로 표현됐는지를 함께 확인한다. '주장 없음'이라는 포괄 라벨이 구체적인 COMMITTED 분류를 지울 수 없게 코드에서 보수적으로 집계한다. 정상 추측·신의 새 거절을 차단했던 중간 회귀를 이 구분으로 검증한다.

`subjectReference`는 상대방/응답 신 자신/이름으로 지정한 사람·제삼자/해당 없음이다. 의사 귀속이 실제로 있는 구간의 상대방 지시는 게임 장면의 `defaultAddresseeSubject`로 해석한다. Primary의 기본 상대는 현재 질문자이며 Secondary는 마지막 실제 전달된 발화자다. 타인의 말에서 가져온 1인칭 주체를 대사의 '너'에 재사용하지 않는다. 이름으로 직접 지정한 대상은 덮어쓰지 않고, 주체·의사 주장이 없는 열린 조건문에 '당신'이 등장했다는 이유만으로 의사를 새로 귀속하지 않는다. 전체 구간을 정확히 복사하는 단계는 긴 질문의 소유주·조건을 생략해 다른 문장으로 검사하는 오류를 줄이기 위한 것이다.

주체 분류는 질문자/응답 신/타인/해당 없음의 문맥 내 역할이다. 새 게임 identity나 별도 플레이어 DB를 만드는 것이 아니다. 타인 두 사람 사이의 세밀한 오귀속은 이 역할 비교만으로는 구별되지 않으므로 기존 일반/attribution 검사에 계속 의존한다. 발화자와 인용문 속 인물의 구분 자체는 여전히 모델이 분류한다.

분류와 sourceComparison은 비권위 검토 자료다. 게임 동의·퀘스트 수락·보상·관계를 변경하지 않으며 프로필/기억에 자동 저장하지 않는다. 최종 Review 계약은 그대로이고 두 번째 내부 JSON 스키마만 추가됐다. 모델 응답의 모든 구간과 필드/enum/길이를 검사하며 초안 인용은 원래 unit에서 코드가 가져온다. 수정 안내도 typed 결과와 출처 대비로 코드가 만들며 200자 상한이다. 모델이 별도 종합 verdict나 모순된 correction을 덧붙여 판정을 바꾸지 못한다.

### 당시 개발 후보: v8 (보수적 검토, 완전 해결 아님)

남은 과잉거절에는 [두 주체가 함께 있는 정상 문장](../../검토결과/player-understanding-20261018/claim-final-v8-audit/report-and-self-good.json)이 있다. “친구는 배를 타고, 너는 집에서 책을 읽을 생각이군”을 한 구간의 단일 주체 쌍으로 검사하면서 서로 다른 두 의사를 혼합했다. 일반 대화의 1회 수정 경로로 보내질 수 있으나, 이것을 의미 검토의 정상 판정으로 계산하지 않는다. 따라서 두 오류의 고정 재현 개선과 별개로 **모든 복합 대화에서 정확한 주체/의사 해석을 보장하지 않는다.**

일반 회귀의 과잉거절은 `control_fresh_receipt_immediate_acknowledgement`(게임이 확인한 전달 완료를 의사 주장으로 잘못 집계), `control_wait_request_correct_actor`(실제로 했던 부탁의 회상을 결정으로 분류)다. `quoted-wish-good`는 `sourceComparison` 문자열의 잘못된 이스케이프 등 JSON 형식 오류로 실패해 출력이 차단됐다. 후속 원문 확인에서 `done_reason=stop`, `eval_count=217`이므로 토큰 상한으로 잘렸다고 단정하지 않는다. v7 복원 시험의 새 초대/발언 제안 과잉거절 두 건은 코드의 의사 주체 존재 조건을 고쳐 v8에서 정상 통과했다. 나머지를 완료로 숨기지 않는다.

고정 대사 표의 묶음은 서로 중복된 사례를 포함하며 독립 플레이 세션 수나 일반 정확도가 아니다. 46개·28개·14개는 개발 중 재사용한 회귀다. 추가 11개는 v8 실행에서 처음 평가했지만, 적은 합성 표본의 단회 결과다. 모든 실제 호출은 `gemma4:12b`, `think=false`이며 운영 모델 설정을 바꾸지 않았다.

**실제 생성 최종 확인:** 기본/친밀/경계 관계 8장면씩 총 24건이 자동 검토를 통과했지만, [수동 검토](../../검토결과/player-understanding-20261018/claim-final-v8-manual-review.md)에서 기본 관계 `wish`의 1회 수정 후에도 “찾아가기로 한 마음”이라는 선택 전제가 남은 것을 확인했다. 재검토가 PASS였으므로 **희망→결정 오류는 아직 완전히 해결되지 않았다.** 친밀 관계의 최신 본인 선택 과잉거절과 추측 회피도 남는다. 타인의 계획을 질문자의 확정 계획으로 돌린 명확한 최종 대사는 이번 24건에서 발견하지 않았지만 일반적인 해결 보장은 아니다. `publishable=24/24`를 완료 또는 자연스러움 합격으로 쓰지 않는다.

### 이전 v4 기록 — 최종 합격으로 쓰지 않음

아래는 **중간 후보 `claim-final-v4`**의 고정 대사 판정 결과다. 실제 생성의 수동 확인에서 긴 질문에 포함된 타인 계획의 귀속과 '결정' 단어 없는 희망 강화가 추가로 발견돼 **최종 합격으로 채택하지 않았다.** 이후 결과는 위 v8을 따른다. 빌드 성공과 의미 판정 성공은 별도이며 평가 도구는 판정 불일치/검사 실패가 있으면 결과를 보존한 뒤 실패 종료한다.

합계 **85개 고정 대사의 허용/수정 예상 판정**을 확인했다. 85명의 플레이어나 85개 독립 실제 플레이 세션이 아니다. 46개와 기존 28개는 개발 중 재사용한 회귀다. 11개는 v4 측정 당시 신규였지만 이후 생성 실패를 보완했으므로 다음 후보에서는 재사용 회귀로 분류한다. 일반 V7의 시스템 정책은 최초 재현 요청과 v4 요청을 문자열로 대조해 동일함을 확인했다.

v4 핵심 반복 13/13과 생성 24/24 자동 발행 후보 확보는 의미 품질 합격이 아니었다. [친밀 관계 foreign](../../검토결과/player-understanding-20261018/claim-final-v4-generated-warm/foreign.json)은 타인의 계획을 질문자의 결심으로 전제한 긴 질문이 1회 수정 후에도 남았고 재검토가 PASS였다. [경계 관계 wish](../../검토결과/player-understanding-20261018/claim-final-v4-generated-guarded/wish.json)는 희망을 '가서 묻겠다는 의지가 확인됨'으로 높였지만 PASS였다. 반면 [기본 관계 wish](../../검토결과/player-understanding-20261018/claim-final-v4-generated-baseline/wish.json)는 결정 과장을 실제 검토가 잡고 희망 표현으로 수정했다. 자동 지표만으로 완료 처리하지 않았으며 두 잔여 사례를 별도 `audit-produced` 회귀로 고정했다.

검토 HTTP 요청은 각각 79/46/17회로 모두 `gemma4:12b`다. 대비 46개는 검토 구간당 모델 시간 평균 약 2.84초, 일반 28개는 전체 검토 평균 약 4.15초였다. 서로 다른 코호트의 단회 측정이며 속도 향상이나 운영 지연 보장이 아니다. 전자는 개발 GameTest와 짧게 병행한 구간도 포함한다.

개발 통합 GameTest는 **최종 v8에서도 1/1(9 시나리오)** 통과했다. 수정 후 허용, 반복 거절, 통신 실패, 잘못된 초안 인용, 퇴장으로 무효화된 방, 구조 수정 후 허용/거절, 보조 신 수정, 위험 키워드 없는 희망→결정 수정의 실제 게임 발행 경로를 검사했다. [최종 격리 로그](../../mythictrpg-main/build/player-claim-guard-20261018-v8/logs/latest.log)에 정상 저장·종료까지 기록돼 있다. 새 격리 폴더의 최초 `server.properties` 없음 로그 후 정상으로 시험을 완료했다. 소켓 없는 모의 LLM을 사용하므로 실모델 품질이나 실제 UI 조작의 증거가 아니다. 이 개발 fixture의 초기 기본 모델명 로그는 실제 모델 호출을 뜻하지 않는다. 백그라운드 모델 작업 OFF를 확인하고 fixture에서 클라이언트를 대체했다.

## 비용·한계·다음 작업

- 일반 검토 1회, 그 결과가 PASS이고 canonical 장면이면 전용 검토 1회를 추가한다. 최대 1회 수정 후에도 같은 검토를 수행하므로 의미 검토 HTTP 호출은 한 턴 최대 4회다. 생성기의 기존 파싱 재시도는 별도다.
- 전용 검토는 temperature 0, 출력 예산 `min(8192, max(1024, 192 + 512 × 구간수))`, HTTP 요청당 기존 설정과 60초 중 작은 제한을 사용한다. 대사/원문을 비동기로 처리하며 게임 tick에서 LLM을 기다리지 않는다.
- 추가 검토로 응답 지연·출력 차단 가능성이 늘어난다. 같은 모델에 의존하므로 주체·의사 분류 자체가 틀릴 가능성은 남는다. 작은 합성 대비 사례의 통과를 일반 정확도, 전체 자연스러움, 실제 플레이 만족도로 확대하지 않는다.
- 현재 실제 생성 실패와 과잉거절이 남으므로, 다음은 주장 자체와 조건/추측의 구분, 기존 의사와 실행 사실/부탁 회상의 구분, 최신 본인 선택 반영을 보완하고 새 표현·실제 생성으로 다시 확인하는 일이다. 이 조건을 충족하기 전 완료·운영 적용으로 승격하지 않는다.
- 전체 목적 추출·자동 영속화·변화/철회 상태 누적·관찰자별 장기 연결·콘텐츠 추천은 여전히 별도 미완료다. 이번 대사 가드를 통과했다고 자동 활성화하지 않는다.
- 운영 배포·서버 부팅·실제 클라이언트 조작/대화 검증은 이번 요청에서 수행하지 않는다. 연동/대화 검증/릴리스 절차에 따라 출처·공개 범위·게임 권한을 유지하고 개발 검증과 운영 확인을 구분한다.

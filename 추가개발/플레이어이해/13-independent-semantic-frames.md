# 독립 의미 해석과 주체·강도 고정 비교

2026-10-19, HanesTest. `gemma4:12b` 유지. **독립 해석 후보는 일반 회귀 악화로 기본 경로에서 제외했다. 전체 품질 gate 실패·미배포다.** 기본 경로는 이전 일반 V7 + 관계 V6 검사를 유지하고, 수정 과정의 직접적인 1인칭 복사 차단만 추가한다. 운영 파일·설정·모델·월드는 변경하지 않으며 자동 목적 추론은 비활성이다.

## 조사와 적용 가설

- [NAACL 2024 — Exploring the Factual Consistency in Dialogue Comprehension of Large Language Models](https://aclanthology.org/2024.naacl-long.338/): 당시 ChatGPT/GPT-4, Vicuna, LLaMA2, Mistral 등을 대상으로 대화 주체·대상, 대명사, 후속 정정, 의사 해석 오류를 분석했다. 현재 Gemma나 최신 모델의 오류율로 일반화하지 않는다. 논문의 학습 방법은 이번 작업에 적용하지 않았다.
- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs): 스키마 일치가 내용의 의미 정확성을 보장하지 않으며, 단순한 하위 작업으로 나누는 방법을 안내한다. 이번 후보는 형식 강제만 늘리지 않고 원문/초안 읽기를 분리한다.
- [OpenAI CriticGPT, 2024-06-27](https://openai.com/index/finding-gpt4s-mistakes-with-gpt-4/): 오류 검토용 학습과 사람의 검토 보조를 연구했으며, 검토 모델의 허위 문제 지적과 탐지율 사이의 trade-off도 보고했다. 코드 검토 연구이지 한국어 RPG 대화 해결법의 검증은 아니다. 별도 모델·학습·API는 사용하지 않았다.
- [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices): 실제 사용 사례, 경계·적대 사례, 판정 기준과 사람 검토를 함께 유지하도록 안내한다. 여기서는 사전 고정 기대값과 에이전트의 대사 직접 확인을 병행한다. 사용자/독립 인간 평가를 실시한 것으로 표현하지 않는다.
- [Ollama Structured outputs](https://docs.ollama.com/capabilities/structured-outputs): `format` 외에 프롬프트에도 스키마를 제시하도록 안내한다. 마지막 실험 코드에는 반영했으나 이 마지막 보완의 실모델 효과는 측정하지 않았다. 설치 상태는 Ollama0.32.15 / Gemma4 11.9B Q4_K_M이다. 다른 모델 다운로드·교체·유료 API는 사용하지 않았다.

Ollama의 공개 이슈에도 reasoning/structured output 불일치와 출력 순서 관련 보고가 있지만, 이번 native `/api/chat`의 원인이 해당 버그라고 입증하지 못했다. 스키마 속성 순서 등은 후속 통제 실험의 변수일 뿐 확정 원인으로 기록하지 않는다. OpenAI가 이번 한국어 RPG 문제를 이미 해결했다고 주장하지 않는다.

이번 프로젝트의 과잉거절은 유해 요청 거절이 아니라 **잘못된 근거 불일치 판정**이다. 안전 정책의 refusal을 완화하는 작업과 구분한다.

## 원인과 후보 구조

v29는 시간순 출처 인덱스, 현재 입력의 화자 ID, 초안 1·2인칭의 게임 바인딩을 제공했다. v30은 NPC 초안을 보여 주지 않는 원문 읽기를 추가했다. 그러나 검사 모델은 `OTHER의 계획`과 `QUESTIONER에게 묻는 선택`을 설명하고도 정상이라고 판정했고, 원문의 희망에 맞춰 초안의 확정 표현을 희망으로 낮춰 읽기도 했다.

v31/32는 비교한 주체와 의사 강도를 코드로 대조했지만, 두 값을 같은 문맥에서 추출하면 여전히 서로 맞추는 오류가 발생했다. v33~35는 다음 순서를 실험했다. 아래는 **기본 운영 경로가 아닌 평가 전용 후보**다.

1. `RoomSourceReading`: **초안 없이** 원문 발언을 읽고, 발언별 복수 행동의 주체·행동·상태를 추출한다. `UTTERANCE_SPEAKER`의 실제 ID는 코드가 원문 화자로 결속한다. 남의 말을 전한 경우는 별개 주체다.
2. `RoomDraftReading`: **원문 없이** 초안 자체가 말하는 주체·행동 강도와 질문 속 전제를 읽는다. 게임의 화자/기본 수신자 정보와 초안 이웃 문장만 제공한다.
3. 기존 일반 검토: 게임 실행·사실·출처·문맥 검사를 계속 수행한다. 원문 읽기는 오류 가능한 보조 해석이며 사실 권한을 갖지 않는다.
4. 관계 비교: 같은 행동의 원문 claim ID를 선택한다. 초안 해석은 단일 enum으로 고정하고, 원문 주체/상태는 선택한 원문 claim에서 코드가 가져온다. 검사자가 원문 화자나 상태를 다시 쓰지 못한다. 주체 불일치와 희망/미정→결정은 코드가 집계한다.

모델의 읽기·행동 대응 자체는 틀릴 수 있으므로 무오류 보장이 아니다. `CURRENT_NPC_EXPRESSION`은 NPC의 현재 제안/거절이지 과거 플레이어의 계획이 아니므로 별개로 취급한다. 인용·복수 주체·생략·조건 범위의 정확도는 실제 모델 검증 대상이다.

해석은 요청 내부의 진단 데이터다. 원장·기억·성향·게임 상태에 저장하지 않는다. 기존 audience projection, stale/revision 검증, 원래 근거 고정, 최대 1회 의미 수정, 슬롯 밖 보존과 중복 삽입 차단을 유지한다. 손상 응답/알 수 없는 claim/고정 초안 해석의 변경/HTTP 실패는 PASS로 복구하지 않는다. 실험은 canonical 검토 최대 4회 순차 HTTP(각 최대60초), 기본 경로는 최대2회다. 실험의 원문/초안 해석 결과도 사실이 아니므로 코드로 강제 비교하더라도 의미 정확성이 보장되지 않는다.

평가 하네스에서만 `-PindependentFrameEvaluation=true`로 후보를 선택할 수 있다. 게임 측은 인자 없는 `LocalOllamaClient()`를 사용하며 시스템 속성이나 플레이어 입력으로 후보를 켤 수 없다. 인자 없는 생성자의 2회 호출 상한과 기본 정책·스키마·파서 일치는 과거77개 wire 기록 및 가짜 HTTP로 검사한다. `BaselineRoomClaimWitnessAudit`가 이전V6 계약을 보존한다.

일반 회귀 악화의 구체적인 원인:

- 독립 원문 추출이 대화 기록/current text만 인덱싱해 `actuallyHeardMemory`에 있는 약속을 빠뜨린다. 원문 claim 없음이 실제 근거 없음으로 잘못 승격된다.
- 초안만 읽을 때 과거 부탁의 발생, 현재 거절, 타인의 희망을 결정으로 오독한다. 의미 상태를 강제로 묶으면 이 잘못된 해석을 확정하게 된다.
- '의지는 확인했다'처럼 명사보다 내포절이 중요한 표현은 여전히 희망/확정 경계를 틀린다. 문법 예시를 늘리는 것만으로 안정적인 개선은 관찰하지 못했다.

이 후보들의 실패를 다른 판정으로 덮거나 정답을 바꾸지 않았다. v27 실제 초안4개 재생과 새 상황8쌍도 하네스에 추가했으며 실행 여부는 아래 최종 검증 기록을 따른다.

## 기본 경로에 남긴 제한적인 보완

`RoomDialoguePatch` V5는 새 수정문이 플레이어 출처의 1인칭 문장(예: '나는 쉬고 싶어.')을 **인용 없이 그대로 NPC의 새 발화로 복사**하면 `PATCH_COPIED_PLAYER_DEIXIS`로 차단한다. 출처의 실제 역할, 문장 일치, 수정 전후 차이를 검사한다. 명시적 인용과 이미 있던 동일 NPC 문장은 유지하며 자동 치환하지 않는다. 닫히지 않은 따옴표로 검사를 피할 수 없게 한다. 추가 모델 호출이나 수정 재시도는 없다.

이는 정확히 복사된 한국어 1인칭 일부 형태를 다루는 출처 검사다. 생략·바꿔말하기·내포절의 의미를 보장하는 범용 주체 판별기가 아니다. 새 NPC 관여가 추가됐는지 판단하는 의미 보존 검사와 마지막 일반/관계 검사는 여전히 필요하며, 이번 보완만으로 타인 오귀속·희망 과장이 해결됐다고 하지 않는다.

## 검증 기록과 남은 조건

최종 기본 경로와 실험 경로의 결과를 섞지 않는다. 고정 회귀, 실제 새 생성/수정, 에이전트 직접 검토, 오프라인/격리 통합 검증은 별개다. 자동 publishable은 실제 서버 발행이나 의미 합격이 아니다. 전체 통과 전이며 운영 배포·인게임 확인은 하지 않았다. 최종 실행 숫자와 대사별 판단은 이 폴더의 후속 검증 보고와 함께 기록한다.

기본 경로 v36: 고정74/77(오허용1·과잉거절2), 일반27/28(과잉거절1·코드 불일치1), 보존 대조14/14(모델13+직접 복사 구조차단1), 실제 수정6/7 자동 통과. 새 상황8+친밀 관계8의 자동16/16과 별개로 직접 검토에서는 타인 계획 오귀속과 정상 초안 과잉거절에 따른 자기 선택→NPC 지시 변화가 남았다. AI0.1.43 전체 build/check·패키지523클래스 검증은 통과했지만 의미 gate 실패다. 최신 GameTest/서버/UI는 미실행이다. [대사별 검토·최종 실행 기록·해시·미검증 범위](../../검토결과/player-understanding-20261019/claim-v29-v36-manual-review.md)를 따른다.

후속 설계는 누락 없는 **권한 투영된 전체 근거**(대화·청취/자기 기억·게임 사실)와 행동별 시간/긍정·부정/조건을 먼저 다뤄야 한다. '추출 못함'과 '원문이 부정함'을 같은 상태로 처리하지 않아야 한다. 검토 모델의 근거 없는 REVISE를 줄이는 것과 잘못된 PASS를 줄이는 것을 동시에 검증해야 하며, 새 모델 도입 또는 자동 추론 활성화는 이번 범위가 아니다.

# 실제 대화 경로의 Native 기억·관찰 기반 지원

2026-10-20 · `behaivior` 개발 게임1.0.35 / AI0.1.47 · 운영 미배포.

후속 AI0.1.48의 [필요할 때만 참고하는 지원](19-need-only-dialogue-support.md)이 아래 매 턴 관찰 조회·관심 가설 전달 정책을 대체한다. 이 문서의0.1.47 구현/검증은 선행 이력이다.

[17 — 본인 활동 분석](17-minecraft-support-activities.md)과 NPC의 지식을 구분한다. 이번 연결은 기존 방 엔진이 게임에서 허가받은 대화 원문과 관찰 사건을 실제 생성에 사용하도록 한다. 개인 화면의 전체 활동/목적을 NPC에게 넘기거나, 목적 자동 추출을 활성화한 것은 아니다. 모델은 `gemma4:12b`를 유지한다.

## 입력과 권한

1. 게임 `RoomConversationEngine.Request`의 방·턴·revision·플레이어·화자·청중을 기준으로 조회한다. AI가 관찰자나 청중을 추가하지 않는다.
2. 명시적 `recording-retrieval.json`의 `retrievalMode=NEW`이고 기록 저장이 켜져 있을 때만 새 경로를 사용한다. 누락 설정의 LEGACY, 기존 SHADOW 비교는 유지한다. NEW+archive OFF/잘못된 설정은 보수적으로 차단한다. 운영 설정은 변경하지 않았다.
3. Native 원문은 게임의 `openAfterCapture` 완료 경계 이후 조회한다. 선택된 실제 페이지와 휴대 가능한 Native 근거를 함께 전달하며 생성 완료·발행 때 현재 권한을 다시 검사한다. 조회 실패가 구 기억 저장소로의 fallback을 허용하지 않는다.
4. 관찰은 `ExperienceAccess`의 현재 플레이어/화자/청중 lease를 사용한다. 첫 범위는 비공개 단일 신 대화다. 공개/복수 신에서는 이 관찰 지원 입력을 생략한다. 이는 Native 원문 자체의 기존 청중 계약과 별개다.
5. `/mythprofile`의 `admin_only_unprojected` 활동, 개인 메모, 숨겨진 목적을 읽지 않는다. 해당 NPC가 실제 허가받은 사건만 `ObservedSupportMemory`에서 작은 가설로 다시 계산한다. 최종 발화에는 사용한 WATCH/Native 근거 참조를 남긴다.

## 지원 가설의 제한

최대6개 중복 없는 관찰 사건을 사용한다. 현재 생산자로 확인되는 성숙 작물 제거는 FARMING, 승인된 블록 제거 요약은 GATHERING, 처치 요약은 COMBAT_ACTIVITY로 분류한다. 레이드 결과만으로 개인 선택/전술을 판단하지 않는다. 낚시·건축 등 본인 화면의 모든 활동이 NPC에 연결된 것은 아니다.

같은 분류의 서로 다른 사건이2개 이상이면 `POSSIBLE_INTEREST_ONLY`를 제공한다. 여기서 사건 수는 관측 기록 수일 뿐 서로 다른 자발적 선택/에피소드 수를 보장하지 않는다. `voluntaryChoice=UNKNOWN`, `decision=NOT_ESTABLISHED`를 유지한다. 반복 수확으로 농사 선호·능숙함·심기/관리·아이템 획득이나 특정 신과의 만남 결심을 확정하지 않는다. 현재 플레이어의 명시적 정정이 가설보다 우선한다.

AFK·활동 부재는 입력하지 않는다. 관계·보상·가격·난이도·퀘스트의 자동 변경도 없다. 지원 정보로 대사를 만들 수 있을 뿐 기존 게임 실행 권한은 늘지 않는다. 일반 한국어 의미 오류는 [16의 분리 범위](16-behavior-system-scope.md)를 유지한다.

## 응답 지연과 컨텍스트 한도

- Native 준비는 비동기 최대3초, 선택 프롬프트8,192 UTF-8바이트다. 전체 원문 페이지를 보존해 들어가는 것만 선택한다. 조회·증명 발급 실패/시간 초과 시 원문 없음 안내를 넣고 없는 기억을 지어내지 않도록 한다. 저장 자체는 취소하지 않는다.
- 관찰 조회는 병렬로 최대1.5초 대기한다. worker 혼잡/용량 조정 중에는 선택적인 관찰이 생략될 수 있다. 무제한 대기하거나 권한을 완화하지 않는다.
- 조회 전용 추가 LLM/embedding 호출은 없다. 분류·생성 등 기존 대화 호출은 그대로다.
- NEW Primary 경로의 전체 프롬프트 상한은16,000자로 조정한다. 기존12,000자로는 필수 문맥 약11.7k와 회상 근거가 공존하지 못했다. 기존 LEGACY/SHADOW 상한은 그대로다. Secondary의 문맥 예산 확장은 이번 범위 밖이다.
- 상한은 실측 응답시간 보장이 아니다. 실제 모델 생성시간과 서버 부하를 포함한 수치는 검증 보고서에서 별도로 기록한다. 이전/이후 대조 실험 없이 속도 차이가 없다고 단정하지 않는다.

## 한국어 검색과 출처 보존

`RecordedRecallQuery`는 검색어에만 제한적인 한국어 조사 정규화를 적용한다. 예를 들어 ‘디오니소스에’ 질문이 ‘디오니소스를’ 포함한 과거 발언에 도달하도록 한다. 원문·주체 해석·ACL·시점·근거를 수정하지 않는다. 짧은 단어/ID와 공백·기호 경계를 보존하며 빈 전체 이력 검색으로 확대하지 않는다. 완전한 형태소/의미 검색기는 아니므로 동음이의/다른 표현의 회상은 추가 검증 대상이다.

생성 지침은 PLAYER 원문과 GOD의 비유를 구분하고, 원문으로 답할 수 있는 회상을 불필요하게 회피하지 않게 한다. 관찰 밖의 경작/관리 사실은 덧붙이지 않는다. 이는 품질 지침이지 의미 정확성을 보증하는 검증기나 고정 대사 템플릿이 아니다.

## 개발 검증 경로

`NativeDialogueGameTests`는 실제 방 엔진·SQLite·게임 발행을 사용한다. 오프라인에서는 LLM 전송만 대체하고, 명시적 `-ProomLiveDialogue=true` 실행에서는 동일한 LocalOllamaClient를 사용한다. 첫 방 attach가 엔진을 초기화한 후 전송 계측을 설치하고, 매 턴 해당 전송을 사용하는지 검사한다.

검증 시나리오는 타인 비밀 격리, 방 재생성 후 이름 회상, 희망/미결정 유지, 민수 계획의 주체 유지, 조사 형태가 바뀐 회상, 실제 작물 제거→관찰 worker 완료→대사 근거, 공개방 비밀 차단이다. 과거 희망 원문이 프롬프트에 실제 존재하는지도 확인한다. 현재 질문에 나온 대상 이름만으로 회상 통과를 판정하지 않는다. 자동 경로 PASS와 실제 대사의 의미/자연스러움 PASS는 구분한다.

그래픽 `runSupportClient`와 격리 GameTest는 `build/` 아래 새 디렉터리만 사용한다. 개발 fixture의2GB 한도·주시 trial·기록 설정은 운영의100GB 정책을 바꾸지 않는다. 운영 대화 모델 설정은 읽어 fixture에 복사할 뿐 수정하지 않는다. 달라진 fixture 설정이 이미 있으면 덮어쓰지 않고 실패한다.

실행별 결과, 그래픽 증거, 미완료 항목은 [검증 보고서](../../검토결과/native-dialogue-support-20261020/REVIEW.md)와 [브랜치 인수인계](../../인수인계/브랜치실험/behaivior/PROJECT_HANDOFF.md)를 따른다. 전체 검증 전 서버 배포 금지를 유지한다.

# 근거 누적형 목적 상태 — behaivior 개발

2026-10-19. 사용자 승인: 설계 수정 후 단계별 구현, 현재 `gemma4:12b` 유지, 실제 생성·수정 대사 검증, 전체 검증 전 서버 배포 금지. 이전 HanesTest 결과는 이번 구현의 합격 증거가 아니다.

후속 대사 계약 실험은 [15-purpose-reply-contract](15-purpose-reply-contract.md)와 [검증 기록](../../검토결과/purpose-reply-20261019/REVIEW.md)을 따른다. 아래 0.1.44는 목적 상태 기반 구현 당시 기록이며 후속 AI0.1.45 실험을 운영 완료로 뜻하지 않는다.

후속 사용자 결정으로 일반 대화 품질과 이 시스템의 담당·완료 기준을 [16 — 범위 분리](16-behavior-system-scope.md)에 정리했다. 아래 당시의 통합 gate 결과는 보존하되 앞으로 기록/추론, 안전한 게임 연동, 일반 대화 품질을 별도 평가한다. 행동에서 얻은 목적은 잠정적 가설이며 작은 제안 보정에만 사용한다. 서버 배포 금지는 유지한다.

## 1. 분리하는 상태

목적 키는 월드·플레이어·목적 종류·대상이다. 대상은 게임에서 해소한 ID이며 미해소 대상은 확정 ID로 만들지 않는다. 서로 다른 목적은 공존한다.

- 본인 의향: UNKNOWN / INTEREST / DESIRED / CONSIDERING / DECIDED. 마지막 유효한 본인 진술의 의미이지 실제 실행·동의가 아니다.
- 관측 진행: NONE / INFORMATION / PREPARING / PURSUING / ACHIEVED. 실제 행동과 게임 결과를 사용한다. 발언으로 달성을 만들지 않는다.
- 근거 강도: NONE / LIMITED / REPEATED / CONVERGING. 독립 사건과 근거 종류의 수를 나타내며 심리 확률이 아니다.
- 생명주기: ACTIVE / PAUSED / WITHDRAWN / DISOWNED / ACHIEVED. 정정·철회 이전 근거가 옛 목적을 자동 부활시키지 않는다.
- 출처와 가설: 원본 식별자·원본 순서·에피소드·행위자·신호·선택 맥락·시험 여부를 보존한다. 행동으로 추론한 추진은 ‘결심했다고 말했다’로 바뀌지 않는다.

## 2. 근거와 전이 규칙

LLM은 새 발언의 출처 묶인 해석 후보만 낸다. 지속 상태와 강도는 결정적 reducer가 갱신한다. 동일 원본은 한 번만 반영하며 같은 에피소드의 반복은 독립 관측으로 증식하지 않는다. NPC 대사·요약·소문 재전달은 원래 본인의 발언이나 독립 행동으로 계산하지 않는다.

희망 반복은 DESIRED를 유지한다. 명확한 DECIDED 발언 한 번은 현재 의향으로 즉시 인정하되 행동 진행은 올리지 않는다. 중요한 순간의 의미는 게임이 확인한 선택·대안·자발성에서 오며 모델의 분위기 점수가 아니다. 강제 이동, 성능 때문일 수도 있는 보상, 추천에 따른 행동은 목표 추진의 독립 확증에서 제외하거나 제한한다. 질문은 정보 관심이지 만남 완료/결심이 아니다.

대상 관련 자발적 탐사와 선택 등 서로 다른 종류의 행동이 독립 사건에서 합치면 추진 가설을 강화한다. 장기 성향은 해석 배경이며 최신 정정·부정을 덮지 않는다. 철회 후 행동은 모순 근거로 남길 수 있지만 명시적 재개/새 본인 의향 없이 옛 목표를 되살리지 않는다. 목적 변경은 최대 단계 덮어쓰기가 아니라 대상별 이력과 현재 상태의 변경이다.

## 3. 저장·공개 경계

기존 행동 원장의 출처를 재사용한다. 원장에 해석을 보존할 경우 반드시 파생 해석 타입으로 구별하고 기존 사실의 수정·복제본을 만들지 않는다. 원문 일수 제한을 도입하지 않고 기존 월드 100GB 예산·저장 실패/기록 OFF 정책을 따른다. 분석 시작 이전/시험 자료는 제외한다.

NPC 상태는 SELF 전역 프로필을 전달하지 않는다. 현재 NPC가 실제 청취·주시·소문으로 알고 있고 현재 청중에게 공개 가능한 원본만 **먼저 필터한 다음** reducer에 넣는다. 누락된 기록은 철회 없음의 증명이 아니다. 근거가 누락·철회되면 불완전 상태를 표시하고 오래된 강한 목표를 확정하지 않는다. 세션·턴·revision·원본 재검증은 기존 대화 발행 경계를 유지한다.

대사는 모델이 캐릭터에 맞게 작성하며 고정 문장 사전을 늘리지 않는다. 생성·검토·부분 수정 모두 같은 원본과 상태의 제약을 받는다. 목표 상태는 제안 참고 자료일 뿐 퀘스트 수락·보상·호감도·난이도·정사 변경 권한이 아니다.

## 4. 구현 순서와 합격 기준

1. 순수 자료형/reducer: 희망 반복, 본인/타인, 조건·인용, 독립 에피소드, 행동 종류, 선택 맥락, 즉시 정정·철회, 다중 목적, 순서/중복/누락/시험 격리.
2. 기존 원장 재구성/영속 연결: 재시작 후 동일 결과, 저장 실패·OFF, 분석 경계, 다른 월드·플레이어 격리. 현재 콘텐츠에서 생산 가능한 근거와 아직 정의가 없는 입력을 구분한다.
3. 관찰자별 허용 근거와 대사 입력: 비밀/다른 신/청중 변경/철회/늦은 응답 검사. 미검증 자동 해석은 기본 활성화하지 않는다.
4. 동일 Gemma 실제 발언 해석 → 누적 상태 → NPC 생성 → 기존 검토/수정 → 최종 대사 직접 확인. 기존 일반 대사 회귀도 포함한다. 자동 PASS와 직접 의미 검토를 별도 기록한다.
5. 관련 모듈 빌드·핵심 GameTest·패키지 소유권 검사. 전체 gate가 실패하거나 생산자/인게임 검증이 누락되면 미완료·미배포로 보고한다.

대상별 보상·탐사 연결은 작성된 콘텐츠 계약이 필요하다. 디오니소스/스핑크스/새 인물의 정사·보상·지역을 이 작업이 임의로 확정하지 않는다. 확인된 기존 입력과 합성 fixture를 구별하고 fixture 성공을 실제 콘텐츠 연결 완료로 보고하지 않는다.

## 5. 현재 진행

게임 1.0.32 / AI 0.1.44 개발. 서버 배포 없음. `PurposeUtterance.PRODUCTION_ENABLED=false`와 기존 `PlayerIntentPlan.ENABLED=false`를 유지한다.

| 단계 | 현재 소스와 연결 상태 |
|---|---|
| 1. 목적 상태 | `PurposeEvidence` / `PurposeState`: 네 축, 다중 목적, 중복·순서·정정·철회, 독립 행동 수렴, 허용 근거 선필터 구현 |
| 2. 원장·본인 화면 | `PurposeLedger`, `AsyncActionLedger.annotatePurpose/purposes/understandingSnapshot`, `PurposeSelfView` 구현. 기존 자기 메모와 행동 원본을 참조하는 파생 주석 저장·재구성·화면 표시·철회 연결 |
| 3. NPC 연결 | `PurposeUtterance`의 동일 모델 발언 추출과 `PurposeDialogueContext`의 생성/검토/수정 공통 입력 구현. **격리 평가 경로까지만 연결**. 실제 방 대화 자동 추출·Native 기억 영속 연결·관찰자별 실제 권한 어댑터는 미완료 |
| 4. 의미 검증 | 같은 Gemma로 원장→해석→상태→실제 생성·검토·수정을 평가. 자동 PASS와 직접 의미 검토를 구분. 결과는 [검증 기록](../../검토결과/purpose-state-20261019/REVIEW.md)에 기록 |
| 5. 배포 | 전체 gate 미통과/미완료 항목이 있으므로 보류. 서버 JAR·모델 설정·운영 월드 미변경 |

현재 코드의 운영 원본 지원은 **행동 원장 안의 원본**이다. 본인 화면 DECLARE를 SELF_SPEECH 계열로 해석할 수 있지만, 이것을 실제 신이 들은 대사로 취급하지 않는다. 실제 방/공용 채팅의 원본은 별도 Native 기록 계약에 있으므로 자기 메모로 복제하여 우회하지 않는다. 실험의 보상·탐사 대상 연결은 합성 fixture이며 운영 콘텐츠 생산자 구현이 아니다.

## 6. 구현 계약과 제한

- `PLAYER_PURPOSE_EVIDENCE`는 원본 사실이 아니라 파생 해석이다. 동일 월드·플레이어·원본 ID·원본 sequence·에피소드와 원문을 검증한다. 파생 주석을 다시 사실 근거로 쓰지 않는다.
- 쓰기는 `AsyncActionLedger.annotatePurpose(candidate)`를 사용한다. 분석 START 이후 원본만 승인하고 잘못된 해석 후보는 해당 future만 거절한다. 기존 bounded writer·중복 방지·월드 용량 예산·durable receipt를 재사용한다. 게임 스레드에서 `join/get`으로 기다리지 않는다.
- 원장 에피소드는 실제 run ID를 우선하고 없으면 capture session과 12,000 game tick 구간으로 계산한다. 모델이 문장마다 UUID를 만들어 반복 근거를 늘릴 수 없다. 이는 독립성의 보수적 기술 근사이지 플레이 시간·성격 확정 규칙이 아니다.
- 서로 다른 행동 종류 2개 이상이 독립 에피소드 2개 이상에서 합치면 `inferredPursuit`를 만든다. 같은 종류만 반복하면 REPEATED까지이며 DESIRED를 DECIDED로 바꾸지 않는다. 행동 대상·자발성은 콘텐츠/게임 생산자의 계약이 필요하다.
- 본인 화면은 활동과 목적을 같은 worker fence에서 읽으며 최대 16개 카드 제한을 유지한다. 표시 한도와 누락 여부를 알린다. 목적 철회 버튼은 이전 목적 후보 전체에 철회 경계를 남기며 NPC 공개 권한을 만들지 않는다.
- 시작 이후 해석 4,096개 또는 목적 64개를 넘으면 오래된 일부를 확정 상태처럼 반환하지 않고 불완전·빈 목적 투영으로 내려간다. 원본을 삭제하지 않는다. 장기 페이지/증분 checkpoint는 후속 구현 대상이다.
- 현재 MEET 달성 생산자는 없다. DO_ACTIVITY 완료도 동일 대상의 실제 QUEST_COMPLETED/승리 결과만 인정한다. 대화 발언은 완료를 만들 수 없다.
- 게임과 AI JAR은 개발 API 버전에 함께 맞춰야 한다. 구 버전은 새 enum 원장 레코드를 읽지 못할 수 있으므로 새 레코드 기록 이후 구 JAR로 임의 롤백하지 않는다. 이번에는 운영 원장에 새 타입을 쓰지 않았다.

## 7. 다음 통합 단계의 고정 경계

1. 실제 대화는 게임이 발급한 message ID·actualActor·전체 원문·청취/공개 영수증을 사용한다. Native `SourceRef`/dataset/revision/hash와 현재 수신 신·청중 검증을 유지한다. 미리 계산한 SELF 전체 프로필을 NPC에 넘기지 않는다.
2. Native watermark와 행동 원장 sequence는 서로 다른 순서 공간이다. 현재 `sourceOrder`에 둘을 섞어 넣지 않는다. 혼합 입력의 게임 발생 순서·동시 사건·정정 경계를 명시한 어댑터와 교차 저장소 재시작 시험을 먼저 추가한다.
3. 작성형 보상·지역·퀘스트의 정확한 대상 연결, 선택 대안·강제성·추천 여부를 게임 생산자가 낸다. 아이템/지역/신 이름의 문자열 유사도로 목적을 만들지 않는다. 아직 없는 신별 정사나 보상 연결표는 임의 확정하지 않는다.
4. 생성 시작과 발행 직전에 room/turn/revision, NPC 청취 근거, 공개 청중, 원본 변경/철회, 데이터셋·분석 경계를 재검증한다. 실패 시 해당 해석이 섞인 대사를 발행하지 않는다. 다른 신의 지식이나 늦게 끝난 이전 턴을 재사용하지 않는다.
5. 이 어댑터의 실제 GameTest, 복수 신/플레이어 공개 범위, 클라이언트 화면 및 자연스러운 대사 gate가 끝나야 자동 경로 활성화를 검토한다. 현 단계의 합성 원장+실제 LLM 시험은 이 통합 검증을 대신하지 않는다.

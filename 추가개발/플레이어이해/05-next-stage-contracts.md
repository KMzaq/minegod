# 후속 구현 계약 — 아직 구현 완료가 아닌 설계

현재 실행 범위는 [구현 상태](04-implementation.md)와 [후속 검증](07-followup.md)을 따른다. 이 문서는 목표 계약이다. `RAID_CHOICE`의 축소 입력/집계와 비활성 목적 후보 단계만 코드화했으며, 아래 모든 필드·장기 상태·관찰자 연결이 구현됐다는 뜻이 아니다. 확정된 레이드 규칙으로 해석하지 않는다.

## 1. 입력과 분석 단위

원본은 기존 플레이어별 행동 원장이다. 신마다 원본을 복제하지 않는다. AI 대화 원문·실제 청취 기억과 주시·소문은 기존 저장소의 출처를 참조한다. 자기 화면의 메모는 NPC 입력이 아니다.

후속 `EvidenceRef`의 필수 필드:

| 필드 | 의미 |
|---|---|
| worldId, actorId | 게임의 월드·플레이어 identity. 이름으로 결합하지 않음 |
| store, sourceId, sourceRevision | 실제 원본 위치·버전. LLM이 임의 생성하지 못함 |
| occurrenceId, episodeId | 중복 사건과 독립 관측 단위 구분 |
| observedAt, receivedAt | 사건 발생과 청취·소문 전달 시점 구분 |
| provenance | 실제 행동, 본인 발언, 타인 발언, 소문, 파생 추론 |
| scopeProof | 게임 측 관찰/청취/소문 범위 및 공개 재검증에 필요한 참조 |
| coverage, test | 계측 가능 구간·누락·시험 자료 여부 |

최소 가설 단위는 `(worldId, playerId, observerScope, domain, hypothesisKey, rulesVersion)`이다. `observerScope=SELF`는 자기 화면 전용이고, NPC scope는 기존 게임 ID와 지식 계약을 사용한다. 동일 플레이어를 다수 신이 서로 다르게 해석할 수 있지만 사실 원본을 다르게 저장하지 않는다.

## 2. 일반 플레이 성향

분석할 수 있는 행위와 추정 가능한 성향을 구분한다. 현재 1차 화면의 농사·블록 제거·처치·퀘스트·레이드는 **활동 관측**이지 아래 모든 축의 구현이 아니다.

| 후속 축 | 필요한 근거 | 금지하는 단축 판단 |
|---|---|---|
| 탐험/정착 | 방문 가능 구역·체류/재방문·강제 이동 구분 | 이동거리만으로 탐험 선호 |
| 준비/즉흥 | 선택 가능한 준비 시간과 준비 행동 | 장비 가격으로 성실함/실력 |
| 도전/안정 | 실제 선택 가능한 난이도·위험과 선택 | 사망 횟수로 무모함/비겁함 |
| 독립/협력 | 동료 참여 기회와 공동 행위 | 혼자 접속한 시간을 비협조로 판단 |
| 공동 기여 | 공동 목표에서 실제 지원 선택·기회 | 피해량 순위만으로 기여도 |
| 서사/인물 관심 | 허용된 대화·질문·자발적 추적 | 퀘스트 강제 대사를 진짜 욕구로 판단 |
| 실험/반복 | 같은 조건의 전략 변경·재시도 | 실패 자체를 실험 선호로 판단 |

장기 요약은 원본 참조와 규칙 버전에서 재생성 가능해야 한다. 최근 창과 누적 창을 함께 보여 주되, 시간 경과로 원문을 삭제하지 않는다. 첫 정책 후보는 최근 10개 독립 에피소드와 이전 누적 비교이며, 충분한 분모가 없으면 UNKNOWN으로 둔다. 이 창 크기와 아래 기준은 게임 운영 후 조정할 **설계 기본값**, 검증된 심리 척도나 확률이 아니다.

## 3. 레이드 선택 계측

게임이 실제 기회가 열리고 닫힐 때만 신호를 발행한다. AI가 거리·명단을 재해석해 기회를 생성하지 않는다. 예를 들어 기믹 접근이 불가능하거나 다운된 플레이어는 ‘기회 있었으나 무시’의 분모에서 제외한다.

후속 신호에는 `runId/encounterVersion/phaseId/decisionId`, 실제 playerId, 역할(미확정 가능), choiceKind, opportunity 상태, 선택과 결과, 강제 여부, 중단 이유, 원본 참조, test가 필요하다. `decisionId+playerId+choiceKind`로 같은 기회를 한 번만 센다. 기회 철회·서버 취소·재시작은 성향 근거가 아니다.

- 기믹 참여: 접근/인지 가능한 기회, 참여 시도, 실제 해결을 분리한다.
- 동료 지원: 지원 가능 기회, 지원 시도, 유효 효과를 분리한다. 과잉 회복량을 성향 점수로 더하지 않는다.
- 위험 대응: 선택 가능한 안전 경로·시간이 있었는지부터 확인한다. 장비·역할이 다른 플레이어의 수치를 단순 비교하지 않는다.
- 실패 후 대응: 자발적 재도전 선택과 연결 장애/파티 해체를 구분한다. 모집에 참가한 사실은 도전 동기의 확정이 아니다.

초기 판단 후보: 3개 이상의 독립 run과 8개 이상의 유효 기회 전에는 제한적 관측만 표시한다. 한 run이 전체 근거를 독점하지 않도록 run별 영향 상한을 둔다. 비율은 유효 기회 분모와 함께 제시하고 ‘협조적 87%’ 같은 인격 확률은 만들지 않는다. 성공률·성향·숙련도를 분리한다. 반대 선택이 생기면 함께 표시하며 기존 평가를 고정하지 않는다.

**생산자 연결 순서:** 공통 선택 계약/중복·취소 테스트 → 시험 레이드에서 test 신호로 기술 검증 → 확정된 정식 레이드 기믹에 opt-in 연결 → 실제 플레이 검증. 현재 시험 레이드의 기존 무보상·비정사·중요사건 미발행 정책을 유지하며 시험 결과는 정식 프로필에서 제외한다. 보스 규칙을 이 설계가 새로 확정하지 않는다.

## 4. 목적 추론과 정정

목적 상태: `CANDIDATE → SELF_STATED/ONGOING → RETRACTED/SUPERSEDED/ACHIEVED`. 모든 상태 전이가 필수는 아니다. `ACHIEVED`는 해당 게임 결과 또는 ‘본인이 달성했다고 말했다’는 별도 진술 분류로만 성립한다. 대사 생성 성공을 목적 달성으로 처리하지 않는다.

출력 후보의 필드: 목적 종류, 해소된 대상 게임 ID 또는 미해소 이름, 현재/가정/인용/대리 질문 여부, 지지·반대 EvidenceRef, 대안 설명, 상태, 범위, revision. 대상 ID는 게임 레지스트리에 있는 후보 목록에서만 해소한다. 미등록 이름은 발화 속 표현으로 남길 수 있으나 신 등장/등록 권한이 되지 않는다.

의미 추출은 기존 `TurnInterpretation`의 현재 발화 인용 조건을 완화해서 해결하지 않는다. 별도 bounded 후보 단계가 허용 근거 ID를 선택하고, 결정적 검증기가 ID·원문 인용·화자·시간·scope를 검사한다. LLM의 0~100 자신감으로 사실 승격하지 않는다. 잘못된 인용/없는 근거는 후보를 버리되 기존 대화는 계속한다.

1. 질문만 한 경우: 그 인물에 관한 관심의 약한 후보. 직접 만나려는 목적은 미확정.
2. 여러 차례 소식을 찾고 직접 할 말이 있다고 한 경우: 만남/연락 의도의 유력한 해석 가능. 상대의 위치·비밀·만남 성공은 모름.
3. 친구 부탁이라고 정정: 자신의 만남 목적을 철회·대리 탐문으로 재해석. 같은 근거로 옛 목적을 재생하지 않음.
4. 농사로 관심을 옮김: 현재 대화에 농사 관심을 우선. 옛 목적은 강제 삭제가 아니라 과거/철회 상태로 유지.
5. 속임수일 가능성: 신의 성격상 의심할 수 있으나, 실제 거짓말로 원장·보상을 바꾸지 않음.

‘그 뜻 아니야’ 같은 대화 정정은 그 발화를 실제 들은 인물의 해석만 갱신한다. 자기 화면 정정은 SELF 분석만 갱신한다. 두 조작을 전세계 NPC에게 자동 전파하지 않는다. 서로 모순되는 소문/발언은 소스별로 병존할 수 있다.

## 5. 관찰자별 대화 연결

입력 순서: 게임 권한 확인 → 관찰/청취/소문 검색 → 해당 NPC의 보유 범위 필터 → 현재 청중에게 공개 가능한 근거 필터 → 후보 추론 → 대사 생성. 자기 전역 프로필을 계산하고 비밀 출처만 제거하는 방식은 금지한다. 비공개 지식의 존재 자체를 공개 단정의 확률에 섞지 않는다.

신 A만 들은 목표를 신 B가 맞히면 실패다. B가 실제 전달받은 소문이 있다면 소문으로만 표현한다. 소문 신뢰도와 목표 확신도를 혼동하지 않는다. 지식 만료·관찰 철회·청중 변경 시 원본 권한을 재검사한다.

캐시는 최소 월드/플레이어/관찰자/방/청중 fingerprint/roomRevision/turnId/근거 revision/규칙 버전으로 격리한다. 생성 이후 전달 전에 기존 room token·기억 revision·콘텐츠 generation·지식 허용을 다시 검사한다. 늦은 결과는 버리며 다른 방의 다음 턴으로 이동시키지 않는다.

자연스러운 사용은 ‘항상 나를 평가함’이 아니다. 최근 실제 전달 대화에 같은 목적 해석이 있으면 반복 억제한다. 초기 후보는 같은 해석을 새 독립 근거나 직접 질문 없이 다시 끼워 넣지 않는 것. 사용자가 근거를 묻거나 정정하면 언제든 설명/수정할 수 있다. 전투 중 임의 팝업은 금지하며 장면 전환·휴식 등 적절한 순간을 게임 입력으로 받는다. Primary/Secondary는 각자 허용 근거와 가치관을 사용하고, 보조 신이 새 관점을 더하지 못하면 침묵한다.

검증은 고정 문장 정답이 아니라 **의미**를 평가한다. 같은 근거라도 직설적인 신/장난스러운 신/냉담한 신은 다른 반응을 할 수 있다. 과한 공감이나 모두 친절한 답변을 합격 조건으로 삼지 않는다.

## 6. 게임 반영과 순서

우선안은 기존에 작성되고 현재 적격한 콘텐츠의 제안 순서/대사 선택뿐이다. 보상·가격·호감도·난이도·정사 자동 변경은 사용자 추가 결정과 별도 정책이 필요하다.

후보 제공자는 기존 퀘스트·활동의 실제 적격 목록과 공개 허용 정보를 반환한다. 추론은 그 목록에서 후보를 좁히는 힌트이며 새로운 questId/보상/참가자를 생성하지 않는다. 명시적 거절은 해당 제안을 억제한다. 추천을 받아 수행한 행동을 곧바로 ‘원래 선호의 독립 증거’로 재사용하지 않아 자기강화 루프를 막는다.

제안 → 필요한 본인 확인 → 게임 재검증 → 실제 실행 결과 → 허용된 대화/기억이라는 기존 흐름을 유지한다. 욕구 추정은 확인을 생략할 근거가 아니다. 일반 NPC까지 확장할 때에도 기존 entity identity와 실제 지식 provider를 연결해야 하며, 모든 NPC가 신의 지식을 공유한다고 가정하지 않는다.

우선순위: 현재 자기 화면 안정화 → 레이드 선택 입력 → 출처 검증 목적 후보 → 관찰자별 연결·실제 모델 품질 통과 → 적격 콘텐츠 제안. 원본 저장·설계 계약·코드 연결·실제 모델·인게임·배포를 각각 완료 판정한다.

# 목적 대사의 의미 계약과 대화 연결 — 실험 설계

2026-10-19, `behaivior`. 현재 Gemma 유지. 서버 배포·자동 목적 추출 활성화 없음.

후속 사용자 결정: [16 — 담당 범위 분리](16-behavior-system-scope.md). 이 문서의 일반 한국어 응답·화행 검토 실험은 별도 대화 품질 과제로 보존한다. 행동 이해 시스템의 구현은 실제 원본·가설 갱신·권한별 입력·작은 제안 보정을 우선하며, 일반 대화 전체 개선을 선행 조건으로 삼지 않는다. 실제 목적 연동에서 주체/단계/공개 범위를 지키는 검증은 유지한다.

## 가설과 이전 실험과의 차이

기존 13번 실험은 원문과 초안을 각각 LLM으로 다시 해석해 비교했으나 누락·오독을 코드가 확정하면서 정상 대사를 거절했다. 이번에는 14번의 출처 묶인 목적 상태에서 **표현 가능한 핵심 구절을 코드로 구성**한다. 모델은 제공된 구절 ID와 말투를 선택하고 후속 대화를 작성한다. 주체·대상·긍정/부정·희망/결정은 재표현하지 않는다. 전체 대화를 입력별 고정 답변으로 바꾸지 않는다.

참고: [Rasa CALM](https://learning.rasa.com/rasa-pro/architecture-of-an-assistant/)의 로직/표현 분리, [재표현의 의미 변화 한계](https://rasa.com/blog/contextual-rephrasing-with-small-llms), [CoVe](https://aclanthology.org/2024.findings-acl.212/)의 검증 분리, [CheckList](https://aclanthology.org/2020.acl-main.442/)의 행동 대조 시험. 다른 모델/언어의 효과를 현재 모델의 보장으로 간주하지 않는다.

## 계약

1. 현재 NPC·청중에게 허용된 원본으로 생성한 `PurposeDialogueContext.Prepared`만 입력한다. 별도 지식 권한이나 전역 플레이어 프로필을 만들지 않는다.
2. 출처를 재집계해 투영 일치를 확인한다. 불완전한 투영, 표시 이름 미해소, 최신 출처와 연결되지 않는 상태에는 핵심 구절을 발급하지 않는다. 출처가 없다고 목적이 없다고 말하지 않는다.
3. 희망/고려/결정은 **해당 말을 했다는 인정**이다. 행동 누적은 결정을 발급하지 않는다. 철회는 중단 선택을 인정하며 이전에 추진 결심을 했다는 과거를 만들지 않는다. 완료·보상·퀘스트 실행은 이 계약의 대상이 아니다.
4. 모델 출력의 핵심 구절 ID를 서버 코드가 실제 문장으로 바꾼다. 후속 자유 텍스트는 여전히 오류 가능하므로 최종 전체 대사를 검증한다. 핵심 구절을 선택하지 않는 NONE도 허용하여 관련 없는 턴마다 목적을 되풀이하지 않는다.
5. 한 번의 생성에서 하나의 핵심 구절만 선택하는 초기 한정 실험이다. 다중 목적/다중 신 발행 연결은 아직 아니다. 실제 게임 참가자·청중·revision 권한을 대체하지 않는다.

## 좁은 의미 검토

행위자, 추진/중단 및 의향 단계, 자발성, 직전 화행 수용을 분리한다. 모델이 내는 OK/VIOLATION/UNKNOWN은 오류 가능한 검사 결과다. VIOLATION은 실제 출력의 정확한 인용과 구체적인 수정 방향을 요구한다. UNKNOWN은 PASS나 명확한 오류로 승격하지 않고 발행 보류로 남긴다. 기존 일반 검토도 대조군으로 보존하며 새 검토가 게임 사실/실행 검사를 대체하지 않는다.

‘들어주겠다’에 역제안하는 것 자체는 오류가 아니다. 원래 제안을 이해하고 거절한 뒤 역제안하는 것과, 이해하지 못한 역할 반전을 구별한다. 신의 친절함·수락·짧은 대사를 강요하지 않는다.

수정은 기존 1회 부분 수정기를 사용한다. 원본 근거와 구절 밖 의미 보존 검사를 유지하고, 수정 후 전체 대사를 다시 검토한다. UNKNOWN의 근거 없는 전체 재작성이나 무한 재시도는 하지 않는다.

## 순서와 gate

1. 의미 구절 발급/ID 파싱/불완전·비공개·주체·단계의 순수 시험.
2. 이전 실제 생성 실패문 고정 재생: 과장과 정상 철회 인정, 타인 계획, 청취 제안의 역할 반전/정상 역제안.
3. 같은 모델로 이전 원장 상태를 이용한 새 생성, 실제 부분 수정 및 최종 대사 직접 확인. 상태 입력 재사용 시험과 원문 추출부터 시작한 end-to-end 시험을 구분한다.
4. 새로운 이름·단계·부정·관계의 최소 대조쌍과 일반 28개 회귀. 자동 PASS를 자연스러움 합격으로 사용하지 않는다. 코드/패키지 검증과 의미 검증을 구분한다.
5. 실험 성공 후에만 실제 방/Native/관찰자 어댑터 통합을 검토한다. 전체 gate와 실제 연결 전에는 배포하지 않는다.

실행 결과는 [비교 검증 보고](../../검토결과/purpose-reply-20261019/REVIEW.md)에 기록한다. 실험 구현·빌드·실제 모델 시험은 수행했지만 전체 gate는 실패했다. 제한11개에서 목적 의미 보존을 확인한 것과 일반 대화의 자연스러움/역할 해석을 해결한 것은 다르다. 검토 모델을 추가한 후보도 고정 대조에서 악화되어 운영 활성화하지 않는다.

## 비교 후보와 범위

- `PurposeReplyPlan`: 원본/투영/질문자/NPC 결속 검사, 주체가 고정된 핵심 구절 조합, 화자·청중·Proposal을 모델이 바꾸지 못하는 출력. 자기 메모가 청취 근거로 변하는 운영 연결은 만들지 않았다.
- FREE: 핵심 구절 뒤의 자유 후속 문장. 이 부분에 과장·대화 역할 반전이 재발할 수 있다.
- BOUNDED: 목적 구절이 발급된 시험 턴에서 후속 문장도 제공된 표현 집합으로 제한한다. 자발적 행동 수렴이 있을 때만 잠정적 연관 추정을 선택지에 넣는다. 일반 잡담·타인 인용 등 목적 구절이 없는 턴은 FREE로 남는다. **실제 플레이의 자동 턴 라우터가 아니며**, 반복성·성격 표현·관련성 손실이 별도 실패 조건이다. 이 모드의 의미 보존을 전체 RPG 대화의 자연스러움 해결로 보고하지 않는다.
- `ReplyMeaningAudit`: 행위자/확정 수준/부정/자발성/화행의 별도 판단. 같은 구절의 중복 지적은 하나의 부분 수정으로 병합한다. UNKNOWN은 발행·자동 수정 모두 보류다. 기존 일반 검토 결과를 덮지 않는다.
- `ReplySurfaceReading`: 원문을 보지 않는 출력 해석 보조 실험. 최신 목적 상태의 다시 추출이 아니지만 이 해석도 오류 가능하다. 저장·게임 권한·새 근거로 승격하지 않는다. 추가 호출의 이득과 비용을 비교하며 전역 검토 경로에는 붙이지 않는다.

실험 클래스는 `LocalOllamaClient`의 명시적인 별도 진입점만 사용한다. 기본 `submit`/`submitReview`, 이전 일반/관계 검토 및 자동 추출 비활성 상태는 유지한다. AI 개발 버전 0.1.45, 게임 API 1.0.32. 운영 설정/파일은 그대로다.

# 플레이 중 변하는 신 간 관계 시스템

## 구현 결과 (2026-09-01)

- 서버 공용 sparse SavedData에 `화자 → 대상` 방향별 점수(-1000~1000), 상태 태그, revision,
  변경 원인, 최근 이력 16개를 저장한다.
- `ALLIED`, `TRUCE`, `AT_WAR`만 대칭 태그로 취급해 반대 방향에 원자적으로 동기화한다.
  두려움·원한·존경·무관심 등은 방향별로 독립적이다.
- 데이터팩 전이 로더, 모순 태그·범위·God ID 검증, 여러 방향의 원자적 적용을 구현했다.
- 전이별 `maxApplications`를 월드에 저장해 기본 1회인 사건의 중복 적용을 막는다.
- `mythictrpg:god_relation` 조건으로 퀘스트·등장·향후 사건을 현재 점수와 태그에 연결할 수 있다.
- AI는 `aiEnabled=true`인 등록 전이 ID만 제안할 수 있고, 관계 변경은 항상 플레이어 확인 후
  서버가 다시 검증한다. 점수·태그·대상 신을 AI가 자유 입력할 수 없다.
- 조회·이력·미리보기·적용 관리자 명령을 추가했다.
- 현재 참가자에게 필요한 방향의 동적 관계만 AI Context에 전달한다.

상세 작성 형식과 닉스 사례의 모델링 기준은
`mythictrpg-main/docs/GOD_RELATION_SYSTEM_GUIDE.md`에 정리했다. 실제 닉스·제우스·아프로디테
관계 데이터는 확정 God ID와 전체 관계도를 받은 뒤 추가해야 하므로 이번 작업에서는 만들지 않았다.

메인 모듈·AI 응답 모듈·Content Registry 전체 빌드와 183개 필수 GameTest를 통과했다. 빌드 JAR은
아직 실제 서버·클라이언트 폴더에 배포하지 않았다.

## 목적

게임 진행과 플레이어 선택에 따라 신과 신의 현재 관계가 변화하도록 한다. 예를 들어 동맹 결성,
휴전, 배신, 갈등 심화, 봉인 협력, 세력 이탈 같은 상태를 세계 공용 데이터로 저장하고 대화·등장·
퀘스트·사건 조건에서 사용할 수 있게 한다.

정적 혈연·창조·숙적 관계는 Content Registry의 `social_relations`에 유지한다. 이 문서는 정적 관계를
덮어쓰지 않고 그 위에 쌓이는 **현재 세계 상태**를 다룬다.

## 작업 전 상태

- 정적 신 간 관계 태그 로더와 조회 API는 Content Registry에 존재한다.
- 플레이어와 신의 관계는 플레이어별 affinity를 중심으로 저장한다.
- 세계 공용 `MythicWorldState`는 현재 신 해금과 퀘스트 진행 트랙을 저장한다.
- 세계 공용의 신 대 신 관계값, 관계 이력, 동맹·전쟁 상태는 없다.
- 동적 신 관계를 Condition Engine, 후보 선택, AI Context에 전달하는 계약도 없다.

## 확정된 설계 항목

- 숫자 점수와 상태 태그를 함께 사용한다.
- 현재 관계는 서버 전체에 공유한다.
- 관계 변화는 등록 전이로만 수행하며, 역전이·복구 전이를 별도로 작성할 수 있다.
- 기본은 방향성이며 동맹·휴전·전쟁만 대칭이다.
- AI 전이는 플레이어 확인이 필수다.
- 모순 조합은 서버 규칙에서 거절한다.
- 저장 데이터 버전 오류는 원본을 보존하고 읽기 전용으로 거절한다.

초기 검토 때 사용한 결정 질문은 아래와 같다.

구현 전에 아래 항목을 세계관 기준으로 확정해야 한다.

1. 관계를 숫자로 저장할지 상태 태그로 저장할지
2. 관계가 서버 전체에 공유되는지, 세력별·시대별 인스턴스를 허용할지
3. 관계 변경이 영구적인지, 시간 또는 복구 퀘스트로 되돌릴 수 있는지
4. 방향성 관계인지 대칭 관계인지
5. 플레이어 개인 선택이 세계 공용 관계를 바꿀 수 있는 조건과 권한
6. 동시에 허용되는 상태 조합과 금지 조합
7. 사건 실패·서버 복구·데이터 버전 상승 시 처리 방법

## 권장 데이터 모델

초기 구현은 복잡한 연속 수치보다 검증 가능한 상태와 제한된 점수를 함께 사용하는 방향을 권장한다.

```text
DynamicGodRelation
├─ sourceGodId
├─ targetGodId
├─ affinityScore        제한된 범위의 현재 관계도
├─ stateTags            ALLIED, TRUCE, HOSTILE, AT_WAR 등 허용 태그
├─ revision             낡은 비동기 결과 방지
├─ lastChangedGameTime
├─ causeId              퀘스트/사건/관리자 변경 원인
└─ boundedHistory       최근 중요 변경만 제한적으로 보관
```

- 내부 저장 키는 정렬된 쌍 또는 방향성 키 중 하나로 통일한다.
- 상태가 대칭이어야 하는 경우 서버가 양쪽을 한 트랜잭션으로 갱신한다.
- 정적 `RT_FATHER`, `RT_CREATOR` 등은 동적 상태로 변경하거나 삭제하지 않는다.
- 무한 이력은 SavedData에 저장하지 않는다. 전체 감사 로그가 필요하면 별도 로그 저장소를 둔다.

## 구현 단계

### 1. 저장소와 마이그레이션

- 전용 `SavedData`를 추가하거나 `MythicWorldState`의 새 dataVersion으로 확장한다.
- 알 수 없는 미래 버전과 잘못된 ID는 기존 원칙대로 안전하게 거부한다.
- 관계값, 태그, 이력 길이와 문자열 길이에 상한을 둔다.
- 저장 실패 또는 잘못된 데이터가 정적 콘텐츠를 손상시키지 않게 한다.

### 2. 서버 서비스

아래와 같은 단일 authoritative 서비스를 둔다.

```text
GodRelationService
├─ query(source, target)
├─ validateChange(request)
├─ applyChange(request)
├─ compareAndApply(expectedRevision, request)
└─ recentChanges(source, target)
```

- AI가 서비스를 직접 호출하지 못하게 한다.
- 퀘스트나 사건의 검증된 Executor만 변경 요청을 제출한다.
- 한 변경이 여러 관계를 바꾸면 전체 검증 후 원자적으로 커밋한다.

### 3. 조건 엔진 연결

필요한 범위에서 다음 조건을 추가한다.

- 특정 신 쌍의 현재 상태 태그
- 관계 점수의 최소·최대 범위
- 최근 특정 원인으로 관계가 변경되었는지
- 특정 세력 내 동맹 또는 전쟁 수

조건은 현재 Context와 인덱스를 사용하고 전체 신 쌍을 매 tick 순회하지 않는다.

### 4. AI Context 연결

- 현재 대화 참가자와 직접 관련된 동적 관계만 포함한다.
- 정적 관계와 동적 관계를 구분해 전달한다.
- AI는 관계를 묘사할 수 있지만 값을 변경했다고 단정하지 못하게 한다.
- 관계 변경 Proposal이 필요하면 등록된 템플릿과 서버 Validator를 사용하는 별도 액션으로 제한한다.

### 5. 퀘스트와 사건 연결

- 퀘스트 완료 후 관계 변경을 실행하는 서버 전용 결과 타입을 추가한다.
- 원인 ID, 변경량, 허용 상태 전이를 데이터팩에 명시한다.
- 메인 스토리 관계 변화는 반복 수령이나 중복 커밋이 불가능해야 한다.
- 관계 변화 때문에 콘텐츠가 영구 소실될 경우 반드시 복구 경로를 함께 설계한다.

### 6. 운영 명령

예상 명령:

```text
/mythadmin relation gods get <sourceGod> <targetGod>
/mythadmin relation gods history <sourceGod> <targetGod>
/mythadmin relation gods preview <transitionId>
/mythadmin relation gods apply <transitionId>
```

자유 숫자 입력보다 데이터팩에 등록된 전이 ID를 적용하는 방식이 안전하다.

## 예상 수정 위치

- `mythictrpg-main`의 world SavedData 또는 신규 관계 SavedData
- 신규 `GodRelationService`와 관계 전이 데이터팩 로더
- Condition Engine의 동적 관계 조건
- 퀘스트/사건 결과 Executor
- AI Conversation Snapshot과 Context bridge
- 관리자 명령과 GameTest

## 테스트 계획

1. 저장·재접속·서버 재시작 후 관계 상태가 유지되는지 검증한다.
2. 방향성 및 대칭성 정책이 정의대로 적용되는지 검증한다.
3. 잘못된 태그, 범위 초과, 존재하지 않는 God ID를 거부하는지 검증한다.
4. 같은 퀘스트 완료가 관계를 두 번 변경하지 않는지 검증한다.
5. 여러 관계의 원자적 변경 중 하나가 실패하면 전부 미적용되는지 검증한다.
6. 낡은 revision의 비동기 AI 결과가 폐기되는지 검증한다.
7. 관계 조건이 후보 인덱스를 우회해 전체 God scan을 만들지 않는지 검증한다.
8. 정적 가족 관계와 동적 적대 상태가 동시에 AI Context에 구분되어 전달되는지 검증한다.

## 완료 기준

- 동적 관계의 source of truth와 변경 권한이 MythicTRPG 서버에 있다.
- 저장·마이그레이션·중복 방지·원자적 커밋 테스트가 통과한다.
- 현재 참가자에게 필요한 관계만 AI Context에 전달된다.
- 관계 변화가 퀘스트·등장 조건에 사용될 수 있다.
- 운영자가 변경 원인과 현재 상태를 조회할 수 있다.
- 모든 비가역적 변화에는 명시적인 복구 또는 관리자 복원 경로가 있다.

## 주의점

- AI의 자연어 판단만으로 세계 공용 관계를 바꾸지 않는다.
- 플레이어 한 명의 사소한 대화가 서버 전체 전쟁을 일으키지 않도록 권한 단계를 둔다.
- 관계 수치와 상태 태그가 서로 모순되지 않도록 허용 전이표를 사용한다.
- 신 800명 기준 전체 관계 행렬은 최대 639,200개의 방향성 쌍이 될 수 있으므로 실제로 존재하는
  관계만 sparse하게 저장하고 조회 인덱스를 사용한다.

# 원래 목표와 현재 대화방의 재통합

2026-09-23. 사용자가 차이점 확인 후 원래 목표에 맞춘 설계·작업을 요청했다.
이는 새 방을 없애거나 LP/구 코드를 통째 복원하는 작업이 아니다. 현재 공개/비밀방,
권한·기록 on/off·세션 격리를 보존하며 원래 기능을 명시적 방 계약으로 연결한다.

## 1. 목표와 작업 순서

| 단위 | 구현 목표 | 완료 판단 |
|---|---|---|
| A | 방향별 동적 신 관계를 일반 대화·무리 선택에 재연결 | 현재 화자→현재 참가 신만; 원인/숨겨진 사건 제외; 생성 중 관계 변경 시 취소 |
| B | 04 AI 사건 연출과 방 지정 Hook 재연결 | 게임 확정 사실만; 청중 교집합 공개 정책; 잘못된 방/화자/만료 Hook 거절; 실패 fallback |
| C | 실제 청취한 신의 기억 연결 | 발화 신과 기억 소유 신 구분; 게임 발행 증명; 중복·철회·다른 청중·기록 off 검증 |
| D | 제한된 Primary/Secondary 순차 반응 | 먼저 전달된 Primary 발언만 Secondary에 전달; 독립 프로필/관계/기억; 침묵 허용; 행동 권한 없음 |
| E | 전체 채널 원문/장기기억/지식 통합 | 기존 05의 M1~M5 저장·권한·검색 및 M7 수용 기준으로 별도 검증 |

A~D는 기존 기록 체계의 한계를 명시한 호환 연결이다. 이것을 05의 M1~M7 완료나
무기한 100GB 기억 구현으로 부르지 않는다. 저장소 설계는
[05 단계별 계획](05_AI_장기기억_다중신_대화_시스템/08_단계별_구현계획.md)을 단일 기준으로 유지한다.
이번 소스 작업 중 테스트를 통과한 것과 실제 서버/LLM에서 검증한 것을 구분한다.

## 2. 관계 입력

- 정적 관계는 콘텐츠 레지스트리, 현재 관계 score/tags/revision은 게임 저장소에서 읽는다.
- 현재 스키마의 score/tags는 화자 자신의 현재 태도이며 비밀 사건 기록으로 취급하지 않는다.
  상대→화자 또는 다른 신끼리의 내면 상태를 화자에게 전지적으로 공급하지 않는다.
- cause/history/전이 ID는 대사 입력에서 제외한다. 과거 전쟁의 구체적 사건, 봉인·승패는
  관계 태그에서 추정하지 않고 Story 지식/공개 계약을 통과해야 한다.
- 생성과 적용 사이 방·청중·관계 revision을 비교한다. 이후 비밀 관계 태그가 필요하면
  공개 메타데이터 계약을 먼저 추가해야 하며 현재 입력을 비밀 저장소로 재활용하지 않는다.

## 3. 사건과 공개

- 03 게임 엔진이 조건·확률·결과·효과를 결정한다. AI는 결과를 바꾸거나 없는 사건을 실행하지 않는다.
- 04 provider는 현재 설정된 모델/스케줄러를 사용한다. 실패 시 작성된 대체 문구를 유지한다.
- 방 대화에는 공개 가능한 Story 의미와 허용 Hook 별칭만 포함한다. 실제 Hook token은 모델에 주지 않는다.
- 비밀방은 모든 플레이어와 청취 신에게 안전한 내용의 교집합, 전역 공개방은 공공지식만 사용한다.
- Hook 제안은 방 generation/화자/플레이어에 귀속되고 기존 확인 UI와 서버 검증을 거친다.
- 일반 SECRET 로어에는 아직 작성자 공개 정책이 없으므로 Story 공개 정책이 생겼다는 이유로
  전부 허용하지 않는다. 소문·퀘스트 자동 알림도 기존 개인 포트를 다른 방에 임의 재사용하지 않는다.

## 4. 순차 대화

1. 게임이 입력을 수락하고 방 턴 권한을 발급한다. 새 입력은 이전 생성을 무효화한다.
2. Primary의 자기 프로필·관계·공개 지식·허용 기억으로 생성한다.
3. 게임이 유효성을 재검사하고 실제 대사를 전달·기록한다. Proposal은 게임에서 별도 검증한다.
4. 방이 유지되고 최초 플레이어가 대사를 전달받은 경우에만 Secondary 후보를 생성한다.
5. Secondary는 fresh snapshot과 실제 전달된 history, 자기 기억으로 한 번 반응하거나 침묵한다.
6. Secondary에는 아이템/관계/퀘스트/초대/퇴장 등 어떠한 Proposal 실행 권한도 없다.
7. 오류·지연·새 입력·방 변경 시 보조 반응만 생략한다. Primary의 이미 전달된 대사를 취소하지 않는다.

초기 범위는 확정된 05 설계대로 플레이어 1명·신 2명이다. 그 밖의 방은 기존 한 신 응답을
유지한다. 최대 64플레이어·16신의 참가 지원을 축소하지 않는다. 보조 신의 매턴 의무 발언,
플레이어 없는 무한 신끼리 대화, 특정 신 예시대로 강제 전개하는 규칙을 만들지 않는다.

## 5. 검증과 운영 경계

- 단위 테스트: 잘못된 방향/신/청중/room/turn, 침묵, 잘못된 화자, Secondary 권한,
  공개 허용 교집합, 관계 변경, 청취 기록·중복·기록 off, fallback/Hook 검증.
- 관련 게임/AI 컴파일과 오프라인 회귀. 테스트 예시의 합격은 실제 LLM 자연스러움 증거가 아니다.
- 서버 파일·월드·프로필·모델 설정은 변경하지 않는다. 배포·부팅·다인 HUD·실제 LLM 수용은 별도다.
- 구현 결과와 잔여 범위는 후속 인수인계에 기록하며 이 설계표만으로 완료를 주장하지 않는다.

# 통합 신 대화 시험 명령

2026-09-21 개발 소스 기준. **실제 `server/`에는 아직 배포하지 않았다.** 게임 1.0.11과 AI 응답 0.1.12를 이번 소스로 함께 다시 빌드해야 한다. 같은 버전 번호의 이전 JAR에는 아래 기능이 없다.

후속 게임 1.0.12/AI 0.1.13에서는 [공개·비밀 대화방](CONVERSATION_ROOMS.md)이 추가됐다. 아래 `/ai_test`는 이전 단일 플레이어 회귀 시험용으로 유지되며, 공개·비밀 병행/다인 합류/병합·분리는 `/mythroom open`으로 검사한다. 같은 플레이어가 두 시험 경로를 중복 시작할 수 없다. 아직 배포되지 않았다는 상태는 동일하다.

## 사용법

OP 권한 2 이상인 플레이어가 실행한다.

```text
/ai_test <on|off> <신 이름 또는 ID> [다른 신 이름 또는 ID ...]

/ai_test on 데메테르 포르투나
/ai_test off mythictrpg:demeter mythictrpg:fortuna
/ai_test status
/ai_test stop
```

이름은 로드된 프로필의 `displayName`과 정확히 일치해야 한다. 공백이 있는 이름은 큰따옴표로 감싼다. 전체 ID와 유일한 ID의 path도 사용할 수 있으며, 모호한 이름은 전체 ID를 요구한다. Tab 자동완성은 콘텐츠 레지스트리 기준이다. 신은 **게임 God Definition과 AI 프로필 양쪽에 같은 ID로 등록**되어 있어야 한다. 프로필 135개가 있다는 이유만으로 모든 신이 게임에 등록된 것은 아니다.

세 번째 신부터는 같은 명령 뒤에 이름/ID를 이어 적는다. 현재 콘텐츠 **소스**의 기본 프로필은 데메테르·포르투나·test5이고, 게임 기본 정의에는 test5가 없다. 루브라스는 반대로 게임 정의는 있지만 현재 프로필 소스에는 없다. 외부 데이터팩/JAR 구성에 따라 달라질 수 있으므로, 이 작업이 세 번째 신의 누락된 콘텐츠까지 새로 작성한 것으로 해석하지 않는다. 세 신 테스트는 독립 fixture로 검증했으며 실제 LLM 시험 전에 사용할 세 번째 신의 양쪽 정의를 준비해야 한다.

신은 1~16명까지, 입력 순서대로 등록하며 중복은 제거한다. 한 명이라도 유효하지 않으면 전체 시작을 거절한다. 이미 활성 대화가 있으면 덮어쓰지 않는다. 시험 대화는 `/ai_test stop`으로 종료하고 다시 시작한다. 기존 일반 게임 대화는 게임 측 종료 수단으로 먼저 끝낸다.

시작 후 일반 채팅이나 `/ai_test say <내용>`으로 입력한다. `!`로 시작하는 공개 채팅은 기존 방식대로 대화 입력에서 제외한다. `relationship`, `emotion`, `debug`, `status`, `stop` 보조 명령은 유지한다. 구 `/ai_test start ...`는 새 형식 안내만 출력하며, 별도 `participants` 명령은 제거했다.

시험용 관계·감정 태그는 기존처럼 중립에서 시작하며 위 보조 명령으로 세션에 설정한다. 신별 게임 관계 수치를 영구 변경하거나 새 원본 관계 DB를 만드는 기능은 아니다.

`/mythadmin interaction god ...`는 등장 정책·Encounter를 시험하는 **게임 관리자 도구**로 유지한다. 기억/다중 신 대화 시험을 여는 표준 진입점은 이제 위 `/ai_test on|off ...`다. `mythadmin dialogue`의 고정 HUD 출력과도 다르다.

## on/off의 정확한 의미

| 구분 | `on` | `off` |
|---|---|---|
| 현재 세션의 최근 대화 문맥 | 사용 | 사용 |
| 권한이 있는 기존 기억 검색 | 사용 | 사용 |
| 이번 플레이어 발언·NPC 답변의 개인 기억 기록 | 저장 허용 | 저장하지 않음 |
| 이번 대화를 원문으로 하는 새 파생 기억 | 허용 | 원문을 저장하지 않으므로 새 후보 없음 |
| 이번 대화에서 새 소문/수신 평가/대화 회복 처리 | 전역 모드·별도 설정·공개 권한에 따라 허용 | 차단 |
| AI 시험 분석 로그·요청/응답 로그 | 기록 | 기록하지 않음 |

`off`는 기억을 지우지 않고 읽기 권한도 없애지 않는다. 세션 중 문맥은 메모리에만 유지하다 종료 시 버린다. 다른 세션과 설정을 공유하지 않는다. 과거에 저장한 자료의 유휴 인덱싱이나, 이 대화와 무관한 실제 게임 행동 기록까지 중단하는 스위치는 아니다. Minecraft 자체 관리자 명령 기록, 외부 모드 및 Ollama의 자체 로그까지 제어하는 보안 기능은 아니다.

전역 설정 `config/mythictrpg/ai-memory-foundation.json`의 `mode`는 별개다.

- `PERSONAL`: `on`으로 만든 기억은 현재 운영 개인 기억 저장소에 남아 이후 같은 신과의 대화에서 검색할 수 있다.
- `RUMOR_TEST`: 기존의 분리된 소문 시험 기억 저장소를 사용한다. 관련 소문 기능이 별도로 활성화되어야 한다.
- `OFF`: 기존 기억 검색도 전역 비활성이다. 저장되는 것처럼 오해하지 않도록 `/ai_test on ...`을 거절한다. `/ai_test off ...`는 현재 세션 문맥만으로 대화한다.

명령이 전역 설정·기존 자료·모델을 자동 변경하지 않는다. 기존 자료를 다른 저장소로 자동 이관하지도 않는다.

## 다중 신 대화와 격리

참가 신은 3명 이상도 받을 수 있지만, **현재는 플레이어 한 턴에 신 한 명이 답한다.** 모든 신이 한 요청에서 동시에 말하거나 자율적으로 연속 토론하는 기능은 아니다.

- 특정 이름/ID를 부르면 해당 신을 선택한다.
- 평범한 후속 발화는 직전 신과 대화를 이어간다.
- 이름 지정 없이 “모두”, “다들”, “각자”, “다음 신”, “다른 신” 등으로 부르면 등록 순서대로 다음 신을 선택한다.
- 여러 이름을 직접 부르면 언급한 신들 사이에서 순환한다. 이 선택은 빠른 규칙이며 자연어 의도 추론 전체를 대체하지 않는다.

발화자를 기억 조회 **전에** 고정하고, 두 단계의 처리는 그 신의 기억·페르소나·관계 지침·지식만 사용한다. 실제로 대화에 출력된 이력은 참가 신들이 공유한다. 다른 신의 비공개 프롬프트를 공유하지 않는다. 종료/재시작/게임 세션 교체 뒤 늦게 도착한 답변은 적용하지 않는다.

`on`의 플레이어 발언은 그 자리에 참여한 각 신의 개별 기억 키에 기록한다. NPC 발언은 **발언한 신의 키에만** 기록하며, 다른 신 자신의 발언으로 복사하지 않는다. 다른 신이 들은 NPC 발언은 현재 세션 문맥에서 사용할 수 있지만, 이를 별도의 장기 청취 기억으로 저장하는 기능은 아직 없다.

원문에 `godAudience`를 추가했다. 다른 신들이 함께 듣는 요청에는 그 신들에게도 공개됐던 기록만 검색한다. 예전 자료처럼 신 청중 정보가 없으면 **소유 신 한 명에게만 공개된 기록**으로 해석한다. 따라서 혼자 있을 때 회상하던 사적 기억이 그룹 대화에서는 나오지 않을 수 있다. 파생 인덱스의 원문 선택·정정 연결에도 같은 경계를 적용한다.

기존 관찰 경험/소문 계약은 플레이어 청중만 표현한다. 다른 신에게 공개할 권한을 추측하지 않도록 **다중 신 시험에서는 해당 관찰 경험·소문 참고 및 소문 생성/회복 경로를 제외**한다. 한 신 대화의 기존 경로는 유지한다. 후속 M 설계에서 NPC 청중 계약까지 연결해야 이 제약을 해제할 수 있다.

## 게임 기능과 저장 위치

이 명령은 게임이 승인한 **대화/기억 시험 범위**를 만든다. Encounter를 실행하지 않으며 신 해금·이름 식별·호감도를 변경하지 않는다. 실제 아이템 지급·퀘스트 수주·월드 변경의 실행 권한을 부여하지 않는다. Proposal이 생성되어도 게임 Gateway에서 실행은 거절된다. 실제 게임 기능까지 시험하려면 원래 게임 Interaction 경로를 사용한다. `/mythtalk join`으로 시험 대화와 운영 다인 대화를 섞는 것도 거절한다.

- 개인 기억: `<world>/mythictrpg-ai-memory-lp-v1/`
- 소문 시험 기억: `<world>/mythictrpg-ai-memory-rumor-test-v1/`
- `on` 분석 로그: `<world>/mythictrpg-ai-test-logs/<플레이어 UUID>/`
- 원문 상태 조회: `/ai_memory status`, `/ai_memory list` (현재 선택 화자의 기억)

이 작업은 기존 LP 파일 저장에 명령별 기록 정책과 신 청중 필드를 추가한 것이다. **M0 이후의 새 SQLite 아카이브·무기한 전체 RAW·100GB 합산 저장·Primary/Secondary 연속 생성 M1~M7을 완성한 것이 아니다.** 새 필드가 없는 과거 자료는 읽을 수 있으나, 새 자료를 기록한 뒤 구 JAR로 하향 복원하는 것은 검증하지 않았다.

## 검증 범위

개발 JAR 컴파일 및 실제 생성 메서드를 사용하는 오프라인 fixture로 이름 파싱, 세 신 이상 선택, ON/OFF별 기록, 공유/사적 기억 필터, 원문 재시작, 늦은 응답, 일반 대화와 Quest/Reward/validator feedback 격리를 검사한다. 검증 결과와 실행 여부는 인수인계 최신 절을 따른다.

배포 후에는 `on`에서 특정 사실을 말하고 종료 → 같은 신의 `off`에서 회상 → `off`에서만 말한 새 사실이 다음 세션에 없음을 확인한다. 다중 신에서는 이름을 바꿔 부르며 각 신의 말투, HUD 이름, 과거 사적 기억 비공개도 확인한다. 이 실제 LLM·클라이언트 확인은 아직 수행하지 않았다.

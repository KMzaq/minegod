# 08. 단계별 구현 계획

## 1. 작업 단위와 기본 규칙

M0~M7은 이 통합 설계의 새 작업 번호다. 과거 행동/기억 로드맵의 단계 번호와 섞지 않는다. **M0 문서 확정 완료, M1~M7 미착수이며 신규 코드 구현 완료 단계는 없다.** 기존 구현은 [00](00_현재기준과_결정.md)의 재사용 기반이다.

각 요청은 지정 단계까지만 수행한다. 선행 계약·관련 회귀·현재 dirty 변경을 확인하며, 완료하지 못한 수용 조건을 다음 단계에서 이미 통과한 것으로 취급하지 않는다. 의미 모델/실제 서버 실행·배포는 별도 승인이다.

## 2. 전체 순서

| 단계 | 핵심 결과 | 선행 | 운영 동작 변화 |
|---|---|---|---|
| M0 | 현재 기준/계약/패키징/관리 저장소 목록 고정 | 없음 | 없음 |
| M1 | 월드 SQLite·합산 quota·복구 기반 | M0 | 기본 OFF |
| M2 | 전체 대화 RAW 수집·진단 | M1 | 승인된 시험에서 RECORD_ONLY |
| M3 | 행동/주시/소문 참조와 지식/공개 경계 | M1~2 | 기존 판정 보존, shadow로 검증 |
| M4 | EVENT/RELATIONSHIP/SUMMARY 파생 | M3 | 후보 저장. 대사 반영은 별도 |
| M5 | 기간 제한 없는 검색·화자별 context | M2~4 | SHADOW 비교 후 명시 ON |
| M6 | 1플레이어·최대 2신 순차 발언 | M5 | 새 세션 경로만 opt-in |
| M7 | 통합 수용·운영 전환·복구 검증 | M6 | 별도 승인한 시험/배포 범위 |

M3의 저장 포트 설계와 M2의 채널 조사처럼 독립 부분은 병행 가능하지만, 원문·권한 계약을 각자 다르게 구현하지 않는다. 본 문서 작성만으로 실행/배포 단계까지 승인된 것이 아니다.

## M0. 최신 기준 재고정·연결 계약

2026-09-20 완료: [M0 결과와 산출물](M0_기준확정/README.md). 코드/서버 동작은 바꾸지 않았다. 아래 범위는 완료한 조사·계약의 기준이며 실제 hook·용량 강제·native 로딩이 끝났다는 의미가 아니다.

범위:

- 인수인계 최신 기록/실제 소스/설정/배포물 및 사용자 미커밋 변경 확인.
- 새 capture hook와 기존 `DialogueMemoryBridge`/SocialRuntime 중복 통지를 막는 호출 지도.
- 02 계약의 v1 adapter 대응표, 저장 포트/스레드 소유, 현재 모든 채팅 채널 목록.
- 03 quota의 실제 전용 파일 목록과 게임 원본 제외 목록, active/test dataset 구분.
- JDBC 버전·라이선스·native/NeoForge 패키징 방안과 의존성 확보 계획. 임의 설치 없음.
- 현재 무기한/100GB가 아닌 제한들을 목록화하고 새 경로/기존 경로 적용 차이 명시.

산출물은 단계 기록과 계약 대응/시험 명세다. 이 단계는 다시 거대한 설계를 만드는 단계가 아니며 새로운 기술 차단점만 해결한다. 게임 동작·월드 데이터는 변경하지 않는다.

완료 조건: 모든 기존 source의 owner/ID/revision/현재성 검증 지점이 정해지고, 구 데이터 제외가 게임 진행도 삭제를 뜻하지 않음을 확인. 새 핵심 사용자 선택이 필요하면 그 항목만 질문한다.

## M1. 영속 저장·quota·장애 기반

범위:

- schema migration, world/dataset 검사, 단일 writer/제한 read pool, 불변 원문/receipt/work item transaction.
- managed store 합산·쓰기 예약·checkpoint/temp 공간·90/95%·FULL/누락 상태 구현.
- 게임/AI의 제한된 storage API와 inactive defaults. 기존 원장 파일 형식은 보존.
- 새 RAW에 총건수 12,000개/신별 2,000개/1GiB 검증 상한을 이어 붙이지 않음.
- 소문/주시/원장 기록 writer의 quota 참여 adapter. 실제 보상/월드 상태 저장은 차단하지 않음.

완료 조건: 작은 quota로 경계·WAL·임시본·동시 예약 시험, 64-bit 100GB 설정 검증, worker 강제 종료/재시작·손상 보존·다른 world 거부, JDBC 패키징/offline 단위 검사. 실제 Minecraft 로딩은 이후 승인된 검증으로 구분.

금지: 서버 설정 변경, 기존 데이터를 시험이라며 삭제/이관, 게임 원장의 SQLite 일괄 이전.

## M2. 전체 대화 수집

범위:

- 기존 신/HUD·공유 대화·공개 채팅·귓속말/팀/등록된 모드 채널 adapter.
- 수락 입력과 실제 출력 분리, 중앙 발화 ID와 수신 receipt, 긴 본문 무절단 보관.
- 전송 취소/모델 실패/중복 hook/부분 수신·누락 진단.
- 향후 대화 시스템 교체용 adapter contract와 지원 채널 coverage 표.

완료 조건: 실제 지원 채널 각각 fixture와 전달 지점 추적, 청중 수만큼 원문이 복제되지 않음, 비밀 대화 RAW는 보관하되 AI 공개 안 됨, 원문 hash/순서 검증. 미지원 채널이 있으면 “전체 수집 완료”로 종료하지 말고 정확히 보고.

금지: 모든 raw를 소문 생산자에게 보내기, 프롬프트/초안/인증 명령을 대화 원문으로 저장하기.

## M3. 행동·주시·소문 참조/권한 통합

범위:

- 기존 source/proof/receipt의 source adapter, durable cursor, KnowledgeReceipt.
- 관찰 획득과 현재 공개 가능성 분리, 신도 포함하는 청중 검사.
- 기존 소문 평가/회복 version과 NPC 대사 source 계보, 철회/복원 재검증.
- 공용 원장 조회·관리자 archive 조회가 AI에게 노출되지 않는 포트 분리.

완료 조건: 09의 비소급 관찰·차폐·전서구 대상별 차단·미수신 신·공동 사건·취소 직전 응답 시험 통과. 원장 재생이 보상/소문을 재발행하지 않음.

금지: 전서구/관측 정책의 빈 콘텐츠를 임의 생성, PERSONAL/RUMOR_TEST 의미 변경, 별도 affinity DB.

## M4. 파생 기억 계층

범위:

- 기존 Derived/MemoryIndex 모델 backend를 새 store/work queue에 연결.
- EVENT/RELATIONSHIP/SUMMARY의 typed claims, 출처/관점, 정정 링크, coverage.
- 모델 없이 저장할 수 있는 구조 정보는 결정적으로 처리. 해석은 모델 후보로 구분.
- idle admission·source hash/model digest·재시도/중단·재시작 유지.

완료 조건: 원문 불변, 정정·취소·이행 주장/게임 사실 구분, mixed audience 요약 차단, 요약→요약의 근거 손실 방지. 모델 모의 검증과 실제 의미 품질을 별개 보고.

금지: 매 행동·매 턴 추가 LLM 의무 호출, 사과 한마디로 affinity/보상·평판 변경.

## M5. 검색·context 전환

범위:

- 모든 기간 FTS/원문/시간/entity 조회, bounded 의미 후보와 페이지 조회.
- 현재성을 검사한 source 묶음으로 화자별 context 구성.
- SHADOW에서 기존 경로와 비교하되 신규 결과로 게임 액션/대사를 바꾸지 않음.
- 30일 hard filter 제거, 색인 지연/공백/PARTIAL 상태 및 운영 진단.

완료 조건: 과거·정정·주장·소문·다른 player/god·비밀 fixture, 긴 원문 뒤쪽 검색, 적재 메모리 상한/응답 취소 시험. 100GB 전수 의미 검색을 지원한다고 과장하지 않고 크기별 coverage/지연/recall 측정 계획 또는 결과 제공.

금지: 현재 모델의 실제 회상 검증 없이 “자연스러움 개선 완료”, 권한 실패 뒤 더 넓은 legacy context fallback.

## M6. 다중 신 발언 조정

범위:

- 게임이 승인한 발언 계획·Primary/Secondary, 화자별 독립 context와 순차 생성.
- 실제 출력된 공용 transcript만 다음 신에 전달, 필요한 경우만 Secondary.
- 새 경로 Primary-only action scope, 다음 턴 역할 전환·stale 결과 차단.
- 기존 다인 단일 신/퀘스트 동의 경로 회귀와 새 조합 미지원 안내.

완료 조건: Primary만 아는 비밀 미유출, 각 신의 서로 다른 기억/관계 반영, secondary 무단 Proposal 거부, 역할 전환 시 올바른 game owner, timeout/새 입력/합류 시 취소. 기존 다인 퀘스트 수주·아이템 소비·보상 횟수 유지.

## M7. 통합 수용·전환

범위:

- 사용자 승인된 격리 서버·실제 모델로 1인1신→1인2신, 기존 2인 이상1신을 검증.
- 1/4/6인 지연·tick·GPU/메모리·기록/색인 지연·재접속/정상 종료/복구 수용.
- 새 dataset 기준 시작, legacy test 제외 확인, 버전 조합/백업·rollback drill.
- 실제 콘텐츠/전서구가 없으면 그 경로는 미수용으로 남기고 자동 활성화하지 않음.

완료 조건: 09의 필수 불변식과 승인된 실제 시험 통과. 소스/컴파일/오프라인/GameTest/실제 모델/인게임/JAR 배포를 각각 보고. 운영 ON은 별도 승인 및 실제 매핑 완료 후만.

이후 다인·다신 전체 확장, 실제 엔티티·콘텐츠 제작, 대규모 ANN, 전체 legacy 분리는 별도 작업으로 이어간다.

## 3. 단계별 공통 보고 양식

변경 owner/파일 → IO/호환 영향 → 실행한 검사와 실제 결과 → 생략/미검증 → 보존한 기존 상태 → 다음 단계 준비/차단점. 기존 수천 개 assertion 기록을 재실행하지 않고 이번 결과로 복사하지 않는다.

기능/계약 상태가 실제로 바뀌면 기존 단일 가이드와 인수인계에 간단히 후속 기록을 남긴다. 이 설계의 과거 baseline을 오늘 구현 상태로 덮지 않는다.

## 4. 다음 요청에 사용할 문장

M0는 완료했다. 다음에는 아래 **M1 요청문**을 사용한다. 첫 요청문은 M0 범위 이력으로 남긴다.

> 추가개발/05_AI_장기기억_다중신_대화_시스템의 설계를 기준으로 M0만 진행해줘. 최신 변경과 기존 기능을 재확인하고 계약 대응표·수집 채널·100GB 합산 저장소 목록·패키징 계획을 확정해줘. 파일 삭제·월드 초기화·서버/실제 모델 실행·배포는 하지 말고, 필요한 새 결정만 질문해줘.

M0 이후:

> 위 설계와 M0 결과를 기준으로 M1만 구현하고 관련 컴파일·오프라인 검증까지 진행해줘. 기존 사용자 변경과 시험 데이터를 보존하고 서버 설정·월드·배포 파일은 바꾸지 마. 의존성 확보에 추가 승인이 필요하면 요청해줘. 다음 단계는 자동 진행하지 마.

뒤 단계도 M번호와 허용 검증 범위를 명시한다. M7 요청 시에는 실제 모델·격리 서버 실행·배포 중 무엇을 허용하는지 따로 지정한다.

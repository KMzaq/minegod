# 01. 전체 구조와 모듈 책임

## 1. 데이터 흐름

| 입력 | 원본 소유자 | 기억으로 들어오는 형태 | 최종 사용 |
|---|---|---|---|
| 수락/전달된 대화 | 게임의 ConversationArchive | 단일 RAW + 실제 발화자/청중/전달 근거 | 신이 직접 들은 발언·약속 등 |
| 중요 행동·관측 활동 요약 | 기존 게임 원장 | 원장 참조 + 신별 관찰 증명 + 허용 투영 | 실제 주시 경험 |
| 받은 소문 | 기존 소문/평판 서비스 | root/receipt/assessment 참조 + 허용 전언 | 소문임을 구분한 인식 |
| affinity·퀘스트·진행 상태 | 기존 게임 Provider | 현재 읽기 snapshot | 사실 판정·행동 제약 |
| 신 프로필·로어·정적 관계 | 콘텐츠 registry + 기존 게임 정의 | 해당 신·청중에게 허용된 정적 자료 | 말투·성격·배경 |

위 입력 → 권한별 파생 기억 → 검색 → **화자별 RETRIEVED CONTEXT** → 대사/Proposal → 게임 재검증 → 실제 출력/실행 → 다음 기록 순서다. 출력된 대사를 같은 사건의 독립 증거로 되먹이지 않는다.

## 2. 새 구성요소의 책임

아래 이름은 후속 구현용 제안이며 아직 존재하는 클래스라는 뜻이 아니다. 현재 패키지와 충돌하지 않는 `recording`/`dialoguecontract` 등의 하위 패키지로 배치한다.

| 구성요소 | 위치/소유 | 역할 |
|---|---|---|
| `WorldRecordingService` | MythicTRPG 서버 | 월드 identity, SQLite 생명주기, 단일 writer, quota, 원문·파생 저장 포트 |
| `ConversationCaptureAdapter` | 게임 채널별 | 실제 서버 수락/전달 지점에서 원문·청중 snapshot 수집 |
| `ConversationArchive` | 게임 | 원문과 전달 기록. AI 없는 서버에서도 기록 가능 |
| `WorldRecordingBudget` | 게임 | SQLite와 기존 기록 저장소의 합산 예약/사용량/90% 알림 |
| `KnowledgeAccessService` | 게임 | 대화 직접 수신/관찰/소문 근거와 현재 공개 권한의 capability 발급·검증 |
| `MemoryProjectionStore` | 게임 제공 저장 포트 | AI 소유 비권위 파생 행 저장. 게임 사실/보상 API는 제공하지 않음 |
| `MemoryCoordinator` | AI 응답 | 기존 Derived/Index runtime을 연결, 후보 생성·정정·작업 진행 관리 |
| `MemoryRetriever` | AI 응답 | 허용된 자료만 검색/순위화하고 출처를 보존 |
| `SpeakerContextAssembler` | AI 응답 | 화자별 성격·관계·근거·청중 context 구성 |
| `TurnOrchestrator` | AI 응답 + 게임 계약 | 발언 계획 제안·화자별 순차 생성. 화자 허가/최종 적용은 게임 |

SQLite 물리 저장은 게임이 호스팅하지만 파생 기억의 내용은 AI의 해석이다. 같은 파일에 저장한다고 AI의 평가가 게임 사실이 되지 않는다. AI에 JDBC 연결/SQL 문자열/원장 전역 조회 포트를 노출하지 않고 타입이 제한된 비동기 포트를 제공한다.

이 선택은 AI가 꺼져도 전체 대화를 기록하고, 한 writer와 합산 용량으로 운용하기 위한 것이다. 새 독립 모드나 원격 DB 서버는 만들지 않는다. JDBC는 게임 모드 한 곳에서만 패키징하고 클라이언트에서는 DB/native 라이브러리를 초기화하지 않는다.

## 4. 스레드와 커밋 경계

1. 게임 스레드: 현재 참가자·화자·상태·공개 조건으로 제한된 immutable snapshot 생성.
2. 저장 worker: 원문/관련 작업을 transaction으로 저장. 저장 결과만 game executor로 회신.
3. 검색/모델 worker: snapshot과 허용 자료만 사용. Minecraft 객체를 비동기 접근하지 않음.
4. 게임 스레드: session/turn/generation, 참가자, 관련 증거·공개 revision을 재검증.
5. 정상일 때만 대사 전달 또는 기존 Gateway 실행. 이후 실제 결과를 기록.

기존 원장 파일, SavedData, SQLite 사이의 원자적 transaction은 없다. 게임의 durable receipt 뒤에 참조를 기록하고 idempotent cursor로 재개한다. 게임 행동 원장을 재생하며 퀘스트/아이템/소문 발행 같은 부수 효과를 다시 실행하지 않는다.

기록 장애가 게임 진행을 막지는 않는다. 다만 상태는 정상 저장과 구별해야 하고, 기록되지 않은 턴을 영속 기억이라고 안내하지 않는다. 현재 세션의 제한된 휘발성 대화는 유지할 수 있다.

## 5. 제약이 바뀌는 지점

기존 `ConversationMemoryContext`를 임의 가변 객체로 바꾸지 않는다. 신/플레이어가 하나라고 가정한 v1 소비자는 adapter로 유지하고 v2 capability를 별도 추가한다. 새 화자의 읽기 scope를 만들었다고 행동 scope까지 확장하지 않는다.

권한 검증 실패 시 기존의 더 넓은 자료/공유 프롬프트로 fallback하지 않는다. 안전한 현재 대화만으로 생성하거나 응답을 취소한다. 게임·AI 버전이 맞지 않으면 새 기능만 명시적으로 비활성화한다.

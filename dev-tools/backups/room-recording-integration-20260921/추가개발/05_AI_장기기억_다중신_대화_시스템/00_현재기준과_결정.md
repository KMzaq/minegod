# 00. 현재 기준과 결정

2026-09-20 / 설계 기준점. 후속 구현자는 착수 시 최신 인수인계와 실제 변경분을 다시 확인한다.

## 1. 실제 확인한 기반

| 영역 | 현재 기준 | 이번 설계의 대응 |
|---|---|---|
| 행동 기록 | `ActionRecord`, `ActionLedgerStore`, `ImportantEvents`; 일반 행동 통계 우선, 중요 결과 상세 기록 | 생산자를 다시 만들지 않고 조회·근거 참조 연결 |
| 주시 | `WatchContract`, `AsyncGodWatch`, 보상 claim의 주시 획득, 차폐·활동 요약 | 실제 관찰 증명과 원본 revision을 재사용 |
| 경험 읽기 | `ExperienceAccess`, `ExperienceLease` | 게임 발급 읽기 권한 및 최종 현재성 검증 확장 |
| 개인 기억 | `MemoryJournal`, `DerivedService`, `MemoryIndexRuntime`, `RecallSearch`, `HybridRetrieval` | 저장 인터페이스 교체와 계층 통합. 기존 회상 의미·정정/격리 회귀 보존 |
| 모델 | CPU bge-m3 + 기존 Gemma 무접속 정리, `ModelAdmission` | 모델 교체·추가 설치 없이 재사용 |
| 소문·평판 | `CourierRumorService`, `SocialRuntime`, `ReputationService`, `OllamaSocialReview` | 실제 생성/수신/설득 회복 연결 보존. 별도 평판 엔진을 만들지 않음 |
| 다중 플레이어 | `AiConversationRuntimeService.joinConversation`; 명시 합류·새 공유 세션·최대 16명 | 기존 퀘스트 동의/개인 이력 경계를 유지 |
| 다중 신 | 기존 primary/secondary 참가자와 대사 계획은 있으나 기억 context는 단일 god 중심 | 각 신의 권한·기억을 독립 조립하는 실행 경로 추가 |
| 빌드 | 현재 게임 API JAR + `mine/mine` legacy AI + checked Gradle overlay | 생성 결과만 수정하지 않음. 전체 legacy 분리는 이번 필수 범위 아님 |

특히 `DialogueMemoryBridge.preparedSpeakers`는 개인 기억이 들어간 경우 다른 신의 발화를 제한한다. 이를 단순 제거하면 개인 기억이 다른 화자에게 섞인다. 신규 다중 신 생성은 화자별 독립 context로 이 제약을 안전하게 대체해야 한다.

근거: [최신 사회적 연결](../../docs/SOCIAL_PIPELINE_COMPLETION_20260920.md), [최신 기록/주시 구현](../../docs/MEMORY_POLICY_IMPLEMENTATION_20260920.md), [다인 대화·퀘스트](../../mythictrpg-main/docs/QUEST_PARTICIPATION_GUIDE.md).

## 2. 구현·검증·배포를 구분

- 개발 버전: 게임 **1.0.11**, AI **0.1.12**. 두 개발 JAR 해시가 인수인계 47절과 일치함을 설계 전 읽기 전용으로 확인했다.
- 실제 서버 배포 파일: 게임 **1.0.2**, AI **0.1.3**, 콘텐츠 **0.1.0**, PERSONAL.
- 기존 11,782 assertion PASS는 앞 작업의 오프라인 검증 기록이다. 이 설계의 검증 결과나 실제 플레이 횟수가 아니다.
- 다인 퀘스트에는 격리 GameTest 이력이 있다. 기억 모델에도 합성 한국어 실제 호출 이력이 있다. 모든 기능이 모델/게임 미시험이라고 뭉뚱그리지 않는다.
- 실제 관찰→기억→소문/회복의 운영 종단, 다인 HUD·지연·부하·복구 수용은 남아 있다. 전서구 엔티티/별도 스폰·실제 콘텐츠 매핑도 남아 있다.

모델 관련 서버 설정 두 파일은 준비돼 있지만 구 배포 AI가 이를 통해 새 기능을 실행하는 것은 아니다. [모델 연결 기록](../../docs/MEMORY_MODEL_CONNECTION_20260920.md)을 기준으로 한다.

## 3. 사용자 확정 사항

| 결정 | 적용 의미 |
|---|---|
| 구조 변경 허용, SQLite 의존성 허용 | 설계·후속 구현의 선택지. 지금 의존성 설치/배포 권한은 아님 |
| 행동은 플레이어별 게임 기록 | NPC별 원본 행동 일지 금지. 공동 사건은 동일 사건 ID 공동 참조 |
| 신의 기억은 대화·주시한 행동·허용 소문 | 서버 전체 보관 자료와 신의 획득 지식을 분리 |
| 우선 전체 대화 기록 | 채널별 수집 adapter. 향후 신 대화 UI/라우팅 변경은 adapter에서 수용 |
| 일수 제한 제거, 월드당 100GB | 원문과 유효 기억에 날짜 기반 만료/검색 제외를 적용하지 않음 |
| 옛 기억·로그는 시험 데이터로 제외 | 새 namespace에 자동 import하지 않음. 원본 보존 |
| 우선 1플레이어·최대 2신, 이후 다인·다신 | 새 경로 초기 수용 범위. 기존 최대 16인 경로를 축소하지 않음 |

“전체 대화”는 “일반 이동/채굴도 매번 상세 행동으로 기록”이라는 뜻이 아니다. 행동 기록 선별은 [현재 단일 정책](../../docs/ACTION_RECORDING_POLICY_20260917.md)을 유지한다.

## 4. 이번에 선택한 기술 기본값

다음은 별도 콘텐츠 확정이 아니라 구현을 진행할 수 있게 정한 추천안이다.

- 신별 DB가 아닌 **월드별 단일 SQLite 파일**. 게임 소유 저장 서비스가 대화 원문과 AI의 비권위 파생 자료를 구획하여 저장한다. 기존 게임 원장은 이전하지 않는다.
- 100GB는 100GiB가 아닌 십진 바이트 상한이다. 합산 대상/제외 항목은 [03](03_전체대화수집과_저장용량.md)의 단일 정의를 따른다.
- 자동 원문 삭제·FIFO 덮어쓰기 없음. 여유가 부족하면 파생 작업을 먼저 보류하고, 더 기록할 수 없으면 누락 상태를 알린다. 무한 보관과 유한 디스크가 동시에 무한 수집을 보장할 수는 없다.
- Primary는 해당 턴의 진행 화자, Secondary는 선택적 보조 화자다. 초기 새 경로의 게임 Proposal은 Primary만 사용한다. Secondary의 행동이 필요하면 다음 턴에 게임이 역할을 전환한다.
- 원문 수집을 AI 모듈의 모델 성공에 의존시키지 않는다. 서버에서 수락한 대화는 모델 실패에도 남긴다.
- 모든 활성 운영 기능을 한 번에 교체하지 않고 기록/검색/다중 신 전환을 독립 플래그로 나눈다.

## 5. 유지할 기존 결정

주시 시작은 메인 퀘스트 완료나 affinity 임계값이 아니라 실제 **주시 보상 지급**이다. `GodAttentionState`의 메인 수주 권한과 다르다. 획득·현재 관측 가능·실제 목격은 별개다. 차폐 중 일을 나중에 통계 차이로 복원하지 않는다.

소문은 대상 플레이어별로 관리한다. 전서구 사냥 차단의 귀속은 사냥자가 아니라 관찰 대상이다. 기수신 소문과 새 전달 차단을 구분한다. 개인 해명에 따른 회복은 게임 검토를 거친 해당 신의 인식 변화이지 전 세계 원문 삭제가 아니다.

RisuAI, 언어 습득/해독, 전서구 엔티티 제작, 레이드 규칙, 새 수치 평판/보상 밸런스는 이 설계의 구현 범위가 아니다. 미정 신별 관측·소문 매핑은 비활성 또는 격리 fixture로 둔다.

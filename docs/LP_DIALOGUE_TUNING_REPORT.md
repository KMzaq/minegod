## 적용 내용

1. 중복된 작성 지침·TURN_DIRECTIVE·불필요한 빈 문맥을 줄이고, 현재 발언에 직접 응답하도록 프롬프트를 조정했다. 게임의 실행·공개 권한은 유지했다.
2. 최근 대화와 중복되는 기억 및 짧은 근거를 검색 후보에서 제외한다. 직접 인사는 장기 기억으로 저장하지 않는다. 사용할 기억·벡터가 없으면 임베딩 호출을 생략한다.
3. Proposal은 생략 가능하며 최대 1개다. 없는 행동을 `type=none`으로 채우지 못한다. 간결한 JSON을 요청하고 출력 한도를 260→420으로 늘려 잘림 여유를 확보했다.
4. 활성 대화 세션 중 새 기억 후처리를 시작하지 않는다. 종료·유휴 30초 이후 처리하며 품질 평가는 실제 요청에서도 제외한다. 후처리가 지연되면 새 장기 기억의 의미 색인·요약도 늦어질 수 있다. 원문 저장은 유지된다.

소유 모듈은 `mythai-ai-response`다. 게임 코드나 정적 캐릭터 JSON은 수정하지 않았다. 세부 구현·설정은 [기억 가이드](../mythai-ai-response/AI_MEMORY_RAG_GUIDE.md)의 최신 절을 따른다.

## 실제 모델 비교

같은 기록 입력·이력으로 로컬 `gemma4:12b` 생성 단계만 비교했다. 아래는 **최종 수정본의 마지막 실행**이다. 의도 분류, 기억 검색 대기, 인게임 HUD 시간은 포함하지 않는다. LP 직접 A/B가 아닌 튜닝 전 RAG 버전과의 비교다. 호출 순서·모델 캐시·무작위 생성 영향이 있어 단일 실행 시간으로 지속적인 속도 향상을 보장할 수 없다.

| 입력 | 튜닝 전 생성 | 튜닝 후 생성 | 입력 토큰 전→후 | 출력 토큰 전→후 |
|---|---:|---:|---:|---:|

앞선 두 조정 단계에서도 튜닝본은 각 3개 요청 모두 완전한 JSON을 반환했고, 당시 튜닝 전 버전은 마지막 요청이 출력 한도에서 잘렸다. 중간 결과는 `dialogue-tuning-comparison-first.json`, `dialogue-tuning-comparison-second.json`으로 구분했다. 최종 원문·통계는 [최종 비교 JSON](../mythai-ai-response/build/reports/dialogue-tuning-comparison.json)에 있다.

**확인된 개선은 문맥량 감소와 이번 표본의 출력 안정성이다. 말투·속도의 전면 개선은 확인되지 않았다.** 최종 결과에는 질문에 할 일의 종류를 설명하는 변화가 있었지만, “내게 증명”, “행운”, “주머니” 같은 관념적인 표현과 훈계가 남았다. 일부 제안 설명은 영어이거나 대사와 선택된 퀘스트가 충분히 맞지 않았다. 서버 검증은 그대로 유지되지만, 자연스러움과 정확한 퀘스트 설명은 사용자의 실제 테스트가 필요하다.

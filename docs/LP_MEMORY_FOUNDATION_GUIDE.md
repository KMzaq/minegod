## 구현 범위와 아직 없는 기능

- 게임이 발급한 월드·상호작용·generation·플레이어·신·실제 청중으로 기억을 격리한다. AI가 지정한 ID로 권한을 만들지 않는다. 일반 채팅 전체는 수집하지 않으며 직접 `/ai_test start`만 실행한 세션에는 운영 기억 권한을 주지 않는다.
- 운영 대화 Adapter가 수락한 플레이어 입력과 HUD 페이지/대체 채팅으로 전송한 NPC 발언을 출처별로 기록한다. 전송은 클라이언트가 실제로 읽었다는 확인이 아니다. 플레이어 주장·NPC 발언을 게임의 사실로 승격하지 않는다. 별도 선제 대사 준비 경로는 기억 조회만 연결했으며 그 첫 대사의 장기 기록은 아직 연결하지 않았다.
- 같은 월드·신·플레이어 및 허용 청중을 먼저 제한한 뒤 로컬 한국어 정규화·부분 일치 검색을 한다. 분류와 생성이 같은 참고 자료를 사용한다. 직접 기억과 수신 소문을 **합쳐 최대 3개**, 블록 전체 약 800자 이내다. 관련 없는 턴에는 소문을 매번 넣지 않는다.
- 0.1.3은 후속 발화에 최근 플레이어 문장 최대 2개를 보조 검색하고 자기 귀환에는 6시간 내 이전 세션의 최신 플레이어 발언 1개를 연결할 수 있다. 기록 시각/조건부 생성 지침으로 과거·현재의 연결을 지원한다. 지침 입력은 위 800자 데이터 블록과 별개이며 추가 LLM 호출은 없다. 의미 검색/저장소 자동 정정은 아니다.
- 종료·다시 시작·대화 ON/OFF 전환은 generation을 바꾼다. 선택한 기억의 정정/삭제 또는 소문 취소 후 도착한 응답은 적용하지 않는다. 검증 실패로 남은 pending도 해제한다.
- 선제 대사 준비에 주 신의 개인 기억을 넣었다면 그 신의 대사만 수락한다. 모델이 다른 참가 신의 이름으로 그 기억을 발화하는 것을 거절한다. 이는 다중 신 운영 대화 전체를 새로 지원한다는 뜻은 아니다.
- 개인 기억은 비동기 단일 작성자·제한 큐·파일 잠금·journal/snapshot으로 저장한다. 재시작 복원, 중복 거절, 정정/삭제 revision, 오래된 작업의 삭제 기억 재생 방지를 구현했다. 저장 실패는 로그/상태에 표시하며 기억 없이 대화를 진행할 수 있다.
- 소문은 게임의 별도 SavedData에 관찰 근거·주장·수신 기록으로 나눠 둔다. 수신 완료와 내용의 진실성은 별개다. AI 쪽에는 현재 신·대상·청중에 허용된 읽기 결과만 전달한다. 게임의 변경 API는 소문 패키지 내부로 제한했다.
- 전서구 상태 머신에서 사냥은 **관찰 대상 플레이어의 소문만** 차단한다. 다른 플레이어의 전파는 유지한다. 이전 generation의 관찰·대기 전달·늦은 발행은 거절하고 복합 대상 자료로 차단을 우회하지 못하게 한다.

다음은 **아직 구현/연결하지 않았다**:

- 중요한 약속·사건의 자동 AI 추출/요약, 발언을 통한 자동 정정, 퀘스트·건축 등 `GAME_CONFIRMED` 이벤트의 자동 기억 연결. 현재 중요 기록은 관리자 `pin`, 정정은 내부 API 기반이다. 중요한 약속을 알아서 평생 기억하는 완성본이 아니다.
- 의미 임베딩·벡터 DB, 후처리 모델 스케줄러, 오래된 원문의 자동 보관/삭제. 현재 망각은 검색 우선순위와 유효 기간에만 적용한다.
- 실제 전서구 엔티티·하늘섬 조우·사망 이벤트 연결·재생성, 사냥자와 관찰 대상이 다를 때의 귀속 정책.
- 대화/장비/업적의 자동 목격 판정과 맥락형 소문 후보 생성, 발행 중요도 검증, 신화권별 전파망·관심/신뢰, 큰 업에 의한 대표 명성 교체·관계/퀘스트 불이익·회복 콘텐츠.

따라서 전서구·소문 API를 만든 것만으로 실제 게임에서 소문이 자동 발생하거나 사냥 시 차단되는 것은 아니다. 실제 연결 전에는 설계 10절의 미확정 콘텐츠 선택을 확인해야 한다. 현재 시험 상태 머신은 제안 기본안(기존 수신 유지, 미전달 무효화, 긍정·부정 함께 차단, 재생성 후 미전달 일괄 재전파 없음)을 검증한다. 이 값을 운영 밸런스로 승인받았다고 해석하지 않는다.

## 설정과 안전 경계

설정 위치는 해당 실행 폴더의 `config/mythictrpg/ai-memory-foundation.json`이다. 후속 세팅으로 실제 서버에는 PERSONAL을 명시했다. [예제](examples/ai-memory-foundation.example.json)는 OFF인 문서용 예제로 실제 서버 설정과 다르다. 설정은 재시작 시 읽는다. 누락·손상·알 수 없는 schema/mode·4KB 초과는 OFF로 처리한다.

| mode | 동작 |
|---|---|
| `OFF` | 새 기억 검색·저장·프롬프트 주입·소문 효과 없음. 기존 LP 대화 경로 유지 |
| `PERSONAL` | 개인 발언 기록/검색만 사용. 기존 게임 행동 권한은 그대로 |
| `RUMOR_TEST` | 개인 기억+수신 소문 대사 시험. **그 실행 서버의 모든 AI Proposal 실행을 차단**하고 대화 시작의 NPC 방문 퀘스트 진척·AI 발화 기반 신 식별 변경도 억제 |

RUMOR_TEST는 일반 운영 모드가 아니며 별도 시험 환경용이다. 모든 Minecraft 행동을 읽기 전용으로 만드는 샌드박스는 아니다. 이동·전투 등 다른 게임 기능이나 다른 모드까지 비활성화하지 않는다. AI가 효과를 실행했다고 말하는지까지 자동 검증한 것도 아니다.

새 필드는 기존 Snapshot/Proposal 생성자를 바꾸지 않는 별도 `com.sande.mythictrpg.ai.memorycontract.ConversationMemoryContext` 계약이다. 1.0.2에서 게임 계약을 AI의 레거시 `ai.memory` 패키지와 분리했다. 필드/저장 형식은 같다. MythicTRPG만 행동 권한과 게임 사실을 소유하며 FTB Quests의 수주/팀 공유/보상 소유권은 바꾸지 않았다. 콘텐츠 신 ID·프로필도 그대로다. [액션 가이드](../mythictrpg-main/docs/AI_ACTION_INTEGRATION_GUIDE.md)의 Validator/Executor를 우회하지 않는다.

## 저장·보존·진단

AI 저장 경로는 해당 월드 루트 아래 다음과 같다. 과거 `mythictrpg-ai-memory` 또는 v2 자료를 자동 이관하지 않는다.

- PERSONAL: `mythictrpg-ai-memory-lp-v1/`
- RUMOR_TEST: `mythictrpg-ai-memory-rumor-test-v1/` — 시험 소문이 개인 운영 기억으로 섞이지 않도록 분리
- 게임 소문: 별도 SavedData 키 `mythictrpg_memory_rumor_v1`

개인 journal은 성공한 저장의 순번과 삭제 ID를 보존한다. snapshot은 임시 파일 기록 후 원자적으로 교체하고 이전 snapshot을 남긴다. 손상/미지원 자료는 자동 덮어쓰지 않고 사용 중지한다. 소문 SavedData의 미지원 원문도 보존한다. 파일 잠금으로 같은 저장소의 중복 작성자를 거절한다.

초기 기술 상한은 대기 256건, 저장소 12,000건, 신·플레이어·월드별 2,000건, 삭제 ID 50,000건, 파일별 64MB다. 가득 차면 신규 저장을 거절하고 로그로 알린다. 사소한 발언은 오래될수록 순위가 낮아지고 30일 후 일반 회상에서 제외한다. **파일에서 30일 후 삭제하는 것은 아니다.** pin은 이 검색 만료를 면제하지만 내용 관련성·공개 범위를 면제하지 않는다. 기간/상한은 코드의 초기 시험 값이며 운영 전 조정·자동 정리 정책이 필요하다. 검색 예산 15ms는 초과 시 참고 자료를 생략하는 방어 장치이지 전체 응답 지연의 실측 SLA가 아니다.

OP 권한 2 이상인 플레이어가 서버 승인 대화 중 자신의 현재 신에 대해서만 사용할 수 있다:

```text
/ai_memory status
/ai_memory list
/ai_memory pin <기억 UUID>
/ai_memory unpin <기억 UUID>
/ai_memory forget <기억 UUID>
```

`list`는 최근 10건과 UUID를 표시한다. `STALE`이면 목록을 다시 확인한다. `forget`은 활성 기억/색인 및 늦은 동일 ID 재삽입을 막지만, 과거 journal 구간·이전 snapshot·외부 백업을 보안 삭제하지 않는다. 개인정보 완전 삭제로 안내하지 않는다. 개인 기억 삭제가 이미 게임에서 수신한 소문을 자동 취소하지도 않는다.

## 빌드와 검증

프로젝트 루트에서 게임을 먼저 빌드한다. `mine/mine`의 AI 소스/JAR 추출 구조를 유지하며 `build/generated`만 수정하지 않았다. 새 AI는 게임 **1.0.2 이상**을 요구하므로 게임 1.0.0/1.0.1과 혼합 배포하지 않는다. 서버/클라이언트 게임 JAR도 한 쌍으로 검증해야 한다. 콘텐츠는 0.1.0 유지다.

```powershell
.\dev-tools\run-mythictrpg-gradle.cmd jar memoryFoundationTest
.\dev-tools\run-mythictrpg-gradle.cmd -p ../mythai-ai-response jar memoryFoundationTest
.\dev-tools\run-mythictrpg-gradle.cmd runMemoryGameTestServer
.\dev-tools\Test-MemoryFoundationRelease.ps1 -ServerProfile PERSONAL
```

GameTest 실행 폴더는 `mythictrpg-main/build/memory-gametest-runtime`이며 실제 `server/`와 분리된다. 아래는 기반 구현 완료(서버 배포 전)의 검증 결과다. 후속 배포에서는 소문 39개/기억 656개를 다시 통과했으며 변경 제외 대상 302개 파일과 새 배포/설정을 구분해 확인했다. 192개 GameTest를 이번 실제 서버 부팅 검증으로 인용하지 않는다.

- 게임/AI JAR 빌드 성공. 소문 상태 머신 **39개 검사**, AI 기억 **656개 검사** 통과.
- 격리 NeoForge **필수 GameTest 192개 모두 통과**. 계약·generation·시험 모드 행동 차단·SavedData 재직렬화/손상 보존 및 기존 퀘스트·스토리 등 회귀 테스트 포함.
- 6개 동시 작성 스레드의 240건 저장·분리·플레이어별 순서, 권한 선필터, 재시작, 정정/삭제/늦은 쓰기, 중복 작성자, 상한/손상, 프롬프트 공유 예산 검증. 실제 6명 LLM 지연 측정과는 다르다.

- 원본 LP JAR: `server/backups/LP/` — 덮어쓰지 않음.
- 검증한 LP AI 소스·필수 입력: `server/backups/LP-source-20260912/` — 298개 파일. 게임 전체 소스는 아님.

기반 구현 완료 당시 서버는 LP였으나 후속 요청으로 새 버전을 배치했다. LP 원본은 보존하며 [배포 안내](LP_PERSONAL_MEMORY_TEST_SETUP.md)를 따른다. 기존 두 AI JAR 교체 스크립트만으로 새 게임/설정까지 복원하지 않는다. 소스 복원에는 패키지 경로 변경을 포함한 최신 합산 목록을 사용하고 최초 36개 목록만 사용하지 않는다.

향후 사용자가 소스 복원을 요청하면 다음 순서로 별도 작업한다:

1. 현재 해시와 차이 목록을 비교하고 후속 변경을 별도 백업한다. Git 전체 reset이나 프로젝트 폴더 전체 삭제는 하지 않는다.
2. 목록의 `MODIFIED` 파일만 906개 스냅샷의 동일 `workspace/` 경로에서 복원한다. `ADDED` 파일은 정확한 개별 경로를 확인해 별도 보존 후 활성 소스에서 제거한다. 그 외 기존 미커밋 변경은 유지한다. 개발 검사/이력 문서는 복원 상태에 맞게 별도로 갱신한다.
3. 버전/build.gradle/오버레이도 함께 복원하고 이전 생성물과 섞이지 않게 새 빌드를 검증한다. LP 동일성 검사로 **새로 빌드한** AI 응답/콘텐츠를 비교한다. 개발 버전 산출물을 LP로 오인하거나 신구 JAR을 동시에 배포하지 않는다.
4. 서버 파일 교체는 별도 승인·정상 종료·게임/AI/클라이언트 조합 확인을 거친다. 월드 전체와 플레이어 진행도를 되감지 않는다. 새로운 SavedData를 사용한 월드의 LP 다운그레이드는 별도 시험해야 한다.

복원 데이터와 경로는 보존·검증했지만 **현재 개발 소스를 실제로 다시 LP로 되돌리지는 않았다**.

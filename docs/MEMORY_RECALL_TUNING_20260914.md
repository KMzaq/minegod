## 관찰과 수정

9월 14일 21:12~21:15(KST) 포르투나 대화에서 `난 수영을 못해`는 저장됐고, 재시작 후 `수영을 해보려해`의 생성 요청에도 전달됐다. 그러나 답은 `꽤나 용기 있는 시도네. 물속으로 뛰어들 준비는 됐어?`였다. 저장/조회 성공과 자연스러운 회상 성공은 다르다. `바다에 놀러가려고` 턴에는 수영 기억이 선택되지 않았다. 짧은 잡담·반복 금지 지침이 기억 활용과 충돌할 가능성을 확인했다.

- 현재 문장 외에 **최근 플레이어 발언 최대 2개**를 보조 검색한다. 지시어/후속 질문 또는 현재 문장과의 어휘 연결이 있을 때만 사용하고 명시적 화제 전환에는 끈다. NPC 말은 검색 주제의 근거로 쓰지 않는다. 직접 일치보다 낮은 가중치이며 기존 15ms/최대 3개 예산을 공유한다.
- 자기 귀환을 표현하는 짧은 인사에는 **6시간 이내 다른 세션의 최신 플레이어 발언 1개**를 연결할 수 있다. 모든 재접속에 일괄 주입하는 요약이 아니다. 신/플레이어/월드/청중 조건은 그대로며 소문/NPC 발언은 귀환 연결 대상이 아니다.
- 실제 참고 기억이 있을 때만 생성 system에 `MEMORY_USE_POLICY`를 추가한다. 개인 특성·약속·변화·정정과 현재 발언의 연결을 일반적인 짧은 잡담 선호보다 우선한다. 매번 회상을 말하거나 모든 신을 친절하게 만들지는 않는다. 게임 권한·화자·공개 범위·출력 스키마는 우회하지 않는다.
- 기억의 기록 시각을 전달하고 글자 예산이 부족하면 새 발언을 우선 보존한다. 현재 정정은 과거 정보보다 우선 해석하도록 안내한다. **저장소 자동 정정/중요도 분류를 구현한 것은 아니다.**
- `MEMORY_RECALL` 로그에 binding 여부, 선택된 기억 UUID, 참고 블록 길이를 남긴다.
- 활성 세션 중 거절된 `/ai_test start`가 먼저 기억 연결을 끊던 결함도 수정했다. 거절 여부를 검사한 뒤에만 초기화한다.

수정 소유자는 AI의 `MemoryRecallPolicy`, `MemoryJournal`, `DialogueMemoryBridge`, 검사된 Gradle 오버레이다. `mine/mine` 원본이나 `build/generated`를 직접 고치지 않았다. 공개 게임 DTO, SavedData/기억 journal 스키마, 퀘스트·보상·FTB 권한은 그대로다.

## 성능과 제한

운영 대화의 LLM 호출 횟수/모델/출력 상한은 늘리지 않았다. 기억이 없으면 기존 생성 system도 그대로다. 기억이 있으면 활용 지침·시각 텍스트가 추가되므로 입력 처리 비용은 조금 늘 수 있다. 전체 응답시간이 개선됐다고 실측하지는 않았다.

**`바다`만으로 `수영을 못함`을 의미적으로 항상 찾아내는 기능은 아직 없다.** 최근 맥락에도 관련 단서가 없으면 다음 단계의 의미 검색이 필요할 수 있다. 귀환/후속 발화 감지는 제한적인 언어 패턴이다. 특정 예시의 고정 NPC 답변이나 임베딩 모델은 추가하지 않았다.

## 인게임 시험

1. `/mythadmin interaction god @s mythictrpg:fortuna 대화를 시작하자.`로 승인 대화를 연다. 마지막 문자열은 **신의 첫 대사**로 기록되므로 플레이어 자기소개/개인 정보는 넣지 않는다. 자신의 말은 시작 뒤 일반 채팅으로 입력한다.
2. `/ai_memory status`, `/ai_memory list`로 저장 상태를 확인한다. 직접 `/ai_test start`는 여전히 운영 기억 시험 경로가 아니다. `/ai_test stop`은 AI 대화/기억 연결을 종료하지만 기록은 삭제하지 않는다. HUD 상태 표시가 남을 수 있고 G키는 숨김뿐이다.
3. `난 수영을 못해`를 기록하고 새 승인 대화에서 `수영을 해보려해`를 말해 본다. 이어 `이번에는 배워보려고`도 시험한다. 기대 기준은 과거와 현재의 연결이지 고정 정답 일치가 아니다.
4. `이제 배워서 할 줄 알아`라는 정정을 받아들이는지, 화제 변경 후 같은 기억을 반복하지 않는지, 다른 신에게 개인 기억이 새지 않는지 확인한다.

## 0. 통계와 인정 실적 및 사건 기록의 구분

- Minecraft 누적 통계는 기존 게임 원본으로 유지한다. 기본 통계로 얻을 수 없는 실적만 필요한 카운터로 보완한다.
- 업적·보상용 채굴 실적은 [정책 3절](ACTION_RECORDING_POLICY_20260917.md)의 출처 규칙을 적용한다. 설치/생성 출처가 없는 블록의 인정은 게임 규칙이며 자연 생성의 입증이나 목격 증명으로 승격하지 않는다.
- 기록 대상으로 선별한 사건만 아래 사건 계약으로 저장한다. 일반 처치/이동을 상세 저장하지 않아도 기존 관찰 이벤트·퀘스트/조우/스토리 처리까지 중단하는 것은 아니다.
- 기본 통계/인정 실적의 공개 범위와 직접 관찰 사건의 공개 범위를 혼동하지 않는다. 통계만으로 구체 시각·장소·목격자를 재구성하지 않는다. 일상 주시 집계는 허용 구간만의 제한된 요약으로 설계하며 시간 창/상한·신별 관측 범위의 실제 매핑/계약 적용은 남았다.
- 위 정책에 맞춘 출처 추적·실적 소비자·사건 필터의 소스 적용/검증은 미완료다. 기존 카운터나 원장을 일괄 초기화하지 않는다.

## 2. 논리 레코드 v1

아래는 단계별 **추가 계약**이다. 행동 사건의 실제 생산자는 2단계의 게임 소유 `ActionRecord/Draft`다. 3단계는 `WatchContract.Watch/Proof`, `WatchStore/WatchJournal`, `AsyncGodWatch`에 매핑하며 세부 저장 방식은 3단계 기록을 따른다. 누락 필드를 AI가 채우지 않는다. 미지원 버전은 capability 불가용으로 처리하고 원문은 보존한다.

### 행동 사건

| 필드 | 의미/검증 |
|---|---|
| schemaVersion | 최초 1, 지원하지 않는 버전은 실행/투영하지 않음 |
| worldId, eventId | 게임이 발급하는 월드 ID와 영구 발생 ID. 모델 입력 아님 |
| sourceRef, sourceRevision, dedupKey | 원천 기록/어댑터와 revision, 동일 **발생**의 중복 키. 같은 행동 종류/같은 tick이라는 이유만으로 별개 사건을 합치지 않음 |
| sequence | 원장 내 단조 순서. 재시작 후 유지. tick 초기화/차원 이동과 별개 |
| actorId, subjectIds | 행동자와 영향을 받은 실제 대상. 플레이어/엔티티 종류 구분 |
| occurredAtUtc, gameTick, dimensionId, gameDayTime | 실제 발생 시점과 게임 시간. nullable인 값은 이유 기록, 임의 추정 금지 |
| type, outcome, payload | 등록된 타입별 제한 payload. 시도/취소/실패/피해/처치/완료를 구분 |
| visibilityRef | 게임이 정의한 민감 필드/공개 조건 참조. 원장의 존재만으로 신에게 공개하지 않음 |

이동 샘플은 이동 횟수/거리의 완전 기록이 아니다. 동일 적에게 여러 공격은 각각 발생 키가 필요하다. 실제 피해 적용 전 취소 가능한 알림을 성공 결과로 기록하지 않는다. 타입별 완료 판정 지점은 2·5단계 지원표와 테스트로 확정한다.

5단계는 위치/차원/텔레포트, 채굴 요청·시도·반환·제거, 근접 공격 시도/반환·피해, 지상 줍기, 사망, 퀘스트 완료/평가 type/outcome을 추가했다. 새 원본은 `mythictrpg:detail/<type>` 출처와 `admin_only_unprojected`, 알맞은 subject kind를 요구한다. `attempt_id`는 시도/결과 연결이며 독립 업적 2회라는 뜻이 아니다. 기존 작물 제거/차원/새 상세 행의 다른 측면을 중복 합산하지 않는다. 새 타입은 GodWatch/Experience에 자동 투영하지 않는다. schemaVersion=1의 enum 확장이므로 새 행 저장소의 구버전 다운그레이드는 보장하지 않는다.

AI 파생 자료는 원문 ID+SHA-256+추출 버전, 기존 world/god/player/audience와 현재성 검사를 유지한다. index-v2는 모델 digest/차원을 분리하고 정정 후보의 전후 원문 해시를 함께 보존한다. 자동 추출 종류/정정 링크는 비권위 후보이며 원문 삭제/중요도 확정/게임 실행을 허용하지 않는다. 게임 사실·목격·보상 authority를 만들지 않는다. 경험 집계는 lease의 모든 근거를 유지하고 동일 사건 ID를 1회만 센다. 실제 지원/미적용 경계는 5단계 후속 기록을 따른다.

### 후속 상세 결과 계약 요구 (아직 DTO에 적용하지 않음)

- 전투 결과: 게임이 확정한 네임드/제작 전투 ID와 개체/실행 ID, 결과·발생 시점, 차원/좌표/바이옴, 실제 참가자와 처치 판정자를 구분해야 한다. 한 전투를 여러 참가자에게 보여줄 때 같은 사건을 공동 참조하고 필드별 공개를 검증한다. 기존 단일 `actorId`를 모든 참가자/보상자로 해석하지 않는다.
- 퀘스트·업적: 종류/중요도로 누락시키지 않는다. 퀘스트의 의미 있는 상태 전환과 제작/바닐라/외부 모드 업적·발전 과제 달성을 게임 결과로 받아 식별자·당사자·시점·장소와 연결한다. 완료/전역 무효화/보상 지급 상태는 각각 구분하며 일반 행동의 매번 상세 로그를 다시 요구하지 않는다.
- 위치·바이옴은 실제 발생 지점에서 동결한다. 현재 위치나 현재 바이옴으로 과거 사건을 채우지 않는다. 오프라인 등 확인할 수 없는 필드는 불가용 사유를 남긴다.
- 기존 `ActionRecord`에 바이옴·전투 공동 참가자·업적 전용 계약 전체가 있는 것은 아니다. schemaVersion, 예산, 생산자/소비자, 재생/구버전 호환을 함께 검토하고 구현/시험해야 한다.

### 주시 상태

| 필드 | 의미/검증 |
|---|---|
| worldId, godId, targetPlayerId, watchId | 기존 게임 God ID 사용, 신/대상별 독립 상태 |
| eligibilityRef | 조건·관계 등 게임 원본의 자격 근거와 revision |
| policyId, policyVersion | 신별 관측 범위/가림/비밀 정책. 미확정이면 운영 비활성 |
| state | ACTIVE / PAUSED / ENDED. 자격 있음과 ACTIVE는 별개 |
| effectiveFromSequence, effectiveUntilSequence | 게임이 확정한 반개구간 [시작, 종료). 같은 tick 내부 경계도 순서로 판단 |
| causeRef, revision | 시작·중지·종료 이유와 변경 버전. 모델의 감정/호감도 추정으로 생성하지 않음 |

주시 시작 이전의 과거 원장을 열지 않는다. 주시 종료는 이미 본 기억의 일괄 삭제가 아니다. 반면 관측 오류로 근거가 취소되면 파생 자료를 무효화한다. 신 수×플레이어 수×전체 원장을 매 tick 순회하지 않고 대상별 활성 구독 인덱스를 사용한다.

후속 콘텐츠 흐름은 서버 공용 해금·개인 조우와 별도로, 작성된 퀘스트 보상 ‘OOO의 주시’의 실제 개인 지급을 획득 근거로 삼는다. 메인/첫 완료자/같은 팀이라는 사실만으로 자동 부여하지 않는다. 기존 보상 claim/선택/오프라인·재시도 처리를 사용하고 획득 기록과 현재 ACTIVE/PAUSED/ENDED 관측 상태를 구분한다. 구체 지급 타입/영속 연결은 미구현이며 단순 title 해금으로 대체하지 않는다.

보상 획득 계약은 등록된 신·플레이어·지급 출처/영수증과 기존 world 범위를 참조해야 한다. 지급권 예약·선택 대기·실제 적용·관측 가능을 구분하고 같은 지급 재생/다른 퀘스트의 동일 신 보상으로 중복 활성화하지 않는다. 미등록 신이나 불허 보상은 게임 검증에서 거절한다. 구체 schema/호환/복구 방식은 생산자와 소비자를 함께 수정할 때 확정한다.

상위 존재의 신전 같은 영역은 신별 차폐 정책으로, 누구도 외부에서 볼 수 없는 공간은 외부 주시 전체 차단으로 설계한다. 획득 상태는 유지하되 차폐 구간의 관찰 증명·통계 요약·업적 유래 정보는 관측으로 투영하지 않는다. 영역/위계/허용 신은 명시된 게임 정의만 사용하고 영역을 떠난 뒤 소급 목격하지 않는다. 차단 안내 자체로 비밀 위치를 공개하지 않는다.

일상 활동 요약은 원본 하나의 상세 행동 대신 **관측 가능한 구간과 집계 근거**를 참조할 별도 연결이 필요하다. 주시 시작 전 생애 누적치나 가림/중단 구간을 포함하는 차이를 목격으로 변환하지 않는다. 이벤트별 `eventId` 증명인 현재 계약을 그대로 집계 증명이라고 부르지 않고, 범위·revision·정정/무효화·세션/청중 검사를 유지하는 방식으로 후속 설계한다.

### 관찰 증명

| 필드 | 의미/검증 |
|---|---|
| observationId, worldId, eventId, sourceRevision | 실제 원본 사건과 revision. 원본 없는 증명만 커밋하지 않음 |
| observerGodId 또는 observerRef | 직접 주시 신 또는 실제 전서구 등의 게임 관찰자. 경로를 혼합하지 않음 |
| acquisitionKind | DIRECT_WATCH / PHYSICAL_WITNESS 등 등록된 경로. 수신 소문은 직접 목격으로 재분류하지 않음 |
| watchRef / witnessRef, policyVersion, observedAtSequence | 당시 관측권한·물리 목격과 순서 증명 |
| visibleProjection | 그 관찰자가 실제로 알 수 있었던 필드만 포함. 의도·마음·숨은 행동을 덧붙이지 않음 |
| disclosureRef, revision, state | 현재 청중에게 공개 가능한지 재검증하는 참조와 VALID/REVOKED 상태 |

직접 관측, 플레이어가 말한 주장, 전언, 신의 평가를 서로 다른 출처로 보관한다. 누가 누구의 이야기를 했는지도 유지한다. 복수 플레이어 사건은 필드별 공개 조건을 통과한 부분만 투영한다.

## 3. 기억용 읽기 capability

4단계 실제 구현은 게임 `ai.experiencecontract.ExperienceAccess/ExperienceLease/ExperienceView/ExperienceProjection`과 AI `ExperienceMemory/ExperienceHistory/DialogueMemoryBridge`에 매핑한다. 현재 지원은 성숙 작물 제거 한 종류, 최신 허용 증명 16개→관련 1개다. 생성자 소유권/필드별 공개/500ms 불가용 fallback/최종 동기 검증/후속 대사 계보·새 journal 제어 레코드의 호환 한계는 [4단계 계약 설명](EXPERIENCE_STAGE04_20260915.md#3-게임ai-읽기-계약)을 따른다. 이 논리 계약을 모든 행동·운영 주시·실제 LLM 검증 완료로 해석하지 않는다.

게임이 발급한 현재 대화 범위로만 `ExperienceView`를 요청한다. 요청에 God ID 등이 있어도 허용 근거는 서버 세션이다. 반환은 허용된 관찰 참조/원본 revision/출처/시각/제한된 설명/공개 조건 토큰을 포함한다.

- `available=false`와 ‘허용된 결과 0건’을 구분한다. 허용 밖 사건의 개수·존재·내용을 프롬프트나 플레이어 화면에 노출하지 않는다.
- 읽은 snapshot과 근거별 revision을 보관하고 대사·Proposal 적용 전 현재 세션/turn/generation, 관찰 유효성, 공개 조건을 재검사한다.
- 다른 플레이어의 정상 쓰기로 모든 응답을 무효화하지 않는다. 같은 범위의 관련 정정/삭제/관측 취소는 늦은 응답 적용을 막는다.
- 기록/증명 저장은 제한 큐와 단일 작성자로 비동기 처리한다. PENDING은 저장 성공이 아니다. 실패·용량·관측 공백은 상태/진단에 남긴다.
- 재시도는 sourceRef/eventId/revision으로 멱등 처리한다. receipt cursor는 내구성 확보 후 전진한다. 재생이 퀘스트 완료나 보상을 다시 실행하지 않는다.
- AI 미설치·기억 불가용·신규 capability 미지원이어도 기존 게임 진행은 유지한다. AI는 관측 증명 발급 API를 갖지 않는다.

## 4. 전서구·평판으로 확장할 때 유지할 경계

전서구 사냥은 게임이 지정한 **해당 대상 플레이어의 소문**을 차단한다. 다른 플레이어의 소문까지 전역 차단하지 않는다. 직접 주시와 소문 전달은 별개 경로다. 다른 플레이어가 섞인 자료나 신 간 임의 재전파로 대상별 차단을 우회하지 못한다.

소문을 여러 번 읽거나 NPC가 재진술해도 독립 증거/별도 업적으로 중복 산정하지 않는다. 대표 수식어·호감도 효과·퀘스트 제한/보상은 별도 승인된 게임 정책에서만 적용한다. 해명·반증·취소·회복은 효과 적용 전에 함께 설계한다.

## 5. 확정 정책과 남은 선택

- 주시 범위는 신별 권능·영역·장소/가림 제한이다. 실제 주시 보상을 지급받아 획득하고 특별한 사유가 없으면 지속한다. 메인 자동 부여는 이전 정책이다. 보상 수신/획득·관측/차폐·중복/복구 연결은 미구현이며 운영 매핑·예외/수치는 확인 후 적용한다.
- 다른 신과의 사적 대화는 명시적 공개 근거 없이 전달하지 않는다. 신별 신전 차폐/완전 차폐 방향은 확정됐고 정식 공간 경계·위계/허용 목록은 콘텐츠 매핑 사항이다.
- 주기 좌표+차원/텔레포트 분리, 공격·채집 시도/취소/실패 포함은 9월 16일 당시 요청/구현 이력이다. 후속 결정은 일반 행동 통계 우선, 네임드 이상/제작 전투 결과와 모든 퀘스트/업적 상세 기록, 좌표·바이옴이다. 일상 관찰은 허용 구간의 활동 요약으로 설계했다. 콘텐츠 ID/발전 과제 생산자 연결·모드별 출처 추적 범위와 실제 계약 연결을 후속 검토하며 기존 상세 타입은 OFF로 보존한다.
- 2단계 후속 사용자 답변: 보관 용량/정리 정책은 **측정 결과를 본 뒤 결정**한다. 사용량 **90%에서 서버 알림과 관리자 용량 증설 안내**는 요청받아 구현했다. 자동 삭제/운영 용량/보관 기간을 확정한 것이 아니다.
- 시간 선택은 “내일”은 현실 날짜, 일출·일몰은 Minecraft 태양 기준으로 확정됐다. 기존 회상 코드의 UNSPECIFIED/REAL_KST 지원과 운영 적용은 별개이며 이번에는 서버 설정을 변경하지 않는다. 시간대·게임 일광 snapshot 및 잠자기/시간 명령의 세부 처리와 검증은 남아 있다.
- 전서구 개체 귀속/재생성·기존 수신/미전달 처리·평판 강도: 6~7단계 전에 별도 선택한다.

미확정 정책은 OFF로 두고 명시적인 가짜 사건/시험 정책으로 기반을 검증할 수 있다. 기술 계약 초안 작성이 신별 수치/정밀도/운영 활성화의 승인은 아니다.

## 6. 단계별 필수 검증

2단계: 발생 수·순서·월드 분리·중복·취소/실패·재시작/손상/용량·기존 sink 중복 실행 없음.

3단계: A 주시/B 미주시, 시작 전/직후, 종료/중단/재시작, 비밀·현재 청중, 복합 대상, 근거 취소.

4단계: 허용된 작은 사건 한 종류만 원장→관찰→기억→대화까지 연결. 완료와 보상 지급 실패를 구분. 실제 LLM/인게임 검증은 별도 승인.

9월 17일 정책 후속: 본인/타인 설치 제외, 정상 재배 인정, 생성기 제외, 기록 없는 블록 인정과 알려진 출처 우선 적용, 일반 행동 통계 유지/상시 상세 기록 비대상, 중요 사건 장소/중복/취소/재시작, 정보 공개 경계와 기존 게임 소비자 동작을 검사해야 한다. 아직 새 정책의 구현이나 검증 결과는 아니다.

추가 필수 시나리오: A의 해금 이후 B의 개인 조우, 메인 완료만으로 주시 미지급, 실제 자동/선택 보상 지급→해당 신/플레이어 획득, 공동 정산/랭킹 보상 제외와 주시 대상 구분, 재시도/재접속/중복 보상과 관측 저장 복구, 차폐 중 획득 기록 유지·정보 미획득·차폐 해제 후 비소급, 모든 퀘스트/기본·외부 모드 발전 과제의 온라인/오프라인 기록, 공동 참가자/보상/당시 위치 분리, 일반 몹 통계 유지, 중요 기억 정정·기한 경과만으로 실패 확정 금지·반복 회상 비증폭을 검증한다. 이번에는 문서 검사만 수행한다.

0~1단계 당시에는 이 게임 경로를 구현/실행하지 않았다. 이후 2단계에서 행동 원장, 3단계에서 주시/관찰 증명 소스와 오프라인 연결을 구현했다. 운영 주시/AI 공개는 아직 연결하지 않았다. [0~1단계 기록](RECALL_STAGE01_20260915.md), [2단계 기록](ACTION_LEDGER_STAGE02_20260915.md), [3단계 기록](GOD_WATCH_STAGE03_20260915.md)의 완료/미검증 범위를 구분한다.

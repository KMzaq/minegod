# 6단계 전서구·소문 — 선행 점검 및 콘텐츠 결정 대기

> **후속 상태:** 사용자가 엔티티/스폰 이벤트를 나중에 만들고 자동 스폰·재생성 OFF로 진행하도록 요청했다. 이에 따른 소스·오프라인 결과는 [6단계 연결 기반 구현](RUMOR_STAGE06_IMPLEMENTATION_20260920.md)과 인수인계45절을 따른다. 이 문서의 아래 ‘대기/미착수’는 **구현 전 점검 당시 이력**으로 보존한다.

2026-09-20 / 선행 검사·백업 완료 / 6단계 새 소스 미착수 / 배포·서버 실행 없음

## 요청 범위와 결론

사용자는 최신 로드맵의 6단계를 요청하면서 선행 조건의 실제 확인과 기존 백업·검증·실행 제한 유지를 요구했다. 현재 소스는 게임1.0.8/AI0.1.10이며 서버 배포물은 게임1.0.2/AI0.1.3/콘텐츠0.1.0이다.

**독립된 개발 시험 구현을 준비할 소스 기반은 있으나 전체 운영 선행 조건은 충족되지 않았다.** 또한 로드맵10절에서 구현 전에 결정하도록 둔 콘텐츠 선택 두 묶음이 아직 답변 대기다. 이 점검을 6단계 구현 완료나 운영 적용 승인으로 해석하지 않는다. 이번에는 Java/빌드 설정/서버 설정/배포물/월드/기억을 변경하지 않고 점검 결과와 확정 답변만 문서에 기록했다.

새 백업은 기존 도구의 `memory-stage05` 라벨을 그대로 사용했지만 **6단계 요청 전 현재 상태**를 보존한 것이다. 기존2326개는 소스/문서/설정/기존 개발·배포JAR/개인 기억/시험 로그/데이터팩 등 manifest 범위이며 전체 지형 백업은 아니다. LP 및 이전 snapshot을 덮어쓰지 않았다.

### 재사용할 코드와 권한 경계

- `RumorLedger`: 이미 관찰 대상 UUID→전서구 entity UUID→epoch, 증거/주장/미전달/수신을 분리한다. 사망은 관찰 대상에만 적용하고 재시작·재생성 뒤 오래된 전달을 거부한다. 현재 정책 일부는 기존 시험용 제안 기본값이며 운영 승인과 구분한다.
- `RumorSavedData`: 게임 스레드에서 변경하며 버전/손상 격리와 읽기 전용 수신 조회가 있다. AI에 ledger 변경 권한을 공개하지 않는다.
- `ImportantEvents`, 관찰·주시 계약: 게임 사건을 기록한다고 곧 전서구가 목격한 것은 아니다. 원문 로그를 읽어 목격을 추정하지 않는다. 실제 개체/거리/차원/가림/허용 발췌의 증명이 별도로 필요하다.
- `DialogueMemoryBridge`, 기존 오버레이: 허용된 신·현재 청중의 수신 소문을 RUMOR_TEST에만 선택하며 첫인상 대사 경로와 늦은 응답 재검사가 있다. 같은 신화권 자동 공유나 전역 단일 태그를 만들지 않는다. 기존 RUMOR_TEST의 Proposal/방문 진척/식별 변경 차단은 유지한다.
- 물리 개체·사망 hook/재생성, 정책별 관측·발행/수신자 선택은 미연결이다. 기존39개 상태 머신 검사만으로 실제 Minecraft 전서구가 동작한다고 하지 않는다.

## 콘텐츠 질문과 받은 답변

확정 답변:

- **A를 관찰하는 전서구를 B가 사냥해도 A의 소문만 차단한다.** 사냥자 B, FTB 팀, 지역 또는 서버 전체로 확장하지 않는다. 이 귀속은 기존 상태 머신과 일치하며 [소문 설계](LP_LONG_TERM_MEMORY_DESIGN.md)에 반영했다.

답변 대기:

1. 전서구의 수·하늘섬 배치·이동 속도·재생성 조건을 정식으로 정할지, 이번에는 **대상별 한 개체를 관리자가 지정하는 개발 시험 경로**만 구현하고 자동 스폰·재생성은 OFF로 남길지.
2. 기존 제안인 **이미 전달된 소문 유지 / 미전달분 폐기·재생성 후 재전송 없음 / 긍정·부정 모두 차단 / 초기 전파는 전서구만 / 이번은 대사 반영만, 관계·보상 불이익 없음**을 채택할지.

그 밖의 정식 외형/에셋·관측 범위/가림 예외·신별 정보망/관심/출처 신뢰·자연스러운 맥락 후보의 발행 기준은 운영 전에 작성할 콘텐츠다. 위 개발 시험 경로를 택하더라도 운영값을 임의 확정하거나 실제 서버에 명령/설정을 적용하는 승인은 아니다. 관계·퀘스트·경제적 불이익과 회복은7단계로 남긴다.

## 이번 검증 결과

게임 컴파일·오프라인 **1317개 PASS**:

합계 **3938개**를 이번에 새로 재실행했다. 손상 NBT/지원하지 않는 데이터 검사의 ERROR 로그는 예상 거부 사례이며 최종 assertion/빌드 결과는 PASS다. 1/4/6인 합성 파일 fixture는 실제 tick/게임 모드 조합/LLM 지연 측정이 아니다. 신규 JAR 생성·배포, 서버/GameTest 실행, 실제 모델 호출·설치, 월드·플레이어 데이터 변경은 없다. 이전 합성 호출 승인을 이번의 상시 모델 실행 권한으로 사용하지 않았다.

개발 모듈의 오프라인 검사가 기존 Log4j 로그 네 파일(`mythictrpg-main/logs/`의 latest/debug 및 압축 회전 로그)을 갱신했다. 변경 전 로그도2326개 snapshot에 보존돼 있다. 실제 `server/logs`나 월드 로그를 갱신한 것이 아니다. baseline과의 차이는 문서3개·개발 시험 로그4개이며 나머지2319개는 불변이다. 새 점검 문서는 별도1개다.

## 다음 작업

답변 대기 두 묶음을 확인한 뒤 승인된 범위만 구현한다. 개발 시험 경로라면 기본 OFF·명시적 대상/정책으로 개체 생명주기→관측 근거→후보/발행→신별 수신→대사까지 좁은 범위를 연결하고, 대상별 사망/취소·지연 전달·재시작·정보 공개·다른 모드 영향의 오프라인 검사를 추가한다. 실제 부팅/다인 품질·부하·콘텐츠 운영 검증은 별도 허가 후 수행하며 미실시 상태를 유지한다.

이 문서는 **6단계 완료 보고가 아니라 점검·결정 대기 기록**이다. 7단계는 시작하지 않는다.

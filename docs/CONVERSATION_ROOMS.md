# 공개·비밀 대화방 — 개발 구현 가이드

2026-09-23. 게임 `mythictrpg-main` 1.0.16 / AI 응답 0.1.17 / 콘텐츠 레지스트리 0.1.1은 기존 방 전체에 다섯 기능을 연결한다. [전체 방 통합·검증](FULL_ROOM_DIALOGUE_INTEGRATION_20260923.md)이 현재 기준이다. 앞선 [제한적 재통합](ORIGINAL_GOALS_REINTEGRATION_20260923.md)의 1인·2신 반응/단독 비밀방 Hook/PUBLIC 로어 제한은 대체한다. 세 JAR은 서버에 배포했고 클라이언트 필수 게임 JAR도 1.0.16으로 맞췄다. 배포 뒤 서버 부팅·실제 모델·클라이언트 검증은 아직 하지 않았다. `/ai_call` 사용법은 [AI 호출 명령](AI_DIALOGUE_TEST_COMMAND.md)을 따른다.

## 확정한 동작

| 종류 | 입력·출력 | 참가·위치 |
|---|---|---|
| 공개 고정형 `PUBLIC_FIXED` | 일반 채팅. 신 대사와 플레이어 발언을 전역 채팅에 표시 | 시작점과 이어진 동일 바이옴 구역에서 말하면 합류. 구역당 고정방 하나 |
| 공개 이동형 `PUBLIC_MOBILE` | 일반 채팅. 전역 채팅에 표시 | 참가 플레이어 중 한 명의 16블록 이내에서 말하면 합류 |
| 비밀 `PRIVATE` | `/s 할말`. 방 참가자에게만 표시 | 참가 신의 초대와 대상 플레이어의 수락으로 합류. 거리·차원으로 자동 퇴장하지 않음 |

- 같은 신과 플레이어가 **공개방 한 곳 + 여러 비밀방**에 병행 참가할 수 있다. 한 신/플레이어가 서로 다른 공개방 두 곳에 중복 참가하지는 않는다.
- 공개 채팅을 보았다고 자동으로 참가자가 되지 않는다. 비참가 공개 수신자는 개인 HUD 참가자 목록에 넣지 않는다.
- 채팅은 `│[A·공개] 이름: 대사` 형식이다. 코드는 살아 있는 방 사이에서 유일하며 종료 후 재사용한다. 권한에는 코드가 아닌 UUID와 revision을 쓴다. 색은 보조 표시라 중복될 수 있다.
- 공개 이동방끼리 닿으면 병합하고, 이동방이 고정방 구역에 들어오면 고정방으로 병합한다. 서로 다른 기록 정책의 시험 방은 병합하지 않는다.
- 떨어진 플레이어 무리별로 공개방을 분리한다. 각 신은 자기 페르소나, 게임 관계 수치, 기존 대화와 다른 참가 신에 대한 정적 관계 및 **자신→상대의 현재 동적 태도**를 받아 어느 무리에 남을지/떠날지 LLM으로 제안한다. 서버가 후보·현재 위치·방/청중/관계 revision을 다시 확인한다. 관계 원인·비밀 사건·다른 신의 내면은 공급하지 않는다. 기존 주시 권리는 변경하지 않는다.
- 고정방의 플레이어가 구역 밖으로 나가도 이 판단을 사용한다. 남은 무리는 고정형, 신이 따라간 바깥 무리는 이동형이 된다. 따라가는 신이 없는 무리는 신 대화방이 생기지 않는다.
- 자연어 작별은 신의 마지막 답변 뒤 그 플레이어를 퇴장시키는 Proposal로 처리한다. 신은 자기 참가를 끝낼 수도 있다. 명령어 퇴장은 즉시 처리하며, 남아 있는 방의 문맥에 이유를 남긴다. 자동 호감도 벌점은 없다.
- Primary 실제 전달 후 다른 현재 참가 신 각각에게 한 번씩 선택적 반응 기회를 준다. 순서에 따라 이미 전달된 발언만 받고 각자 말하거나 침묵한다. 후보 오류는 그 후보만 건너뛰며 새 입력·참가 변경·병합·분리는 이전 연쇄 전체를 만료시킨다. 별도의 1인·2신 제한이나 플레이어 없는 자율 토론은 없다.

## 플레이어 사용법

```text
/s 여기서는 우리끼리 이야기하자.
/mythroom list
/mythroom select A
/mythroom leave A
```

- **H**: 참여 방 목록/비밀방 선택 화면. **G**: 우측 UI 숨김/표시만 변경한다. 대화 자체 ON/OFF가 아니다.
- 비밀방 하나면 자동 선택되고, 여러 방이면 선택된 곳으로 `/s`가 간다. 새 비밀방 참여 시 그 방을 선택한다. 선택이 없거나 오래된 경우 오류를 표시하며 **일반 채팅으로 대신 보내지 않는다.**
- 채팅 화면에 `/s`의 대상 방 안내를 표시한다. H는 일반 플레이 중 열고, 채팅 중에는 `/mythroom list`의 선택 링크도 사용할 수 있다.
- 초대 메시지의 `[참여]`를 클릭하면 `/mythroom accept <초대토큰>`을 실행한다. 토큰은 대상 플레이어 전용이며 방 변경/종료 시 만료된다.
- 신 이름은 플레이어별 식별 상태를 따른다. 모르면 `????`, 정체가 확정되면 실제 이름을 표시한다.
- 신 대사는 채팅에 원문을 한 번 남기고 HUD에서는 최대 180 code point 단위로 나누어 기존 순차 출력 큐에 넣는다. 서버측 분할 검사와 별개로 실제 폰트/다중 방 큐 사용감은 미검증이다.

## 관리자 시험

```text
/ai_call public off mythictrpg:demeter
/ai_call private off mythictrpg:demeter mythictrpg:fortuna
/ai_call private on mythictrpg:fortuna
/ai_call mobile off mythictrpg:fortuna
/mythroom invite_test <비밀방코드> 다른플레이어
```

- 위 `/ai_call`은 각각의 사용 예다. 공개방이 이미 있는 플레이어가 또 공개방을 만들 수는 없다. 병합 시험의 다른 공개방은 별도 플레이어가 시작한다. 실제 코드는 `/mythroom list`에서 확인한다.
- `/ai_call`과 `invite_test`는 OP 권한 2가 필요하다. `invite_test`는 시험 방에서만 신 초대를 모의한다. 실제 플레이어에게는 무단 비밀방 합류 권한을 주지 않는다.
- 전체 신 ID만 사용한다. 한글 이름·짧은 path는 거절하며 공백/쉼표로 최대16신을 지정한다. 시작 전에 모든 ID의 AI 프로필과 게임 정의를 검사한다.
- `on`: 새 대화 기록/허용된 기억 저장. `off`: 기존 기억 읽기와 현재 방 문맥은 사용하되 이번 대화의 새 영속 기록을 남기지 않는다. 전역 기억 OFF에서는 시험 `on`을 거절한다.
- 두 시험 모드 모두 실제 아이템/관계/퀘스트 변경은 금지한다. 일반 Encounter가 시작한 STANDARD 방에서만 검증된 게임 액션을 요청할 수 있다.
- 기존 `/ai_test ...`와 `/mythroom open ...`은 `/ai_call` 사용 안내만 출력하며 새 대화를 시작하지 않는다. 내부 legacy adapter는 엔진 의존성과 회귀 검사용으로 유지한다. `on/off`와 무관하게 플레이어·신 대사를 채팅창에 표시한다(채팅 숨김/전송 실패 제외).
- 실제 퀘스트를 대화방의 신에게 명시적으로 제출할 때는 `/mythroom confirm <방코드 또는 UUID> <신ID> <퀘스트ID>`를 사용한다. 선택된 비밀방을 임의의 게임 권한으로 해석하지 않는다. 기존 조건·아이템 소비·보상 판정은 게임 퀘스트 서비스가 그대로 수행한다.

## 모듈 경계와 안전 처리

- 게임 `ConversationRoomLedger`가 방·참가자·초대·선택·revision·턴 권한을 소유한다. `ConversationRooms`가 실제 위치와 연결 구역, 수신자, 채팅/HUD, Snapshot/Proposal을 연결한다.
- AI 포트는 `RoomConversationEngine.Request → Result`, 분리 판단은 `SplitRequest → SplitResult`다. 요청마다 `roomId/revision/turnId`, 화자, 참가 신, 공개 여부, history, 신별 관계/게임/기억 문맥을 명시한다.
- 방별 history·비동기 토큰, 방+화자별 활동 상태, 방+화자+플레이어별 검증 피드백을 분리한다. AI 요청에는 선택 화자의 GodState 하나만 넣으며 Secondary에는 Primary의 제안/거절/퀘스트 문맥을 넣지 않는다. 종료·합류·퇴장·병합·분리·새 턴으로 만료된 응답은 적용하지 않는다. history의 원래 청중/청취 신을 보존해 새 청중에게 과거 비밀을 풀지 않으며 Secondary에도 미청취 원문을 따로 넘기지 않는다.
- history의 `sourceRoomId`로 원래 방의 기억 근거를 추적한다. 응답/분리 판단 전에 철회된 근거를 제외하고, 생성 대기 중 철회된 근거도 최종 적용 때 재검증한다. 게임은 결과 전체의 room/revision/turn·선택된 화자를 검증하며 다른 신이 섞인 응답을 부분 전달 완료로 처리하지 않는다.
- `conversation_leave`, `conversation_end`, `conversation_invite`는 제한된 게임 제어 Proposal이다. 모델이 참가자를 직접 추가하거나 임의 방 UUID를 지정해 실행하지 못한다.
- 실제 액션은 `AiActionGateway.submitRoom`에 방을 명시한다. 확인 시에도 해당 방 generation/신/플레이어를 재검증한다. 퀘스트 모집 동의·문맥·확인은 방별이고 다른 방의 “응”으로 수락하지 않는다. 개인/전역 퀘스트의 실제 원본 상태는 기존 게임 저장소에 남는다.
- 연결 구역 판정은 같은 차원의 동일 바이옴 블록 간 6방향 연결이다. 로드된 청크만 사용하며 청크 생성/강제 로드를 하지 않는다. 경로를 아직 증명할 수 없으면 `UNKNOWN`으로 보류한다. 같은 바이옴 ID라는 이유로 떨어진 섬을 합치지 않는다.
- 고정 조우 commit **전에** 실제 구역 handle·방 슬롯·플레이어·신을 예약한다. 실패 시 반환하고 성공 시 방으로 이전한다. 구역 판정은 tick당 제한된 작업량으로 진행한다. 바이옴 편집/정의 교체 생산자는 `invalidateFixedRegions()`를 호출해야 하며 자동 감지까지 구현한 것은 아니다.
- 상한: 서버 256방, 플레이어당 64방, 방당 64플레이어/16신, 최근 history 64행. 새 청취 기억은 방의 전체 규모를 지원하며 기존 개인 journal의 16인 제한에 묶이지 않는다. 이 수치는 부하 시험으로 보증한 동접 수가 아니다.

## 기록 위치

- 읽기용 대화: `<서버 루트>/ai-dialogue-logs/<플레이어명>/<날짜_시간>_<참가신>_<방UUID>.txt`.
- 게임 `publishPlayer/publishGod`의 불변 `RoomDialogueEvent`로 참가자별 수락 입력/실제 전송 대사를 기록한다. 초기 Encounter 대사와 LLM 없이 처리한 **플레이어의 동의 발언**도 포함한다. 시스템이 별도로 보내는 동의 요청/결과 안내까지 모두 수집한 것은 아니다. 전역 공개 관전자에게 TXT를 복제하지 않으며 파일명의 참가신 표기는 리소스 ID path이다.
- TXT에 message UUID, room/revision, sourceTurn(없으면 NONE), chat 전송 여부와 HUD 성공 페이지 수를 남긴다. 한 논리 대사는 페이지마다 다시 쓰지 않는다. 숨긴 채팅/오프라인/전송 실패는 성공 수신으로 기록하지 않지만 본인의 수락 입력은 보존한다. 이는 서버 전송 결과이지 클라이언트 열람 확인이 아니며 수신자별 완전한 표시 view 저장은 후속이다.
- 분류/생성 진단: `<월드>/mythictrpg-ai-room-logs/<방UUID>/<요청플레이어UUID>/room-<날짜>.txt`.
- 신별 청취 기억: `<월드>/mythictrpg-ai-room-heard-v1/`. 질문자와 무관하게 실제 청취 신으로 조회하며 기존 개인 journal은 호환 조회한다. 방 원장/선택/현재 history는 메모리 상태이며 서버 재시작 시 대화방 자체를 복원하지 않는다.
- `heardGodIds`는 단순 참가 목록과 별개인 게임 발행 청취 증명이다. Story상 부재/봉인 신을 제외하고 실제 원문 화자와 기억을 가진 신을 구분한다. 부분 HUD만 받은 플레이어는 `fullTextReceiverIds`에 넣지 않는다. 원문의 직접 증거와 인용 계보를 영속 보존하고 나중 회상 때 원래 공개 정책을 재검증한다. 공개 발언은 들었던 신이 새 플레이어에게 다시 말할 수 있지만 비밀방 발언은 원래 청중 범위를 자동 확대하지 않는다.
- 파일은 서버 운영자가 읽는 관리 기록이다. 인게임 비밀방 수신 제한이 OS 관리자에게까지 파일 접근을 차단하는 것은 아니다. `off`는 이 방의 신규 대화/진단/기억 기록을 만들지 않는다.
- 이 TXT writer는 bounded 비동기 큐와 경고를 사용하는 기존 관리 기록이다. 신규 SQLite 단일 RAW/100GB quota/전체 채널/영속 중복 방지 구현은 아니며, 디스크 실패·비정상 종료의 기록 공백 가능성이 있다. 원문 한도를 넘으면 경고 실패로 처리하고 조용히 잘라 저장하지 않는다.

## 남은 검증과 범위

1. 실제 서버 2인 이상으로 공개 노출/비밀 비노출, H/G, 초대, 다른 차원 비밀대화, 병합·분리와 이동 중 지연 응답 폐기를 확인해야 한다.
2. 실제 LLM의 작별/초대/무리 선택·보조 반응 품질과 지연·부하는 별도 측정 대상이다. 전체 참가 규모에서 선택적 반응을 지원한다. Primary는 신 이름 지정/이전 화자 기준이며 Secondary는 자기 Story Hook만 게임 검증에 제안할 수 있다. 각 요청은 180초 timeout이며 최신 방·턴·청중·근거를 재검증한다.
3. 추가 관계 수치→9단계 변환 규칙을 새로 만들지 않았다. 현재 방 Snapshot은 원본 affinity와 미정임을 표시하고 기본 R_NEUTRAL/E_NEUTRAL을 쓴다. 모델이 문맥을 해석할 수 있지만 별도의 누적 감정 저장소가 완성된 것은 아니다.
4. 일반 로어 단계·프로필 필드·예시는 레지스트리의 보유 지식과 작성된 공개 정책을 교차한다. Story 사실/위장 설명/Hook/정식 연출도 전체 청중 정책을 검사한다. 다인·다신·공개 Hook을 지원하되 기존 자료의 공개 권한을 자동 확대하지 않는다. 관찰·소문의 기존 원본 권한은 별개로 유지하며 실제 들었던 대화의 기억과 혼동하지 않는다.
5. 기존 소문 생성/설득 회복 후처리는 플레이어 단일 세션 포트라 새 방에서 호출하지 않는다. 이를 방별 포트로 옮기는 작업, 기존 게임발 퀘스트 완료/평가 자동 AI 연출의 방 목적지 지정은 후속 통합이다. 퀘스트 게임 판정 자체와 명시적 방 액션/제출은 구분한다.
6. 퇴장 뒤 남은 방은 명령어 퇴장 맥락을 알지만, 마지막 플레이어가 떠나 닫힌 방의 “무례한 퇴장”을 장기 사건으로 저장/관계에 자동 적용하는 기능은 만들지 않았다. 신의 강제 종료는 해당 신 자신이 방을 떠나는 방식이며 특정 플레이어 추방 전용 Proposal은 아직 없다.
7. 바이옴별 확률 조우 선정, 저장된 방 재접속 복구, Minecraft entity의 실제 동행/이동은 이번 구현이 아니다. 이동형은 대화 범위/참가 구조다.

## 빌드·배포 구분

- 게임 개발 산출물: `mythictrpg-main/build/libs/mythictrpg-1.0.16.jar`.

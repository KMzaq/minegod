## 구현 내용

1. **질문 연결:** 게임이 발급한 월드/신/플레이어/청중/generation 범위 안에서만 RecallFocus를 유지한다. 간접 회상 다음의 짧은 재요청은 원래 질문과 그 질문 시점으로 조회한다. 최대 3개 후속 턴/5분이며 명시적 화제 전환·확인/감사·세션 변경 시 해제한다. NPC의 반문/거절을 플레이어 계획으로 사용하지 않는다.
2. **원문 기반 검색:** 기존 단어/부분 일치와 플레이어 문맥을 재사용하고 계획 표현·상대 시간·허용된 최근 원문을 보조 경로로 사용한다. 질문 자체·단순 재요청을 답의 근거로 재검색하지 않는다. 명시적 개인 회상에서는 필요한 최근 원문을 기존 ‘히스토리 중복 제외’ 때문에 버리지 않는다. 주로 플레이어 발언을 회상하는 단계이며 모든 NPC 약속/타인 관계의 구조화 기억까지 완성한 것은 아니다.
3. **시간·정정:** 원문 기록 시점과 상대 날짜를 구분한다. REAL_KST를 명시했을 때만 코드로 한국 날짜를 계산한다. 미정/게임 시간 표현을 현실 날짜로 단정하지 않는다. 변경·취소·추가 일정·조건부·타인 발언은 원문을 지우지 않고 불확실/복수 근거로 제공한다. 자동 정정 sidecar나 임베딩은 아직 없다.
4. **저장 대기:** 제한된 pending 캐시로 수락된 원문을 같은 서버에서 다시 읽을 수 있게 했다. PENDING_NOT_DURABLE을 표시하고 저장 실패·삭제·retired ID를 재검증한다. 저장 성공/재시작 후 복원과 pending은 다르며 크래시로 미커밋 발언은 유실될 수 있다.
5. **비동기·권한:** 신규 검색은 2개 worker/16개 대기 작업의 제한 실행기에서 처리한다. 게임 스레드에서 허용 범위의 불변 자료만 전달하며 worker는 살아 있는 player/world를 읽거나 LLM을 호출하지 않는다. 결과 적용은 session/turn/generation/청중/근거를 다시 검사한다. 다른 플레이어의 저장은 해당 응답을 무효화하지 않지만 같은 허용 범위의 정정·삭제·새 기록은 재검증한다.
6. **응답 지침:** 명시적 회상은 기존 ‘새 사건 공유’/‘NPC 질문에 대한 답’ 지침과 분리한 INFORMATION directive로 전달한다. 기존 분류 enum/출력 JSON/게임 DTO는 변경하지 않는다. 순수 회상 directive는 Proposal을 만들지 않으며 다른 턴의 기존 Gateway 권한은 그대로다. FOUND/AMBIGUOUS/NO_MATCH/UNAVAILABLE/PENDING_INDEX를 구분하고 조회 실패를 새로운 적대감이나 허구의 과거로 설명하지 않도록 한다. 실제 모델이 지침을 잘 따르는지는 미검증이다.
7. **예산·진단:** 직접 기억+소문 합계 최대 3개, 기본 데이터 블록 800자/재질문·복수 근거 1,200자 상한. 실제 프롬프트에 들어간 ID만 최종 선택으로 기록한다. 긴 인용은 잘림을 표시한다. 단계 1에서는 분류 후 재검색 없이 같은 자료를 사용하고 `evidence_reselected=false`로 기록한다. 검색 경로·상태·이유·pending·검색 소요와 최종 intent/directive를 로그에 남긴다.

신규 경로의 전체 대화 context가 12,000자를 초과하면 끝의 권한/화자/출력 규칙을 잘라 보내지 않고 요청을 실패 처리하며 pending을 해제한다. 원문 안의 가짜 섹션 표식을 파싱해 권한 블록을 찾지 않는다. 긴 콘텐츠의 우선순위별 문맥 압축은 후속 개선 여지가 있다.

새 기억 전용 LLM 호출·추출·재작성 루프는 추가하지 않았다. 복합 인사에 실제 회상 질문이 섞인 경우처럼 과거 고정 인사 경로가 잘못 종료하던 턴은 기존 분류/생성 경로로 넘어갈 수 있으므로 모든 턴의 호출 수/응답 시간이 동일하다는 보장은 아니다.

## 설정과 복원

읽기 위치: 실행 폴더의 `config/mythictrpg/ai-recall.json`. [예제](examples/ai-recall.example.json)는 **OFF/UNSPECIFIED**이며 서버에 복사하지 않았다.

| 키 | 값/처리 |
|---|---|
| schemaVersion | 1 |
| recallV2 | false면 기존 회상 경로, true면 신규 경로 |
| timeBasis | UNSPECIFIED 또는 REAL_KST. 게임 날짜 해석은 아직 지원하지 않음 |

서버의 첫 승인 대화 연결 시 읽고 실행 서버별로 보존한다. hot reload는 없으며 운영 설정 변경/재시작은 별도 승인이 필요하다. 누락·손상·미지원 값·4KB 초과는 기존 경로로 돌아간다. 기능 OFF는 원문 삭제나 LP JAR 복원이 아니다. 기존 OFF/PERSONAL/RUMOR_TEST 설정과 시험 모드 실행 차단은 유지한다.

소스 복원을 요청받으면 [이번 변경 목록](recall-stage01-changes-20260915.csv)을 확인하고 `MODIFIED`는 직전 백업의 동일 경로를, `ADDED`는 이번에 추가된 정확한 파일만 대상으로 별도 보존 후 처리한다. build.gradle/버전/오버레이/테스트도 함께 복원하고 다시 컴파일·JAR 내용을 확인한다. build/generated만 수정하거나 git reset/폴더 통삭제로 복원하지 않는다. 그 뒤 LP까지 돌아가려면 [기반 복원 가이드](LP_MEMORY_FOUNDATION_GUIDE.md)의 기존 0.1.3까지의 합산 목록도 적용 대상 검토에 포함해야 한다. 이번에는 복원/배포하지 않았다.

## 미검증·다음 단계

- 실제 gemma4:12b의 회상 답변/성격·관계/자연스러움, 신별 말투 비교, 1/4/6명 전체 지연, HUD·서버 부팅은 남아 있다. 현재 서버 대화가 이미 개선됐다고 주장하지 않는다.
- 대규모 의미 회상, 자동 요약/정정·영구 중요도 판정, 전체 보관 정책, 전서구/주시/행동 원장/평판 효과는 다음 단계다. 원문 선택은 한국어 표면 표현과 시간 단서에 의존하므로 임의 표현을 항상 이해하는 의미 검색은 아니다.
- 관계 읽기 감사: 현재 LP facade의 QuestReward/SocialAuthority Provider 설치는 non-null 검사만 하고, Adapter는 R_NEUTRAL/E_NEUTRAL로 시작한다. 별도 관계 DB를 만들거나 매핑을 임의 연결하지 않았다. 실제 관계 입력 연결은 로드맵 4단계의 독립 패치로 검증해야 한다.
- 시간 기준과 주시 범위를 비차단 질문으로 요청했으나 이 기록 시점에는 미응답이다. 게임 기록 정밀도·보존/주시 임계값은 해당 구현 전에 정한다. 미확정 정책을 운영에 켜지 않았다.
- 2단계 최소 행동 원장 구현의 기술적 출발점은 정리됐다. 1단계의 인게임 품질 수용은 아직 아니다. **2단계는 시작하지 않았다.**

연동 스킬 기준으로 게임 권한/IO 호환과 늦은 응답 격리를 유지했고, 대화 검토 스킬 기준으로 회상·정정·말투 문제를 분리했으며, 릴리스 스킬 기준으로 소스/오프라인/JAR/미배포·미부팅을 구분했다.

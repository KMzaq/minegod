# 유저 행동 기록과 실적 인정 정책

2026-09-20 / 확정 정책 + 승인된 1~5단계 공통 기반 소스·오프라인 적용 / 미배포·운영 검증 미완료

> 현재 구현 범위·계약·테스트·미지원은 [9/20 구현 기록](MEMORY_POLICY_IMPLEMENTATION_20260920.md)을 따른다. 아래 설계 방향 전체가 운영 활성화됐다는 뜻은 아니다.

## 1. 문서의 기준과 범위

[원본 기획서 v0.1](../인수인계/Mythic_TRPG_기획서_v0.1.docx)의 18장 PHASE 4-A 목표에 따라 **Minecraft Statistics를 우선 재사용하고, 기본 통계로 얻을 수 없는 값만 추가 집계**한다. 7·14장의 제한된 상태/요약과 무한 위치 로그 방지, 13장의 중요한 사건 기억 방향도 유지한다. [기존 개발 가이드](../mythictrpg-main/docs/mythic-trpg-development-guide.md)의 Custom Gameplay Counter 원칙과 연결한다.

이번 사용자 결정은 이전의 상세 일상 기록 요구를 조정한다. 일반 행동을 매번 상세 사건으로 남기는 대신 **기본 누적 통계 + 보상에 인정되는 실적 + 중요한 사건 기록**을 구분한다. 이 문서는 해당 범위에서 [실행 로드맵](ACTION_OBSERVATION_MEMORY_ROADMAP_20260915.md)의 과거 상세 수집 방침보다 우선한다. 원본 Word 기획서는 기준점으로 보존하며 이번에는 수정하지 않았다.

9월 20일 후속 결정은 이전의 **메인 퀘스트 완료→자동 주시** 조건을 **퀘스트 보상으로 주시 획득**으로 대체한다. 첫 완료자/메인 여부 자체가 주시를 부여하지 않는다. [참여 유형 가이드](../mythictrpg-main/docs/QUEST_PARTICIPATION_GUIDE.md)의 실제 지급 대상·선택 결과에 주시 보상을 연결했으며 실제 퀘스트 정의에는 아직 넣지 않았다.

정책 문서 작성 당시에는 소스 변경 승인이 아니었다. 이후 사용자의 ‘최신 설계를 반영한 1~5단계 소스 구현·오프라인 검증’ 승인으로 위 구현 기록의 범위를 적용했다. 기존 데이터 삭제·새 월드 생성·운영 활성화·6단계 착수는 포함하지 않는다.

## 2. 확정된 기록 범위

| 구분 | 확정된 방향 | 구분해야 할 한계 |
|---|---|---|
| 일반 채굴·이동·일반 몬스터 처치 | 기본 통계로 얻을 수 있는 블록별 채굴 수, 이동 거리, 몹 종류별 처치 수 등을 우선 활용 | 통계에 없는 정확한 발생 장소·시각·행동 의도를 복원하지 않음 |
| 일상 행동의 상세 원문 | 일반 좀비 한 마리 처치나 평범한 이동·채굴마다 장소·시각을 붙인 영구 행동 일지를 운영 기본으로 요구하지 않음 | 기존 게임의 순간 이벤트·퀘스트 조건 감지·집계까지 제거하는 결정은 아님 |
| 업적·보상용 채굴 실적 | 아래 3절의 출처 규칙을 적용한 실적을 별도 집계 | Minecraft 기본 통계 자체를 수정하거나 총 채굴 수에서 총 설치 수를 단순 차감하지 않음 |
| 전투 결과 | 네임드 몬스터를 포함한 그 이상급 대상과 레이드 등 별도로 제작된 전투 콘텐츠의 결과만 상세 기록 | 공격 한 번/피해 한 번마다의 전투 일지를 요구하지 않음. 일반 몹 단독 처치는 기본 통계 |
| 퀘스트·업적 | 제작 퀘스트·업적과 Minecraft 기본 및 외부 모드 발전 과제를 포함해 전부 상세 기록 대상으로 삼음 | 기록 대상의 포괄성과 상태 전환/달성 판정을 구분. 실제 완료·보상 지급을 혼동하지 않음 |
| 개인 대화·기억 | 기존 개인 회상 개선을 유지하고 중요한 사건·약속은 오래, 사소한 잡담은 점차 잊는 방향 유지 | 일반 행동 원장을 줄이는 결정이 대화 원문/개인 기억의 삭제 승인은 아님 |

장소는 사용자가 선택한 **좌표와 바이옴**으로 기록하고, 같은 좌표가 다른 차원에 존재할 수 있으므로 기존 차원 ID도 유지한다. 사건 당시의 좌표/바이옴 ID를 저장하며 나중의 월드 상태로 소급 생성하지 않는다. 마을·지역·구조물 이름은 필수 기록 항목으로 추가하지 않고, 바이옴을 특정 마을 이름으로 바꿔 말하지 않는다.

### 상세 기록을 구성하는 방식

아래는 사용자가 위임한 설계 방향이다. 구현된 생산자와 아직 연결되지 않은 콘텐츠/공개 경계는 구현 기록 2절을 따른다.

- **전투는 결과 단위:** 언제(실제 발생 시점과 게임 시간), 어디서(차원·좌표·바이옴), 무엇과(등록된 몬스터/전투 콘텐츠와 해당 개체/실행 식별자), 누구와(게임이 확인한 실제 참가자), 어떤 결과였는지를 묶는다. 승리만 남겨 패배를 성공으로 꾸미지 않으며, 패배·철수·중단은 해당 전투 시스템이 확정한 경우에만 기록한다. 단순 접속 종료로 철수/패배를 임의 판정하지 않는다.
- **네임드 판정:** 이름표 문자열이나 임의 전투력 수치가 아니라 게임에 등록된 네임드/전투 콘텐츠 분류를 사용한다. 전서구처럼 약하더라도 지정된 네임드는 대상이다. 레이드 안의 일반 몹은 해당 레이드 결과에 포함할 수 있지만 그 이유로 일반 몹 개별 상세 처치 로그를 다시 켜지 않는다.
- **공동 전투:** 처치 판정자와 공동 참가자를 분리한다. 주변에 있었거나 같은 팀이라는 이유만으로 참가자로 만들지 않고 기존 전투 시스템의 참여 근거를 사용한다. 지원 역할을 포함할 구체 판정은 기존 콘텐츠 규칙을 따르며 새 기여도/보상 공식을 임의로 만들지 않는다. 한 전투 결과를 공동 참조하고 참가자별 열람 가능 정보만 투영한다.
- **퀘스트는 모두 대상:** 메인·사이드·즉석 등 기존 게임에 존재하는 퀘스트 종류를 중요도로 누락시키지 않는다. 게임이 제공하는 수주·완료·실패·포기·전역 완료로 인한 무효화 등의 의미 있는 상태 전환과 결과를 보존한다. 매 tick 진행 수치나 일반 몹 처치 하나마다를 별도 상세 사건으로 남긴다는 뜻은 아니다.
- **업적은 달성 결과:** 업적 ID, 달성자, 달성 근거/시점/장소를 기록한다. 기록을 읽거나 AI가 칭찬한 횟수를 새 달성/보상으로 세지 않는다. 사용자는 프로젝트 업적뿐 아니라 바닐라·외부 모드 발전 과제도 포함하기로 확정했다. 실제 달성 전환을 원본 ID·당사자·시점과 연결하고 중복 알림/재로그인으로 새 달성을 만들지 않는다. 숨겨진 발전 과제의 조건/달성 정보를 모든 신이나 청중에게 공개하는 승인은 아니다. 다른 모드의 판정·보상은 변경하지 않는다.
- **기록과 보상 분리:** 실제 완료자·수주자·FTB 팀 공유 상태·보상 수령자는 각각의 게임 원본을 사용한다. 전역 퀘스트가 완료됐다는 이유만으로 모든 수주자를 개인 완료자로 기록하지 않는다. 완료/수령 대기/지급 실패를 구분한다.
- **좌표 기준:** 단일 몬스터 처치에서는 결과가 발생한 대상 위치, 제작 전투에서는 게임이 확정한 결과/전장 위치, 퀘스트·업적에서는 실제 상태 전환 위치를 사용한다. 오프라인 처리처럼 당시 위치를 확인할 수 없는 경우에는 이유와 미확인을 남기며 현재 위치나 가짜 좌표로 채우지 않는다. 정확한 API·저장 형식은 후속 계약 구현에서 정한다.

## 3. 채굴과 재배 실적 인정 규칙

기능 완성 후 **새 월드를 만들고 시작부터 추적을 작동**시키는 것이 사용자의 운영 전제다. 지금 기존 서버 월드를 초기화하거나 교체하라는 요청이 아니다.

| 실제 출처/행동 | 콘텐츠의 업적·보상 실적 | 사용자 결정 |
|---|---|---|
| 본인이 직접 설치한 블록을 다시 파괴 | 채굴 실적 제외 | 확정 |
| 다른 플레이어가 직접 설치한 블록을 파괴 | 채굴 실적 제외 | 확정. 서로 설치·파괴해도 인정하지 않음 |
| 플레이어가 심고 성장시킨 작물의 정상 수확 | 정상 수확 실적 인정 | 확정 |
| 플레이어가 심고 성장시킨 나무의 정상 벌목 | 정상 벌목 실적 인정 | 확정. 원목 블록을 직접 재설치하고 부수는 행위와 구분 |
| 돌 생성기 같은 반복 생산 시설의 산출 블록 | 채굴 실적 제외 | 확정. 적용할 생성 방식·모드별 목록은 후속 확인 |
| 설치·생성 출처 기록이 없는 블록 | 자연 생성으로 간주하여 채굴 실적 인정 | 확정. 옛 설치 블록일 가능성만으로 별도 불이익을 주지 않음 |

위 구분을 적용할 때 다음 경계를 지킨다.

- 알려진 플레이어 직접 설치·생성기 출처를 먼저 구분한다. **설치자 UUID가 없다는 이유만으로 이미 확인된 생성기 산출물까지 인정하지 않는다.** 재배·성장한 작물/나무는 위의 정상 실적 예외를 적용한다.
- 기록 없는 블록을 인정하는 것은 게임의 실적 처리 정책이다. 실제 자연 생성임이 입증됐다거나 신이 발생 과정을 목격했다는 증거로 바꾸지 않는다. 추적 오류가 있었다면 오류 진단도 숨기지 않는다.
- 기존 Minecraft 통계와 콘텐츠의 인정 실적은 다른 값이다. 이번 범위만으로 바닐라 발전 과제나 무관한 모드의 보상 규칙을 변경하지 않는다. 콘텐츠 보상을 판정할 때는 보정된 실적을 사용하도록 후속 연결이 필요하다.
- 별도 집계는 확인된 성공 결과를 한 번만 센다. 취소/실패·중복 알림·재시작 재생으로 실적이나 보상을 늘리지 않는다. 기존 퀘스트/FTB/보상 소유권은 유지한다.
- 기존 건축용 설치자 추적을 우선 검토해 재사용한다. 피스톤·낙하·폭발·모드 변환 등으로 이미 아는 출처가 잘못 사라지지 않는지 검증한다. 정확한 저장 형식이나 모든 특수 동작의 지원 완료를 이번 문서에서 선언하지 않는다.
- 블록 출처 판별에 필요한 차원·좌표는 내부 식별 정보다. 이를 플레이어의 전체 이동/행동 일지로 누적하거나 그대로 AI 프롬프트에 전달할 필요는 없다.

농사 시설 전체나 몬스터 농장의 보상을 자동으로 금지하는 것으로 확대 해석하지 않는다. 작물/나무의 정상 실적 인정은 위에서 확정했고, 별도 자동화 보상 규칙은 이번에 결정하지 않았다.

## 4. 시간과 지식 공개

### 시간에 관한 사용자 결정

- **“내일”은 현실 달력 날짜**를 기준으로 해석한다. 발언 시점을 기준으로 정한 예정일을 나중의 검색/추출 시점에 따라 다시 이동시키지 않는다.
- **“해가 뜨면”, “해가 지면”은 Minecraft 내 태양/일광 주기**를 기준으로 한다. 현실 시각으로 일괄 바꾸지 않는다.
- 서버 시간대 설정과 적용 확인, 잠자기·시간 명령·차원별 일광 차이의 세부 처리는 별도 확인 사항이다. 현실/게임 시간의 위 구분 자체를 다시 미응답으로 취급하지 않는다.
- 약속 시점이 지났다는 이유만으로 실제 이행·실패나 보상 지급을 확정하지 않는다. 날짜 해석 정책 확정과 현재 코드/설정의 지원 여부는 별개다.

### 기존 권한 경계 유지

게임이 집계/기록한 사실, 신의 직접 관찰, 플레이어의 발언, 소문은 서로 다르다. 모든 누적 통계를 모든 신에게 공개하거나, 통계 차이만으로 구체적 장소·시각·목격을 만들어내지 않는다. 알고 있는 정보와 현재 청중에게 공개할 수 있는 정보도 분리한다.

주시 범위는 신별 권능·영역·장소/가림 조건 제한을 유지한다. 시작 근거는 **해당 플레이어에게 실제 지급된 퀘스트 보상 ‘OOO의 주시’**이며 특별한 방해 사유가 없으면 지속한다. 메인/첫 퀘스트 완료, 수주, 관계 수치만으로 자동 지급하지 않는다. 전서구 사냥으로 막는 소문은 **해당 플레이어에 관한 소문**이며 다른 플레이어 전체의 소문을 막지 않는다. 전서구 개체/전파 기능의 구현 완료를 뜻하지 않는다.

### 신의 해금과 개인 조우 및 보상형 지속 주시

| 단계 | 확정된 콘텐츠 의미 | 구현/권한 경계 |
|---|---|---|
| 신 해금 | 신별 해금 조건을 달성하면 서버 공용으로 해금. A가 해금해도 B가 자신의 조우 조건을 만족하면 조우 가능 | 해금 조건이 나중에 불충족하거나 A가 로그아웃해도 자동 재잠금하지 않음. 특별한 재잠금 사건만 예외이며 구체 사건/재잠금 연결은 미구현·미확정 |
| 조우 조건 | 기본 요소는 지역·아이템·행동·확률. 신마다 전부 또는 일부 사용하고 연계 퀘스트에 의한 조우도 가능 | 모든 신에게 네 요소를 강제하지 않음. 게임의 기존 출현/상호작용 조건과 연결하고 AI가 조우 확률을 임의 판정하지 않음 |
| 실제 조우 | 해금된 신과 해당 플레이어가 실제로 조우 | 조건 통과/출현 가능과 실제 조우 커밋을 구분. 해금만으로 전원 조우·식별·주시를 등록하지 않음 |
| 퀘스트 보상 | 작성된 퀘스트 보상으로 ‘OOO의 주시’를 실제 획득 | 메인/사이드 분류보다 명시된 보상과 개인 지급 결과가 기준. 어떤 퀘스트에 넣을지는 콘텐츠 설정이며 모든 퀘스트에 자동 추가하지 않음 |
| 지속 주시 | 플레이어에 신별 ‘OOO의 주시’ 획득 상태를 기록하고 허용 범위에서 관측 | 획득 상태·현재 관측 가능 여부·실제 목격 증명은 별개. 특별한 방해 사유가 없으면 유지 |

해금 조건과 조우 조건은 콘텐츠 개념이다. 기존 코드의 `unlockConditions`, `appearanceConditions`, `interaction_rules`, 실제 조우 커밋을 하나로 합치거나 이름만으로 같은 기능이라고 취급하지 않는다. 확률의 구체 값·재추첨 간격과 신별 조건 데이터는 기존 설정을 확인하고 정식 콘텐츠에서 정한다.

기존 `GodAttentionState`는 `MAIN_ENTRY` **수주** 시 메인 퀘스트 접근 권한을 위한 주목 대상을 저장한다. 보상형 지속 주시와 동일하지 않으며 이번 결정은 메인 수주 권한을 바꾸지 않는다. 게임의 보상 지급 근거와 기존 신/플레이어별 `WatchContract`를 연결하고 AI에 별도 획득 원본 DB를 만들지 않는다. 근거는 [보상 가이드](../mythictrpg-main/docs/REWARD_SYSTEM_GUIDE.md), [보상 타입 코드](../mythictrpg-main/src/main/java/com/sande/mythictrpg/quest/reward/RewardEntry.java), [주시 계약](../mythictrpg-main/src/main/java/com/sande/mythictrpg/gameplay/watch/WatchContract.java)다. 현재 보상 타입에는 주시가 없으며 칭호 문자열만 추가해 구현 완료로 간주하지 않는다.

### 주시 보상과 플레이어 기록 — 후속 구현 설계

- 플레이어별로 기존 God ID를 참조한 **‘포르투나의 주시’** 같은 획득 상태와 지급 출처를 남긴다. 단순 칭호 표시나 기간제 포션 가호가 아니라 관측 자격을 가진 게임 상태다. 기존 칭호/가호 슬롯을 덮거나 임의의 단일 신 독점 제한을 추가하지 않는다. 구체 UI 위치와 저장 스키마는 기존 플레이어/주시 저장소를 검토해 정한다.
- 기존 보상표·직접 보상·선택 보상의 검증/개인 claim 경로를 재사용하는 방향이다. 지급권 생성/선택 대기/실제 지급/관측 활성화를 구분한다. 선택 보상이면 그 항목을 고르기 전에는 획득하지 않는다. 오프라인·일시 실패·재시도는 기존 지급 규칙을 따르며 AI의 완료/보상 대사만으로 획득시키지 않는다.
- 획득 기록과 관측 활성화 연결은 동일 지급 근거로 재처리해도 한 번만 적용되도록 설계한다. 이미 획득한 같은 신의 주시를 중첩하거나 관측 구간을 초기화하지 않는다. 다른 보상이 함께 있으면 그 보상은 기존 규칙대로 처리한다. 지급 저장/관측 저장 사이 중단에 대한 재개·일관성 검사도 구현 대상이며 현재 원자적 보장을 주장하지 않는다.
- 수신자는 새 SOLO/GROUP/COMPETITIVE/RANKING의 **실제 개인 보상 대상·선택 결과**를 따른다. 공동 완료자/랭킹 제출자 전체가 무조건 받는 것이 아니다. 랭킹에서 완료됐어도 보상 구간 밖이면 주시를 자동 지급하지 않는다. 기존 유형 없는 퀘스트나 개인 즉석 SIDE에도 자동으로 새 타입을 삽입하지 않으며, 후속 구현에서 검증된 보상 정의로만 허용한다.
- 후발 플레이어도 자신에게 허용된 다른 퀘스트에서 이 보상을 받는 방식으로 설계할 수 있다. 따라서 첫 입문 완료자 선정은 더 이상 주시 시스템의 필수 정책 질문이 아니다. 기존 메인 접근/재수주/모집 규칙을 바꾸거나 후발용 퀘스트를 자동 생성한다는 뜻은 아니다.
- 신별 관측 정책이 없거나 차단된 곳에서 보상을 받았어도 획득 기록과 관측 허용을 혼동하지 않는다. 근거/정책/게임 상태가 모두 유효할 때만 새 관측을 시작하며 과거 기록은 소급 목격하지 않는다. 보상 대상 신은 등록된 설정으로 검증하고 AI가 임의로 다른 신의 주시를 수여하지 못하게 한다.

### 주시를 가리는 공간 — 사용자 방향과 기술 설계

사용자가 예로 든 **더 상위 존재의 신전 같은 공간**, **누구도 외부에서 관측할 수 없는 특수공간**을 지원하는 방향이다. 신전 이름이나 신화 상식만으로 위계/차폐 범위를 임의 추론하지 않는다.

- **신별 차폐:** 등록된 영역의 소유/관측 허용 정책으로 특정 신의 원격 주시를 차단한다. 어떤 존재가 더 상위인지, 신전 주인/동급의 예외를 허용할지는 정식 콘텐츠 매핑으로 정한다. 전역 전투력 숫자 비교로 대체하지 않는다.
- **완전 차폐:** 지정 공간은 외부 주시 경로를 모두 차단하도록 설계한다. 임의의 강한 신 예외를 만들지 않는다. 공간 안의 일반 플레이어 시야/직접 대화까지 금지하는 별도 규칙은 추가하지 않는다.
- 차폐 중에도 ‘OOO의 주시’ 획득 상태는 유지하며 새 관측만 막는다. 나와서 정책이 허용되면 이후 관측을 재개한다. 차폐 중 통계·업적·퀘스트 증가나 누적 요약으로 내부 일을 뒤늦게 목격한 것처럼 전달하지 않는다.
- 기록하는 것과 신에게 전달하는 것은 다르다. 서버의 중요 사건/발전 과제 기록은 유지하되 관찰 증명·요약·현재 청중용 프롬프트에서 차폐와 공개 범위를 검사한다. 관측 불가 사유의 안내 자체가 비밀 장소 이름/좌표를 누출하지 않도록 한다.
- 정식 영역 ID·차원/경계·허용 신 목록은 운영 전 매핑한다. 기존 권능/영역/가림 계약은 재사용하지만 `WatchContract.Area/Scene.occluded`가 이 콘텐츠 전부를 이미 처리한다고 하지 않는다. 대화 접근권·소문망은 별개이며 차폐를 우회하는 새 전파 경로를 추가하지 않는다.

### 위임받아 선택한 자연스러운 일상 관찰 방식

1. **중요 결과는 사건 기억으로:** 관측 권한이 있는 신에게 전투 결과·퀘스트·업적을 관련 경험으로 전달한다. 서버가 상세 기록한 모든 사건을 모든 신에게 공개하지 않는다.
2. **일상은 관측한 구간의 활동 요약으로:** “요즘 농사에 공을 들였구나”처럼 허용된 행동량/추세만 제한된 집계로 기억한다. 정확한 위치·시각을 가진 일상 원문을 상시 저장하거나 매 행동마다 LLM을 호출하지 않는다. 숫자는 근거가 있고 질문에 필요할 때만 사용한다.
3. **전체 누적 통계를 목격으로 바꾸지 않음:** 기본 통계 차이를 사용할 때도 전 구간이 관측 허용됐음을 확인해야 한다. 허용 구간별로 기준점을 나누고, 중단/가림/재접속 공백을 건너뛰어 증가량 전체를 합산하지 않는다. 통계만으로 범위를 구분할 수 없는 행동은 허용된 순간 이벤트에서 제한된 카운터만 집계한다. 실제로 본 구간의 근거/범위를 보존한다.
4. **지속 주시와 항상 대사는 다름:** 특별한 방해가 없는 한 주시 상태를 유지하고, 대화 주제·신의 성격·관계와 관련 있을 때 관찰을 자연스럽게 꺼낸다. 매번 활동 보고나 감시 알림을 말하지 않는다. 기존 자발 대사의 허용·쿨다운을 우회하지 않는다.
5. **일시적 관측 불가와 관계 종료를 구분:** 로그아웃·서버 재시작·일시 가림만으로 주시 관계를 영구 삭제하지 않는다. 관측 불가 구간에는 새 경험을 만들지 않고, 재개 시 과거 공백을 소급 목격하지 않는다. 신의 부재·플레이어의 특수 상황에 의한 중지/종료는 게임이 명시적으로 판정해야 하며 구체 콘텐츠는 미정이다.

위 관찰 방식은 사용자에게 위임받은 설계 선택이다. 일반 행동 집계→허용 경험, 주시 보상→개인 획득→명시 정책 관측은 개발 소스에 연결했다. 집계 창은 0(비활성)이며 기술적 안전 상한과 실제 운영값을 구분한다. 새로운 관계 DB나 자동 관계 임계값은 추가하지 않았다.

### 위임받아 채택한 편안하고 자연스러운 개인 기억 설계

사용자는 앞서 제안한 미해결 약속·중요 고백/해명·관계 전환의 우선 보존에 추가 제외 요구가 없으며 자연스러운 개선을 위임했다. 다음을 후속 구현 기준으로 선택한다. 실제 모델 검증이나 영구 보존 수치 확정은 아니다.

1. **중요 결과와 미해결 일을 우선:** 게임이 확정한 관계 변화/중요 사건, 플레이어가 명확히 말한 약속·중요 해명은 근거와 함께 우선 보존한다. 대화 해석은 후보이며 ‘본인이 말했다’와 ‘실제로 일어났다’를 구분한다. 감정 추정만으로 관계 수치·이행/실패를 바꾸지 않는다.
2. **기억의 핵심은 남기고 세부는 덜 꺼내기:** 해결된 약속은 중요한 결과·관계 의미를 요약으로 남기는 방향이며 미해결 약속처럼 계속 재촉하지 않는다. 반복 잡담은 중복 묶음/회상 우선순위 감소를 사용하되 원문 삭제 승인은 아니다. 짧은 기간·모든 기억 영구 보존을 임의 설정하지 않는다.
3. **현재 대화가 먼저:** 현재 질문·기분·관계에 필요한 소수의 기억만 가져온다. 매번 과거를 언급하거나 감시 보고·확인 질문을 반복하지 않는다. 신별 개성과 까칠함을 지우거나 모든 신을 친절한 비서로 만들지 않는다.
4. **정정과 변화 존중:** 사용자의 명확한 계획 변경/해명에 연결된 이전·이후 근거를 비교한다. 농담·가정·전언을 사실이나 자동 취소로 확정하지 않는다. 한 번의 실수/취향 발언을 영구 성격으로 고정하지 않고 후속 변화도 반영한다. 소문/평판 효과는 6~7단계와 분리한다.
5. **회상한 횟수를 새 증거로 세지 않기:** NPC의 반복 발화나 검색 횟수만으로 중요도가 무한히 올라가지 않게 한다. 신·플레이어·청중별 권한과 원문/사건 계보를 유지하고, 공유 대화 합류 전 개인 기억을 새 청중에게 유출하지 않는다.
6. **대화 지연을 억제:** 매 행동/매 턴에 추가 요약 LLM을 강제하지 않고 기존 제한된 유휴 처리·검색 상한·실패 시 기본 검색을 유지한다. 중요한 것으로 판정했어도 현재 원문 한도나 30일 조회 제한을 우회할 보존 구조 없이는 ‘계속 기억한다’고 하지 않는다. 보호 기억·요약 아카이브·삭제 정책은 용량 측정 후 별도 검증/확정한다.

## 5. 남은 콘텐츠 매핑과 운영 선택

주시를 퀘스트 보상으로 획득하는 방식, 기본/외부 모드 발전 과제 포함, 자연스러운 기억 기준, 신별 차폐/완전 차폐 방향은 확정·위임받았다. 이전 메인 자동 주시나 업적 포함 여부를 다시 미응답으로 취급하지 않는다. 1~5단계의 공통 기반 설계는 이 기준으로 이어갈 수 있으며 남은 것은 다음과 같다.

1. **콘텐츠 매핑:** 실제 주시 보상을 넣을 퀘스트·대상 신·기존 보상 단계/선택지, 네임드/전투 ID, 차폐 공간의 경계·신별 허용 목록을 연결한다. 존재하지 않는 위계·공간·후발 퀘스트를 임의 생성하지 않는다. 새 정책은 수주 권한/보상 밸런스 변경 승인이 아니다.
2. **관측/기억 운영값:** 신별 기본 관측 영역, 특별한 중지/종료 예외, 활동 요약 시간 창/상한과 중요 기억의 보존 구조를 구현·시험으로 구체화한다. 콘텐츠 예외를 정하지 못하면 해당 경로는 비활성/시험 정책으로 유지한다.
3. **보관·운영 수치:** 바뀐 기록 범위로 부하·용량을 측정한 뒤 보관 기간/한도/정리 방식을 결정한다는 기존 선택을 유지한다. 한도 90% 서버 알림·관리자 증설 안내와 서버/GameTest/실제 모델/설치/배포 별도 허가를 유지한다.
4. **전서구 콘텐츠:** 대상 플레이어만의 소문 차단은 확정이다. 개체 귀속·재생성/차단 종료·전파 조건은 6단계 전에 논의하며 지금 자동 시작하지 않는다.

생성기 종류별 감지, 기존 설치 추적의 성장/이동 처리와 소비자 연결은 우선 코드·모드 구성으로 확인할 기술 과제다. 코드 조사로 해결할 부분까지 사용자에게 규칙 선택으로 떠넘기지 않되, 실제 실적 인정 범위가 달라지는 예외는 확인 후 질문한다.

## 6. 구현과 검증의 남은 일

- 최신 공통 기반 소스와 오프라인 검사 4,608개를 완료했다. 기록 선별·출처/인정 실적·중요 사건/바이옴·보상형 주시·차폐·일상 집계·개인 회상은 [구현 기록](MEMORY_POLICY_IMPLEMENTATION_20260920.md)의 지원 범위다. 실제 운영 수용 완료는 아니다.
- 등록형 참여/즉석 SIDE의 채굴 보상 목표는 인정 실적 경로로 연결했다. 이후 추가하는 자체 업적/FTB 목표는 해당 counter를 사용해야 하며 무관한 바닐라/모드 보상을 일괄 변경하지 않는다.
- 실제 콘텐츠 ID·보상표·차폐/관측 영역 매핑, 별도 레이드 엔진/지원 참가자 근거, 발전 과제 이벤트를 쓰지 않는 외부 업적, 비공개 퀘스트/업적의 명시 공개 정책은 추가 연결이 필요하다. 현재 원격 AI 투영은 이 비공개 사건을 차단한다.
- 실제 설치 취소·피스톤·낙하·성장·모드 생성기 동작, 보상/주시 재접속과 저장 중단, LLM 자연스러움·지연·1/4/6인 부하는 별도 승인된 운영 시험에서 확인한다. 순수/bytecode 검사를 인게임 검증으로 취급하지 않는다.
- LP·작업 직전 백업을 보존했고 서버 설정/배포물/월드·플레이어·기억 데이터는 변경하지 않았다. 서버/GameTest·실제 모델·설치·배포·6단계는 미실행이다. 최신 인수인계는 42절이며 38~41절은 설계/이전 개발 이력이다.

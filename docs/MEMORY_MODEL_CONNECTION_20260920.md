## 결론과 적용 범위

현재 장비에서는 **CPU bge-m3 의미 검색 + 기존 Gemma4의 무접속 시간 기억 정리**를 선택했다. Qwen 7B 전용 정리기를 별도로 띄우는 것보다 이번 합성 시험의 정확도/처리 시간이 좋았다. 추가 모델 다운로드·설치는 하지 않았다. 주 대화 모델과 대화 설정, 게임/FTB/콘텐츠 소스는 그대로다.

AI 소스 **0.1.10**과 해당 서버용 설정 두 파일을 준비했다. **JAR 배포는 하지 않았으므로 현재 서버의 게임 1.0.2 / AI 0.1.3에서는 새 모델 연결이 아직 동작하지 않는다.** 배포 승인 후 게임 1.0.8 이상과 AI 0.1.10의 맞는 조합, 서버/클라이언트 및 런타임 의존성을 별도 검증해야 한다. 서버/GameTest 실행, 실제 플레이어 대화 호출, 월드 기억 이관은 하지 않았다. 6단계 미착수.

작업 전 LP 소스 298개, 이전 기반 906개, LP 원본 JAR 3개를 검증하고 현재 상태 **2,311개** 파일을 `server/backups/before-memory-stage05-20260920-161949-064/`에 추가 보존했다. LP와 앞 작업의 143804 snapshot을 덮어쓰지 않았다. 이 백업은 manifest 범위의 소스·문서·설정·JAR·기억·로그·데이터팩이며 전체 지형 백업이 아니다.

## 합성 한국어 실제 모델 측정

사용자가 합성 데이터 실제 호출을 별도로 승인했다. 실제 백엔드의 모델 digest 전후 검사·응답 검증을 통과한 결과이며 플레이어 원문/기억은 사용하지 않았다. Minecraft 전체 응답시간이나 일반 정확도 점수로 해석하지 않는다.

| 측정 | 결과 |
|---|---|
| bge-m3 CPU 4스레드, 문서 6개 + 질의 7개 | 첫 로딩 포함 약 4.10초, 이후 약 48~59ms. 관련 질의 6/6에서 목표 문서가 1순위 |
| bge-m3 GPU 비교 | 일부 준비 후 요청 약 35~75ms이나 약 2.5초 재지연 및 질의 1.5초 제한 초과 발생. 원인을 GPU 부족 하나로 확정하지 않음 |
| Gemma 기존 분류 지침 | 8개 중 2개 kind+relation 일치. 개인 경험/전언 분류 혼동, 잘못된 관계 참조가 있어 지침 수정 |
| Gemma 개선 지침 | 기본 7/8 + 새 사례 4/4 = **11/12**. 첫 호출 약 4.7~5.2초, 나머지 약 0.98~1.53초 |
| Qwen 2.5 7B CPU, 동일 개선 지침 | 기본 6/8 + 새 사례 3/4 = **9/12**. 첫 호출 약 15초, 나머지 약 4.6~8.7초 |

두 모델 비교는 같은 요청 지침·8192 문맥·512 출력 한도를 사용했지만 **배치 하드웨어는 다르다**. 이는 모델 자체의 우열이 아니라 이 장비에서 채택할 운영 배치 후보의 비교다. Gemma도 단순 취소 발언 1건을 CONDITIONAL로 분류했다. 합성 12건만으로 자연스러움/정확도 개선을 보장하지 않으며, 모든 정리 결과는 검증되지 않은 후보로만 사용한다.

원시 결과는 빌드 정리와 분리된 [측정 근거 보존 폴더](evidence/memory-models-20260920)에 타임스탬프별 JSON 7개를 해시 대조 후 복사했다. 비교 기준은 `extract-gemma-1789891487934.json`, `extract-qwen-1789891526283.json`과 각각의 `*-validation-*` 결과다. 첫 Gemma 실패 결과와 GPU 중단 전 부분 결과도 삭제하지 않았다. GPU 결과는 질의 3개까지만 기록됐고 다음 호출에서 HttpTimeoutException으로 시험이 중단됐으므로 완주 자료로 해석하지 않는다. 최종 `/api/ps`에서 측정 모델은 자동 만료되어 0개였다. 기존 프로세스를 종료하거나 전역 Ollama 설정을 변경하지 않았다.

## 연결 설정

- [개인 회상 설정](../server/config/mythictrpg/ai-memory-recall.json): recallV2 ON, REAL_KST. 기존 PERSONAL 설정 유지.
- [검색/정리 설정](../server/config/mythictrpg/ai-memory-index.json): 의미 검색 ON, 정리 ON, 정확한 모델 이름+SHA-256 digest 고정. API는 숫자 loopback만 허용한다.
- bge: CPU, 4스레드, 1024차원, 마지막 요청 후 600초 상주 요청. 확실한 단어 검색 결과는 의미 질의를 생략한다. 명시적 회상에서 필요한 질의만 **최대 350ms** 기다리고, 미적재·과부하·오류·모델 변경 시 기존 검색으로 복귀한다. 최초 로딩을 350ms에 완료한다는 뜻이 아니다.
- 의미 유사도 문턱 0.60. 측정한 관련 질의의 최고 점수는 약 0.556~0.671, 무관 질의는 약 0.467이었다. 기본 0.75는 모두 놓쳤고 0.60도 관련 2건은 놓치므로 만능값이 아니다. 무관 검색을 억제하는 보수적 시작값이며 추가 실제 회상 시험이 필요하다. 유사도는 확정된 기억/사실을 뜻하지 않는다.
- 정리: 기존 gemma4:12b 재사용, 접속자 0명·전경 요청 없음일 때만 한 건씩. 8192 문맥, 출력 최대 512토큰, 요청 최대 30초, 마지막 요청 후 60초 상주 요청. 최대 6개 같은 신·플레이어·월드·청중의 원문만 입력한다. 모든 문맥이 아주 긴 최악 사례의 품질은 미측정이다.
- 접속/대화 대기 발생 시 백그라운드 HTTP에 인터럽트를 보내 양보한다. 실제 transport가 끝나기 전에는 입장권을 반환하지 않는다. Ollama의 GPU 계산이 즉시 멈춘다고 보장하지 않는다. 공용 Ollama를 사용하는 외부 앱까지 이 스케줄러가 통제하지 않는다.
- 새 원문 벡터 생성도 무접속 시간에 수행한다. 장시간 연속 접속 중 아직 색인되지 않은 새 발언은 기존 단어/최근 원문 검색으로 처리하며, 즉시 모든 새 발언이 의미 검색되는 구조는 아니다.

검색 색인은 독립 **256MiB / 12,000행** 상한이다. 1024차원·1200자 합성 원문 6행은 96,144바이트(평균 약 16KB)였다. 재시도 보존 행/모델 변경 이력도 상한에 포함하므로 12,000개의 서로 다른 기억을 항상 보장하지 않는다. 벡터 성분 메모리 상한도 유지한다. 원문 저장 한도·보존 기간·자동 삭제 정책은 변경하지 않았다. 90% 바이트 사용 시 기존 서버/관리자 증설 안내를 유지하고 가득 차면 신규 색인만 거부한다. 색인 증설은 원문 증설과 별개다.

## 소스 수정 및 안전 경계

1. `MemoryIndexSettings.Execution`: 요청별 CPU/스레드/문맥/출력/상주/유사도/단어 검색 우선 설정. 누락 시 이전 기본값, 잘못된 설정은 OFF. 기존 호출용 생성자는 유지했다.
2. `OllamaMemoryBackend`: 출력 JSON Schema·원문 인용 상수·관계 참조 범위를 제한하고 한국어 분류 의미를 명확히 했다. 단순 계획 재진술은 이행으로 받지 않는다. `extractive-v3` 지문으로 구 추출 후보와 분리한다. [구조화 출력 공식 문서](https://docs.ollama.com/capabilities/structured-outputs). 형식 제한은 의미 정확도를 보장하지 않으므로 원문 대조도 유지한다.
3. `MemoryIndexRuntime`: 정리 실패/전경 양보 시 이미 계산한 벡터를 보존하고 재사용한다. 잘못된 요약 때문에 의미 검색까지 막지 않는다. 벡터와 정리 후보는 각각 최신 원문/모델/공개 범위를 확인한다. 원문 변경·삭제·세션/청중 경계, SHADOW의 원래 결과 유지, 실패 3회 제한을 보존했다.
4. `HybridRetrieval`: 의미 검색에서도 반복 원문이 세 슬롯을 독점하지 않게 중복을 제거한다. 최대 3개 원문과 불확실성을 유지하고 실제 퀘스트 완료/관계/보상을 판정하지 않는다.
5. `ModelAdmission`: 접속 또는 전경 대기에 백그라운드를 협조적으로 중단한다. 기존 전경 동시성·큐 용량과 게임 스레드 비차단 구조를 유지했다.

새 benchmark는 `memoryModelBenchmark -PmemoryLiveApproved=true -PmemoryBenchmarkMode=...`로 명시 요청할 때만 실행한다. `build/check`에 연결하지 않았다. 반복 실행도 사용자의 실제 모델 호출 허가가 필요하며 승인 플래그가 영구적인 사용자 권한을 뜻하지 않는다. [문서용 설정 예제](examples/ai-memory-index.example.json)는 OFF를 유지한다.

# 개인 장기기억 서버 테스트 세팅 — 2026-09-14

> 2026-09-14 최신: 회상 개선본 **AI 0.1.3**을 배치했다. 게임/클라이언트 **1.0.2**, 콘텐츠 0.1.0, PERSONAL은 유지한다. LP 원본과 수정 직전 상태를 보존했고 빌드/오프라인 710개 검사를 통과했다. 서버는 실행하지 않았으며 실제 모델 비교는 Ollama 미실행으로 연결 실패했다. [회상 개선 기록](MEMORY_RECALL_TUNING_20260914.md)을 참고한다.

## 적용 결과

사용자 요청으로 실제 `server/`에 개인 기억 시험 버전을 배치했다. **서버를 실행하거나 중지하지 않았다.** 배포 직전 Java 실행 인자를 확인해 Gradle 빌드 데몬만 있고 서버 포트 25565가 비어 있음을 확인했다. 부팅·접속·실제 LLM 대화는 사용자가 실행한 뒤 확인해야 한다.

| 대상 | 배치 파일/설정 |
|---|---|
| 서버 게임 | `server/mods/mythictrpg-1.0.2.jar` |
| 서버 AI 응답 | `server/mods/mythai_ai_response-0.1.3.jar` |
| 서버 콘텐츠 | 기존 LP `mythaiaicontent-0.1.0.jar`, 변경 없음 |
| 클라이언트 배포용 게임 | `server/client-required-mods/mythictrpg-1.0.2.jar`, 서버와 SHA-256 동일 |
| 새 설정 | `server/config/mythictrpg/ai-memory-foundation.json`: schemaVersion=1, mode=`PERSONAL` |

## 사용자가 테스트하는 순서

1. Minecraft 클라이언트를 종료한 상태에서 실제 런처 `mods`의 기존 MythicTRPG 1.0.0/1.0.1 JAR을 모드 폴더 밖에 보관하고 위 클라이언트용 **1.0.2** JAR로 교체한다. 신구 버전을 동시에 설치하지 않는다. 다른 필수 FTB/Architectury JAR은 기존 파일을 유지한다. 서버 전용 AI/콘텐츠 JAR은 클라이언트에 넣지 않는다. 이번 세팅은 런처 폴더까지 자동 수정한 것이 아니다.
2. 기존 Ollama를 준비한 뒤 `server/start-neoforge-ai-server.bat`로 실행한다. Java 21 / Minecraft 1.21.1 / NeoForge 21.1.248은 기존과 같다. 부팅 오류가 생기면 콘솔/최신 로그를 확인하고 임의로 다른 JAR을 섞지 않는다.
3. 접속 후 **평소 게임에서 신과 대화를 여는 경로**로 시작한다. OP라면 `/mythadmin gods`로 실제 신 ID를 확인하고 `/mythadmin interaction god @s <신 ID> 대화를 시작하자.`를 사용할 수 있다. 기존 등장/상호작용 정책에 따라 시작이 거절될 수 있으며 이 세팅은 해금이나 관계를 임의 변경하지 않는다.
4. 대화 중 OP 권한 2 이상이면 `/ai_memory status`와 `/ai_memory list`로 현재 신에 대한 자기 기억의 준비/저장 여부를 확인한다. 처음 잠깐 불러오는 중일 수 있다. `기억 기능 OFF 또는 서버 승인 대화 없음`이면 현재 게임 대화 세션이 실제로 열렸는지 확인한다. **직접 `/ai_test start`만으로 연 세션은 이 기억 시험 대상이 아니다.**
5. 예를 들어 `여행 간식으로 호박빵을 가장 좋아해.`라고 말하고 저장을 확인한다. 로그아웃했다가 다시 접속하여 같은 신과 새 대화를 연 뒤 `내가 여행 간식으로 무엇을 좋아한다고 했지?`라고 묻는다. 새 세션을 쓰는 이유는 최근 대화 히스토리만으로 답하는 경우와 구분하기 위해서다. 단순 키워드 검색이므로 원래 주제 단서가 있는 질문부터 시험한다.
6. 다른 신에게 같은 기억이 무단 공유되지 않는지, 관련 없는 대화에 기억이 반복 삽입되지 않는지, 응답시간·말투가 달라지는지 비교한다. 모델이 그럴듯하게 추측할 수도 있으므로 답 하나만으로 저장 성공을 판정하지 말고 상태/목록과 함께 확인한다.

`/ai_memory pin <UUID>`로 중요 기억을 지정하거나 `unpin`, `forget`으로 관리할 수 있다. 아직 중요한 약속을 자동 분류하는 기능은 없다. 기록은 첫 승인 대화부터 월드의 `mythictrpg-ai-memory-lp-v1/`에 새로 생성하며 예전 기억을 자동 가져오지 않는다.

## 검증과 미확인 항목w

이번 회상 개선은 게임/클라이언트 파일을 유지하고 AI만 갱신했다. 빌드와 기존 기억 검사 656개+신규 회상 검사 54개, 합계 710개를 통과했다. 과거 소문 39개/격리 GameTest 192개 기록은 별도 이력이며 이번에는 서버를 부팅해 재실행하지 않았다.

백업 해시·배포 파일/설정·구 JAR 중복 제거·서버/클라이언트 게임 일치는 다음 읽기 전용 명령으로 확인한다:

```powershell
.\dev-tools\Test-MemoryFoundationRelease.ps1 -ServerProfile PERSONAL
```

기본 `-ServerProfile LP` 검사는 배포 전 LP 상태를 기대하므로 현재 서버에는 맞지 않는다. `Test-LPBuild.ps1` 기본 실행의 `NOT LP`도 새 개발 버전에 대해서는 정상이다.

새 AI 0.1.3의 부팅/인게임/실제 생성 품질/동시 접속 지연은 미검증이다. Ollama 재생은 연결 실패했으며 기존 0.1.2 사용자의 부팅·대화 로그와 구분한다. 보호 대상 파일 검증만으로 실제 실행 호환성 전체를 보장하지 않는다.

## 백업과 되돌리기

회상 개선 직전 100개 파일/기억/로그와 AI 0.1.2는 [최신 백업](../server/backups/before-memory-recall-tuning-20260914-212335-935/file-manifest.csv)에 추가 보존했다. AI 0.1.3만 되돌리는 방법과 전체 LP 복원은 다르므로 [회상 개선 기록](MEMORY_RECALL_TUNING_20260914.md)을 따른다. 아래 29개 파일은 최초 PERSONAL 배포 전 백업이다.

교체 직전 29개 파일을 [배포 직전 백업](../server/backups/before-personal-memory-deploy-20260914-194200-226/file-manifest.csv)의 `workspace/` 아래에 보존했다. 기존 활성 JAR 3개는 추가로 같은 백업의 `retired-active/`에 옮겨 두었다. 삭제한 파일은 없다. 원본 `server/backups/LP/`, LP 소스 298개, 구현 직전 전체 소스 906개 백업도 그대로다. 월드·플레이어·관계·퀘스트 진행도를 초기화하거나 복원하지 않았다.

우선 개인 기억만 끄고 비교하려면 서버를 정상 종료한 뒤 새 설정의 mode를 `OFF`로 바꾸고 재시작한다. 기억 데이터는 보존된다. **OFF는 LP 바이너리/소스 복원과 다르다.**

LP 바이너리 복원을 요청하면 정상 서버 종료·현재 시험 상태 추가 백업 후 새 게임/AI JAR을 모드 폴더 밖에 보관하고, 배포 직전 백업의 게임 1.0.0 / AI 0.1.0과 클라이언트 게임을 함께 복원해야 한다. 새 기억 설정도 별도 보존해 비활성화하며 신구 JAR을 함께 두지 않는다. 기존 `Restore-LP.ps1`은 새 게임/버전 변경을 처리하는 도구가 아니므로 그대로 실행하지 않는다. 새 SavedData를 사용한 월드의 다운그레이드는 별도 검증이 필요하다. 게임 진행도를 되감거나 새 기억 폴더를 무조건 삭제하지 않는다.

소스 복원은 [기반 가이드의 선택 복원 절차](LP_MEMORY_FOUNDATION_GUIDE.md)를 따른다. 기반 완료 시점의 36개 차이 목록은 이력이며 패키지 수정 후에는 [최신 합산 차이 목록](memory-foundation-current-changes-20260914.csv)을 함께 확인한다. 현재 소스는 수정된 기반 버전이며 LP로 되돌리지는 않았다.

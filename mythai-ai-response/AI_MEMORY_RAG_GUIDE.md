# 보관용 실험 가이드 — OPELA 참고 + Hybrid RAG (LP 미적용)

2026-09-12에는 서버와 개발 소스를 LP로 복원했다. 이후 9월 13~14일 별도의 [개인 기억·소문 기반](../docs/LP_MEMORY_FOUNDATION_GUIDE.md)을 추가하고 후속 요청으로 서버에 PERSONAL 시험 버전을 배치했다. 최신 기준은 [서버 시험 안내](../docs/LP_PERSONAL_MEMORY_TEST_SETUP.md)와 [인수인계 30절](../인수인계/PROJECT_HANDOFF.md)이다. 이 문서 전체는 중단된 과거 실험의 설명이며 아래 기본값·기능·빌드·검증 결과를 LP 또는 새 기반 기능에 적용하지 않는다. 당시 실험 소스/빌드 스크립트는 `server/backups/before-LP-source-restore-20260912/mythai-ai-response/`에 보존한다.

## 2026-09-11 LP 보존 후 대화 튜닝

초기 OPELA/RAG 구현의 실제 테스트에서 답변 지연, 추상적인 반문, 과도한 Proposal과 JSON 잘림이 확인되어 다음을 수정했다. 아래 초기 구현 설명과 차이가 있으면 이 절을 우선한다.

- 개선 전 두 AI JAR은 `../server/backups/LP/`에 LP로 보존했다. 원본 해시와 호환 게임 JAR, 복원 절차는 그 폴더의 README에 있다. `../dev-tools/Restore-LP.ps1 -VerifyOnly`로 무변경 검증하고, 서버 종료 후 같은 스크립트로 복원한다. 월드와 v2 기억을 되감지 않는다.
- 튜닝 직전 JAR·설정·AI 소스는 `../server/backups/pre-dialogue-tuning-20260911/`에 따로 보존했다.
- `DialoguePromptTuning`이 운영 생성 프롬프트의 중복 작성 지침과 두 번째 TURN_DIRECTIVE를 줄인다. 게임 행동 금지·승인·참가자·공개 범위는 유지한다. 한 신 대화에는 비어 있는 신 간 관계 블록을 넣지 않는다. 캐릭터 콘텐츠 JSON 자체는 바꾸지 않았다.
- 생성 스키마는 대사 화자 수를 현재 화자 수로 제한하고, Proposal을 생략 가능·최대 1개로 제한한다. 가짜 `none` 타입을 제외한다. 대사·제안의 대상은 `player`로 제한하고, 짧은 제목·요약과 compact JSON을 요청한다. 생략한 proposals는 기존 parser가 빈 목록으로 읽는다. 최종 게임 Gateway 검증은 그대로다.
- 서버 출력 한도는 260→420이다. 최대 허용량이며 매번 420토큰을 생성하는 것은 아니다. 길이 부족을 막되 최대 1제안과 간결한 직렬화로 통상 생성량을 줄인다. 긴 대사는 기존 HUD 페이지로 전달한다.
- 직접 인사 경로는 장기 기억에 저장하지 않는다. 기존 기억도 짧은 근거와 최근 대화에 그대로 있는 근거를 제외한 뒤 순위를 매긴다. 최근 대화를 검색 질의에 덧붙이지 않는다. 검색 후보나 사용할 벡터가 없으면 임베딩 호출을 생략한다. 검색이 없으면 빈 기억 블록도 생략한다.
- 기본/테스트 서버 설정: retrievalLimit=3, memoryPromptCharacters=1200, analyzeEveryTurns=8, shadowEvaluation=false, maintenanceIdleSeconds=30. shadowEvaluation=false일 때 실제 모델 요청과 스키마에서도 품질 평가를 제외한다.
- 대화 세션이 활성인 동안에는 임베딩 색인·기억 추출 등 새 후처리를 시작하지 않는다. 세션 종료 후 유휴 30초 조건을 만족하면 실행한다. 이미 시작한 외부 요청은 선점 중단하지 않으므로 다른 세션이 그때 시작하면 자원 경합 가능성은 남는다. 대기 상한과 만료로 생략된 요약 대신 입력 원문은 보존된다. 대화 중 새 기억은 최근 히스토리와 키워드 검색으로 사용하고, 의미 색인은 이후 생성될 수 있다.
- 일회성 자발 대화 State도 종료 시 정리해 후처리가 영구 정지하지 않도록 했다.
- `dialogueComparison`은 기록된 동일 입력·최근 대화로 튜닝 전/후를 순차 재생한다. 실제 운영 helper와 스키마를 사용하지만, 기록된 중복 기억 제거 등을 재현한 생성 단계 비교이며 인게임 종단 테스트나 LP와의 직접 A/B는 아니다. 결과는 `build/reports/dialogue-tuning-comparison.json`에 저장한다.

부팅·배포 및 최종 측정 결과는 [인수인계](../인수인계/PROJECT_HANDOFF.md)의 최신 LP 기록을 따른다. 말투 만족도는 사용자 인게임 테스트로 판단한다.

## 적용 범위

- 실제 `GodAiDialogueService → AiTestDialogueAdapter` 경로에 연결했다. 별도로 사용하지 않는 legacy MemoryRetriever만 수정한 것이 아니다.
- 게임의 플레이어별·신별 affinity를 읽어 9단계 대화 지침을 선택한다. 게임 수치나 보상 정책을 변경하지 않는다.
- 최근 대화, 신별 일시 감정, 관련 장기 기억과 정적 프로필을 함께 사용한다.
- 퀘스트 완료·평가 대사 및 한 플레이어 대상 자발적 상호작용에도 읽기 전용 기억 검색을 연결했다. 서버 사건 설명을 플레이어 발언으로 저장하지 않는다.
- 여러 플레이어에게 전달되는 자발적 장면에는 개인 기억을 넣지 않는다. 현재 자유 대화 facade는 플레이어 1명 + 신 최대 2명이다.

[OPELA](https://github.com/smilegate-ai/OPELA)는 대화 데이터·수집 지침·평가 정보를 제공하는 프로젝트다. 이 구현은 공감, 자기개방, 능동성 등 그 관점을 참고한 자체 구현이며, OPELA 엔진 이식·데이터 학습·공식 평가 점수 재현이 아니다. 데이터셋이나 대화문을 복사하지 않았다.

## 요청 처리

1. 게임 스레드에서 플레이어·참여 신·실제 관계 수치와 현재 턴을 고정한다.
2. 비동기 검색 전에 월드 → 플레이어 → 신 → 현재 청중의 공개 범위를 필터링한다.
3. 현재 발언과 최근 문맥 일부를 질의로 사용한다. 실제 `bge-m3` 임베딩 코사인 유사도와 키워드·중요도·최근성을 합산해 관련 기억만 고른다.
4. 신별 검색 결과를 번갈아 제한된 프롬프트 예산에 넣는다. 출처·시각·원문 근거를 함께 전달하고, 기억은 지시나 확인된 게임 사실이 아니라고 명시한다.
5. 캐릭터·관계에 맞는 답변, 공감, 회상, 자기 감상, 후속 질문, 종료 중 필요한 반응을 선택하게 한다. 항상 친절하거나 질문하도록 강제하지 않는다.
6. 화자 ID를 서버가 지정한 enum으로 제한한 JSON Schema를 요청별로 사용한다. 감정 키도 같은 실제 ID만 허용한다.
7. 완료 시 세션·턴·frame·관계 수치를 다시 확인한다. 재생성은 같은 검색 문맥을 재사용한다. 무효화된 응답은 대사·기억·감정에 반영하지 않는다.
8. 최종 대사가 수락되면 입력 원문을 영속화한다. 여유 시간에 기억 추출·임베딩 색인·진단 평가를 처리한다.

단순 인사 빠른 경로는 유지한다. 그 입력은 저장하지만 매번 의미 검색·LLM 생성을 실행하지 않는다.

## 기억과 정정

저장 경로는 실제 월드 아래 `mythictrpg-ai-memory/memories-v2.json`이다. 서버 월드 이름이 `world`이면 `server/world/mythictrpg-ai-memory/`에 생성된다.

주요 필드: `id`, `player`, `god`, `heardBy`, `source`, `kind`, `text`, `evidence`, `createdAt`, `importance`, `supersededBy`, `vectorModel`, `vector`.

- `PLAYER_REPORTED`: 플레이어가 그렇게 말했다는 기억이다. 실제 아이템 소유, 퀘스트 완료, 신의 약속 이행 등을 보증하지 않는다.
- 원문은 `RECENT`로 저장한다. 추출 후보는 취향·능력·목표·약속·미해결 화제·주장으로 제한한다.
- 추출 결과의 sourceId, 참여 신, 원문 인용을 검증한다. 원문에 없는 인용이나 다른 플레이어·신의 기억 교체는 거절한다.
- 명시적 정정 표현이 있고, 추출기에 제시된 기존 기억 ID가 일치해야 이전 항목을 대체한다. 단순 유사 화제로 정정하지 않는다. 시간과 대체 상태를 검사해 오래된 분석이 최신 정정을 뒤집지 못하게 한다.
- 요약에는 원문 근거를 남긴다. 인용 검증은 요약 의미의 완전한 진실성을 보장하지 않는다. 정정 표현 인식과 대상 선택도 모델·규칙의 한계가 있다.
- 결정적인 턴 ID로 중복 저장을 막고, 같은 공개 범위의 동일 내용은 통합한다. 쌍별 상한에 도달해도 새 입력이 들어갈 자리를 유지한다.
- 원자적 파일 교체와 직전 `.bak` 백업을 사용한다. 손상된 파일은 자동 초기화하지 않고 해당 기억 기능만 실패 처리한다.
- 재접속·정상 재시작 뒤 같은 월드·플레이어·신으로 복원된다. 종료 시 디스크 쓰기는 최대 2초 대기한다. 강제 종료·디스크 장애에서 완전 무손실을 보장하지 않는다.

기존 `server/mythictrpg-ai-data/memories.json`은 그대로 보존한다. 이전 스키마에는 현재 필요한 공개 범위·원문 출처 정보가 없으므로 자동 이관하지 않는다. 과거 파일을 읽는 legacy 구현과 v2는 별개다. 과거 기억 이관은 대상·출처·공개 범위를 확인하는 별도 작업이다.

## 관계·감정·공개 범위

- 관계 원본은 `PlayerMythDataService`다. 기본 표시 단계 경계는 `[-800,-500,-250,-50,50,250,500,800]`이며 게임의 -1000..1000 값을 분류한다. 신규 게임 밸런스나 관계 원본 DB가 아니다.
- `/ai_test`의 명시적인 관계·감정 테스트 override는 유지한다. override 변경과 참가자 변경은 진행 중 턴을 무효화한다.
- 생성 JSON의 `emotions`는 발언한 신의 허용된 감정만 수락한다. 확실하지 않으면 `{}`를 허용한다. 감정은 원인 발언과 함께 세션 내에서 최대 3턴 참고하고, 현재 말·사과·정정에 따라 재해석한다. 영구 호감도로 저장하지 않는다.
- 참가자가 바뀌면 이전 사적 히스토리와 놀이·감정 상태를 비운다. 장기 기억은 청중 필터를 통과한 것만 다시 검색한다.
- 현재 Story 대화 조회는 해당 플레이어에게 공개할 범위만 검증하므로, 신이 두 명인 공동 프롬프트에는 그 개별 Story 문맥을 넣지 않는다. 공동 청중용 공개 계약이 생기면 확장할 수 있다.
- 실제 액션의 최종 권한은 기존 MythicTRPG Gateway다. 실행했다고 잘못 주장한 대사가 차단되면 그 응답의 Proposal도 보내지 않는다. 기억이나 품질 평가로 보상을 실행하지 않는다.

## 설정과 장애 대응

최초 사용 시 `server/config/mythictrpg/ai-memory.json`을 생성한다. 배포 전 현재 서버 설정을 임의로 만들거나 덮어쓰지 않았다. 설정 변경은 다음 서버 시작부터 적용한다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| enabled | true | 기억 검색·저장·후처리 활성화 |
| embeddingModel | bge-m3 | 대화 모델과 별도인 다국어 임베딩 모델 |
| embeddingTimeoutSeconds | 8 | 임베딩 요청 시간 제한 |
| analysisTimeoutSeconds | 60 | 후처리 LLM 요청 시간 제한 |
| maxMemoriesPerPair | 160 | 플레이어·신 쌍별 보관 상한 |
| retrievalLimit | 5 | 신별 검색 후보 상한 |
| memoryPromptCharacters | 2200 | 기억 데이터 공통 문자 예산; 정책 문구 제외 |
| minimumSimilarity | 0.48 | 키워드가 안 겹칠 때 의미 검색 최소 유사도 |
| analyzeEveryTurns | 4 | 기억 추출 주기; 정정·세션 종료 시 조기 처리 |
| shadowEvaluation | true | 수락된 대사에 대한 관찰용 품질 기록 |

임베딩 API는 기존 대화 URL의 `/api/chat`을 `/api/embed`로 바꿔 호출한다. 다른 커스텀 API 경로는 지원하지 않는다. [Ollama embed API](https://docs.ollama.com/api/embed)와 [bge-m3](https://ollama.com/library/bge-m3)를 사용한다. 이번 작업에서 bge-m3 모델을 설치했으며 기존 대화 모델 `gemma4:12b`와 서버 설정은 바꾸지 않았다.

실패 시 가짜 벡터를 만들지 않고 키워드 검색으로 전환한다. 임베딩 오류 뒤 60초 동안 재시도를 쉬며, 누락·구버전 색인은 백그라운드에서 제한적으로 복구한다. 차가운 모델의 첫 로딩은 제한 시간을 넘을 수 있다.

검색 워커 2개/대기 16개, 디스크 워커 1개/대기 128개, 후처리 대기 최대 24개를 사용한다. 대화 생성 중에는 새 후처리를 시작하지 않지만 이미 시작한 Ollama 호출은 선점 중단하지 않는다. GPU 메모리·모델 로딩·동시 접속 수에 따라 응답 지연이 늘어날 수 있다. 후처리가 120초 이상 기다리면 생략할 수 있으며, 이미 저장한 원문은 남는다.

## 관찰용 품질 평가

같은 월드 폴더의 `retrieval-YYYY-MM-DD.jsonl`은 검색 모드·지연·기억 ID·점수를 기록한다. `quality_shadow-YYYY-MM-DD.jsonl`은 공감 적절성, 자기개방 적절성, 주도성, 흥미, 일관성, 불편함 대응을 기록한다. 각 채널은 일일 약 8MiB에서 추가 기록을 멈추지만, 날짜별 파일 자동 삭제는 하지 않는다.

평가는 프로젝트용 -1/0..4 진단이다. -1은 비적용, 높은 수치는 적절한 대응을 의미하며, 불편함이 많을수록 높은 점수를 주는 방식이 아니다. 실제 최종 대사가 있으면 일관성·흥미를 모두 평가 불가로 반환한 결과는 사용하지 않는다.

점수로 대사를 자동 교체·재생성하거나 호감도·보상을 바꾸지 않는다. 기존 제한적 대화 복구 경로를 유지하며, 전송/파싱 재시도와 별개로 품질 점수 기반 반복 생성은 추가하지 않았다. 로그에도 플레이어 정보나 대화 근거가 들어갈 수 있으므로 외부 공유 전 검토해야 한다.

추출·평가 요청도 JSON Schema로 sourceId·God ID·종류·점수 범위를 제한한다. 문법·범위 검증과 실제 의미 정확도는 별개이며, 저장 단계의 원문·소유권·시각 검증도 계속 수행한다.

## 빌드 입력·호환·배포

- 새 원본: `src/main/java/.../ai/rag/`, `DialogueRagBridge`, `DialogueRequests`.
- `dialogue-upgrade.gradle`이 legacy 입력을 읽어 `AiTestDialogueAdapter`, `LocalOllamaClient`를 재생성한다. 생성 폴더만 수정하면 안 된다. 기존 `DialogueTurnDirective` 오버레이도 유지한다.
- 최종 JAR에는 새 LocalOllamaClient를 한 번만 넣고 legacy 동명 클래스는 제외한다. 이전 결합형 게임 JAR을 배포하지 않는다.
- 응답 모드 `build/libs/mythai_ai_response-0.1.0.jar`, 콘텐츠 모드 `../mythai-ai-content-registry/build/libs/mythaiaicontent-0.1.0.jar`가 배포 후보다. 둘 다 서버 전용이다.
- 서버 배포는 기존 JAR 백업, 정상 종료 확인, 변경 파일만 교체, 부팅·리소스 로드·인게임 대화 확인 순으로 별도 진행한다. `server/mods`, 클라이언트 파일, 월드, 기존 기억 파일은 이번 구현 과정에서 교체·초기화하지 않았다.

작은 서버용 JSON 저장소라 데이터가 커지면 전체 파일 쓰기 비용이 커진다. 전용 벡터 DB, 서버 검증 사건의 범용 장기기억화, 개인 기억의 다인 공개 승인, legacy 기억 이관, 감정·품질 평가 보정은 별도 확장 영역이다.

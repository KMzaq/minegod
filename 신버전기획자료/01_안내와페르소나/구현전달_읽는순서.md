# 구현 전달: 읽는 순서와 작업 경계

## 0. 이 묶음으로 하는 일

이 자료는 Minecraft 콘텐츠의 **저술 기획과 구현 계약**이다. JSON은 복사 설치하는 모드·데이터팩이나 검증된 런타임 스키마가 아니다. 기존 시스템 기반에 실제 등록 ID, 저장소, 서버 판정, NPC/LLM 입력, 모델·텍스처·애니메이션, 지급·수신 처리를 연결하는 구현이 필요하다. 문서에 `action`, `receipt`, `CAS` 또는 상태 이름이 있어도 그 API가 이미 제공된다는 뜻이 아니다. 지원 여부를 기존 코드와 대조하고, 없는 부분은 구현 작업으로 분리한다.

105패킷·772명 상세 원고와 공용 캠페인·전투·성장, 242명 현행 활성화, 전투 시각·판정 연결, 전체 지식 연결의 기획과 정적 검수·통합을 마쳤다. `색인.json#/all_authoring_complete`는 true이며 **저술 기획의 완료**를 뜻한다. `/runtime_ready`는 false로, 실제 모드 구현·자산 제작·게임 시험·실측 밸런스 완료를 뜻하지 않는다. `/release_ready`는 기획 묶음의 출고·패키징 검사 준비 여부이며 의미는 `/release_ready_scope`에 있다. 이 플래그를 게임 배포·실행 검증으로 해석하지 않는다. 참조색인은 연결 원고의 스냅샷이므로 후속 변경 시 영향받는 경로·포인터·해시를 다시 대조한다.

아래 경로는 모두 배포 묶음 최상위 기준이다. `파일.json#/필드`는 파일 안의 JSON Pointer다. 동봉 `구현전달_참조색인.json`은 정확한 현재 경로·포인터·내용 해시를 제공하는 탐색표이며 등록표가 아니다. 배열 번호는 스냅샷 값이므로 항목의 키를 함께 확인한다.

## 1. 네 범주를 한 인물 단위로 읽기

1. `먼저읽기.md` → `색인.json#/records`에서 대상 `record_key`를 찾는다.
2. 같은 항목의 `persona`, `story`, `quest_scope`, `knowledge`를 연다. 페르소나는 정체·성격, 스토리는 저자용 서사, 퀘스트는 수행·보상, 지식은 실제 앎·공개 경계다. 서로 대신할 수 없다.
3. 각 범주의 `현행추가저술_연결색인.json#/records`에서 **같은 관리키**의 `base_document`와 `current_detail_document`를 함께 읽는다. 공유 상세 파일이면 해당 인물만 선택한다. 상세에 그 범주의 변경이 없으면 기본값을 유지한다. 패킷의 `범주연결.json`도 최상위 기준 경로다.
4. 해당 인물의 현재 활성화 연결이 있으면 그 계약을 함께 적용한다. `스토리/현행활성화계약/색인.json#/records`가 진입점이다. 연결표의 존재만으로 실제 해금·출현·퀘스트 완료를 만들지 않는다. 연결이 없거나 null인 것도 무조건 접근 가능하다는 뜻이 아니다. 해당 인물의 기본·현재 상세 계약과 미확정 상태를 유지한다.

772명 전부를 동시에 엔티티로 생성하거나 한 프롬프트에 넣지 않는다. 필요한 인물·장면과 현재 상대, 관계, 실제 수신 지식만 선택한다. 미탄생·기록 전용·비언어·봉인 인물의 제약을 유지하며 동명 인물을 합치지 않는다. 모든 인물에게 MAIN·전투·보상을 일괄 생성하지 않는다.

### 적용 우선순위와 ID

- 중앙 출발점은 `퀘스트/공통설계/시간_조우_성장_운영정책.json#/priority`다. 현행 확정 정체·해금·금지·원수량 → 해당 내용 소유 개인팩/전투팩의 현재 채택 필드 → 종류별 전역기준 → 운영정책의 명시적 빈칸 기본값 순이다. 중앙 정책이 모든 개별 예외를 덮는 단일 만능 규칙은 아니다.
- 활성화는 `스토리/현행활성화계약/00_현행활성화_공통계약.json#/precedence`, 대화는 `페르소나/공통/관계와_상황별_대화계약.json#/source_precedence`, 기본 공격 전환은 아래 SS·BC 계약의 지정 범위를 따른다.
- `original_profile`, 원문 동일값인 `source_contract`, `인물별범위`, 전환의 `original`·`before`·`presentation`은 보존·비교 자료다. `adopted_detail`, 명시된 current/override/채택 필드는 그 지정 범위만 보강한다. 과거 후보의 `override: null`로 최신 채택을 지우거나, 보존 원문 전체를 현재 실행값으로 덮어쓰지 않는다.
- 원문 논리 이름만 남은 인용은 `퀘스트/공통설계/원문참조_연결색인.json`에서 실제 보존값으로 찾는다. 연결되지 않은 필드가 존재한다고 추정하지 않는다.
- `record_key`는 관리 식별자다. 예를 들어 `페르소나/인물/RPG-S01-001.json#/original_profile/godId`는 보존된 생산 프로필의 ID 근거이며, 엔진 등록 완료의 증거가 아니다. 같은 파일의 `/current_identity/registered_god_id`는 null, `/current_identity/runtime_registration_status`는 not_verified다. 실제 등록·변환표와 일치하는지 확인한 뒤 연결한다. 폐기된 테스트 God ID CSV로 되돌리지 않는다. 아이템의 편집키·제안 definition ID·실제 registry ID도 분리한다. `퀘스트/전투모드통합/무기별_SimplySwords_매핑_기획.json#/identity_policy`에 따라 C03/C05/합일검 편집키를 임의 등록 ID로 발급하지 말고 실제 등록·변환표를 검증한다.

## 2. 구현 순서: 의존성부터 고정하기

아래는 의존성 순서이지 각 영역 전체를 완성한 뒤 다음 영역을 시작하라는 뜻이 아니다. 먼저 기존 원고에서 현재 구현 가능한 한 인물·한 장면을 골라, 그 범위에 필요한 저장·접촉·청중·실제 수행과 수신을 끝까지 연결하고 ⑦의 해당 인수 사례를 바로 시험한다. 보상이나 전투가 없는 대상에 시험용 권리·전투를 추가하지 않는다. 이후 실제 보상·전투가 있는 기존 대상으로 범위를 넓혀 중복 방지·복구·입력·판정을 검증한다. 772명 전체 적재나 모든 시스템 완성을 첫 실행의 전제로 삼지 않는다.

### ① 엔진 안전 상태·저장·복구

먼저 `퀘스트/공통설계/시간_조우_성장_운영정책.json`의 `/state_separation`, `/clocks`, `/atomic_contract`를 구현 대상으로 분해한다. 권위 서버, 영속 journal, 유일키·원자적 예약, 실제 엔티티/인벤토리와 원장 대조, 재시작 복구가 뒤 단계의 전제다. DB와 외부 인벤토리가 자동으로 한 트랜잭션이라는 가정은 금지한다.

세계 해금, 단일 본체, 추첨 창·후보·결과, 개인 MAIN, 완료, 보상권, 실물 전달, 지식 수신을 별도 상태로 유지한다. 불명확 결과는 대조 전 재생성·재지급하지 않는다. 현실 UTC·서버 가동시간·시뮬레이션 tick·실제 활동시간을 문서대로 구분한다. 로그아웃·재접속·교체로 기록을 초기화하지 않는다.

### ② 관계·관측·청중별 지식

`페르소나/공통/관계와_상황별_대화계약.json`의 `/inputs`, `/priority`, `/relationship_update_separation`, `/acceptance_cases`와 `지식/공통계약/02_지식공급_기획계약.json`의 `/layers`, `/knowledge_gate`, `/state_machine`, `/canonical_grant_requires`, `/receipt_idempotency_design`을 연결한다.

저자 정사·미래 분기, 실제 사건, NPC 직접 관측/허용 전언, 플레이어별 수신, 대화 기억, 정식 Knowledge grant를 구분한다. 관계와 현재 맥락에 따라 태도는 달라지지만 LLM 발화 자체로 권리·완료·관계를 확정하지 않는다. 파티·세계 해금만으로 비공개 경험을 공유하지 않는다. 실제 청중·수신 증거가 없는 정보는 모르는 상태로 둔다. 등록되지 않은 지식 ID는 `/unknown_runtime_id_policy`에 따라 임의 발급·적재하지 않는다.

현재 전체 연결은 `지식/최종연결/00_전체연결_읽는순서와경계.md`에서 시작한다. 같은 폴더의 다음 정확한 필드를 읽는다.

- `01_772명_기본앎과현행저술_연결.json#/범위`, `/인물`, `/기본앎필드`, `/현행조건부지식필드`: 전체 105패킷·772명과 같은 인물의 실제 상세 포인터. 빈 loreKnowledge 때문에 허용된 자기 과거·관계 기억을 삭제하지 않으며 조건부 사건과 섞지 않는다.
- `02_공용73사건_전달끝점.json#/장면`, `07_공용사건_사실층과수신근거.json#/장면`: 장면별 실제 결과·전달 끝점·청중·재개 근거. 언급된 인물이 자동 청중인 것은 아니다.
- `03_원문값_실제전달파일_동등연결.json#/동등연결`, `/추가활성화_연결표`와 `08_기존원문별칭_동등성재확인.json#/동등연결`: 원문과 실제 전달 보존값의 연결. 동등성 표가 원문 자체나 신규 지식 권한을 대신하지 않는다.
- `06_수신과정정_전달계약.json#/전달순서`, `/회귀인수사례`: 개인별 실제 수신·정정·부분 재개. `09_시각관측_지식경계와활성화대기.json#/수신경계`, `/활성화인물연결`: 시각 표시와 242명 활성화가 개인 앎·참여 권리를 자동 생성하지 않는 경계.

이전 `지식/완결퀘스트_사건연결색인.json`, `지식/공통계약/03_현재사건_연결색인후보.json` 및 `05_원문참조_연결확장후보.json`은 역사 참조로 보존한다. 과거 447참조·37패킷 범위를 현재 전체 범위로 안내하지 않는다. `지식/최종연결/04_기존447참조_보존연결.json#/references`는 그 447앵커를 보존하는 표이며 현재 필드 수와 합산해 신규 지식 수로 세지 않는다. `05_보존논리포인터_해석후보.json#/후보`는 보존 내부 포인터의 해석후보일 뿐 현재 실행값이나 프롬프트 전체 주입 지시가 아니다.

### ③ 세계 해금·개인 조우·단일 본체

운영정책의 `/general_encounter`와 `/atomic_contract`, 활성화 공통의 `/initialization`, `/site_and_observation`, `/body_state_machine`, `/personal_separation`을 적용한다. 실제 한 명의 유효 달성이 세계 공통 해금이 되지만 현재 조우는 그 시점 조건을 충족한 실제 개인이 주체다. 해금자·조우주체·MAIN 첫 유효 명시 수락자·보상 수혜자는 자동으로 같아지지 않는다.

초기접근 인물에 새 해금 과제를 얹지 않는다. 이미 유효한 해금·본체·권리를 소급 잠그지 않는다. 미로드/불명확 본체를 최초 미배치로 취급하지 않는다. 존재·생사·봉인·접촉 모드를 유지하고 같은 본체와 접근 가능한 친구의 합류를 구분한다. 전용 조우와 일반풀에 중복 등록하지 않는다. 원문 허용 차원과 기존 자연 지형·공간에서 실제 부지를 바인딩하며 신화차원이나 새 전용 건축을 요구하지 않는다.

현재 활성화의 정확한 범위는 `스토리/현행활성화계약/색인.json#/records`의 242명과 `/scope_limit`이다. 미포함 인물은 기존 개별 정의를 유지한다. 같은 색인의 `/additional_source_links` 및 `색인.json#/current_activation_source_link_extensions`가 추가 근거표 3개를 연결한다: `스토리/현행활성화계약/00_BOOTSTRAP_최종근거연결표.json#/records`(33명), `스토리/현행활성화계약/추가56명_근거연결.json`(루트 배열), `스토리/현행활성화계약/04_A1_최종근거연결.json`(루트 배열, 105명). 기존 48명과 추가 194명의 참조 근거를 찾는 표이며 새 출현·권리·추첨을 실행하는 파일이 아니다. 전용 조우 일정·확률과 조건부/선택 분기는 일반 조우값이나 일괄 AND로 바꾸지 않는다.

### ④ MAIN·획득권·재고·실물 전달

`퀘스트/공통설계/전역기준.json#/claim_and_inventory`, `퀘스트/전투와보상/공통실행.json#/rights_count_rule` 및 `/execution_scope_priority`, 개별 퀘스트의 수락·완료·보상·실패 복구 계약을 적용한다. 정의가 있다는 사실, 수락, 실제 수행 완료, 선택권/획득권 생성, 재고 예약, 실물 인수는 각각 다르다.

첫 수락자 소유, 최초/반복 한도, a/b 선택, 무보상 결말, 수령실패 복구, 고유성은 원문/현행 개별 계약대로다. 재지급은 같은 권리 복구인지 별도 권리인지 구분한다. 신격 장비의 기본 무한내구는 `전역기준.json#/fixed_principles/divine_equipment_default_durability`에 따르며 명시된 유한내구 콘셉트 예외를 보존한다. 무한내구는 소실불가나 무제한 재지급 허가가 아니다. 친구 합류나 새 개정본 읽기로 보상권을 복사하지 않는다.

### ⑤ 장비·스킬·SS/BC 기본 공격·VFX

읽는 순서: `퀘스트/전투와보상/색인.json` → 해당 콘텐츠 원본 → `추가정의_참조색인.json`의 별도 본편·개인 정의 → `퀘스트/전투모드통합/전투모드_통합기획.json` → `무기별_SimplySwords_매핑_기획.json` → `전환_구현전달_기획.json` → `배포실물_정적확인.json`.

- 기존 **13개 실제 무기**를 다루는 전환이다. SS 원본을 개명하는 것이 아니라 허용 리소스를 참조하는 별도 무기를 구현한다. 13개 전부가 SS 근접검인 것도, 13개 신규 획득권을 추가하는 것도 아니다. 원본 passive/on-hit/active/channel·보석·회복·공속·쿨 초기화를 자동 상속하지 않는다. 라이선스·의존성 조건도 통합 계약에서 확인한다.
- `전환_구현전달_기획.json#/weapons`에서 `key`를 찾고 `route`, `after_initial_design`, `acquisition_source`를 읽는다. BC_NATIVE_BASELINE의 평타 범위·콤보·양손·타격 시점이 변경 전 수기 평타 기하보다 우선한다. 현재 초기 수치는 `after_initial_design`이며 `before`로 되돌리지 않는다. 다만 `/numeric_adoption`의 배포 프로필 일치 조건을 먼저 확인하며, 배포값이 다르면 전후표를 재계산·검수한 뒤 활성화한다. LEGACY_GEOMETRY와 동시에 적용하지 않는다.
- 같은 파일 `/weapons/4`는 `CTL-FOX-W01` 부채의 CUSTOM_FAN_EXCEPTION, `/weapons/9`의 C03_GUIDE_BOW와 `/weapons/11`의 C05_OPEN_PATH_BOW는 RANGED_EXCEPTION이다. 각각 기존 부채·활 경로를 유지하며 SS 근접 프리셋으로 강제하지 않는다. 곡괭이 등 제외 비무기도 근접검으로 변환하지 않는다.
- 기본 공격과 무기 고유 스킬, 독립 K/J 습득 스킬, 레이드 NPC 지원을 분리한다. 무스킬 무기에 스킬을 붙이지 않는다. 커스텀 검기·패링·대시의 별도 서버 판정과 VFX는 BC가 대신 구현해 주지 않는다. 통합 계약 `/input_contract`, `/events`, `/damage_application_contract`, `/boss_bridge`로 입력 경쟁·중복 적중·피해 중복·보스 접속 범위를 확인한다.
- `전역기준.json#/accessories`와 통합 계약 `/mana`, `/cooldowns`를 함께 구현한다. 장신구 자유 2칸, 적법한 별도 권리의 동일품 2개, 전투 중 교체를 지원하되 같은 권리 복제는 금지한다. 기본 마나 200+착용 증가량, 현재 최대 마나의 초당 1% 회복이다. 최대치 증가로 현재 마나를 공짜 충전하지 않으며, 교체·재지급·재접속으로 쿨·사용 기록을 초기화하지 않는다.
- `퀘스트/스킬연출/읽는순서.md`, `00_공통연출기준.json`, `효과별`의 해당 정의와 전투별 연출 문서를 읽는다. 준비→이동/발사→명중→종료, 실제 스윕 부피·벽/아군/다부위 판정, 소리·모델·텍스처·애니메이션을 구현한다. 작은 큐브 대체물만으로 완성 처리하지 않는다. 판정연결 계약에서 예고 외피·지금 위험한 코어·피해 없는 잔상을 구분하며, 허용된 안전여유 예고를 실제 판정으로 오인하거나 코어와 실제 위험 부피를 모순되게 구현하지 않는다.

시각·판정 연결은 `퀘스트/스킬연출/판정연결/00_읽는순서와_연결원칙.md` → `00_시각판정_공통계약.json#/단일기준`, `/채택_표시문법` → `01_패턴별_연결.json#/패턴` 순으로 읽는다. 같은 폴더의 `02_플레이어와지원_연결.json#/콘텐츠`, `/BC무기`는 플레이어 스킬·지원과 평타를 연결하고, `03_현장조작과원본_연결.json#/현장행위`, `/원본6` 및 `03A_보조전투_연결.json#/기존장면`은 현장 수행·원본·기존 보조전투의 범위를 보존한다. `04_구현전_인수.json#/사례`, `/패턴별추가`는 구현 후 수행할 시험이지 촬영·플레이 완료 기록이 아니다.

### ⑦ 실제 인수시험과 조정

지금까지의 근거는 저술 검수, 참조/수치 정적 검산, 일부 배포 JAR 리소스·프로필의 정적 대조다. **Minecraft 실행, NeoForge/Java 실행·호환, 실제 UI·API 연결, 모드 간 동작 호환, LLM 평가, 동시 5인, 렌더·영상·TPS 측정은 수행되지 않았다.** 개발 브랜치 API, 배포 JAR의 정적 존재, 실제 훅 동작은 서로 다른 증거다.

구현 후 각 계약의 인수 사례를 실제 로그·화면·영상으로 검증한다. 특히 재시작 중 중복 지급/본체, 동시 수락 경쟁, 오프라인·사망·후발자, 장신구 교체와 마나/쿨, 청중 밖 비밀 누출, 벽/아군/다부위 적중, 입력 잠금, 정확 버전의 기본 공격·커스텀 스킬 분리, 실제 1~5인 전투와 TPS를 확인한다. 정적 DPS·전투력·예상 시간은 실측 결과가 아니므로 목표값과 실측을 분리해 기록한다. 변경은 원래 획득권·개별 예외를 보존하며 전후 수치와 근거를 남기고 연결 참조를 함께 갱신한다.

# 공통 수행·회차·수령 계약

## 문서상태
채택된 완결 저술 기획이며 실행 스키마가 아니다. API·게임·서버 구현 및 실전 시험은 미실행.

## 접근
세계 해금은 누군가 한 번 성립시키면 공통. 현재 적격 조우 주체·원문 공용 후보풀/NONE·확률, 등장 후 동일 본체 접촉, 개인 수락을 분리한다. 이미 가능한 초기 접촉을 새 활동으로 잠그지 않는다. 원문 미채택 해금 후보는 과거 접근을 소급 봉쇄하지 않는다. 본체·봉인·생사·의사·발화 모드를 매 실행에 확인하며 부재자의 자동 응답0.

## 식별
accepted canonical EP와 기존 카드ID만 사건 원장키로 쓴다. 다른 제목은 표시 별칭이고 신규수주/권리/보상 원장을 만들지 않는다. world_uuid+canonical_id+original_event_uuid가 회차, 개인기여는 여기에 player_uuid. 신규 사건은 새로운 실제 필요·원물·당사자 동의가 있을 때만 별도 회차이며 완료된 물건/사고를 되감지 않는다.

## 수락과완료
수락은 실제 조건·범위·비용·대상·선택안을 보여주고 받은 명시 동의. 질문/농담/예측/친분은 수락 아님. 필수 실제 행동 만족 순간 완료. 정상 OR 대안은 하나만으로 해당 결말, 선택후기·실습·감사·미대여품반환은 새로운 완료 AND 조건이 아니다. 중단·부분성과·미발생 절정을 성공과 구별한다.

## 소유와복구
원물=현보관+실소비+실이전+실손실. 대여·가공·반환은 같은UID 계보로 기록. 이전 수락묶음은 품목/정수량/소유자/수령자/인도위치 스냅샷을 고정하고 실인도·미인도 잔량을 대조한다. 없는 물자·보장되지 않은 환급을 만들지 않는다. 원문 보장 대체재·정수량 협상은 보존하며 아래 기획의 고정 기본 물품으로 덮지 않는다. 보상권 생성과 실인도·수신은 별도, 수령 공간 부족·접근 불가·접속종료이면 같은 delivery_id의 미인도만 대기. 불확실 결과는 실제 슬롯/원물 영수증 확인 전 재지급 금지.

## 실패재개
사망·이탈·접속종료·서버재시작에는 마지막 실제 행위와 소비·현재 원물·하선/발언/수신을 보존하고 안전중단한다. 재개시 본체/허락/부지/재고 재확인 후 남은 부분만 수행. 실제 사망 드롭·파손은 현행 규칙이며 자동 재료 환급0. 진행 중단으로 영구 적대·벌금·물자 손해를 생성하지 않는다.

## 5인합류
5명 A–E가 같은 회차에 합류해도 NPC 본체·원물·완료된 사건은 하나다. A 수락·B 운반·C 후발·D 오프라인·E 거절의 상태를 따로 둔다. B가 실제 수행할 때만 자기 기여, C는 지금 남은 일의 동의와 수행만, D의 개인 완료·지식0, E는 일반 접촉 유지. 역할 분담은 권장이지 최소 인원이나 다섯 명 동시접속 조건이 아니다. 공동 수행 결과와 개인 지도권은 각 원문 자격대로.

## 후발과MAIN
후발은 현재 남은 행동에 자기 수락으로 참여하거나 공개 결과를 실제 읽는다. 과거 기여·칭찬·사적 기억·수령권 복제0. 기존 MAIN은 첫 유효 명시 수락자만 소유하며 부재시 자동 양도0. 신규 SIDE의 MAIN 없음은 기존 MAIN 삭제가 아니다.

## 지식

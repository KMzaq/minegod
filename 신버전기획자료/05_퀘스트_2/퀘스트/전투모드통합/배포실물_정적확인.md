# 정확 배포물 정적 확인

## 결론

Simply Swords 1.70.2-1.21.1 NeoForge와 Better Combat 2.4.0+1.21.1 NeoForge의 실제 JAR를 실행하지 않고 ZIP 자료로 읽었다. 실제 13개 무기 중 SS 후보 10개에 쓰는 5종의 모델·텍스처·프로필이 확인되었다. 기존 개발소스 관측과 해당 배포의 배율·각도·upswing·range_bonus·상속 관계가 일치한다. 실제 전환안 10행의 배율·산술평균 입력도 일치하여, 이 정적 대조에서 수치 재계산 사유는 발견되지 않았다. 부채 1개와 활 2개 예외는 유지한다.

이는 신규 아이템 구현, 정확 NeoForge 21.1.248 호환, NPC 후킹, 화면, 실효DPS, 5인 플레이 또는 영상 검증의 완료가 아니다. 설치·게임·Java 코드 실행은 모두 0회다.

## 무기 프로필

아래는 JSON 상속 연쇄를 따라 상위 필드를 읽고 자식이 명시한 필드를 우선한 정적 결과다. 실제 로더의 병합·기본값·조건 평가는 별도 시험한다. range_bonus는 절대 사거리가 아니고, angle 0을 사거리/범위 0으로 해석하지 않는다.

### longsword
- 상속: data/simplyswords/weapon_attributes/diamond_longsword.json
- 단독 조건 없는 단계 배율: [1, 1, 1.4]; 각도: [120, 120, 0]; upswing: [0.5, 0.5, 0.5]; range_bonus: 0.1.
- two_handed 명시: 없음. 실제 기본값/한손 동작 미확정.

### cutlass
- 상속: data/simplyswords/weapon_attributes/diamond_cutlass.json → data/bettercombat/weapon_attributes/sickle.json
- 단독 조건 없는 단계 배율: [0.9, 0.9]; 각도: [120, 120]; upswing: [0.5, 0.5]; range_bonus: 0.
- two_handed 명시: 없음. 실제 기본값/한손 동작 미확정.
- 상위 sickle의 range_bonus -0.25를 SS 자식이 0으로 덮어쓴다. 추가 1.2/1.3 단계는 각각 DUAL_WIELDING_SAME_CATEGORY 및 MAIN_HAND_ONLY/OFF_HAND_ONLY 조건이 있다. 현 단독 정책의 0.9/0.9 계산을 유지하고 무조건 4타 평균을 쓰지 않는다.

### greathammer
- 상속: data/simplyswords/weapon_attributes/diamond_greathammer.json → data/bettercombat/weapon_attributes/heavy_axe.json → data/bettercombat/weapon_attributes/double_axe.json

- two_handed 명시: True

### glaive
- 상속: data/simplyswords/weapon_attributes/diamond_glaive.json → data/bettercombat/weapon_attributes/glaive.json

## 의존성 메타데이터 전사

각 META-INF/neoforge.mods.toml에 실제 적힌 필드만 옮겼다. 의존성 설치나 버전 조합 해석을 승인하지 않는다.

### simplyswords: loaderVersion [4,)
- modId=neoforge, mandatory=True, versionRange=[4,), ordering=NONE, side=BOTH
- modId=minecraft, mandatory=True, versionRange=[1.21, 1.22), ordering=NONE, side=BOTH
- modId=architectury, mandatory=True, versionRange=[13.0.11,), ordering=AFTER, side=BOTH
- modId=fzzy_config, mandatory=True, versionRange=[0.6.6,), ordering=AFTER, side=BOTH
- modId=simplytooltips, mandatory=True, versionRange=[0.1,), ordering=NONE, side=CLIENT
### bettercombat: loaderVersion [2,)
- modId=neoforge, type=required, versionRange=[21.0,), ordering=NONE, side=BOTH
- modId=minecraft, type=required, versionRange=[1.21,), ordering=NONE, side=BOTH
- modId=playeranimator, type=required, versionRange=[1,), ordering=AFTER, side=BOTH
- modId=cloth_config, type=required, versionRange=[15.0.0,), ordering=AFTER, side=BOTH

SS의 neoforge versionRange는 실제로 [4,)이며 이를 [21.1.248]이나 다른 범위로 교정해 전사하지 않았다. 이 SS TOML dependencies에 Better Combat 항목은 없다. 반대로 BC에는 playeranimator와 cloth_config가 선언돼 있다. 이 사실은 SS/BC의 상호 기능 또는 정확 로더 호환이 보장된다는 뜻이 아니다.

## 클래스·helper 경계

ItemsRegistry에 DIAMOND_LONGSWORD/CUTLASS/GREATHAMMER/GLAIVE/KATANA 필드와 대응 ID 문자열이 존재한다. 실제 레지스트리 등록 실행/스택 생성은 확인하지 않았다.

SimplySwordsAPI 클래스에 applyAbilityBoltDamage, applyAbilityMagicDamage, applyAbilityMagicDamageThroughIframes, applyEntityWeaponHit, applyEntityWeaponPostHit의 public static 선언이 존재한다. 정확 descriptor는 JSON에 기록했다. HelperMethods·ForgeHelperMethods와 BC WeaponAttributes/WeaponAttributesHelper/WeaponRegistry/PlayerAttackHelper/ServerNetwork도 존재한다. SS 일반검에는 hurtEnemy 및 inventoryTick 선언이 있다. 개발문서의 postHit 명칭을 이 NeoForge 배포에 그대로 호출할 수 있다고 쓰지 않는다.

메서드 선언 확인은 부작용·호환 mapping·안정된 공개 API 계약·사용 권한·NPC 사용 가능을 확인한 것이 아니다. 기존 SS helper 미채택 결정, 고정 기술피해와 NPC 지원 원행동 분리는 유지한다. 개발문서가 설명한 iframe/implicit/인챈트/postHit 세부 동작까지 이번 클래스 구조 읽기만으로 배포 검증 상태로 바꾸지 않는다.

## 현재 기획에 반영할 수 있는 범위

- “JAR 검증0” 전체를 호환확정으로 바꾸지 않고 “선정 리소스·프로필 정적 검증, 게임0”으로만 좁혀 적는다.
- 평타 프로필의 정확 참조 animation ID 존재는 확인됐다. 기존 우클릭 고유기술의 애니메이션 ID를 자동 채우지 않는다.
- 개발관측 수치 일치만 승격한다. 렌더/효과차단/이벤트 순서/NPC/실효DPS/5인 시험은 계속 미확인이다.
- 본 확인 범위 밖의 구현·후킹·실효 성능은 완료로 표시하지 않는다.
- 원본 JAR, PNG, 애니메이션 원문, 소스코드 및 라이선스 원문은 사용자용 산출물에 포함하지 않는다.

# COMBAT-MOD-03 · 신규 무기, 기본공격, 기술과 레이드 전환

정확 배포물 추가 확인: 같은 폴더의 배포실물_정적확인.json 및 .md가 선정한 5종 모델·텍스처·프로필과 관련 평타 클립의 실제 JAR 정적 대조 근거다. 이 범위에 한해 이전의 JAR 미확인 표기를 보완한다. 기본값·후킹 동작·정확 로더 조합·렌더·실효DPS·멀티플레이는 여전히 미시험이며 수치 전환안은 변경하지 않는다.


## 1. 이번에 결정한 것

이 문서는 **채택된 초기 전환 저술**이며 실행 스키마·데이터팩·완성 코드가 아니다. SS 리소스를 기반으로 별도 mythictrpg 아이템을 만들고 BC의 정상 기본공격을 사용한다. 무기 13개 중 10개를 근접 native 후보로, 부채 1개와 활 2개는 기존 별도 경로로 둔다. 30개 비무기와 추가정의 참조 18개를 빠짐없이 대조했다. 본편 주요전투 8개와 키메라를 검토하되 모두를 같은 레이드 형식으로 바꾸지는 않는다.

실물 ID·획득권·세계유일성·이야기 콘셉트·무스킬 여부·신제 무한내구와 명시 유한내구·우클릭과 K/J 역할은 보존한다. 신규 보상권리 0개다. 현재 원고는 변경하지 않았다. 이후 통합에서는 이 문서의 전후값과 모든 동일키 참조를 함께 개정한다.

SS 1.70.2 NeoForge / BC 2.4.0+1.21.1 NeoForge / NeoForge 21.1.248가 목표다. 이번 수치 산술은 앞선 통합/매핑 계약에 저장된 **가변 개발브랜치 프로필 관측**을 사용한다. 정확 배포 JAR SHA·상속 병합·클립·실타점·5인 동작·커스텀NPC 호환을 검증했다는 뜻이 아니다. 다른 배포값이 나오면 그것을 옛 기하에 맞춰 재작성하지 않고 이 표의 초기값과 계산을 재검토한다.

## 2. 공격력 재배분의 의도

단독 상태에서 실제 선택 가능한 단계만 평균한다. longsword 1/1/1.4, SS greathammer 1/1/1.5, glaive 0.8/0.8/1.4, katana 0.8/1.2/1.2/0.8, cutlass 단독 0.9/0.9를 사용했다. cutlass 부모 sickle의 조건부 쌍수 1.2/1.3을 평균에 넣지 않았다. SS greathammer는 BC hammer가 아니라 heavy_axe 상속 후 자체 attacks를 덮은 관측이다.

기본 속도는 유지하고 **기존 A0 ÷ 적격 콤보 평균**을 새 A0 초기값으로 정했다. 이 값은 단독·무인챈트·무버프·비치명·매 단계 동일주기라는 조건에서 장기 원시 기본출력을 기존 수준으로 맞추는 출발점이다. 모든 무기를 같은 DPS로 만드는 공식이 아니다. 원래 8.8, 10, 11.2, 11.25, 12, 14.4, 16.8 등 역할별 차이는 남는다. 넓은 native 범위의 다수 적 효율, 양손의 방패 포기, 느린 마무리와 중단 손실은 평균으로 상쇄되지 않는다.

총공격을 나누는 것이지 무기 modifier만 나누는 것이 아니다. 플레이어 기본1이면 무기 modifier=A0−1. 재질 M이 별도로 더해지는 생성자는 인자=A0−1−M. 기본 공속4인 ADD 경로는 modifier=목표속도−4. 배포 API가 다르면 실제 총합을 역산한다. 이 문서가 검증된 생성자 호출 코드를 제공하는 것은 아니다. 속성의 소수 정밀도를 지원하지 않는 저장소면 몰래 정수로 반올림하지 말고 표를 다시 계산한다.

CP 원식과 계수는 그대로다. W=무버프 무기기여=A0−플레이어 기본기여라는 기존 정의에 따라 변경된 W도 함께 기록한다. E/K/J는 자동 재평가하지 않는다. BC 임시배율·실제 타점·공속·다중적 총피해를 CP의 A나 W에 집어넣지 않는다. 이로 인한 CP 표시 차이는 설명 대상이지 전투력 하드컷의 근거가 아니다.

공방검의 기존 총7.5는 A0=6에 날카로움II 1.5가 추가된 비교값이다. 새 A0=5.294117647에 인챈트를 별도 1회 적용한다. 인챈트가 콤보 뒤 고정추가인 조건에서는 장기12가 유지되지만 콤보에 포함되는 배포경로라면 12.32가 되는 민감도가 남는다. 배포 내부 순서를 확인하기 전 완전 동등하다고 말하지 않는다. 힘도 평균에 따라 실제 이득이 달라지며 강한 가호를 무료로 평준화하지 않는다.

## 3. 단일 피해 파이프라인

A0는 플레이어 기본+실제 공격손 무기만이다. Strength/약화, 인챈트, 레이드 추가항, 장신구 F, BC temp_attack, 치명/충전/방어를 제외한다. 정상 속성에 이미 +3L이 있으면 또 더하지 않는다. BC combo/dual/multitarget 처리는 native 한 번만, 정상 공격 경로는 치명/인챈트 한 번만 담당한다.

그 정상 공격의 방어 전 결과에 적격 레이드항 0.04×A0×L과 개별 허용 F만 한 번 더한다. 이 두 항을 다시 콤보·치명으로 증폭하지 않는다. 합친 하나의 피해를 기존 방어·보호·저항·보스게이트·흡수·HP 경로에 전달한다. CP식을 실행피해로 호출하지 않는다. H01 A0=9, 힘I, 비치명·무인챈트의 개발콤보 조건은 9.96/9.96/17.16이며 이것은 방어 전 적격레이드 입력이다. 12.36에 0.8/1.4를 재곱하는 계산은 잘못이다.

우클릭 기술의 원시6/8/7/10/5/24, H03 피해0은 별도 경로다. 기본공격력·Strength·BC 콤보를 자동 가산하지 않는다. 우리 기술을 BC 추가 스윙으로 다시 실행하거나 SS 능력 도우미를 거쳐 두 번 계산하지 않는다. 아테나 응수는 성공 조건이 맞은 원공격자만, 합일검 기믹접촉은 무피해다.

SS awakening/implicit/runes/gems/on-hit/passive/active/channel/공속/회복/쿨리셋은 기본 반입0이다. 효과 없는 우리 아이템과 허용된 리소스 참조가 안전한 기본 경로다. 태그·인벤토리틱·전역이벤트·재련을 별도 감사하며 툴팁 삭제만으로 차단했다고 하지 않는다.

### fast_attacks와 독립 피해게이트

BC의 fast_attacks가 timeUntilRegen을 0으로 바꿔도 아래 서버 판정은 살아 있어야 한다. 이는 BC 타격 기하를 다시 만드는 것이 아니라 피해 승인 마지막 접점이다.

1. 본체/소유자/시도 식별 → 같은 eventId 재전송과 동일 스윙의 다부위 중복제거.
2. 대상 생존·관계·참가/지역·현재 무적·기믹상태·기존 패링/회피 판정. 여기서 취소된 사건은 게이트 최대값이나 적중·흡수·매듭을 갱신하지 않는다.
3. 원문 순서의 방어 후, 흡수/HP 전 유효 후보 d 산출.
4. 해당 전투에만 (canonicalAttempt, bossCombatId, verifiedOwner) 10tick 창 적용. 최초 유효시각 s, 최대 M. [s,s+10)에서 전달=max(0,d−M), M=max(M,d), 창 연장0. s+10은 새창. 8→4→10이면 8/0/2. 서로 다른 두 소유자8씩이면16.
5. 이 차액을 흡수/실HP에 한 번 정산. HP>0 적중 조건만 원래 규칙대로 발행. 내구는 승인된 정상 스윙의 원문 적격 적중을 기준으로 최대1회, 다부위/다수대상으로 증식0.

공방 수호체·협곡 난폭수·C05·C07·C26·키메라의 명시 소유자창을 각 원문대로 바인딩한다. 키메라의 별도 명시 도트 펄스를 직접공격창과 무조건 합치지 않는다. C10/C11/C17/T03/T04에는 위 창을 일괄 신설하지 않는다. 이들의 기존 피격무적·개별 태그 정책을 유지하는 호환 접점을 확인한다. BC fast 설정 때문에 그 정책을 유지할 수 없으면 해당 조합은 출시하지 않는다.

회피기술의 실제 순간무적, phase GATE, 제압후 무적은 timeUntilRegen 한 숫자에 의존하지 않고 권위 있는 상태/종료시각으로 최종 피해접점에서 판정한다. 무적 종료 직후 과거 취소피해를 예약해 되살리지 않는다. 패킷을 소유자 없는 새 공격으로 만들어 창을 우회하지 않는다. C26 canonicalEventUUID는 시도 전체에 고정되며 매 타격 새UUID가 아니다.

### SS 도우미 경계

공식 개발문서의 applyAbilityBoltDamage는 인챈트 보정·iframe 우회, applyAbilityMagicDamage는 정상 iframe 및 NeoForge Iron’s 저항, ThroughIframes는 우회, applyEntityWeaponHit는 timeUntilRegen 초기화·implicit/인챈트 callback/postHit 경로를 가질 수 있다. 이 경로들을 고정 피해인 우리 기술의 단순 전달기로 채택하지 않는다. applyEntityWeaponHit와 applyEntityWeaponPostHit를 같은 타격에 병용0. delegated hit의 sourcePlayer는 귀속, actor는 실제 위치/방향/속성/스택이며 이를 섞어 원격 타격하지 않는다.

findClosestAbilityTarget은 우리 적대/아군 필터를 대신하지 않고 isValidAbilityTarget도 NPC 관계·레이드 참가권을 자동 이해하지 않는다. 우리 허용표로 적격 대상을 먼저 결정한다. Iron’s 설치 시 SS 기본 능력 쿨감·spell max 경로가 달라질 수 있으나 이번 통합에는 그 연동효과를 채택하지 않는다. 이 단락도 개발문서 관측이며 배포 확정 주장이 아니다. 출처: https://github.com/Sweenus/SimplySwords/blob/Architectury-1.21/developer-docs/api/combat-and-damage.md

## 4. 입력, 취소와 양손

서버는 IDLE→BC 준비→유효타점→BC 회수→IDLE을 BC 생명주기에서 관측한다. 별도 옛16tick/25tick 평타 타이머를 병렬 가동하지 않는다. 기술도 승인→준비→활성/발사→개별 회수라는 별도 행동 ID를 가진다. 같은 tick은 서버 첫 유효 승인 하나뿐이다.

서버 재접속/차원전환 때 공격 영수증과 다음 가능시각을 복구한다. 일반 쿨은 서버가동tick 기반이며 종료중 소급감소0. BC가 필요한 시각을 공개하지 않는 배포이면 검증된 버전별 어댑터가 필요하고, 접점 없이 추측 타이머를 겹쳐 출시하지 않는다.

반복 feint로 첫타만 뽑는 운용은 실제 reset 대기와 다음승인시각을 로그로 검사한다. 표의 ‘첫타만·리셋비용0’는 그 비용을 뺀 **비교 상한**이지 가능한 플레이를 보장하는 회전이 아니다. first-hit spam이 단순히 빠르다는 이유로 콤보를 강제 완주시키지는 않는다. 준비 전환을 취소하는 방어 선택은 가능하되 피해/공속 이득을 복제하지 않는다.

## 5. 시각과 실제 판정

BC 평타는 native 애니메이션·native 타점·native 후보 판정이며, 우클릭 검기/패링/전뢰/불씨는 별도 연출이다. 관우 무스킬 장도에 검기를 붙이지 않는다. 다짐망치에 울림을 붙이지 않는다. 기존 짧은 망치/중량추는 손잡이·머리 실루엣과 공속으로 구별하되, native 180도 2회+마무리의 확대는 명시된 평타 전환이다. 그 확대를 우클릭 스턴·낙뢰 범위까지 늘리는 근거로 쓰지 않는다.

각 실제 native 프로필 range_bonus는 절대 사거리가 아니다. angle=0은 해당 각도검사 생략이지 범위0이 아니다. 기본 도달거리·부위 AABB·profile 병합·벽검사·서버 다중대상 설정을 합친 실제 결과로 표시한다. 모델이 길다고 별도 ray나 70도 판정을 추가하지 않는다.

- t0 비용24/쿨160 승인, [0,2) 손목 준비, [2,4) 날 모양이 잡힘. t4 승인 눈원점 O에서 발사, [4,14) 속도1블록/tick으로 최대10블록, t10 손 회수 종료. 발사 이후와 회수 종료는 다르다.

## 6. 수치 검산을 읽는 방법

동봉 ‘무기별_전후와노출창.md’에 전후 A0/W·타격열·첫타·완주를, ‘레이드별_전환검토.md’에 9전투의 수치·모든 패턴 참조를 정리했다. CSV와 재현 스크립트는 모두 읽기용 산술이다.

- 시간별 표: 0.5/1/2/3/5/10/20/26/60초, 적1/3/5, 보조표적 q=1/0.5. 실제로 모든 적이 매 단계 형상 안에 있어야만 그 합이 가능하다. 단일보스에 n배를 넣지 않는다. 활/부채의 n>1은 자동광역 비적용이다.
- 기본 타점은 실수 주기20/s, 준비비율0.5 가정이다. 12.5tick을 엔진에서12 또는13tick 고정이라고 주장하지 않는다. 정확 정수틱 양자화·콤보 지속/초기화·애니메이션 길이는 배포측정 항목이다.
- 기술교대 표: 자유시점 우클릭→선택 K/J 기준프로필→평타 우선, 기술후 콤보첫단계로 돌아가는 보수적 분석 분기. 실제 native reset 규칙을 바꾼다는 뜻이 아니다. 완전명중·조건응수성공·허용도트·비행5tick 가정이어서 달성 보장0이다.

- 원시피해·10tick창후피해를 나란히 놓되, 후자는 무방어 단일소유자 직접사건 민감도다. 키메라처럼 도트창 예외가 있으면 해당 행을 실제규칙으로 분리한다. 실전 DPS라고 부르지 않는다.

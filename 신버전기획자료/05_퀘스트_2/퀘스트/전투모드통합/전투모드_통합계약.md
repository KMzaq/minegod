# Simply Swords 기반 신규 무기와 Better Combat 통합 계약

문서 ID: COMBAT-MOD-INTEGRATION-01, 개정2(BC 기본 동작 우선). 채택된 기획 전환안이며 실행용 데이터팩·구현 코드가 아니다. 설치·게임 실행·실서버 시험은 하지 않았다.

## 1. 채택 구조

Simply Swords(이하 SS)는 무기 외형·무기군·관련 리소스를 재사용하는 의존 모드, Better Combat(이하 BC)은 플레이어 근접 평타의 유일한 실행 주체, mythictrpg 통합부는 기존 이야기·획득권·기술·자원의 실행 주체로 둔다. SS의 고유무기를 이름만 바꿔 지급하는 방식은 채택하지 않는다.

새 등록 아이템은 기존 mythictrpg 정의 ID와 연결한다. 콘텐츠 ID·권리 ID·실물 UUID·등록 아이템 ID는 서로 다른 개념이다. 기존 정의 ID가 이미 아이템 레지스트리를 점유한 경우 다시 등록하지 않고 동일 레지스트리의 구현을 교체한다. 기존 것이 다이아몬드 검 component 변형뿐이었다면 같은 mythictrpg 정의를 새 아이템에 연결하는 이관표를 만든다. 합일검처럼 아직 문서 키만 있는 것은 문서 키를 기존 등록 ID였다고 꾸미지 않는다.

기본 구현 방침은 효과 없는 자체 무기 아이템 + 검증된 SS 리소스 참조 + 전용 BC 무기 프로필 + 기존 개별 우클릭 기술이다. SS 고유무기 클래스를 직접 상속해 기능을 모두 얻은 뒤 일부만 끄는 구조는 기본안이 아니다. 일반 무기 기반 클래스도 개발소스에서 implicit 초기화 경로가 확인되므로 plain이라는 이름만으로 무효과라고 간주하지 않는다. 설치 의존성으로 우선 재사용하며 자산 복사·수정·재배포는 실제 확보한 허용 범위에서 진행한다. 사용자가 라이선스 확보를 맡았다는 사실을 이미 허락받았다는 뜻으로 쓰지 않는다.

## 2. 버전 경계

- 확인된 목표 배포물: SS 1.70.2, Minecraft 1.21.1, NeoForge 배포 파일 8746001. [공식 배포](https://www.curseforge.com/minecraft/mc-mods/simply-swords/files/8746001)
- 확인된 목표 배포물: BC 2.4.0+1.21.1-neoforge, 공식 버전 ID VhIOvcXP. [공식 배포](https://modrinth.com/mod/better-combat/version/2.4.0%2B1.21.1-neoforge)
- 정확한 NeoForge 21.1.248 조합과 5인 전용 서버는 미시험이다. 필수 의존성의 정확한 버전은 해당 배포물 메타데이터를 대조한 뒤 고정한다.
- SS Architectury-1.21 개발문서는 확장 방향 참고다. 그 문서의 API·채널링·활성 단축키·NPC 연동을 위 배포 jar가 모두 제공한다고 보장하지 않는다. BC 1.21.1 개발브랜치의 필드도 배포 버전과 대조해야 한다.

## 3. 시스템별 소유권

1. BC 단일 소유: 근접 평타 입력 실행, 선딜·타격시점·회수, 실제 스윙 후보 판정, 콤보 단계, 쌍수 교대, 평타 애니메이션·풍절음.
2. 통합부 소유: 사용권 검사, 허용 대상/지역 필터, 개별 스킬 피해 및 필요 시 평타 보정, 중복 제거, 내구 정산, 우클릭 기술, K/J 습득 기술, 마나, 장신구, 가호, 보스 허용표, 원장.
3. SS에서 채택한 리소스: 검증된 모델·텍스처·렌더 참조 또는 무기군 기반의 새 제작물. 기능 상속과 외형 재사용을 별도 승인 목록으로 관리한다.
4. NPC/보스 AI와 기믹: 기존 별도 컨트롤러 소유. BC 플레이어 평타를 장착만으로 NPC 전투 AI에 자동 이식하지 않는다.

기존 EXPANDED_NORMAL_ATTACK의 별도 좌클릭 타이머·자체 광역 피해 실행기는 BC 전환 대상에서 제거한다. 보호·권리·내구 조건은 BC 한 번의 승인/피해 전달 과정에 연결한다. 종전 평타의 정확한 부채꼴·대상수·주보조 배분은 전환 전 기준으로 보존하되, 추천안은 BC 기본 프로필의 실제 동작으로 바꾸고 아래 전후표로 공개한다. 원형 수치·기하를 전부 복제하는 어댑터는 대안이지 필수 전환비용이 아니다. BC가 때린 뒤 옛 광역 공격을 한 번 더 호출하는 방식은 금지한다. 필요한 접점이 목표 배포물에 없으면 버전별 어댑터를 구현·시험하기 전 해당 무기를 활성화하지 않는다. BC를 애니메이션 전용으로 쓰고 별도 평타 실행기를 숨겨 유지하는 것도 이 계약과 다르다.

## 4. SS 효과의 기본 차단과 선택적 재작성

다음은 원본에 실제로 존재할 때의 감사 분류다. 모든 SS 무기가 모든 기능을 가졌다는 뜻은 아니다.

- on-hit: 원본 적중 발동·연쇄·추가탄·보석 발동은 가져오지 않는다. 새 콘텐츠에 명시된 효과만 자체 이벤트로 작성한다.
- passive: 소지/착용 틱, 오라, 암묵 효과, 각성, 소켓과 무작위 룬은 기본 상속0. 보조손이나 인벤토리에 넣어 얻는 숨은 보너스도0.
- active: 원본 우클릭과 SS 전용 주손/보조손 활성 입력은 새 아이템에서 실행0. 기존 mythictrpg 우클릭 1개만 서버 승인한다.
- channel: 원본 누르고 유지하기, 해제 폭발, 반복 비용/회복은 상속0. 새 채널 기술이 필요하면 별도 콘텐츠의 시작·유지·종료·비용을 정의한다.
- 공격속도/피해: SS 기본 소재 속성과 신규 속성을 덧셈하지 않는다. 기존 총공격력·총공격속도를 실물에 한 번만 부여한다. 공속 버프가 우클릭 쿨까지 줄이지 않는다.
- 회복/흡혈/마나: SS 자동 회복은 상속0. 기존 가호·장신구·음식의 회복은 출처별로 유지한다.
- 쿨 초기화/각성 전환/교체 보너스: 상속0. 새 실물·새 형태·재접속으로 기존 쿨이 새로 생기지 않는다.

이는 검증할 허용목록 정책이지 '모든 능력 끄기' 설정이 있다는 주장이 아니다. 클래스 상속, 전역 이벤트, 아이템 태그, 소켓/재련 조합, 특수 입력별로 각각 차단을 입증해야 한다. 표시 툴팁만 숨기는 것은 차단이 아니다. [SS 개발문서의 상속 예시](https://github.com/Sweenus/SimplySwords/blob/Architectury-1.21/developer-docs/unique-weapon-walkthrough.md)

## 5. 입력과 행동 잠금

서버에서 현재 권리·생존·기절·지역·진행 중 행동을 확인한다. 같은 tick에 평타/우클릭/J가 도착하면 서버 승인 순서 첫 유효 행동만 실행한다. 선행 행동이 승인됐으면 후행 입력은 무소모 거절하며 늦게 자동 발사하지 않는다. 반복 입력은 새 승인 없이 추가 피해를 만들지 않는다.

BC 평타의 시작/타격/종료를 행동 잠금에 연결하되 별도 평타 시계를 만들지 않는다. 우클릭/KJ 기술 동안에는 BC 공격 시작을 금지하고, BC 평타 회수 중에는 새 기술을 금지한다. 이미 시작된 평타를 우클릭으로 무료 취소해 패링하는 것은 허용하지 않는다. 새 평타의 콤보 배율·타점·회수는 선택한 BC 프로필을 따른다. 기존 기술의 잠금은 그대로다. BC의 일반 feint는 피해 전 취소만 가능하고 피해를 준 뒤에는 이미 시작한 회수·공격 재사용 가능시각을 교체로 앞당기지 않는다. 이 잠금은 BC 생명주기에 연결하며 별도16tick 평타 시계를 강제로 겹치지 않는다.

상자·문·NPC를 직접 지정한 상호작용 및 Shift+우클릭이 기술보다 우선이다. 스킬 없는 무기는 이 입력에서 기술을 만들지 않는다. 보조손 사용과 주손 기술을 동시에 소비하지 않는다. K 목록에서 선택한 독립 기술을 J로 사용하는 기존 방식, 특수 NPC 지원의 별도 구분을 유지한다.

### 양손과 쌍수의 명시적 전환

양손으로 매핑한 새 무기는 주손에 든 동안 보조손 무기 공격·방패·활성기·음식 사용을 차단한다. 보조손 아이템을 삭제하거나 소유권을 없애지는 않는다. 블록/NPC 직접 상호작용은 유지한다. 이는 H01의 종전 '기존 보조손' 설명과 다른 이번 전환의 명시적 변경이다. H01은 양손 자세를 채택하되 여전히 무스킬이다. 장신구 자유2칸은 손 슬롯과 무관하다.

한손 무기의 쌍수는 BC가 교대와 판정을 맡는다. 단, 신규 mythictrpg 무기의 1차 적용은 문서에 쌍수 허용이 명시된 조합만 허용하고 나머지는 주손 단독 공격으로 제한한다. 양손 무기를 보조손에 넣는 우회는0. 원래 개별 수치가 없는 쌍수 공속 보너스는 새로 무료 채택하지 않으며 초기 허용 조합의 보너스는0으로 설계한다. 목표 BC에서 이를 실현하는 설정/접점을 검증하지 못하면 쌍수 조합만 비활성화한다. 기존 다른 아이템의 서버 정책을 몰래 바꾸지 않는다. 단순 좌우 교대 연출 때문에 E/W/K 평가를 두 배로 계산하지 않는다.

## 6. 피해 사건과 중복 방지

평타는 NORMAL_MELEE, 우클릭은 WEAPON_SKILL, K/J는 LEARNED_SKILL, NPC지원은 NPC_SUPPORT, 기믹 조작은 NON_DAMAGE_INTERACTION으로 분리한다. 이는 기획 분류명이며 실제 엔진 API라고 주장하지 않는다.

각 사건은 실제 시전자 UUID, 소유자/귀속 UUID, 콘텐츠 ID, 실제 공격 손, 행동 ID, 시전/스윙 순번, 대상 전투 ID, 피해 경로를 기록한다. 소환자와 실제 공격 NPC를 구분하되 원문이 정한 귀속만 적용한다. 모든 플레이어·모든 스킬을 같은 공격자 한 명으로 합산하지 않는다.

한 평타의 같은 보스 본체/다부위는 1대상이다. 승인된 대상별 피해 전달은 1회이며 같은 패킷 재전송은0회다. 실제로 여러 번 때리도록 정의된 기술의 서로 다른 펄스까지 하나로 지워서는 안 된다. 연계의 매듭은 무기 기술의 전체 cast당 최초 유효 체력 피해에서1회, 평타·패링 자체·일반 습득·특수지원에는 발동0. 재정비는 원문상 적격 공격시전 종료 시 유효 적중0일 때만1회다.

장신구 고정 공격 보정은 기존 적격 피해사건 단위 규칙을 유지한다. 모든 효과를 '한 스윙1회'로 묶어 고정 보정의 기존 다중표적 규칙까지 바꾸지 않는다. 반대로 SS on-hit가 대상 수만큼 무료 복제되지도 않는다. 추가 피해가 새 on-hit를 재귀 호출하지 않게 원사건과 효과 출처를 연결한다. 치명·힘·인챈트는 BC 평타의 승인된 정상 공격 경로에 한 번만 적용하고 별도 물리/마법 스킬에 자동 복사하지 않는다. H01의 구 주타/보조타 구분은 아래 보존 대안에서만 유지한다.

## 7. 마나·쿨·취소 정산

기본 최대 마나는200, 실제 장착2칸의 증가분을 합산한다. 살아서 접속 중 현재 최대치의 초당1%를 회복한다. 상한 증가로 현재 마나를 채우지 않으며 감소 시 상한으로 자른다. SS 자원 회복·흡혈과 합쳐 새 회복률을 만들지 않는다.

승인 전 실패는 마나/쿨/사용기록 변경0. 승인 시 고유 행동 영수증과 마나 차감·쿨 시작·장신구 스냅샷을 한 논리 거래로 확정한다. 메모리 차감과 DB 기록을 따로 쓰고 원자적이라고 부르지 않는다. 확정 여부가 불분명하면 영수증 대조 후 재개하고, 같은 요청을 새 시전으로 재실행하지 않는다.

승인 후 헛침·벽·면역·기절·사망·로그아웃·해당 무기 교체는 원래 비용과 쿨을 유지한다. 재정비가 명시적으로 허용된 공격만 종료 시 지불량×스냅샷 환급률(합산최대100%)을 한 번 돌려준다. 쿨 환급0, 현재 최대마나 초과분 소실. H03 방어·H01 평타·기믹 접촉에 환급0. 순수 방어 성공을 공격 적중으로 세지 않는다.

일반 스킬 쿨은 플레이어 UUID+같은 스킬 ID로 저장하고, 장신구는 원문의 획득권리별 쿨을 유지한다. 원본/합일 고유물은 원문의 worldUUID+physicalUUID+mode 규약이 별도로 우선한다. 서버 가동 tick 기반 일반쿨과 현실시간 기반 장신구/특수 제한을 섞지 않는다. 서버 종료 동안 일반쿨을 소급 감소하지 않으며 재접속·부활·교체·재지급으로 초기화0. 사망/차원이동/교체 시 잔여 투사체 처리도 각 원문의 구분을 유지한다.

## 8. 획득 우회 차단과 이관

신규 무기는 기존 개인 퀘스트·제작 서비스·합일 원장에서만 지급한다. 일반 제작대·대장장이 조합·SS 전리품·pity 보상·상자 주입·몹 장비 드롭·보석 재련으로 같은 권리를 만들지 않는다. SS 원본 아이템의 자연 획득 경로는 본 서버의 이야기 성장 범위에서는 비활성화하는 운영안을 채택한다. 설정으로 가능한 항목만 설정을 쓰고, 나머지는 서버 레시피/전리품/보상 접점에서 차단한다. JEI 등의 표시 숨김만으로 완료하지 않는다.

SS 원본의 존재와 mythictrpg 권리는 별개다. 원본을 가져와 이름·모델·태그만 바꿔도 사용권을 인정하지 않는다. 관리용으로 소환한 SS 원본도 캠페인 보상·기믹키·평가 장비로 승인0이며, 원본의 전투효과가 새 성장체계를 우회하지 않도록 운영 플레이에서 사용을 차단한다. 이전 정상 획득품이 발견되면 자동 파괴하지 않고 격리·원장 확인 후 별도 처리한다.

이관은 구 실물/claim 확인→같은 권리 잠금→새 실물 교체→영수증 대조→구 실물 무효화의 복구 가능한 절차다. 수령자·내구 잔량·인챈트 허용 범위·쿨·분실정책·정비상태를 보존한다. 이관이 신규 최초획득·무료 수리·새 퀘스트 완료가 되어서는 안 된다. H01 무료 재발급을 신설하지 않는다. 합일검은 세계1개, 원본6개 소모와 단일검1개 생성의 기존 거래를 보존하며 SS 재련을 합일 공정으로 대체하지 않는다.

## 11. 적용 순서와 완료 기준

1. 배포물/의존 버전·리소스 존재·API 접점을 고정한다. 기존 원장/수치 대조표를 만든다.
2. 효과 없는 신규 아이템 하나로 등록ID·실물·claim 보존과 SS 효과0을 확인한다.
3. BC 단일 평타와 기존 실행기 제거를 확인한다. H01을 가장 먼저 시험해 새3연격·타점·형상·다중표적·내구를 검증하고 전환 전 성능과 비교한다.
4. 입력잠금·마나 확정·쿨 보존을 연결하고 H03과 아테나 응수의 차이를 확인한다.
5. 보상 우회·양손/쌍수·장신구/가호·다부위·보스 억제를 확인한다.
6. 공방/협곡 2인과5인, 본편 합일/분산 경로를 회귀 시험한다. HP·쿨·획득권을 자동 재조정하지 않는다.
7. 스킬연출 공통기준의 준비→이동/발사→명중→소멸과 5인 관측을 인수한다. BC 평타 궤적과 자체 기술 메시의 이중 소리/잔상/판정이 없어야 한다.
8. 정확히 통과한 무기만 단계 활성화한다. 실패 무기는 보상 권리를 보존한 채 해당 신규 실행 경로를 잠그고, 옛 판정과 새 판정을 동시에 켜지 않는다.

최종 산출은 기획 계약·무기별 매핑·변경 대조·시험 성적서가 서로 연결돼야 한다. 현재 시험 성적은 모두 미실행이다. 공식 문서는 기능 방향의 근거이고, 성공적으로 실행됐다는 증거는 아니다.

## 12. 전환 추가검수: 속성과 피해의 단일 적용

이 전환의 A0는 정상 플레이어 기본 공격기여+현재 실제 공격손 무기의 기여만 합친 무버프 총공격이다. 힘/약화 등 상태 modifier, 인챈트, 장신구 고정보정, 레이드0.04항, BC combo/dual/sweep 임시배율, 치명·충전·대상방어를 제외한다. H01 정상조건 A0=9. 이 정의는 기존 CP공식의 A를 소급 재작성하지 않는 신규 실행 입력 정의다.

목표 총공격9를 SS/바닐라 생성자 damage 인자9로 그대로 넣지 않는다. 해당 배포 API가 기본1+재질M+인자C를 만드는 경로라면 C=8-M이고 최종 무버프 속성9로 인수한다. 자체 modifier 경로면 플레이어기본1+무기8 한 번만 부여한다. 두 경로 동시 적용0. 속도1.25도 기본4인 additive 경로에서 modifier -2.75이며, 배포 실제 기본/operation이 다르면 결과1.25를 검증한다. 숫자는 조건부 역산이지 검증된 생성자 호출 코드가 아니다.

바닐라 Strength/가호가 이미 공격속성에 +3L을 반영하면 통합부는 +3L을 다시 더하지 않는다. 가호가 같은 효과를 주는 여러 출처의 상한/선택은 기존 규칙을 유지한다. 값 자체가 아니라 modifier 식별자·operation·출처와 실제 포함 여부를 기록한다.

처리 순서는 다음 신규 전환계약으로 명시한다. 이는 배포 후킹 구현 완료 주장이 아니다.

1. 권리·실제손·행동·대상보호 승인 후 A0와 출처별 속성·인챈트·장신구 스냅샷 확보. CP 점수식은 실행하지 않는다.
2. 기본+무기 및 적격 상태 modifier를 엔진 속성에 정확히1회 반영. 프로젝트 고정추가피해는 이 속성에 중복 등록하지 않는다.
3. BC가 해당 단계의 combo 및 허용된 dual/sweep 보정을 자기 경로에서1회 반영한다. 개발소스는 temp_attack ADD_MULTIPLIED_BASE를 사용한다. 통합부가 BC 처리후 피해에 combo를 다시 곱하거나 SS의 피해수치를 더하지 않는다.
4. BC가 호출한 정상 공격 경로에서 충전·치명·적격 인챈트를1회 처리한다. 정확1.21.1 배포 경로의 내부 순서는 소스/단계로그로 확인한다. 날카로움 포함 명목값7.5를 속성7.5로 넣고 날카로움II를 다시 실행하지 않는다.
5. 정상 공격의 방어 전 결과에 프로젝트 추가보정만 합친다. 적격 레이드 직접근접의 추가량은0.04×A0×L, 적격 장신구는 원문 피해사건별 고정량F. 이 두 항은 BC 콤보/치명/인챈트로 재증폭하지 않는 신규 전환안이다. 대상별 적격 여부와 실제 추가량을 기록하고 하나의 피해사건으로 합친다.
6. 합친 원시피해를 기존 damage type의 방어·강인함·저항·보호·무적/보스억제 경로에 정확히1회 전달한다. 실제 대상별 순서를 후킹 완료로 주장하지 않으며 접점/태그 검증 실패시 해당 경로를 잠근다. 갑옷 후 체력에서 보정량을 직접 빼거나 별도 추가공격 호출0.
7. 최종 유효피해·출처·이벤트ID 확정 후 기존 가호/장신구 적중 규칙과 내구를 정산한다. 같은 요청·본체중복·추가효과 재귀0; 의도된 여러 펄스는 별도 유지.

실측 공격속성/방어전 피해에 힘·날카로움·F·레이드항·combo가 이미 포함됐으면 그 항은 재가산0. 어느 단계인지 모르는 최종 float에서 임의로 빼고 다시 더하지 않는다. 소유한 출처 modifier를 이관·제거하고 단일 경로로 정규화한 뒤 결과를 확인한다. 타모드 출처를 안전하게 분리할 수 없으면 해당 조합을 활성화하지 않는다.

A0+3L+0.04A0L은 combo=1·완충·비치명·무인챈트·F=0·무방어·적격레이드라는 제한된 비교식이다. CP식이나 BC 결과를 이 식에 재입력하지 않는다. H01 A0=9/L=1이면 일반직접근접12, 적격레이드12.36인 조건부 단일적용 검산이다. BC 단계0.8/0.8/1.4에는 이 값을 다시 곱하지 말고 정상공격 단계로그+독립 레이드0.36 합성으로 검증한다.

위 근접전환식은 투사체/마법/독립 무기기술/NPC지원에 자동 적용0. 아테나 응수6·합일검24·H03피해0을 무기공격력/힘/콤보로 재증폭0. 장신구는 개별 원문 적격 피해사건 규칙만 적용한다.

### 원문 무적과 BC 빠른공격

BC 개발 ServerNetwork는 allow_fast_attacks일 때 대상 timeUntilRegen을0으로 만든다. 기존 전투계약의 피격무적/두보스10tick억제/페이즈무적은 자동 보장되지 않는다. 초기 캠페인에서는 기존무적을 지우는 설정을 허용하지 않는 운영 기준으로 시작하며 정확배포 설정 적용/성능변화와 독립 보스억제 접점을 확인한다. BC가 원래 리셋하는 것을 전부 끄는 설정이 검증되지 않으면 해당 실행경로를 잠근다. 기존 보스10tick를 다른 모든대상에 강제0.

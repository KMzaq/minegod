# 사건별 지식 전달과 공용 사실의 끝단 연결

## 적용 상태
이 묶음은 실제 전달파일과 인물·장면·수신 조건의 읽기 경로를 잇는 지식 연결 기획이다. 정적 저술 검수를 마쳤으며 기존 지식의 뜻이나 공개 권한을 바꾸는 실행 스키마가 아니다. 정확한 연결 범위는 01의 `범위`를 따른다. 게임·API·LLM 실행은 하지 않았다.

## 현재 갱신 범위
105패킷/772명의 실제 검수통합 상세와 현재242명의 활성화를 연결했다. 기존48명163동등 연결과 추가194명은 별도 집계한다. A1은105명 source_refs687출현/684고유쌍·개별일정105개, B1은56명827참조, BOOTSTRAP은33명148기존전달참조+165원문보존필드다. A1 원문발췌522필드도 실제 원본값과 비교했다. provenance677은 전체 source_refs 수가 아니다.

105패킷·772명·242현행활성화의 연결 기획과 정적 검수를 마쳤다. 이는 모드 설치·엔진 지원·실제 플레이 검증을 뜻하지 않는다. 새194명의 definition이 존재한다는 사실을 실제 등장·NPC 자동 앎으로 바꾸지 않는다.

## 읽기 순서
1. 01에서 같은 record_key의 기본지식과 네 범주 현행 저술을 찾는다. 여러 인물을 담은 공유 JSON은 지정된 인물포인터만 읽는다. 다른 인물의 사적 사건을 혼합하지 않는다.
2. 01의 기본앎필드는 초기 자기 과거·관계·취향·의심·미지와 조건부 사건을 분리한다. 빈 loreKnowledge 때문에 허용된 자기 과거 기억을 삭제하지 않는다. 현행조건부지식필드는 실제 상세 원고의 근거·청중·공개·수신 규칙을 연결하지만 그 존재만으로 실제 사건이 발생한 것이 아니다.
3. 02에서 공용73장면의 선행, 실제결과, 전달끝점, 실제 청중을 결정하는 원문, 중단 후 재개를 함께 읽는다. 등장·언급된 인물은 자동 청중이 아니다. 후발자는 현재 공용상태와 허용된 출처를 실제 읽은 범위만 안다.
4. 03은 실제 원본과 전달파일의 보존값이 같은 위치만 연결한다. 역사 자료의 앎과 공개 제한은 최신 채택의 범위 안에서 읽으며 역사 제안으로 현재 해금·권리·접촉을 되돌리지 않는다. 기존48명 현행활성화의 163전달포인터와 추가3개 근거연결표도 원래 동등성 맵을 통해 확인한다. 동등성 맵을 원본 자체로 내세우지 않는다.
5. 04는 이전에 검수된 447사건 참조를 그대로 유지하는 읽기표다. 01의 더 넓은 현행 필드 수와 447의 사건 참조 수는 서로 다른 단위이며 합쳐서 새 지식 수로 세지 않는다.
6. 05는 보존된 원문 내부 source_pointer를 현행 지식 루트로 오해하지 않도록 하는 별도 해석후보다. 기존 보존 문서를 수정하거나 원문 전체를 NPC 프롬프트에 넣지 않는다.
7. 06은 개인 수신·정정·재개 계약과 회귀 인수 사례다. 07은 공용73장면 원문절의 정확 위치와 복수 층 분류를 제공한다. 자동 분류는 검토 도움이지 실제 발생·허가·의미 검수의 증거가 아니다.

8. 08은 기존 원문색인1490과 이전 검수 확장60의 원본-전달값 동등성을 다시 확인한다. 기존 색인은 변경하지 않고 별도 검산표로 유지한다.

9. 09는 실제 통합된 시각 판정9파일과 색인, 원문191포인터를 연결한다. 경고·잔상·관전 표시는 서사 진실·사적 청중·개인 수신·참여 권리를 만들지 않는다.

## 우선순위와 권한
현재 명부의 정체·존재·접촉/표현과 현행 활성화 계약을 먼저 적용한다. 해당 인물의 검수된 현행 상세에서 명시적으로 채택한 범위만 과거 제안보다 우선한다. 새 수신에는 실제 관측 또는 허락된 전언 수신의 증거가 필요하다. 화자의 자기 앎, 내용과 존재의 공개 허가, 현재 실제 청중 전원의 개별 자격을 따로 검사한다.

저자 진실, 원문 과거, 미래 조건부 결과, 실제 세계상태, 개인 실제 앎은 같은 변수가 아니다. 정체를 입증한 자료가 생겨도 모든 NPC에게 지식이 생기지 않는다. 누군가의 이야기 전달은 그 전달을 받았다는 사실이지 원사건을 직접 목격했다는 증거가 아니다. 공개 기술자료를 읽는 것은 남의 사적인 고백을 들은 것이 아니다.

이 연결표는 새 MAIN·NPC·보상권·관계·사과·회신·동의를 만들지 않는다. 이미 받은 개인 기억은 후발자 합류나 정책 변경으로 삭제하지 않으며, 받지 않은 사람에게 소급 복제하지도 않는다. 거절·반박·침묵은 정상 선택이고 미수신·불통과 같지 않다.

## 중요 연속성
- C05에서는 첫 용 사망과 알 보관을 확인한다. 종말핵이라는 저자용 정체는 후속 근거를 받기 전 개인의 확정 앎이 아니다.
- C18은 기록의 연속성과 실제 보관 원본의 비활성 관측을 통해 검증한다. 공개 기술 발췌와 사적 정체 고백은 다른 전달 경로다. 실제 미열람자에게 자동 지식이 생기지 않는다.
- C12/C13/C20은 옛 저주의 종료와 전후 결속을 구분한다. 용사의 죽음을 반복 대속법·환생·새 희생자의 해법으로 바꾸지 않는다.
- C20은 독립 검증과 외부 접근 자료의 완료다. 여신의 실제 수락, 사과, 용서, 사적 회상의 공개는 별개다. 답을 못 받았어도 기술 검증은 가능하고 답변을 발명하지 않는다.
- 조기 고백의 실제 청중은 기억을 유지한다. 직접 들은 사람, 전언만 받은 사람, 공개기록만 읽은 사람에게 같은 과거를 배정하지 않는다.

## 미완 표기의 판독
현재 상세에서 실제로 미결인 정사·본체 접촉 문제는 해당 제한을 그대로 유지한다. 원문 과거의 ‘미정’, 서버 ID 등록, 실제 배치·좌표, 게임 시험·수신 어댑터의 미완은 서로 다른 종류다. 현재 채택된 저술을 과거 미정 때문에 무효화하지 않으며, 반대로 구현 미완을 실행 성공으로 바꾸지도 않는다. 새 정사 질문을 만들지 않는다.

## 재개와 마감
같은 사건의 실제 완료·열람·전달·부분 수신을 보존하고 아직 안 된 유효 단계만 재개한다. 불명 수신은 원장을 조회하고 현재 접촉·청중·정책을 다시 확인한다. 정정은 원주장 수신 사실과 정정 근거를 함께 보존하며 정정을 실제 받은 개인만 갱신한다.

모든105패킷과242활성화의 최신 색인·SHA·동일 인물 선택·포인터·원본값 동등성을 정적 검수했다. 연결된 원문이나 현재 계약을 변경할 때는 영향받는 참조와 수신 경계를 다시 대조한다. 이 연결표는 원문이나 현재 계약의 실행값을 대신하지 않는다.

A1 추가5명은026/027의 전용 common_contract/access 일정·확률을 유지한다. 전역 general_encounter로 덮어쓰지 않으며 원문 조건부/선택 분기를 일괄 AND로 바꾸지 않는다.

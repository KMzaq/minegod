# 지식 공급·공개·수신의 단일 실행 계약

## 적용 상태
CAMPAIGN-08의 구현 기획이며 실행 스키마·서버 적용본이 아니다. 772개 관리키와 이미 검수된 인물별 지식 원고를 유지한다. 105패킷의 전체 완결 선언이 아니라 현재 작성·통합된 원고의 연결 후보와 공통 처리 계약이다. 기존 지식의 원문·원문 배정 앎·개인 관계·보상 권리를 새 공통 규칙으로 덮지 않는다. 실제 LLM/API/게임 시험은 0회다.

판정 순서는 현재 인물 정체·존재·접촉/표현 가능 → 근거 있는 앎 → 개별 공개 허가 → 현재 청중 → 실제 전달 → 개인 수신 기억이다. 성격·관계·말투는 이 경계를 통과한 내용의 표현을 바꾸며 사실·허락·보상을 만들지 않는다.

## 1. 서로 다른 여덟 층
1. 작가 진실: 설정·미래 결말·미채택 분기·설계 이유. 사실로 확정된 설정도 NPC가 자동으로 아는 것은 아니다. 전체 원고를 프롬프트에 넣지 않는다.
2. 초기 자기 앎: 인물별 self_knowledge_authoring과 원문 knowledge_route_index에 배정된 범위만 공급한다. 빈 loreKnowledge는 자기 앎 전체 삭제가 아니다. 조건부 비밀도 본인이 원래 아는 내용은 유지하되 발설 여부를 별도로 막는다.
3. 실제 사건: 권위 게임 결과가 확정한 행위·성공·실패·부분 수행과 원물 인수. 퀘스트 정의 존재나 생성된 대사만으로 occurred=true가 되지 않는다.
4. 조건부 공개: 이미 가진 앎을 언제 누구에게 어느 단계까지 말할 수 있는지. 신규 습득 조건과 다르다. 비밀 내용과 비밀의 존재 공개를 각각 판정한다.
5. 수신 청중: 실제 들을 사람/NPC의 식별자와 개별 자격. 방 이름·파티 이름·주 수락자만으로 대신하지 않는다.
6. 개인 기억: 해당 개체가 실제 관측하거나 받은 내용·출처·시점·범위. NPC와 플레이어를 각각 기록한다. 이야기 원문과 개인 이력은 별도다.
7. 정정: 기존 주장에 대한 새 근거·철회·새 수신. 이미 들은 사실을 조용히 삭제하거나 부재한 청중의 기억까지 일괄 갱신하지 않는다.
8. 추론: 실제 알게 된 전제에서 얻은 가설. 확신이 높거나 플레이어가 정답을 맞혔어도 숨겨진 작가 진실을 공개하거나 목격 이력을 만들지 않는다.

직접 관측 / 수신 전언 / 검증된 사실 / 추론 / 오해 / 비공개 / 미확인 / 미발생을 별도로 유지한다. 원문에서 오딘·엔릴·바루나의 배정 앎은 보존하되, 미작성 습득 경위를 특정 전달자·시점·과거 목격으로 채우지 않는다. 기록전용 네 인물은 현재 대화 화자로 생성하지 않고 새 수호자는 실제 탄생 전 기억·발화가 없다.

## 2. 지식 획득과 대사 생성의 분리
아래 항목은 기획 입력 이름이며 엔진에 그대로 추가할 JSON 필드가 아니다.

- 인물: record_key, 실제 actor/instance 식별, 현재 존재·접촉·표현 상태. 관리키, profile godId, Story Actor ID는 다른 식별자다.
- 근거: source_document와 JSON Pointer, 실제 event/attempt/occurrence, 확정 결과 버전, 관측자 또는 전달자·실제 수신자, 획득 시점.
- 정보: 원문에 명시된 fact 식별자(없으면 없음), 내용 버전, 사실/주장/추론 상태, 공개 가능한 최소 단위와 최대 단계.
- 대상: 주 응답 상대, 실제 청중 전원, 개별 공개 자격, 실제 방/중계/관전 범위, audience_revision.
- 전달: 발화 의도·생성안·전달 시도·수신 증거·부분 수신 범위·미전달 이유(알려진 범위만).
- 개인권리: MAIN 소유·수락·수행·보상 권리는 별도 권위 저장부에서 읽는다. 지식 획득으로 생성하지 않는다.

처리 순서:
1. 실제 게임 수행 결과를 권위 기록에 확정한다. 실패·중단·부분 인수도 그 범위만 남긴다.
2. 그 사건을 실제 관측한 개체 또는 허락된 보고를 실제 받은 개체를 판정한다. 좌표 근접만으로 관측을 인정하지 않는다. 각 장면의 시야·차폐·청취·보고 규칙을 적용하며 원문 없는 전역 반경은 만들지 않는다.
3. 수신 근거가 있는 개인 지식만 갱신한다. 전언은 전달자의 주장으로 남기고 직접 목격과 합치지 않는다. 이벤트 중복은 같은 근거로 재학습·관계 재가산하지 않는다.
4. 응답 필요 시 그 화자의 초기 앎+실제 개인 기억 중 공개 가능한 최소 내용만 선정한다. 관련 없는 사적 원문은 생성 입력에서 제외한다.
5. 현재 청중 전원에게 허용된 교집합만 발화 후보로 만든다. 제목·요약·호칭·거절 이유·미끼 질문에도 같은 검사를 한다.
6. 기존 관계/개별 성격에 맞춰 말투를 생성한다. 생성 작업은 읽기 전용이며 새 사건·수락·보상·관계값을 확정하지 않는다.
7. 발송 직전 존재·접촉·청중 버전·현재 허가·내용 버전을 재검사한다. 변경 시 미발송안을 폐기하거나 허용 부분만 재생성한다.
8. 실제 전달을 확인한 수신자에게 전달된 범위만 기록한다. 등록 정식 지식의 습득은 정식 canonical 내용·레벨·정책과 완전 수신 증거를 요구한다. 자유 의역을 들었다는 대화 기억과 정식 Knowledge grant를 구분한다.

검사값은 참/거짓/미확인이다. 미확인은 통과가 아니다. 미확인에 의존하는 내용만 보류하며 유효 접촉 아래 무관한 공개 잡담은 가능하다. 접촉 자체 미확인인 경우에는 잡담 fallback도 생성하지 않는다.

## 3. 1:1 · 1:2 · 2:2와 참가·이탈
표기는 플레이어 수:NPC 수다. 반대 구성인 플레이어2:NPC1도 동일하게 전원 자격을 검사한다.

- 1:1: 플레이어 A와 NPC X. X가 A를 상대로 가진 관계값과 실제 기억만 사용한다. 소유자 전용이라도 A가 해당 소유자인지 확인한다. A가 X에게 보낸 말의 실제 수신과 X의 답이 A에게 도착한 것은 별도 기록이다.
- 1:2: A, X, Y. X가 말할 내용은 A와 Y 양쪽에 공개 가능해야 한다. Y가 신·친구·동료라는 이유로 X의 기억이나 A의 비밀을 받지 않는다. Y가 직접 수신한 발언만 Y의 전언 기억이 된다. X의 발언에 Y가 동의했다고 대신 기록하지 않는다.
- 2:2: A, B, X, Y. 각 발화마다 화자·지명 상대·실제 청중을 새로 고른다. A와 X의 깊은 관계를 B와 X에게 복사하지 않는다. X의 사담은 A, B, Y 모두 자격이 있어야 전체 발화 가능하다. 일부만 적격이면 실제 분리된 전달 경로가 있을 때에만 개별 전달하고, 없으면 비밀 존재를 드러내지 않는 주제로 전환한다.
- 중간 참가: 새 청중 C가 들어오면 audience_revision을 올려 미발송안을 재검사한다. C에게 이전 발언·장면·권리·친분을 소급 지급하지 않는다. 요약 요청도 새 전달 사건이며 화자의 앎과 C의 공개 자격을 다시 검사한다.
- 이탈: 이후 전달에서 제외하되 이전에 실제 받은 기억은 유지한다. 단순 접속 종료가 게임 내 자발적 거절·배신·도망의 증거가 아니다. NPC가 실제 관측한 이탈 현상만 말할 수 있다.
- 동시 발언: 서버가 확인한 수신 순서와 응답 대상을 유지한다. 순서 미확인은 덮어쓰기 대신 관련 응답만 보류한다. 다른 NPC의 생성 중 답변을 완료 발언처럼 서로 입력하지 않는다.

## 4. 비공개방과 세계공유 사실
PRIVATE_ROOM은 공개방이 아니라는 공간 정책일 뿐 개인 UUID 자격이 아니다. 방 안의 플레이어와 NPC 전원을 검사한다. OWNER_ONLY도 실제 소유자의 식별과 개인 공개 권한을 대신하지 않는다. PUBLIC이라고 비밀이 공개 정보가 되지 않는다. 중계·관전·공용 일지가 있으면 실제 수신 범위를 포함하며 확인할 수 없으면 민감 내용 송신을 보류한다.

세계 해금은 한 명이 달성하면 공유되지만, 이후 조우 주체·접촉·관계·MAIN·보상·관측은 별개다. 길이 열렸다는 현재 세계 사실을 후발자가 직접 확인할 수는 있다. 그러나 누가 어떤 대가를 냈고 어떤 사적 약속을 했는지, 그 길을 함께 열었다는 기억은 자동 제공하지 않는다. 서버 Fact의 SERVER 범위는 전 NPC 전지성·전 플레이어 Knowledge grant가 아니다. 플레이어별 경험 때문에 세계 해금을 다시 요구하지도 않는다.

파티·친구·같은 전쟁 소속·같은 신화군은 자동 공유 자격이 아니다. TRIGGER_TEAM 또는 ALL_PLAYERS_CURRENT_AND_FUTURE 같은 넓은 엔진 선택자는 실제 원문이 그 대상을 허용하고 각 개인 획득 조건이 성립한 경우만 검토한다. 개인 비밀·MAIN·공적·권리를 이 선택자로 일괄 주입하지 않는다.

## 5. 수신 전 생성, 끊김, 재접속
생성됨 → 검증됨 → 송신 시도됨 → 실제 수신 확인됨을 별도 상태로 둔다. 생성 캐시가 있다는 이유로 NPC나 플레이어가 이미 들었다고 취급하지 않는다.

수신이 불확실한 경우 자동 완료·재지급하지 않고 동일 전달 기록을 조회한다. 실제 미전달이면 현재 접촉·현재 청중·현재 정책을 다시 검사한 뒤 허용 내용만 새 전달 시도로 보낸다. 같은 내용/대상/원사건의 재시도는 중복 기억·보상·관계 누적을 만들지 않는다. 일부 문장만 받았다면 그 부분의 대화 기억만 가능하고 정식 단계 전체 습득은 불가하다. 비밀을 포함한 메시지 중간에 청중이 바뀌면 나머지 송신을 중지하고 이미 받은 실제 범위만 보존한다.

재접속은 관계 리셋도 오프라인 중 대화 자동 습득도 아니다. 본체가 부재하거나 말할 의사가 사라졌다면 과거 생성안을 현재 직접 발화처럼 재생하지 않는다. 허용된 일지 전달은 일지에서 실제 열람한 기록이고 NPC의 대면 목격이 아니다. 미열람 알림·서버 큐 적재를 읽음으로 처리하지 않는다. “답을 못 받았다”와 “거절당했다”를 구분한다.

## 6. 정정·추론·비밀의 표현
정정은 원주장/원근거·정정 근거·버전·대상별 실제 전달 시점을 보존한다. 틀린 보고를 받았다는 기억 자체는 남는다. 정정 수신자만 새 상태를 알며 다른 청중은 아직 옛 주장을 믿을 수 있다. 전역 세계 사실 정정과 개인의 정정 수신도 별도다. 이미 퍼진 비밀은 정책 변경으로 과거 수신을 없었던 일로 만들지 않으며 이후 공개는 최신 허가로 검사한다.

추론은 전제와 불확실성을 함께 전달한다. 네르벨의 기척 소실 관측을 흡수 목격으로 바꾸지 않는다. 여우신의 리듬 대조는 발신자 생존 증명이 아니다. “말할 수 없는 비밀이 있다”라는 거절도 존재 공개 허가가 없으면 금지한다. 단순한 “지금은 다른 이야기를 하자”조차 비밀을 특정하는 맥락이면 침묵이나 공개 가능한 현재 주제로 전환한다.

## 7. 실제 확인된 엔진 연결과 추가 구현
로컬 제공본의 StoryDefinitions.java에서 SET_FACT / GRANT_KNOWLEDGE / EMIT_PRESENTATION 분리, GrantKnowledge의 holder·actorId·factId·level·disclosurePolicyId, FactKnowledgeLevel, FactDisclosureRequest, RoomAudiencePolicy, PresentationDefinition과 오프라인 정책 열거값을 확인했다. 이는 정의 구조 확인이지 전체 런타임 수신 검증 구현 확인이 아니다.

기존 정의를 활용할 수 있는 부분:
- Fact와 Knowledge grant를 별도 행동으로 배치하고 등록 Fact/Actor/Policy를 참조한다. level은 정의상 1–32 범위이며 원문 없는 새 단계는 발급하지 않는다.
- CRITICAL은 SCRIPTED_ONLY, FACT_BEARING에는 factRequests 필요, AI_FLAVOR에는 factRequests 금지, OBSERVABLE_CLUE와 JOURNAL_ONLY는 SCRIPTED_ONLY라는 정의 검사를 지킨다.
- DROP_FLAVOR / ON_NEXT_LOGIN / JOURNAL_IMMEDIATELY라는 정책 이름은 존재한다. 실제 열람·수신·재전송의 보장은 별도 검증 대상이다.
- BuiltinConditionTypes에서 all/any/not, god_affinity, item_ever_obtained, biome, time_range, y_range, god_unlocked, structure_evaluated, god_relation, has_non_raid_blessing 등을 확인했다. god_unlocked의 world 범위, god_relation의 world 범위는 개인 NPC 기억이나 청중 UUID 허가와 같지 않다. UNKNOWN을 NOT으로 통과시키지 않는다.

추가 구현·통합 검증이 필요한 부분:
- 개인별 획득 근거·발화 실제 수신·부분 수신·버전 있는 전달 원장과 중복 방지.
- 화자별 실제 앎 필터, 개인 UUID 청중 자격, 비밀 존재 노출 차단, 전달 직전 청중 변경 원자적 검증.
- 실제 관측/허락된 전언의 장면별 증거 연결, NPC별 기억 저장·정정·추론 출처 보존.
- 재접속·미전달·관전/중계 청중과 실제 일지 열람을 연결하는 어댑터.
- 기존 지식 항목/편집 포인터를 정식 등록 ID에 연결하는 검증. 미등록을 정상 성공으로 넘기지 않는 차단.

RoomAudiencePolicy.permits는 방 공개 여부·플레이어 수·God 집합과 allowedGodIds를 검사한다. 개별 플레이어 UUID의 사적 자격을 이 함수가 보장한다고 쓰지 않는다. 제공된 STORY_AI_PRESENTATION_GUIDE 본문은 로컬에서 찾지 못해 읽은 근거로 사용하지 않았다. 보충자료의 링크만으로 가이드 내용·런타임 보장을 추정하지 않는다. 폐기된 시험용 God ID CSV는 생산 바인딩 근거로 쓰지 않는다.

## 8. 연결 후보 사용과 마감 조건
02 기획 JSON은 위 정책의 구조형 읽기본이며 엔진에 직접 적재하지 않는다. 03 연결색인 후보는 원문 위치와 원문에 실제 기재된 식별자만 연결한다. 편집 참조는 문서명+JSON Pointer이며 게임 Fact ID가 아니다. story_fact.event 문자열에서 임의 ID를 만들지 않는다. fact_id가 기재되어 있어도 등록 증거가 없으면 원문 기획 식별자로만 남긴다.

772명의 인물별 지식 파일은 기존 색인으로 그대로 찾는다. 기존 인물별 완결기획 연결을 새 사건 목록으로 교체하지 않는다. 현재 패킷 상태·참조 수는 03 후보의 작성 스냅샷을 따른다. 새 통합본이 늘면 추가 문서와 달라진 포인터를 검수하고, 미작성 패킷의 지식 획득·청중·정정·개인권리 연결을 별도로 마친 뒤에만 전체 연결 완료를 판단한다. 현재 후보에 없다는 이유만으로 해당 인물의 초기 지식·접촉을 삭제하지 않는다.

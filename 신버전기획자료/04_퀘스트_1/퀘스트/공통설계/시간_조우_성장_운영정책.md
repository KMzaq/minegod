# 시간·조우·성장 운영정책

CAMPAIGN-06 · 기획 채택본 1.0. 실행 스키마나 실제 서버 적용 완료본이 아니다.
신규 퀘스트·MAIN·장비·가호·성장재화는 추가하지 않는다. 이미 확정된 개인팩의 수치와 전역기준은 그 원본을 참조하며, 여기서는 공통 빈칸만 정한다.

## 먼저 구분할 것

누군가 한 명이 실제 해금을 이루면 세계에 공통으로 풀린다. 그다음 현재 조우조건을 충족한 사람들 가운데 확률로 선정된 사람이 등장 주체가 된다. 해금 달성자와 조우 주체가 같을 필요는 없다. 등장 뒤 동행자의 일반 접촉은 가능하지만 개인 인정·관계·MAIN·보상·지식은 각각 자기 실제 이력으로만 생긴다.

기존 배치형 인물, 꿈, 기록, 봉인석 반응을 새로운 무작위 본체로 바꾸지 않는다. 완전 봉인·미탄생·사망 기록역 및 해당 인물의 현재 제한은 그대로다. 등장 전부터 이미 본체와 대화했어야 한다는 순환 조건도 만들지 않는다.

- 스핑크스: 이 문서의 sphinx_encounter가 미정이었던 조우 운영값을 소유한다. 094 개인원고는 이를 참조하고 질문목록·안내 서비스를 작성한다.

스핑크스 보존 근거는 「PROPOSED-EGYPTIAN-SPHINX 인물 연결 원문」의 approved_service_baseline, connection_service_target_policy, present_encounter, current_unlock_scope다. 이 원문은 정확 확률·재진입 간격을 확정하지 않았으며, 이 정책이 정한 초깃값과 094의 질문·안내 콘텐츠는 서로 다른 소유 범위다.

- 일반 조우: 이미 무작위 경로가 허용됐고 별도 확률·간격이 정해지지 않은 인물만 아래 공통 풀에 들어간다. 전용 경로와 중복 추첨하지 않는다.

## 일반 조우의 초기 운영

적격 온라인 후보가 있는 동안의 경로별 활동 300초마다 서버 전체에서 한 번 검사한다. 첫 유효 창도 한 번 검사한다. 성공 확률은 25%, 실제 출현한 같은 인물의 다음 신규 출현 쿨은 서버 가동 1,800초다. 재접속·경계 왕복·방문자 수가 추첨 횟수를 늘리지 않는다. 본체가 현장에서 활동 중이면 이미 있는 본체를 만나며 새로 뽑지 않는다.

순서는 적격성 검사 → 서버창 성공 여부 → 고유 인물별 가중 추첨 → 그 인물의 적격 플레이어 중 균등 1명이다. 같은 인물에 적격 친구가 여섯 명 있어도 인물의 가중치를 여섯 배로 늘리지 않는다. 동일한 조건의 후보에서만 아래 상대 비중이 작동한다.

등급 순서는 최하급, 하급, 중급, 상급, 최상급, 초월급이다.
- 첫 공용 용 승리 전: 8, 6, 4, 2, 1, 0.5.
- 첫 공용 용 승리 후부터 C21 공용 완료 전: 6, 5, 4, 3, 2, 1.
- C21 공용 완료 후: 4, 4, 4, 4, 3, 2.

고위 후보도 처음부터 양수다. C21은 빈도만 바꾸고 새로운 접근 잠금을 만들지 않는다. 새 천장·확정 만남 보장은 없으며 특수 조우를 못 만나도 공개 제작·탐험·공용 성장으로 본편 준비가 가능하다. 확률은 구현 후 체감 조정 대상이지만 현재 채택값을 미정으로 돌려놓지 않는다.

## 스핑크스의 사막 진입

모드까지 실제 설치된 모든 사막형 바이옴을 검토한 목록으로 판정한다. 첫 유효 진입은 한 방문으로 남긴다. 사막 안 청크 이동이나 붙어 있는 사막형 바이옴 간 이동은 새 방문이 아니다. 다음 방문에는 비사막에서 연속 60초 실제 접속 체류가 필요하며 로그아웃 시간은 이 체류를 대신하지 않는다.

미완 60초 구간은 개인 로그아웃·사망·사막 복귀로 끊기면 0부터 다시 센다. 이미 채운 재진입 자격은 다음 실제 사막 진입 한 번에 소비한다. 서버 전체 중단·일시중지는 시간 가산 없이 저장 구간을 보존하되 재개시 같은 체류 상태를 확인한다.

진입 요청은 현재 방문당 하나만 보관한다. 같은 tick 진입은 같은 묶음이고, 묶음은 선착순으로 처리한다. 한 묶음에 여러 적격자가 있으면 주체 한 명을 균등 선정한다. 서버 전체 추첨 확률은 10%, 성공·실패 뒤 서버 가동 300초간 다음 추첨을 하지 않는다. 쿨 중 들어온 방문은 현재 사막에 남아 있으면 대기한다. 쿨 종료 자체는 새 진입이 아니므로 이미 검사한 묶음을 다시 굴리지 않는다. 다른 사막에서 본체가 활동 중이면 새 출현은 보류한다.

질문은 개인팩의 실제 채택 목록에서 무작위 하나를 고정한다. 원문 샘플을 자동으로 최종 문제로 채택하지 않는다. 정답은 안내 자격이지 장비·가호·MAIN이 아니다. 실제 허용된 상대가 가까운 안전 지점에서 같은 본체로 만날 준비를 마친 뒤 안내하며, 그 뒤 다시 확률을 굴리지 않는다. 안내문을 받거나 좌표에 도착한 것만으로 완료하지 않고 실제 정상 대화 개시를 확인한다.

스핑크스 당첨 뒤 출현 전 주체가 이탈·사망·접근불가이면 당첨만 종료하고 같은 묶음의 소비와 이미 시작한 추첨쿨은 유지한다. 다른 사람에게 당첨을 넘기거나 다시 뽑지 않는다. 주체가 적격인 기술적 배치 실패만 같은 예약으로 재시도하며, 출현 여부가 불확실하면 본체 대조 전 재배치하지 않는다.

정답 뒤 적격 대상이 없거나 도착 전 상대가 이동·거절하면 안내는 미이행으로 남는다. 로그아웃해도 정답과 안내 약속은 보존하지만 본체를 무기한 점유하지 않는다. 다시 만날 때 위치·동의·접근을 확인한다. 대화를 실제 시작한 뒤 부탁을 거절당한 것은 정상적인 만남 결과다. 자체 퀘스트나 새로운 보충 과제는 없다.

## 디오니소스의 예외를 보존하는 방법

개인팩의 확률·검사 간격·활동시계·수급 가능한 포션 선택과 원수량을 그대로 참조한다. 옛 세계단계별 포션 제안표를 두 번째 기준으로 적용하지 않는다. 같은 실제 마을은 서버 전체에서 새 등장을 재사용하지 않고, 술 의뢰는 동시에 하나만 활성화한다. 마을의 별칭이나 분할·합병으로 사용 이력을 지우지 않는다. 이미 있는 본체와 일반 대화, 보상 이행, MAIN 재개는 새 등장이 아니다.

현실 48시간은 수락된 포션 접수에만 적용한다. 마감 직전 유효한 전체 접수는 보상 대화가 늦어도 성공이며 정확한 마감시각 접수는 만료다. 부분·오종·초과 물건과 소비되지 않은 반환품은 원소유 원장대로 보존한다. 성공권·장신구·MAIN에는 새 마감을 붙이지 않는다.

a는 실제 양방향 연결 전, b는 실제 실물 지급 전까지 개인팩이 허용한 재선택이 가능하다. 이는 일반 보상의 선택 고정과 다른 명시 예외다. b는 개인 신규 획득 한 번이고 분실 복구는 같은 영구 권리의 대표 실물만 복구한다. 복구로 두 칸 착용·두 번째 권리·MAIN·주시·가호를 얻지 않는다. b 실제 수령 → 별도 MAIN 제시 → 첫 유효 명시 수락 → 실제 완료 → 소유자 주시를 건너뛰지 않는다.

## 동시접속·재시작·실제 수신

- 권위 서버만 추첨. world+route+window/batch에 유일키, 후보 snapshot/weights/version과 생성한 uniform 난수들을 외부행동 전에 durable journal에 저장. 범위 [0,1), U<p 성공. 클라이언트 seed/재접속/새프로세스로 다시 굴리지 않음. 가중선택은 정렬된 canonical_actor의 누적구간, 주체는 정렬된 UUID 균등구간.
- canonical_actor 단위 공용 compare-and-set 예약. 일반조우/디오니소스 연락/스핑크스 방문/레이드 지원/개인 MAIN이 같은 본체 상태를 참조. 원격 통신은 허용 모드로만, 본체 복제가 아님. 진행 중 실제 행동은 새 예약으로 빼앗지 않음. 온라인 같은 우선순위는 요청 sequence→UUID. 새 전역 NPC 동시수 제한은 만들지 않음.
- 서버 시작시 새 추첨/지급 전에 미확정 journal과 실제 entity/인벤/receipt 대조. body 존재하면 같은 instance로 확정; 없음이 검증되면 같은 예약/결과의 배치만 재시도; 불확실하면 대기하고 재생성0. 만료 lock을 무조건 지워 본체복제0. 사용자 이탈은 미래 접견 hold만 해제, 성공권/정답/MAIN 보존.
- 완료, entitlement 생성, 선택, 예약재고, 실물 전달은 별도 단계. 외부 인벤과 DB가 한 트랜잭션이라고 가정0. 중복 event_uuid는 원 receipt 반환. 불명확 실물은 검색·원장대조 후 누락라인만 복구. 늦은 a 응답과 b 지급 경쟁은 같은 선택권 revision을 잠그고 실수신/실지급 한 결과만 commit.
- 대화 송신 성공만으로 실제 수신/안내완료 처리0. 온라인 정상 대화 개시와 수신 확인, 오프라인은 미수신. 청중은 그 시간 실제 들었거나 허용된 기록을 나중에 읽은 사람별. 음악 주변 청취는 MAIN/친분/권리수신 아님.

a 연결이나 b 지급을 시작하기 전에 같은 선택권을 이행중 상태로 잠근다. 실제 이행 여부가 불확실하면 대조가 끝날 때까지 다른 선택의 병렬 이행을 보류한다. 미이행이 확인되면 기존 재선택을 다시 허용하고, 실제 이행이 확인되면 그 한 결과만 확정한다. 취소된 옛 a 요청의 늦은 응답으로 새 양방향 연결을 열지 않는다.
- UTC 역행/큰 점프가 감지되면 신뢰시간과 저장마감을 대조할 때까지 신규 마감판정·지급만 보류. 마감 연장이나 개인 처벌을 자동 발명하지 않음. 재시작 뒤도 원래 accepted_at/deadline 유지.

## 구현 인수 장면

운영값을 나중에 조정해도 이미 시작한 공용쿨의 종료시점과 이미 저장한 추첨 결과는 바꾸지 않는다. 진행 중 활동창은 원래 길이를 유지한다. 새 확률·가중치는 다음 미실행 추첨부터, 새 간격은 다음 창부터, 새 쿨 길이는 새로 시작하는 쿨부터 적용한다. 개인팩의 전용 값은 해당 팩이 계속 소유한다.

1. 한 명이 해금하고 다른 적격 친구가 당첨된다. 비당첨 동행자는 일반 접촉하지만 MAIN·보상을 복제하지 않는다.
2. 한 tick 진입·재접속·중복 이벤트를 여러 번 보내도 같은 추첨 결과와 본체 하나만 남는다.
3. 추첨 저장 뒤 재시작하거나 본체 생성 뒤 응답이 유실되어도 새 난수·분신을 만들지 않는다.
4. 포션 마감 전 접수 기록을 먼저 복구한 뒤 만료를 판단한다. MAIN과 미수령권은 경과시간으로 잃지 않는다.
5. 스핑크스 미이행 안내로 돌아온 사람이 질문을 다시 풀지 않고, 같은 신의 현재 가능한 만남으로 이어진다.
6. a의 늦은 응답과 b 지급이 경쟁해도 한 성공권에서 한 결과만 실제 이행된다.
7. 세계 진행에 뒤늦게 합류한 사람은 공개 길과 상품을 이용하되 과거 참전과 최초보상은 받지 않는다. 공개기록을 읽기 전 사적 사실을 자동으로 알지 않는다.

확률·시간 경계의 정적 계산은 별도로 검산했다. 실제 서버, API, 클라이언트, 멀티플레이, 음원, 실물 지급 시험은 수행하지 않았다. 사막형 registry·실제 마을·안전경로와 원장 연결은 구현 인수사항이다. 스핑크스 최종 질문과 대상별 안내 내용은 해당 개인팩의 별도 범위다.

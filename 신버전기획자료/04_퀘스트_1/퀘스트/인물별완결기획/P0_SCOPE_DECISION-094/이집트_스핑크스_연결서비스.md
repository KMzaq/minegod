# 이집트 스핑크스: 맞혔다고 없는 길이 생기지는 않는다

관리키 PROPOSED-EGYPTIAN-SPHINX · 기존 SERVICE-SPHINX 완결 저술 · 중급

기획 채택본이며 실행 JSON이나 게임 테스트 결과가 아니다. 서비스 1건을 완결한다. 신규 퀘스트·MAIN·가호·장비·스킬·주시·추가 보상은 없다. 테베 스핑크스와 별개다.

## 1. 플레이 흐름
사막의 같은 스핑크스와 인사한다. 문답을 원하면 준비한 목록의 한 문제를 무작위로 받는다. 힌트를 듣거나, 풀이 설명 없이 답만 제출하거나, 그냥 쉬어도 된다. 맞히면 원하는 상대를 말하고 지금 실제로 가능한 가까운 만남을 확인한다. 실제 같은 상대 앞에 도착해 정상 대화를 시작해야 안내가 끝난다.

“맞았어. 어떻게 풀었는지는 네가 들려주고 싶으면 듣겠어.”
“답을 맞힌 것은 그대로야. 하지만 지금 갈 수 있는 만남은 아직 확인하지 못했어.”

## 2. 보존 경계와 조우
기존 세계공통 해금/무해금 경로 유지. 개인 세계재해금 없음. 현재 적격 조우주체와 이후 일반접촉·개인정답을 분리.
스핑크스와 목표 모두 각 한 실제 본체. 사망·완전봉인·부재·현재 응답불가를 새 인격/원격대사로 우회하지 않음.
조우 확률·공용쿨·재진입 자격은 「퀘스트/공통설계/시간_조우_성장_운영정책.json」의 /sphinx_encounter, /atomic_contract, /clocks만 참조한다. 수치를 이곳에 중복하지 않는다. 이미 등장한 본체의 일반 대화에 재추첨을 요구하지 않는다.

## 3. 문답 운영: 이번에 채택한 작은 규칙
- scope: 아래 문항·정규화·안내 대상 범위·서비스 접촉회차·UI 수치는 이번 기획에서 새 채택. 사용자 직접 확정 또는 게임검증이라고 하지 않음.
- contact_distance_blocks: 6
- contact_visit_reset_distance_blocks: 12
- contact_visit: 실제 동일 본체 6블록 안에서 유효 접촉을 시작해 contact_visit_uuid를 발급. UI 닫기/로그아웃/사망/재시작은 새 회차 아님. 기존 회차 종료 뒤 생존 접속 상태에서 같은 본체로부터 12블록 밖으로 실제 이동했다가 다시 유효접촉하면 새 회차. 본체 위치 revision 변화만으로 재발급하지 않음. 최초 후발자도 자기 회차를 받음. 이는 문답 재시도 구분이며 일반대화/사막 조우쿨/재진입 자격을 대체하지 않음.
- attempts_per_contact_visit: 1
- active_pending_guidance_per_player: 1
- repeat: 오답/포기 뒤 다음 실제 접촉회차에서 새 무작위 문항. 정답 미이행 중에는 새 안내용 문항 대신 미이행 재개; 비보상 잡담은 자유. 안내 이행 후 다음 실제 접촉회차에서 같은 서비스 재이용 가능. 누적 보상권/교환권 없음.
- cost: 0
- answer_time_limit: 없음
- guidance_expiry: 없음
- hint_count: 1
- hint_penalty: 없음. 제출 전에 힌트 1개를 반복 열람 가능.

### 선정과 판정
- bank_id: SPH-BANK-01
- bank_version: 1
- source: question_bank
- rule: 활성 검증 문항 24개의 ID를 정렬하고 권위 서버의 uniform U∈[0,1)로 floor(U*N) 선택. 모든 활성 문항 가중치 동일. 이미 본 문항도 포함, 보장/난이도 가중 없음.
- persist: world_uuid+player_uuid+contact_visit_uuid 유일키 아래 question_attempt_uuid, bank_version, question_id/version, 보기 순서, U, 생성 sequence를 출제 전에 저장. 재개·중복 요청은 같은 스냅샷 반환.
- versioning: 진행 중 문항은 원버전 유지. 단 문항 자체 오류가 확인되면 그 attempt를 비소비 취소하고 새 검증 문항 1회 교체하며 오답 벌/정답 취소 없음. 정상 버전 교체로 재추첨하지 않음.
- empty: 적재/검증 문항 0개면 새 출제 없음, 일반 대화와 기존 정답 안내는 유지. LLM 즉석문제는 비보상 잡담으로만 명시 가능.
- primary: 보기의 불변 option ID를 선택한 뒤 “이 답 제출”을 명시 확인. 클릭은 임시선택, 확정 전 변경 가능. 문제/보기/정답 매핑은 은닉 서버 자료.
- text: 자유문장도 받되 NFKC→casefold→모든 공백 제거→문장 끝 .?! 제거만 수행한다. accepted_text의 동일 정규화 값과 정확히 일치할 때 정답 후보. 문자열 포함검색·임베딩 유사도·LLM 추측으로 통과시키지 않음.
- unmapped: 목록에 없는 동의어·오타·설명문·둘 이상의 답·부정문은 미판정, 시도 소비 없음. “어느 보기를 뜻했는지 골라 줘”와 원보기 전부를 보여 주어 본인이 하나 선택. 정답 보기만 강조하지 않음. 의미 동등 답을 철자 벌로 탈락시키지 않는 비징벌 경로다.
- letters: 문항의 A/B/C 대상 이름과 UI 보기 A/B/C는 다를 수 있다. 텍스트 A는 accepted_text의 대상 A로만 해석; UI 선택은 option ID 이벤트로만 받는다. 일반 채팅의 A를 UI ID로 암묵 변환하지 않음.
- commit: 실제 응답자 UUID+활성 attempt+문항 완전 수신+현재 유효 스핑크스 접촉+명시제출 receipt를 원자 비교. 정답은 CORRECT와 동일 attempt의 미이행 안내 1개를 함께 저장. 중복 event UUID는 기존 결과.
- wrong: 명시제출한 비정답 보기만 WRONG. 짧은 이유를 허용청중에 전달하고 회차 종료. 재화·피해·적대·관계 벌 없음.
- agency: 풀이 설명은 선택. 말투·호감·선물·LLM 평가로 정오답을 번복하지 않음.
- authority: LLM은 제시·정리·농담만 담당. 문항 정답, 봉인 해제, 대상 허용, 수신완료, 대화시작을 생성할 권한 없음.

## 4. 상태와 중단·재개
- IDLE → QUESTION_ACTIVE: 유효 접촉과 명시 문답 참여. 증거: 저장된 추첨 + 실제 문항 전달 receipt.
- QUESTION_ACTIVE → QUESTION_ACTIVE: 힌트/미판정 입력/창 닫기. 증거: 같은 attempt 유지; 힌트 수신 별도.
- QUESTION_ACTIVE → WRONG_CLOSED: 명시 오답 제출. 증거: 정오답 고정표와 제출 receipt.
- QUESTION_ACTIVE → ABANDONED_CLOSED: 명시 포기. 증거: 본인 포기; 해설 원하면 청중 검사 후 전달.
- QUESTION_ACTIVE → QUESTION_PAUSED: 접촉 단절/죽음/로그아웃. 증거: 같은 질문 보존; 신규 발화/판정 없음.
- QUESTION_PAUSED → QUESTION_ACTIVE: 같은 본체와 유효접촉 회복. 증거: 같은 문항/보기 다시 전달; 재추첨 없음.
- QUESTION_ACTIVE → GUIDANCE_PENDING: 명시 정답 제출. 증거: 정답 원장과 유일 미이행 안내 원자 저장.
- GUIDANCE_PENDING → TARGET_CHECKING: 본인 대상 선택+현재 적격 확인. 증거: guidance UUID+target key+revision; 새 권리 아님.
- TARGET_CHECKING → ROUTE_READY: 대상 실제 위치/도착·의사·안전·공개범위 확인. 증거: 현장확인과 현재 접견응답, 같은 body instance, 경로 검사.
- TARGET_CHECKING → GUIDANCE_PENDING: 거절/불명/부재/봉인/경로불가. 증거: 정답 보존; 알려진 허용 사유만 설명.
- ROUTE_READY → GUIDED_NOT_MET: 현재 청중 검사 후 안내 실제 수신. 증거: 요청자 route revision 수신 receipt.
- ROUTE_READY 또는 GUIDED_NOT_MET → GUIDANCE_PENDING: 이동/거절/사망/봉인/로그아웃/경로변경. 증거: 만남 전이면 미이행 보존, 일정 hold만 해제.
- GUIDED_NOT_MET → FULFILLED: 요청자 현장 도착+같은 대상 정상대화 실제 개시. 증거: 대상/요청자/위치/발화모드/청중 revision과 양쪽 대화개시 receipt.
- FULFILLED → FULFILLED: 부탁 거절/재접속/중복 도착. 증거: 새 안내/MAIN/추가 보상 없음.

## 5. 실제 안내 대상과 경로
이번 버전에서 개별 검토해 채택한 안내 대상은 guidance_targets의 토트·헤르메스 두 관리키다. 원문이 이 둘만을 확정했다는 뜻은 아니며, 원문에는 완결된 대상 목록이 없고 서비스별 개별 허용 검토가 요구된다. 문답 참여 전에 이번 지원 대상과 현재 만남은 보장되지 않는다는 점을 알린다. 다른 이름을 희망으로 남길 수 있지만 그 기록 자체가 대상 승인이나 향후 확장 약속은 아니다. 이 버전은 두 대상의 안내를 완결하며 확대를 완료 조건이나 후속 필수 작업으로 남기지 않는다. 명부 전체 자동 허용·디오니소스 a 목록 복사는 금지한다. 기존 정답·미이행은 대상 목록 변경으로 삭제하지 않는다. 이미 별도 원문에서 확정된 유효한 안내 약속이 확인되면 이 두 이름 제한만으로 폐기하지 않고 그 승인 범위와 현재 조건을 적용한다.

### 현재 검사와 안내 이행
- eligible_all: 이번 버전 채택 대상 관리키 또는 기존 별도 확정 안내 약속에 명시된 대상 관리키와 원 profile의 동일 배우. 희망 기록이나 명부 등재만으로는 허용되지 않음. / 대상의 현재 세계공통 해금 또는 기존 무해금 경로 / 현재 생존/탄생/봉인/현신이 일반 대면·발화를 허용 / 요청자의 명시된 개인접근 사건/현재 통행권을 충족; 세계해금을 다시 개인에게 요구하지 않음 / 동일 본체 실제 위치와 활동이 접견을 허용 / 본인 접견 의사와 요청자/동행 청중 범위의 유효 응답 / 현재 확인한 가까운 안전 탐험권 경로 / 스핑크스가 실제 수신/현장확인한 정보이며 해당 청중에게 공개 가능
- unknown: 어느 필수 항목이라도 UNKNOWN이면 보류. 내부 엔진은 이유코드로 막더라도 스핑크스에게 그 비밀의 내용·존재·봉인 층을 자동 주입하지 않음. “지금 가능한 만남을 확인하지 못했어”로 제한.
- close_site: 새 절대 거리 상한을 정하지 않는다. 원문대로 운영자가 실제 걸어 검증한 같은 근방 탐험권의 연결 경로로 정의한다. 출발 지점(안내 시 요청자 현재 위치), 도착 지점(대상 실제 접견 위치), 차원, 연속 경유 블록열/표지, 실제 도보 확인자·시점·경로 revision을 저장한다. 가까움 판정은 사전에 검증한 근방 구역 안의 경로 존재로 결정하고 LLM이 먼 성소를 임의로 가깝다고 판정하지 못한다.
- site_acceptance: 기존 통행 허용 지면, 플레이어와 현재 본체의 실제 충돌크기·머리공간, 끊어진 바닥·낙하·용암·익사·진행 중 전투 없음, 현재 요청자의 통행권과 이동수단으로 왕복 가능한지 현장 확인. 새 차원/포탈 생성·블록 파괴·타인 보호구역 침입으로 경로를 만들지 않음. 위험이 생기면 경로만 무효화, 정답은 유지.
- placement: 현재 2명은 이미 실제 자리에서 만나는 경로를 채택하므로 새 대상 스폰이나 이동 기능에 의존하지 않는다. 향후 동의한 이동 경로를 추가해도 같은 본체의 실제 도착 확인 전 ROUTE_READY 불가. 현재 기존 본체가 멀거나 아직 출현하지 않았으면 미이행이다.
- revalidate: 후보 열람→본인 선택→ROUTE_READY 전→안내 전달 직전→요청자 도착/대화 개시 직전마다 body instance/location revision, 접견 consent revision, seal/access revision, route revision, audience 전부 확인. 바뀌면 안내 무효화/미이행 복귀. 알려진 변화는 스핑크스에게 실제 전달된 뒤만 새 대사로 말함.
- no_reroll: 확정 안내 뒤 조우 운을 다시 굴리지 않는다. 만남 직전 조건 변화는 안전 보류이지 확률 실패가 아니다.
- reselection: 완료 전 대상 재선택/보류 가능. 현재 guidance UUID의 revision을 늘리고 옛 대상 예약만 해제. 옛 요청의 늦은 응답은 revision 불일치로 폐기하여 두 만남 의무 생성 금지. 실제 대화 개시 결과 불확실하면 receipt 대조 전 재선택 이행을 멈춘다.
- singleton_concurrency: 대상 본체는 공통정책 atomic_contract로 공유. 이미 진행 중인 행동을 빼앗지 않음. 같은 접견을 원하는 여러 정답자는 각자 대상 동의와 실제 대화 개시 증거가 있으면 한 자리에서 만날 수 있으나 안내 원장은 개인별. 동시 요청은 서버 sequence, 동률 UUID 순서. 사적 청중이 다르면 대화를 순서대로 나눈다.
- no_infinite_hold: 플레이어 로그아웃/사망/명시 보류 시 향후 현장 대기 예약 해제. 미이행은 영구 보존하지만 대상 활동·일반접촉을 잠그지 않음. 온라인 미응답도 NPC가 현재 활동을 계속할 필요가 생기면 예약을 거둘 수 있으며 시스템이 미이행으로 복귀시킴. 새 현실 마감 없음.
- completion: 요청자 본인이 실제 현장에 있고 동일 target body와 정상 대면 발화/수신이 개시된 증거가 있어야 FULFILLED. 시도 인사, 원격 답, 지도 열람, 친구만 도착, 모형, 중단된 대사 송신은 부족하다. 일반 인사 개시 뒤 부탁/비밀/MAIN 거절은 정상 완료이며 되돌리지 않음.
- loss_and_death: 요청자 사망은 일반 게임 사망 처리만; 정답/안내/질문 보존. 스핑크스 사망·완전봉인·부재면 현재 응답·출제·수신 없음, 보존원장만 남고 부활/대리 인격을 생성하지 않음. 대상 사망·봉인·거절이면 만남 전에는 미이행/재선택, 만남 후에는 과거 실제 만남 그대로.
- rewards: 추가 지급 0, 비용 0. 안내 원장 1건은 기존 정답 이행 상태이며 거래 가능한 권리 아이템 아님. 인벤 가득 참은 무관. 재전송/재시작/재도착은 같은 원장 결과 반환.
- recovery: 저장 성공 여부가 불명확하면 attempt/guidance/request/meeting event UUID와 실제 entity·수신 receipt를 대조한다. 같은 정답 성공을 재발급하지 않고 누락된 기록만 복구한다. 실제 만남 확인 전 완료 문구 없음. 스핑크스가 자리에 없으면 시스템 기록 상태만 표시하고 그의 말처럼 새 답을 만들지 않는다.

## 6. 질문뱅크 24문항
이 절의 정답은 제작용이다. 게임에서 문제와 함께 정답표를 노출하지 않는다. 각 문항은 문제 안의 가정이며 실제 상자·돌·사람·경로의 존재나 실물 지급을 만들지 않는다. 본편 스포일러는 전 문항 없음. 공개범위는 질문·보기 실제 청중, 힌트는 요청 시, 정답·해설은 제출 또는 해설을 원하는 포기 뒤다. 같은 활성 문항의 다른 응답자가 있으면 해답을 무단 공개하지 않는다.

### SPH-Q01. 표지 셋
A·B·C 중 보물 상자는 정확히 하나야. A의 글은 “보물은 B에 있다”, B의 글은 “보물은 B에 없다”, C의 글은 “보물은 A에 없다”야. 정확히 한 문장만 참이면 보물 상자는?
보기: A. A / B. B / C. C
정답: A (A)
허용 텍스트: A, a, A 상자, 에이
힌트: B가 보물인 경우 참인 문장이 몇 개인지 세어 봐.
해설: A일 때 거짓·참·거짓. B일 때 참·거짓·참, C일 때 거짓·참·참이므로 A만 하나가 참이다.
오답 예: B / C (각각 위 해설의 전제와 맞지 않음).

### SPH-Q02. 돌아온 표식
출발점을 0으로 적고 동쪽 한 칸을 +1로 적었어. 동쪽 7칸, 서쪽 4칸, 동쪽 2칸을 걸으면 마지막 표식은?
보기: A. +9 / B. -5 / C. +5
정답: C (+5)
허용 텍스트: +5, 5, 동쪽 5칸, 동쪽 다섯 칸, 다섯
힌트: 서쪽으로 간 만큼 빼면 돼.
해설: 7-4+2=5. 이동거리 13과 위치 5는 다르다.
오답 예: +9 / -5 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q03. 한 번의 교환
왼쪽부터 붉음·흰색·검정·파랑 네 천이 있어. 첫째와 넷째를 바꾼 뒤 둘째와 셋째를 바꾸면 왼쪽에서 둘째는?
보기: A. 파랑 / B. 검정 / C. 흰색
정답: B (검정)
허용 텍스트: 검정, 검은색, 검은 천, 검정 천
힌트: 두 교환이 건드리는 자리를 나누어 봐.
해설: 첫 교환 뒤 파랑·흰색·검정·붉음, 다음은 파랑·검정·흰색·붉음이다.
오답 예: 흰색 / 파랑 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q04. 엇갈린 순서
서로 다른 세 상자를 한 번씩 열었어. 나무는 돌보다 먼저, 모래는 나무보다 먼저 열었지. 둘째로 연 상자는?
보기: A. 나무 / B. 모래 / C. 돌
정답: A (나무)
허용 텍스트: 나무, 나무 상자, 목재 상자
힌트: 먼저와 나중을 한 줄로 놓아 봐.
해설: 모래→나무→돌이 유일하다.
오답 예: 모래 / 돌 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q05. 정확히 두 조건
네 문 A·B·C·D 중 열리는 문은 “둥근 표식이 있고 푸른 표식이 없는 문”뿐이야. A는 둥근·푸른, B는 둥근·붉은, C는 네모·붉은, D는 네모·푸른이야. 열리는 문은?
보기: A. A / B. C / C. B
정답: C (B)
허용 텍스트: B, b, B 문, 비
힌트: 둥글다는 조건만으로는 부족해.
해설: B만 둥글고 푸르지 않다. A는 푸르고 C는 둥글지 않다.
오답 예: A / C (각각 위 해설의 전제와 맞지 않음).

### SPH-Q06. 한 자리의 빈칸
네 칸 중 정확히 세 칸에 돌을 하나씩 놓고 한 칸은 비웠어. 첫째·셋째·넷째에 돌이 있다면 빈칸은?
보기: A. 첫째 / B. 둘째 / C. 셋째
정답: B (둘째)
허용 텍스트: 둘째, 2, 2번, 두 번째, 둘째 칸
힌트: 이미 차 있는 칸을 지워 봐.
해설: 네 칸 중 1·3·4가 차 있으므로 2만 남는다.
오답 예: 셋째 / 첫째 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q07. 서로 다른 무게
금속 조각 A는 B보다 무겁고 C보다 가벼워. 세 조각의 무게가 모두 다르면 가장 무거운 것은?
보기: A. C / B. A / C. B
정답: A (C)
허용 텍스트: C, c, C 조각, 씨
힌트: 두 비교를 같은 방향으로 써 봐.
해설: C>A>B다. 실제 게임 아이템 무게 규칙이 아닌 문제 속 전제다.
오답 예: A / B (각각 위 해설의 전제와 맞지 않음).

### SPH-Q08. 경로의 합
분기 없는 길의 구간은 입구→샘 4칸, 샘→돌문 6칸, 돌문→그늘 3칸이야. 입구에서 샘을 거쳐 그늘까지 가는 거리는?
보기: A. 10칸 / B. 9칸 / C. 13칸
정답: C (13칸)
허용 텍스트: 13칸, 13, 열세 칸, 십삼 칸
힌트: 중간 지점에 멈추지 않아.
해설: 4+6+3=13. 지름길은 주어지지 않았다.
오답 예: 10칸 / 9칸 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q09. 남겨 둔 몫
돌 14개 중 2개를 따로 두고 나머지를 세 바구니에 똑같이 나눴어. 각 바구니의 돌 수는?
보기: A. 12개 / B. 4개 / C. 6개
정답: B (4개)
허용 텍스트: 4개, 4, 네 개, 넷, 4개씩
힌트: 따로 둔 돌은 나누지 않아.
해설: (14-2)/3=4다.
오답 예: 6개 / 12개 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q10. 바로 다음 무늬
무늬가 해·달·별 순서를 끝없이 반복해. 첫 칸이 해라면 여덟째 칸은?
보기: A. 달 / B. 별 / C. 해
정답: A (달)
허용 텍스트: 달, 달 무늬, 달무늬
힌트: 세 칸씩 묶고 남는 칸을 봐.
해설: 7번째는 해, 8번째는 달이다.
오답 예: 별 / 해 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q11. 어제의 지도
두 지도 중 하나는 길이 무너지기 전, 하나는 무너진 뒤 직접 확인해 그렸어. 현재도 그 뒤로 변하지 않았다는 전제에서 무너진 길을 피할 지도는?
보기: A. 무너지기 전 지도 / B. 어느 지도든 같음 / C. 무너진 뒤 지도
정답: C (무너진 뒤 지도)
허용 텍스트: 무너진 뒤 지도, 뒤 지도, 나중 지도, 무너진 후 지도
힌트: 이 문제에서는 이후 변화가 없다고 정했어.
해설: 현재와 같은 상태를 직접 확인한 뒤 지도를 택한다. 실제 세계의 모든 최신 전언이 참이라는 뜻은 아니다.
오답 예: 무너지기 전 지도 / 어느 지도든 같음 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q12. 열쇠의 이름
문 A는 열쇠 다, 문 B는 열쇠 가, 문 C는 열쇠 나로만 열려. 가진 열쇠가 나 하나면 열리는 문은?
보기: A. B / B. C / C. A
정답: B (C)
허용 텍스트: C, c, C 문, 씨
힌트: 문 이름과 열쇠 이름을 섞지 마.
해설: 열쇠 나는 C에만 대응한다.
오답 예: A / B (각각 위 해설의 전제와 맞지 않음).

### SPH-Q13. 다른 문장
표지 A는 “세 돌이 모두 흰색”, B는 “흰 돌이 하나 이상 있다”라고 해. 흰 돌 두 개와 검은 돌 하나를 직접 봤다면 참인 표지는?
보기: A. B만 / B. A와 B 모두 / C. 둘 다 아님
정답: A (B만)
허용 텍스트: B만, B, b, 비만, B만 참
힌트: 모두와 하나 이상의 차이를 봐.
해설: 검은 돌 때문에 A는 거짓이고 흰 돌이 있으므로 B는 참이다.
오답 예: A와 B 모두 / 둘 다 아님 (각각 위 해설의 전제와 맞지 않음).

### SPH-Q14. 둘의 자리
세 자리의 왼쪽에는 민이 앉고, 준은 민보다 오른쪽이지만 솔보다 왼쪽에 앉아. 가운데 사람은?
보기: A. 민 / B. 솔 / C. 준
정답: C (준)

## 7. 사실과 실제 수신 지식

### SPH-FACT-QUESTION
- truth: 해당 버전 문항이 실제 제시됨
- learners: 문항을 실제 완전히 수신한 응답자·허용 청중만
- npc: 자신이 실제 준비/읽은 채택 문항만. 문서 채택 자체는 런타임 기억 주입 완료 아님.
- disclosure: 세계 비밀 없음. 같은 활성 문항의 정답 유출은 청중 동의 전 보류.

### SPH-FACT-CORRECT
- truth: 특정 UUID가 해당 attempt의 유효 정답 제출
- learners: 스핑크스가 실제 접촉에서 받은 응답, 본인에게 실제 전달된 결과. 다른 플레이어는 실제 목격/허용 전달만
- npc: 서버 전체 정답 원장을 전지적 기억으로 읽지 않음. 장애복구 원장은 실행상태와 구분.
- disclosure: 정답자 개인 기록. 친구의 도움은 도움 기록이지 정답 소유 복사 아님.

### SPH-FACT-LOCATION
- truth: 특정 revision의 대상 위치/접견 응답/경로를 현재 확인
- learners: 직접 확인자와 허용된 정보를 실제 수신한 스핑크스/요청자/동행
- npc: 출처 UUID 또는 대상 본인, 확인시점, 위치 revision, 전언/관측 구분. NPC가 듣지 못한 내부 봉인 결과는 비공개.
- disclosure: 승인된 위치·접견 범위만. 공개방은 실제 전송이 닿는 온라인 전원, 사적방은 현 청중 전원의 자격 재검사. 비공개 전송 미지원이면 보류.

### SPH-FACT-MET
- truth: 같은 대상과 요청자의 정상 대면 대화가 실제 시작됨
- learners: 요청자·대상과 실제 현장 관측자. 스핑크스는 현장에 없으면 이후 허용된 증빙 전달을 실제 받은 때만 안다.
- npc: 완료 원장 성립은 전체 NPC 지식 획득이 아님. 스핑크스 미수신이면 만남 완료를 회상하지 않음.
- disclosure: 사적 내용은 별도 공개 조건. 후발자는 허용 기록을 실제 읽거나 전언 수신 뒤 출처 있는 정보로만 획득.

- 문답 약 1~4분, 실제 근방 이동·인사 약 2~8분의 기획 추정. 조우 대기/대상 부재는 확정 시간 없음. 실제 도보 측정/플레이시험 결과 아님.
- 전투 성장의 필수 공급원이 아니라 퍼즐의 즐거움과 현재 열린 인물에게 갈 이유. 보상 경제 0, 인사 뒤 관계와 의뢰는 대상 원문대로. 문제를 거절해도 탐험과 일반대화 지속.
- 쉬운 관찰·수량 문항과 보통 논리 문항을 섞는다. 성인 플레이어에게 짧은 휴식형 수수께끼이며 신화시험·서버 비밀시험 아님. 난도별 차등 보상 없음.

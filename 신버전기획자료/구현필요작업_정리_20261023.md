# 신버전 기획자료 적용을 위한 구현 작업 정리

작성일: 2026-10-23 · 비교 기준: `behaivior` 브랜치의 MythicTRPG **1.0.41 소스**와 현재 AI 응답·콘텐츠 레지스트리 소스.

이번 결과물은 **검토 및 작업 목록**이다. 인물·퀘스트를 실제 게임에 등록하거나 코드·기존 기획·서버·월드를 변경하지 않았다. 아래의 ‘구현됨’은 기존 소스에 해당 기반이 있다는 뜻이며, **이번 새 콘텐츠의 등록·배포·실제 플레이 완료를 뜻하지 않는다.**

## 1. 검토 결과와 자료 범위

**기존 대화·Story·퀘스트·보상·전투 시스템을 재사용하되, 새 기획을 실행 형식으로 변환하고 실제 행동·소유권·본체·수신 증거에 연결하는 작업이 필요하다.** 기획 JSON을 그대로 데이터팩에 복사하는 방식으로 적용할 수 없다.

| 자료 | 확인한 범위 | 구현할 때의 의미 |
|---|---|---|
| 전체 인물 | 색인 772명, 네 범주의 기본·현행 상세 연결 | 772명을 모두 신이나 동시 출현 NPC로 만들지 않는다. 기록 전용·미탄생·봉인·비언어·현재 접촉 제한을 보존한다. |
| 상세 원고 | 자료에서 선언한 105패킷 범위와 범주별 현행 연결색인 | 기본 원문, 상세 채택, 역사적 비교값을 구별한다. 파일 수를 독립 퀘스트 수로 세지 않는다. |
| 현행 활성화 | 242명: 세계 해금197, 초기접근10, 제한접촉1, 직접접촉 A안1, 추가 이력 없는 초기 연결28, 순환조건의 최소 관측 분리5 | 242명을 즉시 출현시키라는 뜻이 아니다. 미포함 인물에게 같은 활성화 조건을 일괄 적용하지 않는다. |
| 공용 이야기 | 73장면, 14개 관계·성장 경로 분류 | 세계 진행·실제 개인 참여·MAIN·지식·보상을 분리한다. 루트를 직업이나 배타 캠페인으로 만들지 않는다. |

| 무기 전환 | 실제 무기13종: BC 평타10종, 커스텀 부채1종, 활2종 | 새 무기13종을 추가 지급하거나 모두 검으로 변환하는 작업이 아니다. |
| 전투 묶음 | 주요8건 C05/C07/C10/C11/C17/C26/T03/T04, 키메라, 공방·관우·보조전투 | 기술 시험 수호자가 있다는 사실로 이 전투들이 구현된 것은 아니다. T03/T04 비전투 완료를 유지한다. |
| 연출·지식 | 효과별 연출, 전투 판정 연결, 772명 기본 앎·현행 지식·73사건·242활성화 연결 | 저자 진실과 미래 분기를 NPC의 초기 지식으로 넣지 않는다. |

검토 중 수행한 정적 확인:

- 압축 해제 자료 **5,220파일**과 ZIP 6개의 내부 파일은 내용이 동일하다. ZIP과 해제본을 두 벌의 콘텐츠로 집계하지 않았다.
- JSON **4,155개** 구문 정상. 분할 폴더를 합친 논리 경로 중복 0.
- 루트 인물 색인의 파일 참조 **3,827건**에서 누락 0.
- `구현전달_참조색인.json`의 **70개 파일 참조·SHA-256 및 303개 JSON Pointer** 확인, 오류 0.
- 공통 계약·현행 연결·대표 개인 기획·전투 전환을 현재 파서와 실행 코드에 대조했다. 위 검사는 모든 문장의 정사·밸런스·전체 참조 그래프를 자동 검증했다는 뜻은 아니다. 게임·LLM·렌더·성능 시험은 이번에 실행하지 않았다.

## 3. 실제 구현 작업 목록

아래 W번호는 개발 작업의 참조 번호다. 게임 등록 ID나 신규 퀘스트 ID가 아니다. 한 작업에서 필요한 부분을 작은 범위로 연결하고 바로 인수시험한다. 앞 작업의 전체 인물 적용이 끝날 때까지 다음 검증을 기다릴 필요는 없다.

### W01. 원본 우선순위·ID 대응·실행 데이터 변환

- **기획/콘텐츠 작업:** 관리키 ↔ 현행 이름/정체 ↔ 원문 생산 God ID ↔ 실제 게임 God/NPC/Story Actor ID ↔ profile/lore/퀘스트/보상/전투 ID 대응표를 만든다. 동명 인물·이명·같은 인물의 여러 범주 참조를 구별한다. 기존 제안 ID는 근거 없이 개명하지 않는다.
- **시스템 작업:** 기존 파서에 맞춰 변환·검증한다. 새 필드가 정말 필요한 경우 해당 parser/record·생산자·소비자를 함께 확장한다. 기획 자료 자체를 런타임 파서로 무차별 로드하지 않는다.
- **완료 기준:** 선택한 인물의 네 범주·스킬·퀘스트·지식 참조가 실제 등록 ID 하나로 연결된다. 경로기반 ID·중복 ID·지원 enum·번역키·누락 참조 검사와 정상/오류 reload 확인. 옛 인물·기억·권리를 새 인물로 자동 합치지 않는다.

### W02. 공통 상태·시계·재시작 복구

- **시스템 작업:** 기존 SavedData/lease/claim/Story 원장을 바탕으로 담당 저장소를 정한다. 세계 해금, 추첨, 본체 예약, MAIN 소유, 완료 증거, 보상권, 실물 전달, 개인 수신 상태를 분리하되 같은 사실의 두 번째 원장을 만들지 않는다.
- 외부 효과 전 영속 의도/결과를 남기고 실제 entity·인벤토리·수령 기록과 대조하는 복구를 연결한다. DB와 인벤토리가 자동으로 같은 트랜잭션이라는 가정을 하지 않는다.
- 문서의 5종 시계에 담당 기능을 연결한다. 일반 스킬의 지정 tick 쿨과 현실24시간 특수쿨을 섞지 않는다. 완료/선택/이미 시작한 창·쿨은 설정 변경·재접속으로 초기화하지 않는다.
- **완료 기준:** 추첨 저장 직후, 본체 생성 직후, 재고 예약 직후, 실물 지급 직후, 수신 일부 완료 직후 재시작해도 중복/초기화가 없다. 결과 불명 상태는 대조 전 재실행하지 않는다.

### W03. 세계 해금·실제 현장·조우·단일 본체

- **현장/콘텐츠 작업:** 실제 설치 모드의 바이옴·구조물·차원과 자연 지형에서 부지/안전점/통로/왕복 앵커를 바인딩한다. 새 신화 차원이나 전용 건축을 일괄 전제로 삼지 않는다.
- **시스템 작업:** 242명 현재 채택과 나머지 개별 접근을 연결한다. 일반 풀은 적격 후보가 있을 때 경로 활동300초마다 서버1회, 성공25%, 해당 인물 다음 신규 출현은 가동1,800초 등 현재 채택값을 사용한다. 단계별 가중치·전용 조우 예외를 담당 JSON에서 읽는다.
- 실제 1인의 해금과 현재 당첨 주체를 분리한다. 친구 수가 인물 가중치나 추첨 횟수를 늘리지 않게 한다. PRESENT 본체는 같은 개체로 만나고, 미로드/불명 본체는 새로 만들지 않는다.
- 스핑크스의 사막 방문·밖60초·추첨10%·공용300초·정답 뒤 실제 안내 이행, 디오니소스의 별도 마을/활동 규칙을 일반 풀과 분리한다.
- **완료 기준:** 한 명이 해금하고 다른 적격자가 조우 가능. 같은 tick 진입·재접속·청크 경계 왕복으로 재추첨/본체 복제 없음. 최초 배치 전에 ‘그 NPC와 이미 대화했어야 함’ 같은 순환 조건 없음.

### W04. 페르소나·지식·대화 Context 연결

- **콘텐츠 작업:** 기본 프로필·원문 사례에 현행 성격/상황/관계 지침을 해당 범위만 반영한다. 자기 과거·취향·관계의 기본 앎과 아직 발생하지 않은 개인/본편 사건을 분리한다.
- **시스템 작업:** 기존 단계형 lore·Story Knowledge·방 청중·전달 영수증을 재사용해 현재 존재/접촉/표현 모드 → 실제 앎 → 청중별 공개 → 허용 행동 순으로 Context를 만든다. 전체 772명이나 작가용 스토리를 프롬프트에 넣지 않는다.
- 직접 관측·허용 전언·추론·미확인을 보존하고 정정은 실제 수신한 개인만 갱신한다. 전투 관전 표시나 공용 해금은 사적 지식·과거 참가권을 주지 않는다. 늦은 응답에는 기존 session/revision 재검사를 유지한다.
- **완료 기준:** 친한 사람/초면, 반말/정중한 위협, 강자/약자, 같은 파티의 허가자/미허가자, 발화 거절/비언어/접촉 없음 사례를 로그와 실제 LLM으로 검증한다. 고정 예문 재생을 자연스러움 완료로 보지 않는다.

### W05. 보상권·가호·제공 자격 보완

- **콘텐츠 작업:** 신별6등급·권능·허용 효과·priority·후보·기획 예산을 등록한다. 등급의 기술상한과 신규 보상 운영상한을 분리한다. 행운은 명시된 확률형 사건·아이템 풀에 연결한다.
- **시스템 작업:** B0~B5·직접 제작 장비 예외·최초/반복·선택·재고·실제 지급을 기존 보상 경로에 연결한다. 효과가 없어 보류된 가호가 다른 완료 보상 전체를 영구 차단하지 않도록 처리한다.
- 흡수 잔량과 재적용을 연결하고, 초기 여신 정의만 인간 경로 예외로 판정한다. `RAID_DIRECT`와 ‘레이드를 잡는 퀘스트의 보상’을 구분한다. LEGACY 출처를 추정해 예외화하지 않는다.
- **완료 기준:** 오프라인·인벤 부족·동시 수령·부분 전달·정의 변경·우유·사망·재적용·가호 보류에도 원래 권리·선택·수량을 유지한다. 행운은 세계유일품/신규 권리를 복제하지 않는다.

### W06. 개인 MAIN 소유와 FTB/Story 바인딩

- **콘텐츠 작업:** 각 인물의 MAIN/일반 의뢰/서비스/무보상 기록을 구분하고 실제 목표를 FTB 및 게임 바인딩으로 작성한다. 단순 대화·소개·주시를 수락으로 간주하지 않는다.
- **시스템 작업:** `world + provider + PERSONAL_MAIN`의 첫 유효 명시 수락자1명, offer revision, 도우미/참가자, 완료 후 별도 주시를 연결한다. 현재 다수 주시 수주 방식과 섞이지 않도록 이관 규칙을 정한다.
- 개인 진행은 서버 공용 완료/FTB 팀 진행과 구분한다. FTB는 기존 역할을 유지하고 최종 보상은 게임 claim에서 한 번만 지급한다.
- **완료 기준:** 두 명 동시 수락 시1명만 소유. 다른 사람은 허용된 도움·대화만 가능. 로그아웃·팀 변경·사망·포기 의사로 다른 사람에게 자동 이전되지 않는다.

### W07. 공용73장면·14루트·친구 합류

- **콘텐츠 작업:** 각 scene의 실제 행동/대안/분기/수량/증거/다음 입력/회복을 Story로 연결한다. OR·선택·조건부를 전부 필수 AND로 바꾸지 않는다.
- **시스템 작업:** 세계 변화와 개인 이동/열람/기여/지식/귀향을 분리한다. 조우·봉인 해제·주시·호의·가호·MAIN을 독립 검증한다. 실제 관계/가호/계약이 특정 레이드 참가를 막는 조건도 입장 때 재검사한다.
- 루트 라벨을 바꿔 기존 관계·원한을 초기화하지 않는다. 신수/흉수의 인정은 같은 개인의 실제4인정이며 파티 이력을 합산하지 않는다.
- **완료 기준:** 후발자는 현재 열린 길로 합류하되 과거 참가/최초 보상/비밀은 소급되지 않는다. 다른 루트 병행과 개별 적대 제한이 함께 작동한다. T03/T04 비전투 선택으로도 본편 진행 가능.

### W08. 장비·품질·수치·내구·제공자 등록

- **콘텐츠 작업:** 기본21콘텐츠·공방4정의 및 별도 본편/개인 정의를 실제 무기·방어구·도구·장신구·기술로 분류한다. 무보상/서비스를 아이템으로 변환하지 않는다.
- **시스템 작업:** SwordItem 중심 작성 규격을 필요한 종류만 확장하고 실제 속성·인챈트·사용 행동·전투력 평가를 같은 정의에서 생성한다. A0는 총 공격력, 현재 `attackDamage`는 무기 기여이므로 기본 공격력1을 중복하지 않는다.
- 신제 무한내구, 유한 예외, 대장장이 직접 제작 증거를 지원한다. 품질 이름7개와 신6등급·예산6개·보상 tier를 혼동하지 않는다. 기획 품질을 자동 능력치/새 저장 enum으로 만들지 않는다.
- **완료 기준:** 장비 구성요소·지급 receipt·획득 정체성·W/고유점수가 일치한다. 현물 변경은 기존 장비를 조용히 바꾸지 않고 새 정의/명시 이관으로 처리한다. 조정 원본은 기존 [밸런스 안내](../mythictrpg-main/docs/BALANCE_TUNING.md)에 연결한다.

### W09. 무기·습득 스킬·장신구의 개별 효과

- **시스템 작업:** 기존 공통 마나/쿨·시전 이벤트·선택 UI를 재사용한다. 아테나 성공 응수, 아르테미스 실제 투척/정지 사격, 망치 접촉호·흡수, 토르 전뢰, 부채 직격/조건부 도트, 여우 전투형태, 인간 기술의 준비/회수/종료를 개별 실행기로 구현한다.
- 형태 전환·방어 자세·이동·버프를 전부 고정 피해 한 종류로 흉내 내지 않는다. 출처별 modifier cleanup, 교체/사망/기절/차원이동, 발사 전후 취소 규칙을 적용한다.
- 장신구는 자유2칸·서로 다른 적법 권리 중첩·전투 중 교체를 유지한다. 시전 시작 스냅샷, 한 시전 연계1회, 종료 시 적중0일 때 환급, 권리별 쿨을 유지하고 음악·새 고유 효과를 추가한다.
- **완료 기준:** 동일 스킬 복사 무기로 쿨 우회 불가. 조건 실패 무소모, 승인 후 헛침/벽/면역 비용 유지. 방어/버프에는 공격 헛침 이벤트를 잘못 발행하지 않는다.

### W10. Simply Swords·Better Combat 전환 완성

- [현재 연동](../mythictrpg-main/docs/SIMPLY_SWORDS_INTEGRATION.md)을 기반으로 새10종 근접 외형/평타를 연결하고 부채1·활2는 예외 경로를 유지한다. 스킬 없는 장도/다짐망치에 새 우클릭 스킬을 붙이지 않는다.
- 고정 모드 버전·실제 profile parent/클립/양손/타점/콤보/다중대상 설정을 기획 전제와 대조한 뒤 `after_initial_design`을 적용한다. 다르면 전후표를 재산정한다. 기존 손으로 정한 평타 기하를 BC와 동시에 돌리지 않는다.
- D22 피해 순서, D11 양방향 입력 잠금·feint·교체·재접속 복구를 구현한다. 새 무기의 쌍수/보조 손 제한은 해당 기획 범위에만 적용한다.
- 원본 SS의 implicit뿐 아니라 룬/보석/인벤토리틱/전역 이벤트/재련/회복 등도 새 외형별로 검사한다. 원본 제작·전리품은 캠페인 권리를 발행하지 않게 한다.
- **완료 기준:** 장비13행과 구현인수33사례를 실제 모드 조합에서 검증한다. H01 A0=9·힘I·무인챈트·비치명·기획 콤보 조건의 방어 전 값 9.96/9.96/17.16 등 단계 로그를 맞춘다. 이는 CP 표시식이나 최종 HP 피해와 다르다.

### W11. 실제 전투·기믹·NPC 지원

- **콘텐츠/시스템 작업:** 기존 RaidRuntime·명부·보상·정리를 재사용해 주요8전투, 공방·관우·보조전투·키메라를 등록한다. 적 추가개체·다부위 본체·시야/벽·방어·패턴·경고·기믹 수행·현장 조작을 담당 원고에 결속한다.
- 지정 전투에만 공격자별10tick 차액 게이트를 적용한다. 8→4→10 입력은8/0/2, 서로 다른 두 소유자의8은16. 취소/무적 사건은 창·적중·흡수·연계를 갱신하지 않는다. 키메라 도트 예외와 C10/C11/C17/T03/T04 기존 정책을 보존한다.
- 토르 지원은 허용된 공방/협곡 두 전투만, 실제 본체 예약/동의/이동/복귀로 실행한다. 키메라는 결속된 살아있는 본체의 접근 통로·32블록/같은 차원 등 계약을 만족한 뒤 지원한다. 현재 표시용 분신으로 완료 처리하지 않는다.
- **완료 기준:** 전원 이탈·죽음·미로드·보스 소실·정리 실패·재시작·후발 참가·동일 본체 중복 지원과1~5인 조건을 실제로 확인한다. 레이드 HP 상향으로 입력/피해 오류를 숨기지 않는다.

### W12. 원본6·합일검·공용 시험과 결말

- **시스템 작업:** 원본별 물리UUID·현재 소유/보관·위임·사용권·소모/쿨을 연결한다. 원본 고유 능동7건의 준비·실제 효과·일반 사용과 기믹 조작의 차이를 구현한다.
- 분산/합일 선택, 여섯 소유자의 실제 동의와 지정 사용자 수락, 확정 전 철회, 확정 후 분해 불가, 합일 시 잃는 기능을 반영한다. 내구4096의 명시 변형·휴면·재료 수선·같은UUID 복구를 지원한다.
- C25와 C26의 서로 다른 순서/위치/40tick 조작·임계/최소 게이트를 구현한다. C22~C28 공용 시험·여신 응답과 무응답·세 결말·개인 귀향을 분리한다.
- **완료 기준:** 분산과 합일 모두 같은 본편 결말에 도달 가능. 원본 기능·동의·물체 인수·결말 선택권을 한 검 소유자에게 자동 합치지 않는다. 귀환룡 보상은 담당 정의에서 한 번만 정산한다.

### W13. 개인 사건·서비스·생활의 실제 행동 어댑터

- **콘텐츠/현장 작업:** 각 현행 상세의 `implementation_*`/구현요구를 기존 기능으로 대응하고 부족한 행동만 개발한다. 실제 이동·관찰, NPC/주민·동물, 대상 물품/재료, 장소/소유허가를 결속한다.
- **시스템 작업:** 제작·수선·반환/대여·위탁·거래·보고·편지 인수·실제 청취/공연·수업/출석·합의 대련 등 증거 생산자를 연결한다. 생활 표시권을 신가호나 영구 습득 스킬로 오분류하지 않는다.
- 디오니소스 포션 접수의 현실48시간·전체 유효 접수·a/b 선택 잠금/재선택·b 개인 신규1회와 같은 권리 복구를 구현한다. 성공권·MAIN·미수령 장신구에 새 마감을 붙이지 않는다.
- 에코/요정 관련 실제 비살상 포획·운송·인도·흡수 전 전원 최신 동의·철회 우선·실제 영구부재도 별도 구현한다. 역사적으로 부재인 인물의 새 본체를 만들지 않는다.
- **완료 기준:** 자연어로 ‘했다’고 말한 것만으로 완료되지 않는다. 수선/반환 실패 시 원물·원소유자·이미 소비한 재료를 보존하고 누락만 복구한다. 관계/팀 변경이 동의나 소유권을 대신하지 않는다.

### W14. 모델·애니메이션·음원·판정 시각화

- **자산 작업:** 스킬연출의 효과21개, 대표 검기 시편, 원본/합일검, NPC 본체·지원·보스 패턴에 필요한 모델/텍스처/클립/음원을 제작·연결한다. SS 평타 자산과 우리 커스텀 기술 자산을 구분한다.
- **시스템 작업:** 실제 서버 판정 형상과 클라이언트의 예고 외피·유해 코어·비판정 잔상에 공통 기하/시간 기준을 연결한다. 대표 검기는 12곡선 prism·연속 스윕·벽 우선 TOI·0~10블록 clip을 구현한다.
- 예고선·탈출선 우선순위, 벽/다층, 색·음성에만 의존하지 않는 구분,5인 장식 예산/LOD/늦은 패킷 정리를 적용한다. SVG/산술표/입자 시제품을 완성 렌더 증거로 삼지 않는다.
- **완료 기준:** 정면/측면/1인칭/3인칭/5인 영상과 castId·tick·판정·피해 로그가 일치한다. 실제 유해 범위가 장식과 모순되지 않는다.

### W15. 수치·전투력·자산·기능의 통합 검증

- 신6등급·장비7품질·B예산·실제 tier, 실제 공격력/공속·CP 평가값·고유점수·권리/착용 상태를 교차 검사한다. 기존 CP v2는 유지하며 품질/랭크만으로 점수를 자동 생성하지 않는다.
- 수치 원본은 장비/스킬/전투 JSON 또는 기능별 공용 설정에 둔다. 기획 비교표를 또 다른 실행 설정으로 복제하지 않는다. 이미 발행한 실물/선택 결과의 이관 영향을 함께 기록한다.
- 같은 모델을 여러 정의가 쓰는 경우, 같은 스킬을 여러 무기가 쓰는 경우의 영향 범위를 확인한다. 현재 SS/BC 자동 회귀 결과는 기반 기능의 증거이며 새13무기·본편 전투 통과로 전용하지 않는다.
- **완료 기준:** 가정 기반 산술과 실제1~5인 측정치를 분리하고,1/3/5표적·취소/교대·강한 가호·행운·지연/저TPS·모드 유무를 검증한다. CP 입장 하드컷·필수직업·세계 초기화를 추가하지 않는다.

### W16. 적용·배포·인수 기록

- **적용 작업:** 콘텐츠 원본·서버 데이터팩·로컬 설정·FTB 바인딩과 실제 우선 적용 리소스를 맞춘다. 보관소의 옛 프로필/Story를 활성 경로에 되살리지 않는다.
- **검증/배포 작업:** 선택 범위 변환 검증 → 관련 모듈 컴파일/핵심 시험 → 격리 서버 → 정확한 클라이언트 모드 조합 → 실제 플레이 순으로 진행한다. 문서만 바꾼 단계에는 Java 빌드를 반복하지 않는다.
- **완료 기준:** 소스/자동 검사/JAR/실제 설치/부팅/GUI·LLM·사람 플레이 상태를 각각 기록한다. 기존 월드·관계·기억·획득권 보존 후 이관하고, 운영 배포는 별도 작업 범위에서 수행한다.

| Q05 | 여우신 흡수 해방 | 특정 아이템·획득·사용 증거는 후속 저술, 해방 대상의 힘 복구 방식은 큰 결정이다. 기존 흡수 보호·성장 유지·현재 MAIN/본편을 막지 않는다. |
| Q06 | 신수·흉수 인정/용 발견 현장 | 같은 개인4인정·실제 행동·명시 선언은 확정. 개별 기준/단서·거처 바인딩은 기획/현장 작업이며 모두 사용자 승인 대기로 처리하지 않는다. |

이 표의 Q02~Q06은 [루트 접근 계약](04_퀘스트_1/퀘스트/공통설계/14루트_봉인과친구합류_기획.json)의 `unresolved_canon`에 근거한다. 기획 파일의 역사적 미정 문구가 최신 채택보다 우선하는 것은 아니다.

## 6. 권장 착수 순서

1. **작은 비전투 인물/장면 한 건:** W01의 동일 ID → 해당 범위의 W02/W03 접근·저장 → W04 허용 지식/성격 → 실제 대화·수신까지 연결. 보상 없는 대상에 시험용 보상을 새로 붙이지 않는다.
2. **실제 보상·개인 MAIN 한 건:** 기존 원고에서 대상 선정 → W05/W06/W13의 명시 수락·실제 수행·선택·실물·재개를 끝까지 검증. 동시 수락/재시작/인벤 부족을 함께 확인한다.
3. **실제 근접 무기와 개인 기술 한 건:** W08~W10에 W14 자산을 붙여 기존 SS/BC 조합에서 승인·타격·헛침·교체·보호 대상을 확인한다. 나머지13행은 검증된 공통 기반으로 확대한다.
4. **공용 초반과 첫 실제 전투:** C01~C05, 공방/관우 등 해당 의존 범위만 W07/W11과 연결하고 후발 친구·1~5인·보상 출처를 시험한다.
5. **본편 전체·원본·결말과 상세 인물 확대:** 공용73장면·W12·242활성화 및 나머지 개인 원고를 연결하고 W15/W16으로 종합 검증한다.

772명 전체 적재나 모든 보스/자산의 완성을 첫 실행 조건으로 삼지 않는다. 반대로 첫 인물 하나가 동작한 결과를 전체 콘텐츠 완료로 표시하지 않는다.
